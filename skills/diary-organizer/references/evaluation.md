# 维护与回归评估

本文件用于修改 Skill 后的验证，不是每次整理日记都要执行的步骤。

## 运行脚本测试

项目根目录执行，测试使用隔离数据库，不调用生产数据库或在线模型：

```bash
backend/venv/bin/python -m unittest discover -s skills/diary-organizer/scripts -p 'test_diary_storage.py'
backend/venv/bin/python -m unittest discover -s backend/tests -p 'test_organize_prompt_rules.py'
```

前者验证读取与保存职责、归属、格式、指纹、回滚等；后者防止 Skill 与后端共享语义规则漂移。契约检查不证明模型实际遵守语义。

## 文稿与交互评估

用例在 `evals/cases.json`（相对 Skill 根目录），全部为合成文本。每例包含输入、需要时的后续用户消息及人工核对标准。不要把核对标准交给执行整理的模型；在独立临时目录运行，不连接数据库。运行受保护来源或提交异常场景时使用隔离数据库或模拟工具，禁止借此操作真实日记。

每次规则修改先挑选相关用例，必要时扩展。记录实际模型、运行条件、输出文件、各项通过或失败及具体证据；没有运行的项目标为未运行，不填写虚构分数。语义试跑与脚本测试分别报告。

核对分为以下维度，不要求逐字相同，也不合并成一个掩盖错误的总分：

- 事实与完整性：输出中的人物、动作、时间、关系、结果和确定程度都有原文或用户补充依据；重要细节和思考转折保留。
- 标题人物角色：单独阅读标题，先判断行动、状态或观点归给谁，再核对原文；他人主体须明确，不能依赖正文消除误读。E24 检查他人购买和宠物随行；E25 检查结果型标题中的人物、送检者与维修者、他人身体状态与本人理解变化，以及未表达意图与已作决定的区别。两例均检查本人主体明确时允许自然省略“我”，不机械要求所有标题带人名。
- 个人表达：维持原文视角，去除无意义重复，保留有信息的反复和个人语气；句子自然通顺，指代清楚，事件归属、段落衔接及时间关系有依据。
- 标点与句子结构：标点准确呈现句界、并列、解释、转折和引用；直接引语的引号及句末语气标记完整；不通过标点擅自确定原文含混的事实关系。
- 派生字段：感受和反思不新增认识；计划须有明确未来意向；正文保留完整信息；各字段不相互矛盾。
- 重要性：按影响证据校准，主题、长短和独立成事件不决定等级，不设比例。
- 交互与操作：不凑四题，按回答重新筛选问题；保留用户改稿；局部回答不等于整篇确认；预检不等于保存；来源受限或状态变化时遵守停止条件。

交付前复读检查重点用例为 E19—E23，并结合 E11 检查指定修改范围的保护。分别检查无疑问初稿及用户澄清后的完整稿：表达问题直接修正，关键事实未明才提问，不以通顺为由补写关系或覆盖用户修订。E22 检查名称更正后是否仍修正全文中残缺的口述表达；E23 检查含混对象是否被擅自补成确定事实。评估实际交付文本与交互行为，不以模型声称“已复读”、读文件记录或格式预检通过替代质量判断，也不要求模型输出内部检查过程。

比较旧版与新版时使用同一用例及可比运行条件；可再加入无 Skill 基线。把模型判断不一致和确定错误分开：例如等级相邻但理由有依据，可记录为待校准；无依据补写已发生结果则是事实失败。

## 共享语义维护

保真、已表达的感受与反思、计划边界及重要性分级以本 Skill 为规则依据。后端 `backend/services/ai.py` 保持相同语义，提示词契约测试比较重要性与计划边界，其他语义还需用例验证。后端的展示标记、时间标签和自动流水线与聊天中的自然 Markdown、用户交互不同，不机械复制交互流程。

发现回归时优先做局部修正，再重跑相关用例；不添加固定调用次数、每句来源编号或额外审核产物。


## 修改后的联动复查与分项验收

- 合成原文同时表达找到原因后的轻松、剩余工作带来的疲惫：输出两个 feeling 元素；同一感受的原因与解释保留在一起。
- 合成原文表达两条独立认识：输出两个 reflection 元素；没有认识时为空，不补造。
- 用户把“我很愤怒”改为“我只是担心”：保留人工正文，感受栏不能保留失去依据的愤怒；不擅自解释为成长。
- 用户删除正文中的计划：检查整篇 plans 是否仍有其他事件依据或用户明确意图，不自动把所有计划清空。
- 文件和数据库同时修改同一段：保留两方当前文本，核实冲突；不自动用文件或数据库覆盖另一方。
- 云端首次整理保存后必须暂停；用户通知后无待澄清问题则完成复查与后续三阶段，不能再次等待逐稿确认。复查前后有新改动时重新读取。

以上为 Agent 的实际语义与交互评估场景；程序测试通过不代表内容质量已验证。
