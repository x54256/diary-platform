# Markdown 与转换协议

使用 UTF-8。固定顶层顺序为：全部事件、日记级分析、行动规划。事件 ID 是数据库 ID，标题原样复制。分析以 `- ` 列表表示，每项为完整段落，续行缩进两个空格。无内容时保留栏目标题并留空，不写“无”“暂无”或空列表项。问题解答使用四级标题及自然段回答。不要增加日期大标题、代码围栏或未定义的小标题。

以下为完整格式示例，事件 ID、原标题、内容与日期须替换为实际来源；示例不作为分析依据：

```markdown
## 事件：验证脚本参数

事件 ID：11111111-1111-4111-8111-111111111111

### 情绪分析

### 行为与决策分析

- 先缩小参数范围再逐步验证，能够让每次结果对应到具体修改，便于定位异常来源。

### 关注点与需求

### 可行动建议

- 用一组固定输入验证修改后的参数，并记录结果。

### 认知校准

### 问题解答

#### 问题：为什么每次只调整一个参数？

每次只调整一个参数，能减少多个变化同时影响结果时的归因困难。需要同时改变多个条件时，应明确记录变化组合和验证目标。

### 认知完善

## 日记级分析

### 情绪分析

### 行为与决策分析

### 关注点与需求

### 可行动建议

### 认知校准

### 认知完善

## 行动规划

### 行动：验证修改后的参数

- 来源：E1-S1 | 用一组固定输入验证修改后的参数，并记录结果。
- 全天：是
- 开始日期：2026-10-27
- 重复：NONE
```

## 分析栏目

每个事件必须有七个分析栏目，日记级必须有除“问题解答”之外的六个栏目。事件可按稿件展示顺序排列，转换器以 ID 校验完整覆盖，并按来源事件顺序输出 JSON。

正文允许 `**重点短语**` 和 `<red>风险短语</red>`。结构标题、列表符号由本协议提供；正文不再加序号或另设小标题。正文包含多段时放在同一列表项的缩进续行中，转换时保留换行。

JSON 结构为 `event_analyses`、`diary_analysis`、`action_items`。事件包含 `event_id`、`title` 及七类字段；日记级包含六类字段。分析字段是字符串数组，`question_answers` 是 `{question, answer}` 对象数组。保存脚本将这些字段映射到现有分析表，不改动后端接口。

## 行动来源

先保存事件、日记级分析及空的 `## 行动规划` 标题，再生成来源清单：

```bash
backend/venv/bin/python skills/diary-analyzer/scripts/markdown_to_json.py \
  diary-analyses/2026-10-27/分析稿.md \
  --source diary-analyses/2026-10-27/来源.json \
  --sources-only --output diary-analyses/2026-10-27/行动来源.json
```

- `P1`：来源中第一条后续计划，按后续计划原顺序编号。
- `E1-S1`：来源中第一个事件的第一条可行动建议。E 编号按来源事件顺序，S 编号按该事件当前建议顺序。
- `D-S1`：日记级第一条可行动建议。

每条行动至少一行来源：`- 来源：别名 | 原文连续摘录`；合并多个来源时逐行写出，不得重复同一别名。摘录中的加粗、风险标记也须与对应来源一致。建议修改或排序变化后，重新生成清单并核对全部行动来源；脚本不静默修复不匹配的摘录。

源文件只读；不得为创建行动来源而添加计划或将其他分析类型伪装为可行动建议。

## 推荐日程字段

前三项必填，其余按需填写；不适用的字段省略。省略字段在 JSON 中按下表默认值生成，不在 Markdown 中写 `null`。

| 字段 | 取值与规则 |
|---|---|
| 全天 | 是／否 |
| 开始日期 | YYYY-MM-DD，不早于来源冻结分析日期，预检和保存时也不得早于当前上海日期 |
| 重复 | NONE、DAILY、WEEKLY、MONTHLY_DATE、MONTHLY_NTH_WEEKDAY、YEARLY、WORKDAY、REST_DAY |
| 开始时间、结束时间 | 非全天时同时填写 HH:MM；结束晚于开始；全天省略 |
| 间隔 | 正整数，默认 1；NONE 时仅允许 1 |
| 星期 | WEEKLY 必填，例如 1,3；0 为周日，1 为周一，以此类推 |
| 月内日期 | MONTHLY_DATE、YEARLY 必填，1–31 |
| 月份 | YEARLY 必填，1–12；与月内日期组成有效日期，支持 2 月 29 日 |
| 第几个星期、星期几 | MONTHLY_NTH_WEEKDAY 必填，分别为 1–5、0–6 |
| 截止日期 | YYYY-MM-DD，不早于开始日期；与次数二选一 |
| 次数 | 正整数；与截止日期二选一 |

默认时间与循环定位字段为空，星期为空数组。NONE 不允许循环期限；其他循环类型只填写对应定位字段。自然持续事项的推荐频率按 [行动规划规则](action-planning.md) 判断，向用户表明这是可编辑推荐。

行动规划没有内容时保留空标题，不添加说明正文。完整转换使用上述命令去掉 `--sources-only`，输出改为 `分析结果.json`。转换器只做格式、来源与日程校验，不判断分析观点是否成立。
