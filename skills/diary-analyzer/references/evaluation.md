# 验证说明

## 脚本验证

在项目根目录执行：

```bash
backend/venv/bin/python skills/diary-analyzer/scripts/test_analysis_storage.py
```

转换验证覆盖：完整文档示例、列表与换行保留、空模块、多个问答、同名事件和不同展示顺序、遗漏和未知事件、标题改写、未知栏目、行动来源变更、连续摘录、循环参数及日期、稿件／来源／入库包指纹。

存储验证使用内存 SQLite，复制项目表结构并适配 PostgreSQL 类型与默认值，不连接项目数据库。覆盖首次分析资格、历史轮次拒绝、用户归属、删除／脏数据／过期来源、运行任务拦截、人物资料变更、只读 CLI 流程、确认指纹、单次保存、分析与行动的精确事件关联、元数据及事件内容保留、搜索索引、失败回滚。SQLite 不能验证 PostgreSQL 行锁竞争与真实网络连接；生产环境须继续使用脚本中的事务与行锁，不以本地测试替代它们。

Skill 格式可使用已安装的 `skill-creator/scripts/quick_validate.py` 检查；不自动安装其他依赖。检查所有相对文档链接存在，手动调用策略关闭隐式触发。

## 分析行为检查

首次真实使用时，在实际已整理且未分析的日记上只读导出并生成 Markdown，交付用户阅读；确认前不写入。复查以下场景：

| 输入特征 | 核对结果 |
|---|---|
| 只记录经过，无明确情绪或观点 | 对应模块允许留空，不为完整性补结论 |
| 某事件没有疑问，另一事件有疑问 | 问答只出现在有疑问的事件 |
| 用户表达经验或反思 | 认知完善以原观点为基础，解释含义、条件与边界 |
| 同一事件多种情绪属于同一主线 | 合并成连贯分析，不机械拆成多条 |
| 计划与建议表达同一行动 | 合并行动并保留两类来源 |
| 一句话包含可分别完成的动作 | 拆成独立行动，各有合法来源和推荐日程 |
| 用户只确认了某一条建议 | 继续修订或等待整篇确认，不写库 |
| 建议修改后行动摘录已失配 | 重新生成清单并更新行动来源，校验不通过时停止 |
| 稿件确认后跨日导致日期过期 | 修订推荐日期，重新预检并确认 |

格式校验和数据库测试不能证明分析观点成立。维护规则时同时核对代码中的实际提示词；当前后端 `test_analysis_prompt_rules.py` 中存在与实际规则失配的断言，这些断言不作为本 skill 已有业务规则。修复后端规则或扩展本 skill 的分析标准需另行明确范围。
