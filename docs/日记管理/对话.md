# 单篇日记对话

核对基线：2026-10-29 仓库代码。单篇日记对话用于围绕当前记录澄清问题、理解经历和继续反思。

## 1. 功能约定

- 对话绑定用户和来源日记，以 `source_type=diary_detail`、`source_id=日记 UUID` 保存。
- 用户可以创建对话、加载历史消息、连续发送消息；消息按创建时间排列。
- 当前事实上下文由该日记原文、整理标题、摘要、正文、心情和地点构成，叠加该对话历史消息。
- AI 对话采用问答和引导反思，模型来自管理端“对话”用途配置。
- 对话、消息与作为上下文的日记必须属于当前用户；删除日记不应继续成为普通用户对话的有效来源。
- 发送失败时前端保留尚未成功发送的输入，用户可以重试，避免留下重复的孤立用户消息。

## 2. 请求与事务

[对话路由](../../backend/routers/dialogs.py)提供创建对话、读取消息和发送消息三个入口。完整请求与返回字段见[对话 schema](../../backend/schemas/dialog.py)。

发送消息流程：

1. 校验对话属于当前用户。
2. 在当前数据库事务插入用户消息并 `flush`，使其进入本次历史上下文。
3. 按来源加载日记内容，组装上下文与按时间排列的消息。
4. 调用 [AIService.chat](../../backend/services/ai.py)，取得模型回复。
5. 插入助手消息并统一提交。模型调用失败时由会话回滚，用户消息不提前单独提交。

对话与消息数据模型见[Dialog / DialogMessage](../../backend/models/dialog.py)，会话边界见[数据库会话](../../backend/database.py)。当前接口接受日记详情和 AI 伙伴来源；AI 伙伴的产品设计独立维护。

## 3. 当前实现缺口

| 功能约定 | 当前行为 | 待处理事项 |
|---|---|---|
| 来源属于当前用户且未删除 | 创建对话未核实 `source_id` 的日记所有权；发送时按日记 ID 读取，未限定用户及软删除 | 创建和发送时均复核来源归属与有效性 |
| 来源有效、身份明确 | `diary_detail` 的 `source_id` 当前允许为空 | 确认是否允许无来源的日记对话，随后补齐入口校验 |
| 原需求允许参考近期日记 | 当前只读取当前日记与对话历史 | 将跨日上下文范围、用户隔离与引用方式列为未来设计，不把它写为已实现 |

旧文档曾要求“模型不可用时保留已保存用户消息”。当前事务实现将用户与助手消息作为一次提交，该目标与实现存在差异；本次保留当前事实及客户端保留输入的要求，不改变事务策略。

## 4. 长期规划与边界

原设计提出“24 小时无新消息后反哺人物画像、心路历程、认知洞察”。该能力归属于[数据飞轮规划](../知识库/应用规划/数据飞轮.md)，当前对话路径未实现自动沉淀。自我认知和 AI 伙伴的规划见[自我认知需求](../知识库/应用规划/自我认知.md)及[AI 伙伴需求](../知识库/应用规划/AI伙伴.md)。

## 5. 验收

覆盖本人日记多轮对话、历史顺序、刷新恢复、模型失败事务回滚及输入保留；同时覆盖伪造其他用户日记 ID、已删除日记来源和空来源。前三项来源缺口在修复前不能记为通过。
