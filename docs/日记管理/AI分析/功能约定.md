# AI 分析功能约定

本文定义应用内分析与分析 Skill 共同服务的业务设计。核对基线：2026-10-29 仓库代码及规则文件。当前能力范围与设计对应关系见[实现设计](实现设计.md)。

## 1. 分析目标与事实边界

输入以当前日记结构化事件为事实依据，人物资料用于理解身份、关系和指代。原文保留用于来源核对，不因保存于 State 就视作每个分析模型节点都接收了原文。

**指导思想：日记分析的目标是帮助用户认清自己。**

日记分析不是评价用户，也不是替用户下结论，而是帮助用户从当天记录中看见：

- 自己当时有什么情绪变化。
- 自己采取了什么行为和决策。
- 自己真正关注什么。
- 这些关注背后反映了什么当下需求。
- 自己如何理解这件事。
- 这件事反映出自己看重什么。
- 自己对世界、他人、自己、知识或方法的理解是否存在明显偏差。
- 自己随手记录的想法可以如何整理成更完整的知识框架。
- 自己在日记中提出的问题可以如何获得清晰回答。
- 接下来可以做什么低成本、具体、可执行的调整。

日记分析属于解释层，允许基于当天事实进行推导，但必须遵守以下边界：

- 只分析当天这篇日记，不引用长期历史。
- 不做长期人格判断。
- 不做心理诊断。
- 不给用户贴标签。
- 较强推断必须写依据，依据来自当天结构化日记中的具体事件或事实。

当前日记分析包含：

1. **情绪分析**：帮助用户理解情绪怎么来的，并找到改变路径，包括当下如何化解情绪、未来如何减少坏情绪和增加好情绪。
2. **行为与决策分析**：分析用户当天做了什么、做了什么选择、遇到问题时如何处理、行为带来了什么结果或可能风险，其中核心是判断问题处理方式是否有效，以及如何改进。
3. **关注点与需求**：分析用户当天真正关注什么、当下真正想要什么、正在维护什么，以及用户自己也可能尚未意识到的心理诉求和需求满足方式。
4. **认知校准**：识别用户对世界、他人、自己、知识、方法或事件因果的理解是否存在明显偏差，并在有依据时进行温和纠正。
5. **可行动建议**：基于前三类核心分析结果，给出事件级建议和日记级建议。日记级建议不必是事件级建议的合并，可以包含不归属于任何单个事件、但基于整篇日记整体分析得到的建议。
6. **问题解答与认知完善**：先找出并回答日记中的明确问题和隐性问题，再把日记中的零散知识、随想、判断、类比和问题解答结果，转化为更完整、可复用的认知体系。

### 情绪分析

帮助用户理解情绪怎么来的，并找到改变路径：当下如何化解，未来如何减少坏情绪、增加好情绪。

输出分为两层：

- 事件级情绪分析：展示在对应事件的 Tab 中。
- 日记级情绪总结：展示在分析 Tab 中。

情绪分析只基于结构化日记中的 events，不再回到原始文本查找额外依据。

分析内容：

- 用户出现了哪些主要情绪，属于好情绪、中性或轻度压力情绪，还是坏情绪。
- 情绪是如何变化的，强度如何。
- 哪些具体事实触发了情绪变化。
- 情绪背后反映了什么被触动，例如需求、边界、控制感、确定性、价值排序或自我叙事。
- 情绪背后的真实冲突是什么，例如人的期待与现实规律、控制期待与对象天性、个人需求与对方限制之间的冲突。
- 当下如何化解情绪。
- 未来如何减少坏情绪、增加好情绪。
- 可以区分表层情绪和更深层的情绪，但必须有事件依据。
- 如果某个事件没有明显情绪线索，事件级情绪分析返回空数组。
- 如果整篇日记没有明显情绪线索，日记级情绪总结返回空数组。

处理流程：

1. 识别事件中的主要情绪，区分好情绪、中性或轻度压力情绪、坏情绪，并判断情绪强度。
2. 找出触发情绪的具体事实，不脱离 events 推断。
3. 分析情绪背后的真实冲突，不只站在用户角度，也要看对方、对象或现实条件的客观规律。
4. 挖掘深层根因，例如期待落空、控制感丧失、边界被侵犯、不确定性、价值感受损、责任不清、想改造无法改造的对象。
5. 给出当下化解方向：好情绪分析如何更多创造，中性情绪分析如何转化为行动信号，坏情绪分析如何先降低扩大。
6. 给出未来预防方向：治标是解决这件具体事的根因，治本是通过工作方式、沟通方式、边界设置、预期管理、工具流程或心态调整，减少类似情绪再次触发。

禁止项：

- 不用百分比量化。
- 不做心理诊断。
- 不把短期情绪说成长期状态。
- 不写“你是一个情绪化的人”。
- 不输出无依据的深层解释。
- 不把改变目标写成强行改造他人、动物或不可控条件。

承接的自我认识角度：

- 情绪触发点。
- 控制感与不确定性带来的情绪反应。
- 当下化解方式。
- 未来预防方式。

### 行为与决策分析

帮助用户看清当天遇到问题时的处理方式，判断这种方式是否有效、有什么结果和风险，并找到更好的处理策略。

输出分为两层：

- 事件级行为与决策分析：展示在对应事件的 Tab 中。
- 日记级行为与决策总结：展示在分析 Tab 中。

行为与决策分析只基于结构化日记中的 events，不再回到原始文本查找额外依据。

分析内容：

- 用户先做了什么，后做了什么。
- 用户在关键节点做了什么选择。
- 用户遇到问题时怎么处理，这是本模块的分析核心。
- 用户是主动推进、等待观察、反复确认、寻求外部帮助、暂时回避，还是先处理情绪再处理事情。
- 行为背后体现出的当天应对方式，例如无效重复、短期压制、回避拖延、过度控制或误判问题机制。
- 行为带来了什么结果或影响。
- 可以评价行为有效性。
- 如果事件已有结果，基于结果评价。
- 如果事件还没有结果，可以基于当天事实适当推测后续风险。
- 下次更合理的问题处理方式是什么。
- 如果某个事件没有明显行为或决策线索，事件级行为与决策分析返回空数组。
- 如果整篇日记没有明显行为或决策线索，日记级行为与决策总结返回空数组。

处理流程：

1. 识别用户当天做了什么，以及做了哪些选择。
2. 找出用户遇到的具体问题，并把问题处理方式作为分析核心。
3. 判断当前处理方式是否有效：哪些部分解决了问题，哪些部分没有解决问题。
4. 识别做事方式类型，例如主动推进、等待观察、反复确认、寻求帮助、回避拖延、短期压制、过度控制、无效重复。
5. 分析行为已经带来的结果，以及继续使用该方式可能带来的风险。
6. 如果同一方式重复多次仍无效，要指出问题不是力度不够，而是处理机制可能不对。
7. 给出改进方向：保留有效部分，停止无效重复，换成更符合问题机制的方法。

禁止项：

- 不上升为长期人格。
- 不写“你一直都是……”。
- 不写“你有控制欲”“你是回避型人格”等标签。
- 不脱离当天事实分析行为模式。
- 不把风险推测写成确定结论。
- 不输出高成本建议。
- 不把无效重复解释成单纯不够努力。

承接的自我认识角度：

- 行为反应方式。
- 决策方式。
- 问题处理路径。
- 有效做法与无效做法。
- 行为风险与改进方向。

### 关注点与需求

帮助用户理解自己模糊、未说出口甚至尚未意识到的心理诉求，包括真正关注什么、真正想要什么、正在用什么方式满足需求，以及这种满足方式是否健康、稳定、可持续。

输出分为两层：

- 事件级关注点与需求分析：展示在对应事件的 Tab 中。
- 日记级关注点与需求总结：展示在分析 Tab 中。

关注点与需求分析只基于结构化日记中的 events，不再回到原始文本查找额外依据。

分析内容：

- 用户表面关注什么。
- 用户真正关注的是什么。
- 用户当下真正想要什么。
- 用户正在维护什么。
- 用户对这件事形成了什么理解。
- 这件事反映出用户看重什么。
- 用户没有说出口、自己也可能尚未意识到的心理诉求。
- 用户满足需求的方式是否健康、稳定、可持续。
- 可以分析未说出口的期待，例如希望对方主动回应、希望事情有明确进展、希望自己的投入被看见、希望责任边界更清楚。
- 可以写“你真正想要的是……”，但必须有事件依据。
- 如果某个事件没有明显线索，事件级关注点与需求分析返回空数组。
- 如果整篇日记没有明显线索，日记级关注点与需求总结返回空数组。

内部分析框架：

- 用户表面关注什么。
- 用户真正想要什么。
- 用户正在维护什么。
- 用户如何理解这件事。
- 用户看重什么。
- 用户是否存在自己尚未意识到的隐性需求。
- 用户满足需求的方式是否单一、脆弱或过度依赖外部反馈。

这些问题只作为内部分析框架，不必在展示层显式拆成小标题。输出时应使用自然段，帮助用户理解自己为什么会被这件事牵动。

处理流程：

1. 识别用户表面关注的内容，例如成绩、表现、输赢、对错、对方反应。
2. 从事件、情绪、行为和反复出现的在意点里，推断用户真实关注的内容。
3. 分析用户未说出口、自己也可能尚未意识到的需求，例如陪伴、连接、被看见、被选择、归属感、认可、安全感、掌控感。
4. 判断是否存在关注点错位：表面关注某个指标，实际想要另一种心理满足。
5. 分析需求满足方式是否健康、稳定、可持续，例如是否过度依赖某个人、某个反馈或单一快乐来源。
6. 给出更健康的满足方向：不是否定需求，而是拓宽需求满足路径，让快乐、价值感和支持来源更稳定。

常见分析方向：

- 真正想要什么：被回应、被理解、结果明确、责任清楚、关系稳定、事情推进。
- 害怕或抗拒什么：被忽视、不公平、失控、责任模糊、投入没有回报。
- 正在维护什么：边界、尊严、秩序感、投入感、公平感、掌控感。
- 如何理解这件事：用户把事件解释成什么，例如“我的表达没有被看见”“又是我一个人在推动”。
- 看重什么：效率、公平、尊重、确定性、责任、关系、自主性。
- 关注点错位：表面关注成绩、表现、对错，实际关注陪伴、连接、被看见、被选择或归属感。
- 需求满足方式风险：快乐来源过于单一、过度依赖某个人的反馈、把价值感建立在外部关注上。
- 更健康的满足方向：保留关系中的快乐，同时培养爱好、个人成长、稳定作息或更丰富的支持来源。

禁止项：

- 不做心理诊断。
- 不写长期人格结论。
- 不把推导写成绝对事实。
- 不写“你缺乏安全感”“你很依赖认可”。
- 对“填补内心空虚”这类强心理解释要谨慎，除非 events 有明确依据；更稳妥的写法是指出可能在寻求情绪陪伴、被关注、被选择或归属感。
- 不替用户扩展到原文没有支撑的人生经历。

承接的自我认识角度：

- 未说出口的期待。
- 边界感。
- 控制感与不确定性。
- 自我叙事。
- 价值排序。
- 关注点错位。
- 需求满足方式。

### 认知校准

识别日记中用户对世界、他人、自己、知识、方法或事件因果的理解，判断其中是否存在明显的过度概括、绝对化、误解、片面理解或事实性错误，并在有依据时进行温和纠正。

分析对象：

- 对世界的判断。
- 对他人的判断。
- 对自己的判断。
- 对事件原因的判断。
- 对知识点、方法论、工作方法的理解。
- 对经验教训的归纳。

允许项：

- 指出过度概括。
- 指出绝对化表达。
- 指出事实支撑不足。
- 指出知识理解错误。
- 补充更准确的理解。
- 把“情绪中的判断”和“事实可支持的判断”分开。

禁止项：

- 不否定用户感受。
- 不站在道德高地教育用户。
- 不把所有负面判断都改成积极话术。
- 不在不确定时强行纠错。
- 不对专业知识胡乱纠正。
- 不把认知校准写成行动建议。

与其他模块的边界：

- **关注点与需求**：解释“用户为什么这样看”。
- **认知校准**：检查“用户这样看是否准确、是否过度、是否需要补充”。
- **可行动建议**：给出“下次可以怎么做”。

处理规则：

- 对世界、他人、自我的整体判断，要优先区分情绪表达和事实可支持的结论。
- 对知识点、方法论、工作方法的错误理解，如果有足够把握，可以直接指出并补充更准确理解。
- 如果结构化事件信息不足或模型没有足够把握，应返回空数组，不能装作确定。
- 认知校准输出事件级和日记级两层：事件级结果展示在对应事件的 Tab 中，日记级结果展示在分析 Tab 中。
- 如果某个事件没有明显需要校准的判断，该事件认知校准返回空数组。
- 如果整篇日记没有明显需要校准的判断，日记级认知校准返回空数组。

### 可行动建议

基于前三类核心分析结果，给出用户下次遇到类似情况时可以尝试的低成本、具体、可执行行动。

输出分为两层：

- 事件级可行动建议：展示在对应事件的 Tab 中，只针对单个事件中能明确落地的动作。
- 日记级可行动建议：展示在分析 Tab 中，可以来自某个关键事件、多个事件共同呈现的问题、当天整体情绪/行为/需求分析，或不适合归属到单个事件的整体调整动作。

分析内容：

- 用户下次可以如何化解当下情绪、减少坏情绪触发、创造更多好情绪。
- 用户下次可以如何停止无效重复、保留有效方式、换成更符合问题机制的方法。
- 用户下次可以如何更健康地满足真实需求、减少单点依赖、拓宽快乐、价值感和支持来源。
- 用户下次可以尝试怎么表达。
- 用户下次可以如何降低不确定性。
- 用户下次可以如何区分事实、情绪和解释。
- 用户下次可以如何保护边界。
- 用户下次可以如何把需求说清楚。
- 用户下次可以如何推进事情的下一步小动作。

输出规则：

- 每条建议使用“下次可以尝试……”表达。
- 不限制建议数量，但只输出有依据、可执行的建议，不为凑数量生成建议。
- 可以基于 events 中的具体事实。
- 必须基于情绪分析、行为与决策分析、关注点与需求分析。
- 可行动建议是前三类分析的汇总落地，不重新做一套脱离分析依据的建议。
- 如果某个事件没有明显可行动建议，该事件建议返回空数组。
- 如果整篇日记没有明显可行动建议，日记级建议返回空数组。

处理流程：

1. 从情绪分析中提取情绪触发点、根因、当下化解方式和未来预防方向。
2. 从行为与决策分析中提取有效做法、无效做法、行为风险和改进方向。
3. 从关注点与需求分析中提取真实诉求、心理依赖、需求满足方式问题和更健康的满足路径。
4. 将前三类分析压缩成少量具体动作，避免重复分析。
5. 过滤掉无依据、泛泛而谈、高成本或不可执行的建议。
6. 按事件级和日记级分别输出：事件级建议针对单个事件，日记级建议针对整篇日记呈现出的共性问题。

承接的自我认识角度：

- 从自我理解走向下一次行动。
- 把情绪、需求、边界转化为具体做法。
- 把有效/无效做事方式转化为下次处理策略。

**建议的表达规则：

- 使用“下次可以尝试……”这类建议式表达。
- 不使用“你应该……”这类命令式表达。
- 建议服务于下一次遇到类似情况时的具体行动。
- 建议必须低成本、具体、可执行。
- 不输出泛泛而谈的鸡汤。
- 不输出高成本建议，例如辞职、结束关系、重大关系决策等，除非原文明确表达相关打算。

### 问题解答与认知完善

日记中有些内容不是事件复盘，而是用户在当下记录的随想、知识片段、模糊判断、类比、疑问或尚未想清楚的推理。问题解答与认知完善的目标，是先把日记中的问题回答清楚，再把零散知识和问题解答结果转化为更完整、可复用的认知结构。

认知完善不是认知校准。认知校准检查“这个理解是否准确、是否过度”；认知完善回答“这个念头可以如何变成更完整的知识体系”。

输出分为两层：

- 事件级问题解答与认知完善：展示在对应事件的 Tab 中。
- 日记级问题解答与认知完善：展示在分析 Tab 中，可以综合多个事件中共同出现的随想、问题和知识线索。

处理顺序：

- 先找出日记中的明确问题和隐性问题。
- 直接给出问题和回答，回答必须突出核心重点；复杂问题可以在回答文本内部简要拆解。
- 最后基于日记中的零散知识、随想、判断、类比和问题解答结果，整理成体系化认知。

问题解答内容：

- 回答日记中明确提出的问题。
- 识别并回答“我不知道……”这类隐性问题。
- 回答“这个有什么用”这类价值问题。
- 回答“这个该归到哪里”这类分类问题。
- 回答“这个到底好不好”这类判断问题。
- 如果问题没有可靠答案，拆成“能回答的部分”和“不能可靠回答的部分”。

认知完善内容：

- 把零散想法整理成概念、关系、因果链、适用边界和反例。
- 对日记中提到的知识点补充背景、分类、框架或理解路径。
- 区分事实、观点、推测和价值判断。
- 提炼可以沉淀下来的知识点。
- 给出后续可以继续理解的方向，但不把它写成行动建议。

输出规则：

- 只基于 events 和本环节前序问题解答结果，不输入、不引用原始文本。
- 可以使用模型已有的通用知识进行解释，但不能编造具体事实、数据、来源或确定性结论。
- 没有问题时，问题解答返回空数组。
- 没有需要完善的认知时，认知完善返回空数组。
- 如果问题需要实时信息、专业事实核查或日记信息不足，应拆成“能回答的部分”和“不能可靠回答的部分”。
- 不做心理诊断，不做长期人格判断，不输出行动建议。


## 2. 输出层次、元数据与标签

“六部分”是业务展示分组：问题解答与认知完善在存储中分别使用类型，当前一共七种分析类型。

| 分析类型 | 代码 | 范围 |
|---|---|---|
| 情绪分析 | `EMOTION` | 事件级、日记级 |
| 行为与决策分析 | `BEHAVIOR_DECISION` | 事件级、日记级 |
| 关注点与需求 | `SELF_UNDERSTANDING` | 事件级、日记级 |
| 可行动建议 | `ACTION_SUGGESTION` | 事件级、日记级 |
| 认知校准 | `COGNITIVE_CALIBRATION` | 事件级、日记级 |
| 问题解答 | `QUESTION_ANSWER` | 当前两条实现只生成事件级 |
| 认知完善 | `COGNITIVE_ENHANCEMENT` | 事件级、日记级 |

原业务定义包含日记级问题解答；当前应用内图谱分析校验排除日记级 `question_answers`，Skill 也只设事件级栏目。日记级是否增加问答仍是范围差异，不能以通用响应结构存在字段证明已生成。

元数据包括标题、摘要、地点、整体心情和事件标签。应用内普通分析生成这些值；反馈分析沿用上一轮元数据；当前分析 Skill 保留已有元数据、标签及心情，不把缺省或旧值称为本轮生成。具体输入输出见实现设计。

标签分为 `domain`、`topic`、`person_object`、`psychological`、`knowledge` 五类：

- 领域标签粗分类，例如工作、生活、健康、学习；主题标签串联具体事项，例如版本管理平台、遛狗。
- 人物 / 对象标签指向具体人物、关系与对象；心理主题反映有证据的关注、需求或情绪主题；知识标签指向方法、概念及知识点。
- 优先提取具体主题、人物对象、心理主题和知识点，领域作为辅助。标签依据来自来源明确内容，不能用“成长、感悟、重要、日常”等空泛评价填充。
- 心情已有独立字段，单纯开心或难过不作为标签凑数。
- 用户可以修改标签；页面按类型着色，日记级标签从事件标签去重汇总。

分析正文只读展示，通过评分和反馈推动下一轮修订；推荐日程和独立行动项的编辑属于行动管理。

## 3. 分析轮次与反馈

### 3.1 轮次与反馈对象

一篇日记可以拥有多轮历史分析，同一时间最多一个 `CURRENT` 轮次。每次普通分析或反馈分析成功后生成完整新轮次，上一轮变为 `ARCHIVED`，历史分析及反馈保留。

一个反馈对象由“当前分析轮次 + scope + event_id + analysis_type”确定，针对整个分析类型块，而不是某一条文本。例如“事件 A 的行为与决策分析”是一块。

- 评分为 1—5 星，文字意见可保存；1—3 星要求非空意见，4—5 星可直接保存。
- 同一用户对同一类型块最多一条反馈，再次反馈更新该条记录。
- 只有当前轮次允许保存反馈，资源及事件必须属于当前用户和目标日记。
- 保存失败明确提示并保留用户已填写内容，以便重试。
- 用户重新评分表示认可或重新评价当前内容，`is_inherited=false`。

### 3.2 反馈模式与继承

有效反馈需同时满足 `rating <= 3`、意见非空、`is_inherited=false`。没有有效反馈时，应用内执行普通分析；存在有效反馈时，应用内采用反馈模式，沿用元数据、标签和未命中的分析内容。

反馈模式仍保存完整新轮次：被重写块使用新结果，其余块沿用旧结果。历史反馈复制到新轮次；被修改块的复制反馈标为 `is_inherited=true`，等待用户重新评分，未改写块为 `false`。`source_feedback_id` 保留继承来源。

旧需求要求反馈只影响对应块，例如事件 A 的行为反馈不影响日记级行为总结；当前应用内实现会同时重写日记级同类型分析。此设计差异单列在实现设计，不能将两种规则混写为同一约定。Skill 第一版不支持反馈重分析。

### 3.3 页面交互

- 分析类型标题旁提供星级入口；低分展开意见输入框，高分可立即保存。
- 已评价块显示“已反馈 / 修改”，可查看和编辑完整意见。
- 复制反馈对应的新内容显示“已修改 / 重新评分”，旧星级不代表用户认可新内容。
- 用户重新评分后恢复为当前评价状态。

## 4. 行动规划与衔接

核心分析的“可行动建议”是分析文本。行动规划进一步根据整理后的后续计划和本轮建议生成独立行动项，保存来源摘录、关联建议、推荐日期与循环规则。

- 先完成核心和认知分析，再规划行动；每条行动可独立安排和完成，同一建议拆出的动作保留共同来源。
- 来源摘录必须是输入中的连续文本，不能凭模型重写猜测关联。
- 区分日记日期与冻结分析日期，以 `Asia/Shanghai` 理解相对时间；推荐安排不能写成用户已经承诺的计划。
- 推荐日程保存于行动项，不自动创建正式日程；同步需要由用户执行。
- 具体行动生命周期、同步和来源约束见[日记行动项需求](../../行动管理/日记行动项功能约定.md)及[联动设计](../../行动管理/日记行动项实现设计.md)，文件中的实现状态由行动管理模块单独核对。

## 5. 保存、保留与验收

分析轮次、条目和反馈须按用户隔离，旧轮次保持可追溯；备份恢复保留历史轮次、分析项、反馈继承及日记软删除字段。日记软删除和来源锁规则统一见[录入与维护](../录入与维护.md)。

验收覆盖：

- 事件级分析只依据当前事件；日记级结论有跨事件或整篇依据，不能由单一事件上升为长期人格。
- 每类分析符合本文件定义，空内容返回空数组，问题答案不编造实时或专业事实。
- 事件定位使用稳定 ID，原标题一致，完整覆盖所有输入事件；同名事件互不串位。
- 多次分析保留历史，最多一个当前轮次；反馈低分意见、高分直存、继承待评分和失败输入保留符合约定。
- 结果只有正式保存后才算完成，本地稿件和预检不等同于数据库写入。
- 两种实现分别验证其已支持范围，不以一条路径通过证明另一条路径已对齐。
