# 日记管理

核对基线：2026-10-29 仓库代码。本文用于后续开发和维护，定义模块边界、设计入口与实现关系。各能力的业务约定、当前实现及待确认差异在对应文档中维护。

## 1. 模块职责

日记管理保存用户的原始记录，将内容整理为结构化日记，基于事件进行分析，并提供浏览、收藏、批注和单篇日记对话。日记原文、用户表达与 AI 推导分别保存，页面应让用户辨别其来源。

同一天允许存在多篇独立日记；所有数据按用户隔离。软删除记录不进入普通列表和详情。业务正文、个人分析和模型认证信息不得泄露到普通错误响应。

## 3. 设计与两种实现的关系

AI 整理和 AI 分析均有应用内及 Skill 两种实现。功能设计描述输入、输出、事实边界和验收要求；具体实现分别负责模型调用、人工交互、预检、保存与恢复。

| 方面 | 应用内实现 | Skill 实现 |
|---|---|---|
| 入口 | 用户页面调用 FastAPI，创建后台任务 | 用户显式调用对应 Skill，或完整日记流程进入相应阶段 |
| 处理 | 服务端模型配置、提示词、持久化任务及状态轮询 | 当前稿件、规则文件、澄清与整稿审阅、转换和预检脚本 |
| 整理保存 | 流水线完成后事务写入 | 本地稿件完成后绑定来源、稿件指纹并按确认结果写入 |
| 分析保存 | 建图与分析闭环完成后统一发布 | 当前仅支持首次分析，保留已有图谱与元数据，独立保存分析和行动项 |
| 失败恢复 | 任务状态、checkpoint、冻结配置与来源快照 | 当前稿件、来源导出、入库包和实际保存回执 |

两种路径使用共同数据库模型，但支持范围、人工确认方式及输出并未完全相同。具体差异以各能力的对应表为准。规则文件和源码是各实现的执行入口，本目录负责说明两者如何满足设计及何处仍有差异。

## 4. 主流程与模块衔接

```text
文字录入 / 语音转写 → saved → AI 整理 → organized → AI 分析 → analyzed
                                      ↓                    ↓
                                 浏览、收藏、批注       分析反馈、行动、对话
```

- 语音入口在首个音频上传成功时创建并绑定日记，开始转写时提交日期及已有文本快照，全部转写完成后更新同一日记的完整原文。批次、音频项及恢复机制见[语音录入需求](语音录入/功能约定.md)和[语音录入设计](语音录入/实现设计.md)。
- 知识图谱使用稳定事件 ID 和结构化来源。应用内分析已通过图谱任务接入；事件要点、向量和关系规则见[知识库文档](../知识库/README.md)。日记管理只说明衔接和一致性边界。
- 分析产生可行动建议，行动规划将后续计划和建议转换为独立行动项。用户确认同步后才创建正式日程；领域规则见[日记行动项需求](../行动管理/日记行动项功能约定.md)和[联动设计](../行动管理/日记行动项实现设计.md)。这些文件中的实现状态还需由行动管理模块单独核对。
- Skill 总入口衔接整理、要点、关系、分析，执行边界见[日记工作流](../../skills/diary-workflow/SKILL.md)。
- 模型、渠道和环节用途由管理端配置；备份恢复需保留原文、整理结果、分析历史、反馈、软删除字段及关联记录。

## 5. 核心数据与代码边界

| 对象 / 位置 | 职责 |
|---|---|
| `Diary` | 日记日期、原文、状态、内容修订、脏标记、软删除 |
| `DiaryOrganized`、`DiaryEvent` | 当前结构化结果、结构化修订、有序事件及事件重要性 |
| `OrganizeTask` | 整理 / 分析对用户展示的任务进度与结果 |
| `GraphTask`、`GraphRun` | 应用内建图及分析调度、来源冻结、恢复与发布 |
| `AnalysisRun`、`AnalysisItem`、`AnalysisFeedback` | 分析历史、类型块、当前轮次和反馈继承 |
| `Favorite` | 一条收藏指向日记或事件之一 |
| `DiaryAnnotation`、`DiaryAnnotationComment` | 选区、评论、合并及失效记录 |
| `Dialog`、`DialogMessage` | 用户所属来源对话与消息历史 |

数据模型见[日记模型](../../backend/models/diary.py)、[图谱模型](../../backend/models/graph.py)、[收藏模型](../../backend/models/favorite.py)和[对话模型](../../backend/models/dialog.py)。

前端入口为[首页](../../frontend/pages/index.vue)、[录入页](../../frontend/pages/diary/new.vue)、[日期页](../../frontend/pages/diary/date/[date].vue)和[详情页](../../frontend/pages/diary/[id].vue)。后端业务入口为[日记路由](../../backend/routers/diaries.py)、[对话路由](../../backend/routers/dialogs.py)和[Skill API](../../backend/routers/skill_api.py)。完整字段与请求结构引用[日记 schema](../../backend/schemas/diary.py)，数据库约束见[数据库设计](../系统架构/数据模型与迁移.md)。

## 6. 维护与验证

- 修改事实表达、输出结构或事件粒度时，同时核对应用内提示词、Skill 规则、转换器和前端渲染。
- 修改状态、修订或写入机制时，同时核对正在执行的任务、分析 / 图谱来源锁、人工修订与已有用户关联。
- 所有移动端可编辑控件实际字号至少 `16px`；修改表单后验证 iOS Safari 聚焦不自动放大，并保留用户缩放能力。
- 历史审计和试跑材料只提供当时证据。仍有效的结论需核对后进入当前能力说明，有效排查约束和仍待验证问题已沉淀至两份 AI 实现设计。
