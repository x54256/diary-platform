# 语音录入功能约定

核对基线：2026-10-29。本文定义语音录入的业务行为、交互与验收；处理机制见[实现设计](实现设计.md)。日记的通用状态与编辑规则见[录入与维护](../录入与维护.md)。

## 1. 范围与输入

用户在日记录入页选择归属日期，输入文字并添加一段或多段录音。系统上传文件、异步转写，再把原输入文字与全部有效录音的识别结果合并到同一篇日记。用户离开页面后，后台继续执行。

- 文字输入与语音可以混用；纯文字仍由用户点击保存后创建日记。
- 使用录音文件上传；浏览器录音、实时流式识别、说话人分离及音频长期附件不在当前范围。
- 同一天允许多篇日记；语音批次的日期锁只约束同一环境、同一用户、同一日期的活动批次。
- 当前实现通过应用内页面与后端执行。录音转写完成后，AI 整理、分析按各自入口执行。

## 2. 日记与批次的关系

一批语音关联一篇日记，多个音频项属于同一批次。用户已确认保留提前创建日记、完成后更新正文的实现方式；具体时点经代码核实如下。

| 时点 | 批次行为 | 日记行为 |
|---|---|---|
| 选择文件并创建批次 | 保存日期和当时的输入文字，进入 `COLLECTING` | 仅创建批次时不创建日记 |
| 首个文件上传成功 | 保存音频项并绑定 `diary_id` | 创建 `saved` 日记，正文先保存批次的输入文字 |
| 点击开始转写 | 固定最新日期、文字快照及音频顺序，进入 `QUEUED` | 更新已绑定日记；旧批次没有日记时补建 |
| 全部有效音频成功 | 最终化批次为 `COMPLETED` | 将完整合并文本更新到同一日记 |

批次、音频项是运行期数据；日记是正式业务记录。列表和详情可以展示“已上传录音”“录音转写中”“部分录音转写失败”等语音派生状态，数据库中的日记业务状态仍为 `saved`。

旧文档中的“全部成功后才创建日记”已被上述约定替代。失败、过期和取消的遗留交互差异单独列于第 9 节。

## 3. 文件与顺序

- 单文件默认上限为 300 MiB，即 `314572800` 字节。前端提示仍使用“300 MB”；后端上限由运行配置控制。
- 页面不设固定文件数量上限；容量、网络和提供方模型规格仍约束实际处理能力。
- 应用未实现单独的音频时长校验，时长限制遵循所配置提供方的有效规格。
- 允许格式：`aac`、`amr`、`avi`、`flac`、`flv`、`m4a`、`mkv`、`mov`、`mp3`、`mp4`、`mpeg`、`ogg`、`opus`、`wav`、`webm`、`wma`、`wmv`。
- 前端先检查文件大小和扩展名；后端还检查 Content-Type、空文件和实际字节数。提供方最终决定能否识别。
- 默认按浏览器提供的最后修改时间升序排列，同时间按文件名排序；浏览器不提供真实文件创建时间。
- 收集阶段允许拖拽或上移、下移调整顺序。全部上传完成后才能开始转写；开始后顺序固定。
- 多个文件独立上传，前端最多并行上传 3 个。识别的后台并发与上传并发分别控制。

## 4. 文字合并

开始转写时的输入框文字记为 `base_text`。最终正文按以下顺序生成：

```text
base_text

排序第 1 项的转写文本

排序第 2 项的转写文本
```

各段去除首尾空白；空段跳过；非空段之间保留两个换行。顺序以用户确认的 `sort_order` 为准，不取决于上传或识别完成顺序。部分成功时不将成功音频文本提前写入正式正文。

## 5. 用户流程与交互

### 上传与开始

1. 用户选择日期、输入文字、添加音频，页面展示文件名、大小、上传进度和结果。
2. 上传失败或格式不支持的本地项必须移除或重新选择后，才能开始。
3. 用户调整音频顺序并点击“开始转写”。
4. 页面固定日期、文字与文件顺序，展示排队和识别状态；保留返回入口。
5. 同日期已有活动批次时，拒绝重复开始；其他日期仍可记录日记。

### 全部成功

- 全部未删除音频至少有一项且均识别成功，后台才把完整合并文本写入绑定日记。
- 前端收到 `COMPLETED` 与 `diary_id` 后读取该日记，并用替换导航进入详情页。
- 前端不另行调用日记创建接口，不模拟点击保存。
- 页面关闭、暂停轮询或离开录入页均不影响后台处理。

### 失败、重试与删除

- 仍有排队或运行项时继续处理；所有项结束且至少一个失败时进入 `PARTIAL_FAILED`。
- 展示成功项只读预览和失败项摘要。成功文本在批次完成前保存在运行期数据中。
- 用户可重试单个失败项或全部失败项，复用仍存在的音频；成功项不重复提交。
- 失败音频默认保留 7 天；超过保留期后重试返回过期提示。
- 仅 `UPLOADED`、`FAILED` 音频允许删除；删除失败项后重新评估批次。
- 剩余有效音频全部成功时完成正文合并；没有有效音频时取消批次，不另外以 `base_text` 新建日记。
- 已提前创建的日记不会由批次过期或删除音频流程自动移除。

### 页面状态获取

页面通过轮询读取任务；隐藏时停止安排轮询，恢复可见时立即刷新。任务终态停止轮询。当前正常轮询间隔及错误重试间隔见[实现设计](实现设计.md)，不把轮询作为保存触发条件。

## 6. 个人词表

热词、人物姓名与常用名按用户组成 ASR 词表；定义与维护规则见[热词与人物关系](../../个人资料/热词与人物关系.md)。

设计要求同一批次的音频使用一致的词表内容，资料更新应影响后续批次。当前实现只在首次提交前固定本地词表 ID 与指纹，后续音频复用该绑定，尚未为远端词表提供不可变版本隔离。同用户后续批次会更新同一远端词表，旧批次未提交的音频也能读到更新后的内容；此处仍有实现差异。模型不支持热词时跳过该参数继续转写；不能让一个用户的词表参与其他用户的识别。

## 7. 数据、保留期与权限

- 批次、音频项及日记均按当前用户隔离；其他用户的任务返回不存在。
- 文件保存在 MinIO，原文件名仅供展示，真实对象键由服务端生成。
- 提供方凭据由管理端模型配置维护；前端响应不返回 API Key、对象键、签名下载地址或完整提供方响应。
- 音频成功后尽快删除对象；失败音频保留期默认 7 天。删除失败不撤销已保存的业务结果，由后台清理补偿。
- 未开始批次超过 24 小时清理；`COMPLETED`、`CANCELLED`、`EXPIRED` 元数据默认保留 30 天后删除。
- 完成时清除批次 `base_text` 和音频项转写全文，最终正文保存在 `diaries.original_text`。
- 正式日记随日记备份导出；语音批次、音频项和 MinIO 对象属于运行期数据。数据库恢复前须处理活动批次与音频，具体以备份实现为准。
- 服务重启恢复针对原数据库和持久化存储保持的部署重启；数据库恢复与语音任务恢复分别处理。
- 音频、转写全文、密钥和完整签名地址不得进入普通应用日志；日志保留批次、音频项及提供方请求标识用于排查。
- 移动端可编辑控件实际字号至少 `16px`，不得禁止用户缩放。

## 8. 验收标准

以下为需保持的行为检查，不代表本次重写已执行提供方实测。

- 大小边界、空文件、扩展名与 Content-Type 校验明确，存储失败不破坏其他已上传项。
- 上传成功后仅绑定一篇日记，开始和完成均复用该日记；并发上传、重复轮询及重复最终化不重复建日记。
- 文字与多段音频按确认顺序合并；并发完成顺序不改变正文。
- 离开页面不影响完成；处理中的同日期受到限制，其他日期不受影响。
- 部分失败不提前合并转写全文；重试、删除失败项后可完成，已成功项不重复消耗识别调用。
- 提交结果未知不自动重新提交；服务重启后按已有提供方任务恢复查询。
- 词表构造去重、稳定指纹、同批次复用和不支持词表的降级正确。
- 对象清理失败不回滚日记；过期、取消、终态保留期和权限隔离可核验。
- 前端完成后通过已返回的 `diary_id` 进入详情，不重复保存。

## 9. 已核实的设计与实现差异

| 原约定或界面 | 当前实现 | 处理边界 |
|---|---|---|
| 全部成功才创建日记；失败时没有正式日记 | 首个音频上传成功即创建日记，后续成功更新正文 | 用户已确认保留提前创建方式，本文已按实际三阶段说明 |
| 已开始批次仍可取消并恢复原输入 | `cancel_batch` 只要已有 `diary_id` 就返回 `409`；正常首个成功上传后即触发此限制 | 运行中取消仍是未解决的功能差异，不以代码拒绝等同于目标取消能力 |
| 部分失败面板显示“尚未创建日记”，提供取消按钮 | 已绑定日记存在，取消接口拒绝 | 文案和按钮需与提前创建方式协调；本次只改文档 |
| 同批次使用一致词表，资料更新只影响后续批次 | 仅固定本地 ID/指纹；后续批次可更新同一远端词表 | 需补远端版本隔离或等价协调，当前不能承诺内容快照不变 |
| 页面每 2 秒轮询 | 当前正常 20 秒、状态更新错误后 4 秒，恢复可见时立即刷新 | 实现说明记录实际周期；业务成功不依赖频率 |
| 过期批次清除全部对象键和敏感业务数据 | 转写全文和 `base_text` 清理；对象删除成功后清键，删除失败可能留下待补偿键 | 对象与元数据清理必须分别核验 |
