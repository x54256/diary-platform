# 录入与维护

核对基线：2026-10-29 仓库代码。本文集中定义日记的身份、创建、编辑、来源版本和删除约束；内容表达及页面展示分别见各能力文档。

## 1. 创建与身份

- 一条日记属于一个用户，以日记 UUID 定位，同一天允许多篇；按日期选择时须区分多条记录。
- 手工输入或语音转写形成原文，创建后直接进入 `saved`。用户选定日记归属日期，日期用于后续相对时间理解。
- 原始文本作为事实依据保留，整理结果和 AI 分析独立保存。原文中的命令、引语和对 AI 的讨论属于日记内容。
- 业务约定要求原始文本具有有效内容。当前 `DiaryCreate` 仅声明字符串，后端创建接口未校验去除空白后的非空性，属于待补齐的接口校验。
- 语音入口在首个音频上传成功后创建并绑定 `saved` 日记；开始转写时保存日期及已有文本快照，全部完成后更新同一日记的完整原文。转写期间的状态和限制见[语音录入需求](语音录入/功能约定.md)。

## 2. 状态与来源锁

基本状态路径为 `saved → organized → analyzed`。任务状态独立记录，不能只从日记状态判断能否写入。

| 状态 | 原文与日期 | 再次整理 | 分析 | 删除 |
|---|---|---|---|---|
| `saved` | 可编辑，仍须通过任务与来源锁校验 | 可执行 | 整理完成后执行 | 无活动任务时可软删除 |
| `organized` | 来源未冻结且无活动任务时可编辑 | 来源未冻结且无活动任务时可执行 | 可创建分析任务 | 无活动任务时可软删除 |
| `analyzed` | 锁定 | 锁定 | 应用内支持重新分析；分析 Skill 当前仅首次分析 | 当前接口禁止删除 |

来源锁的当前实现：

- 正在分析或建图时，来源写入被拒绝。
- 任意图谱运行已经保存来源快照，或日记已经分析完成时，`content=True` 的写入被拒绝；冻结发生在结果发布前，失败任务也不会自动解除来源锁。
- 原文、整篇结构化内容、事件标题 / 正文 / 感受 / 反思等写入都受内容锁约束。单事件的重要性覆盖属于另一写入分支，不能据此推断整个事件仍可编辑。
- 同一用户的分析与建图任务由用户锁串行控制；整理还需检查当前日记的运行任务。

旧需求曾要求“已分析日记仍可编辑结构化结果，并提示重新分析”；当前来源锁拒绝这类写入。该差异保留为待确认设计，文档整理不改变锁定策略。

## 3. 原文和结构化修订

- 原文更新与结构化更新采用不同版本：`content_revision`、`structured_revision`。整理记录保存其对应的 `source_content_revision`。
- 已整理日记修改原文后，`is_dirty=true` 表示整理结果需要更新。结构化结果有效性需结合修订号检查，不能仅依赖页面状态。
- 结构化结果按字段更新；未提供字段保持原值。事件通过稳定 UUID 关联，不能按标题或数组顺序猜测身份。
- 结构化内容发生变化时递增 `structured_revision`，并重新生成展示 Markdown。正文、感受和反思按有序数组保存，接口负责兼容数据库中已有的 JSON 字符串。
- 内容字段更新会使对应字段的旧批注失效，详见[批注](批注.md)。
- 整篇重新整理会重建事件；应用内实现会清理旧事件的相关记录，Skill 整篇保存会先检查并拒绝存在用户关联的替换。差异详见[整理实现设计](AI整理/实现设计.md)。

## 4. 删除与保留

当前删除接口禁止 `analyzed` 日记，并在运行中的整理、分析或建图任务存在时拒绝删除。其他符合条件的日记通过 `deleted_at`、`deleted_by` 软删除。

软删除后：

- 普通列表、日历、收藏和详情不再返回记录；也不得继续编辑、整理或分析。
- 原文、整理结果、事件、分析轮次、反馈和任务记录保留，供数据一致性与备份恢复使用。
- 该日记及所属事件的收藏关系被移除。
- 管理员查看、恢复、物理清理属于原需求保留的后续能力，本模块当前未提供相应用户操作入口。

旧反馈需求中的软删除描述以“保留历史数据”为目标，不能据此绕过当前“已分析不可删除”的入口限制。若后续开放删除已分析记录，需一并定义图谱证据、行动项与历史引用的处理。

## 5. 权限与一致性

- 按 `diary_id + user_id + deleted_at IS NULL` 定位日记；事件、标签、收藏、批注和任务必须属于当前用户及目标日记。
- 创建、编辑、删除的事务由路由提交；后台整理使用独立会话，保存时重新读取并锁定日记。
- 原文修改和后台结果发布必须使用相同来源版本，失败重试不能静默覆盖新的人工修改。
- 当前整理 checkpoint 按任务 ID 复用，缺少原文和日期的严格版本指纹校验。失败后来源变更仍可能复用旧中间结果，见[整理实现的待处理差异](AI整理/实现设计.md#6-已核实差异与待处理问题)。
