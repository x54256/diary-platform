# 多轮澄清验收场景

来源：2026-10-21 的两个合成对照场景。下列输入和模拟回答供后续开发复用，规则以[整理功能约定](../AI整理/功能约定.md)为准。

共同前提：无日记日期、无音频，仅本地整理。每轮更新当前稿与已解决/未解决问题；所有事实问题解决后仍需整篇确认。

## 场景A

### 初始输入

```text
请按日记整理 Skill 整理以下日记。仅本地整理，不入库，没有音频，不访问数据库或网络。没有日记日期；这些工作彼此独立，系统、客户和项目名称均需准确。五个名称的转写我没核实，但正确写法我都能提供。
上午给“卡诺”系统补了导出接口，测了一百条没问题，批量的还没测。
下午跟“阿莱”客户开会，确认先做查询，再做导出，具体字段还要等对方发来。
随后给“维塔”项目部署，第一次启动失败，发现端口被占，换端口后启动了。
晚上评估“达摩”模型，回答比原来的快，但有两次漏字段，暂时没决定换。
最后给“希尔”平台提交工单，附了启动日志，对方说先排查，还没回结果。
```

### 依次模拟回答

1. 1 卡诺系统；2 阿莱科技；3 维塔工程；4 达摩模型。以上是这四个名称的准确写法。
2. 平台准确名称是希尔云。

### 预期行为

事实问题数量为4→1→0。首轮问前四个名称，第二轮仅问希尔平台；不猜第五个名称，不重复已解决项。最终采用卡诺系统、阿莱科技、维塔工程、达摩模型、希尔云平台。

## 场景B

### 初始输入

```text
请按日记整理 Skill 整理以下日记。仅本地整理，不入库，没有音频，不访问数据库或网络。人物名称及资料已确认：周总是周明，小林是林晓；两人都负责这个项目。没有日记日期。
今天修了导出错误，验证了五百条记录，暂时没发现问题。修复报告要发给小林或周总中的一位，我只记下了“发给那位负责人”，这里到底是哪位需要核实，我能补充。周五上午我准备去客户现场交付，到时候要带电脑和适配器。
晚上买面，老板多给了一个蛋，我挺高兴。
```

### 依次模拟回答

1. 修复报告发给小林。另外补充一下，我回看了安排，原稿写的“周五上午”不是最后确定的交付时间，后来改过一次。最终去现场的时间我记得，但还没有补进来。
2. 最终时间是下周二下午两点，电脑和适配器照常带。

### 预期行为

事实问题数量为1→1→0。先核实收件人；答后把收件人改为小林，继续问新出现的交付时间。最终保留原定周五上午、后改下周二下午两点的过程，不按执行日期换算。

## 既有验证与后续覆盖

2026-10-21 的两次代理试跑符合上述预期。模型版本未获核验，回答由测试方模拟；该记录只支持这两组场景，不是当前版本已通过的验收。

后续还需覆盖：真实提问组件、用户跳过疑问、一次回答解决多个疑问，以及整篇确认前后数据库保存边界。不得把事实澄清完成等同于整篇定稿。
