# 日记浏览与详情

核对基线：2026-10-29 仓库代码。本文承载日历、时间线、收藏与详情交互，内容生成规则分别引用 AI 整理、AI 分析文档。

## 1. 浏览入口与定位

[首页](../../frontend/pages/index.vue)提供日历、时间线和收藏三种视图，默认进入日历。按当前用户、软删除状态过滤数据。

- 日历按月展示日期、记录数量、整理 / 分析状态及可用心情。月份可前后切换。
- 同日只有一篇日记时直接进入详情；多篇进入[日期列表](../../frontend/pages/diary/date/[date].vue)，按明确身份选择，不自动合并。
- 时间线按日记日期及创建时间倒序分页，显示标题 / 日期 / 状态及预览。
- 收藏视图统一展示日记和事件收藏，事件项链接到所属日记并携带事件定位。
- 页面状态保留视图、月份和滚动位置；下拉刷新更新当前视图，滚动加载不能重复请求已在加载中的页。

后端 [list_diaries / browse_diaries](../../backend/routers/diaries.py)提供日期范围、标签和浏览分页；原需求中的标签筛选能力应区分接口支持与当前页面是否提供控制项，不能仅从参数存在认定完整交互已实现。

## 2. 收藏规则

- 用户可收藏或取消收藏一篇日记或一个事件；请求幂等，取消不存在的收藏也可成功。
- 一条收藏仅指向一种目标，同用户同目标最多一条；后端校验目标属于当前用户。
- 收藏状态刷新后保持一致，软删除日记时移除日记及其事件的收藏关系。
- 首页收藏、详情顶部星标和事件星标共享后端状态，操作失败不伪装已保存。

模型约束见[Favorite](../../backend/models/favorite.py)，接口见日记路由的收藏相关函数。

## 3. 详情状态与主导航

| 日记状态 | 当前布局 |
|---|---|
| 未整理 / `saved` | 显示原文、日期和 AI 整理入口；转写中的展示规则来自语音模块 |
| `organized` | 显示结构化日记及事件列表 / 要点 / 关系图谱切换 |
| `analyzed` | 显示“日记、分析、行动”三个 Tab；日记 Tab 内仍可切换事件列表、事件要点和关系图谱 |

标题优先使用整理记录标题，无标题回退日记日期。顶部显示日记收藏与删除入口；后端状态及任务限制仍是操作权限的最终校验。页面按钮存在不代表写入一定允许，统一规则见[录入与维护](录入与维护.md)。

事件要点和关系图谱通过独立组件按实际可见状态延迟加载；切换不丢失已加载视图，返回来源事件时按稳定事件 ID 定位。图谱自身的建图、召回和关系展示规则见[知识库文档](../知识库/README.md)。行动 Tab 引用[行动管理规则](../行动管理/日记行动项功能约定.md)。

## 4. 日记内容的阅读顺序

事件列表视图纵向展示：元数据 → 摘要 → 可选引入 → 有序事件 → 可选琐事 → 可选后续计划 → 折叠原文。

| 区块 | 数据与显示约定 |
|---|---|
| 地点、心情、日记级标签 | 有值才显示；标签按类型分组，日记级为事件标签去重汇总 |
| 摘要 | `organized.summary`，保持与事件正文的层次区别 |
| 引入 | `organized.introduction`，只有来源存在时显示 |
| 事件 | 标题、标签、重要性、正文、感受、反思及已有分析，按事件顺序展示 |
| 琐事 | `trivia` 非空时显示，默认展开的编号列表 |
| 后续计划 | `plans` 非空时显示，保留数组顺序；计划的内容和排序由整理约定定义 |
| 原始文本 | 默认折叠，展开后保留换行，能否编辑由状态及来源锁决定 |

所有无内容的可选区块隐藏，不用空标题或套话填充。正文段落、感受和反思按有序数组表达；字符串兼容由后端响应组装处理。

## 5. 事件与分析交互

### 5.1 事件卡片

当前 [EventCard](../../frontend/components/EventCard.vue)在查看态始终展开，标题区域吸附在事件正文上方。旧设计中的默认折叠与箭头切换已不对应现状。

- 标题、正文、感受和反思支持对应的行内编辑；双击触发编辑后，取消保留原数据，保存等待服务端结果。
- 显示 AI 重要性和用户覆盖入口，以有效重要性展示。重要性定义见[整理功能约定](AI整理/功能约定.md#4-事件重要性)。
- 标签在标题附近以小号药丸样式展示；收藏按钮独立操作，点击不应误触编辑。
- 长事件阅读时，在内容区顶部吸附当前事件标题；多行标题保持完整可读。切换 Tab、编辑或离开事件区域时清除旧吸附状态。
- 正文、感受、反思、AI 分析有明确的视觉分隔，不能把模型分析展示为原始事实。

### 5.2 分析区块

事件级与日记级分析均分为自我理解和认知整理，保留情绪、行为与决策、关注点与需求、可行动建议、认知校准、问答、认知完善的顺序；当前组件对可行动建议单独展示，其余按分组切换。

- 分析正文只读，内容改变通过反馈及新轮次完成。
- 有值才显示具体类型块，空分组隐藏；全部为空时显示无分析内容状态。
- 问答显示问题和回答，避免把两者合并为普通句子。
- 日记级整体心情单独展示；事件标签保留在日记内容区。
- 星级反馈交互见[分析功能约定](AI分析/功能约定.md#3-分析轮次与反馈)，批注入口见[批注](批注.md)。

业务“六部分”与存储七类分析及事件 / 日记级范围以分析功能约定为准，页面不自行补齐缺失的模型结果。

### 5.3 文本标记与标签样式

现有生成内容含 `**重点**`、`<red>风险</red>` 及相对时间标记时，通过统一渲染保留语义并限制可用标记，不把任意原文当可执行 HTML。正文与分析的重点标记约束来自各自实现，详情支持渲染不代表 Skill 必须默认生成所有标记。

| 标签类型 | 背景 / 文字 |
|---|---|
| `domain` | `bg-blue-100` / `text-blue-800` |
| `topic` | `bg-green-100` / `text-green-800` |
| `person_object` | `bg-orange-100` / `text-orange-800` |
| `psychological` | `bg-purple-100` / `text-purple-800` |
| `knowledge` | `bg-teal-100` / `text-teal-800` |

具体颜色以 [TagBadge](../../frontend/components/TagBadge.vue)为准。查看用标签可小字号，但可编辑控件实际字号不得小于 `16px`；新增或改动移动端编辑表单后须验证 iOS Safari 聚焦不放大，并保留用户缩放。

## 6. 后端组装与前端职责

- 后端按当前分析轮次和事件 UUID 将分析放到所属事件，不让前端通过标题、事件下标或排序字段猜测关系。
- 详情的 `organized.analysis` 返回当前轮次及日记级类型块，`events[].analysis` 返回事件级类型块，前端使用结构化条目保存反馈与批注身份；完整字段见[日记 schema](../../backend/schemas/diary.py)与[analysis_history](../../backend/services/analysis_history.py)。
- 日记级分析和事件级分析使用统一的类型语义；日记整体心情只属于日记级。
- 普通文本数组无内容时用空数组，问答项包含问题和回答；分析不存在时使用空 / null 状态，不构造虚假的分析条目。
- 任务进度从整理或分析状态接口获取。当前分析含建图、分析和行动阶段，旧的固定“第 7 / 8 / 9 环节”文案不能完整描述运行步骤。
- 切换 Tab、离开页面和任务结束时维护轮询及滚动监听生命周期；展示错误与可恢复状态，避免重复触发后台任务。
