# 日记批注

核对基线：2026-10-29 仓库代码。批注保存用户对具体正文或分析文本的选区及评论，必须始终指向用户实际选中的内容。

## 1. 功能与目标范围

当前可创建批注的目标为事件正文、事件感受、事件反思和当前分析项，分别使用 `EVENT_BODY`、`EVENT_FEELING`、`EVENT_REFLECTION`、`ANALYSIS_ITEM`。

旧需求将“日记级字段”一并列为目标，但路由未提供摘要、引入、琐事和后续计划等字段的批注类型。此范围差异待确认，不将未支持的字段写为当前能力。

每个选区记录起止段落、字符偏移、选中文本和前后文。选区可跨段落；起止位置必须有效，结束位置严格位于起点之后，选中文本不能为空。

## 2. 创建与合并

- 先校验日记所有权及有效状态，再校验目标事件或分析项确实属于目标日记。
- 事件目标需提供相符的事件 ID 和字段名；分析目标仅绑定分析项 ID，分析项必须属于当前轮次。
- 同一来源的相邻关系与重叠范围按路由的选区比较规则处理。包含关系复用已有选区，重叠选区合并为覆盖整体的范围，不创建多条相互覆盖的有效批注。
- 合并时保留 `merged_into_id` 和旧记录去向，并迁移 / 保留评论关联，不能丢弃用户意见。
- 用户可以只划线，也可以同时提交评论；评论内容需要非空。

## 3. 评论与软删除

评论支持新增、编辑和删除，均校验所属日记与当前用户。批注与评论采用软删除，记录删除人、时间及原因；删除批注后不能继续通过普通接口维护其评论。

前端在选中文本后展示动作面板；已有批注可打开评论查看面板，展示关联选区的评论，支持编辑及删除。选区和评论错误需在当前页面反馈，保存失败保留编辑内容。

## 4. 内容变化与历史分析

设计约定：批注只能附着到含义一致的原选区，不能因位置变化而错误绑定其他文本。分析轮次更新后，批注只有在对应条目内容和问题均未变化时才可重绑定，不能静默迁移为对变化内容的评价。

当前实现：

- 单事件 `body`、`feeling`、`reflection` 字段变化时，该字段的有效批注由 `soft_delete_event_annotations` 统一标记 `content_changed`。
- 当前实现没有进行文字差异比对后重新定位；即使某一选区文字仍存在，该字段变更也会使旧批注失效。旧需求中“编辑后自动重新定位并保留”的目标仍未完整实现。
- 分析重跑由 `reconcile_analysis_annotations` 按 scope、事件、类型与顺序定位新条目；内容和问题完全相同则重绑定到新条目，否则软删除并标记 `analysis_changed`。旧文档“始终绑定原分析项”的描述不对应当前机制。
- 查询分析项批注时限定当前轮次，未失效且已重绑定的批注在新轮次继续显示。
- 应用内整篇重新整理会物理清理旧事件的批注及评论；整理 Skill 的整篇替换在发现批注关联时直接拒绝。两条实现的替换策略见[整理实现设计](AI整理/实现设计.md)。
