# 待办与目标规划

> 状态：保留规划，独立待办与 OKR 尚未实现。用户已确认本次清理保留。
> 日记行动项与日程已有独立实现，分别见[行动项功能约定](日记行动项功能约定.md)和[日程功能约定](../日程管理/功能约定.md)。

## 1. 功能目标

规划将日记、AI 对话及后续重新设计的回顾能力产生的行动线索，转为全局轻量待办和 OKR，形成记录到行动的闭环。具体来源接入在该能力重新进入设计时定义。

---

## 2. 功能范围

### 2.1 待办事项

#### 创建方式

- 可独立创建
- 可通过 AI 对话过程中产生
- 可从目标（OKR）拆解而来
- 日记整理时提取的待办事项，用户确认后创建到待办模块

#### 待办字段

| 字段 | 说明 |
|---|---|
| 标题 | 待办的标题/内容 |
| 截止日期 | 截止日期或指定日期 |
| 优先级 | 高 / 中 / 低 |

#### 循环待办

- 支持自定义循环规则（如每周一三五、每月第二个周五）
- 待办统一概念，不区分一次性和循环

#### 进度更新

- 用户手动更新待办进度
- 日记详情页显示与该篇日记关联的待办，用户可在此查看待办状态

### 2.2 目标管理 OKR

#### 三层结构

**目标（Objective）**

| 字段 | 说明 |
|---|---|
| 标题 + 描述 | 描述期望达成的结果，如"4月通过软考" |
| 起止日期 | OKR 的开始日期和截止日期 |
| 状态 | 进行中 / 已完成 / 已放弃 |

**关键步骤（Key Results）**

| 字段 | 说明 |
|---|---|
| 标题 | 目标的里程碑 |
| 进度百分比 | 由用户**手动更新**，不自动计算 |

- KR 下关联待办列表，**仅做展示，不参与进度联动**
- 待办与 KR 为**一对一关联**，一个待办只能关联一个 KR

**待办（Tasks）**

- 具体的执行事项

#### 待办展示

- 统一待办列表中展示所有待办（含已关联 KR 和未关联 KR 的）
- 已关联 KR 的待办标记其所属 KR

## 3. 待细化内容

- 日记整理和 AI 对话中待办的提取、确认和创建流程。
- 待办、循环待办、KR 的数据模型与接口设计。
- OKR 进度手动更新规则。
- 日记详情页、待办列表和 OKR 页面之间的关联展示。

## 4. 与当前能力的边界

- 现有日记行动项按单篇日记维护；全局待办尚无独立模型、接口和页面。
- 现有日程保存日期安排和实例完成状态；本规划尚未定义待办与日程双向映射。
- 现有日记行动项的“已开始落实”完成锚点不能直接替代循环待办的进度语义。
- 保留 KR 进度由用户手动更新、待办只展示关联不参与自动进度计算、一个待办最多关联一个 KR 的原规划约定。
- 本轮只整理文档，未新增待办、OKR、自动创建或进度联动实现。
