# 分析反馈与历史分析需求说明

## 1. 背景

当前 AI 分析结果只保留最新版本。用户对分析不满意时，只能点击重新分析，系统无法知道用户不满意的具体原因，也无法把反馈沉淀下来。

本需求要解决两个问题：

- 用户可以对具体分析类型块进行星级和文字反馈。
- 重新分析时，如果存在低分文字反馈，系统按反馈定向修正对应分析内容。

## 2. 目标

- 支持历史分析结果存储。
- 支持对日记级和事件级的每个分析类型块反馈。
- 支持 1-5 星评分和文字反馈。
- 支持带反馈的定向重新分析。
- 支持软删除日记，保留分析、反馈、整理结果、事件和任务数据。
- 备份导出包含历史分析和反馈。

## 3. 非目标

- 暂不做用户侧历史分析版本查看。
- 暂不做反馈审核状态。
- 暂不做 Prompt 反馈沉淀管理端页面。
- 暂不做自动物理清理。
- 暂不做用户侧恢复日记入口。

## 4. 核心概念

### 4.1 分析轮次

`analysis_runs` 表示一次完整分析。

一篇日记可以有多次分析结果。每次普通分析或反馈重新分析成功后，都会产生新的分析轮次。

每篇日记同一时间只能有一个 `CURRENT` 分析轮次。

### 4.2 分析项

`analysis_items` 表示分析轮次中的一条具体分析内容。

它用于保存历史分析结果。前端展示时仍按分析类型聚合展示。

### 4.3 分析类型块

反馈粒度是“分析类型块”，不是单条文本。

一个反馈对象由以下字段确定：

```text
analysis_run_id
scope
event_id
analysis_type
```

示例：

```text
当前分析轮次 + 事件 A + BEHAVIOR_DECISION
```

表示用户对“事件 A 的行为与决策分析”反馈。

## 5. 分析类型

`analysis_type` 使用枚举短码：

| 枚举 | 含义 |
|---|---|
| `EMOTION` | 情绪分析 |
| `BEHAVIOR_DECISION` | 行为与决策分析 |
| `SELF_UNDERSTANDING` | 关注点与需求 |
| `ACTION_SUGGESTION` | 可行动建议 |
| `COGNITIVE_CALIBRATION` | 认知校准 |
| `COGNITIVE_ENHANCEMENT` | 认知完善 |
| `QUESTION_ANSWER` | 问题解答 |

## 6. 数据规则

### 6.1 分析轮次规则

- 每篇日记最多一个 `CURRENT` 分析轮次。
- 普通分析成功后，新分析轮次为 `CURRENT`。
- 重新分析成功后，旧 `CURRENT` 变为 `ARCHIVED`，新分析轮次变为 `CURRENT`。
- 旧分析结果不删除。

### 6.2 反馈规则

- 用户可对每个分析类型块提交反馈。
- 反馈包含 `rating` 和 `comment`。
- `rating` 范围为 1-5。
- `comment` 允许为空。
- 用户选择 1-3 星时，前端必须要求填写 `comment`。
- 用户选择 4-5 星时，立即保存，可不填写 `comment`。
- 同一用户对同一分析类型块只能有一条反馈。
- 再次反馈时覆盖原反馈。
- 重新分析后，上一轮反馈复制到新分析轮次，历史轮次原反馈不修改。
- 被本轮反馈重写的分析类型块，复制反馈标记为待确认。
- 未被本轮改写、只是沿用上一轮内容的分析类型块，复制反馈仍视为已确认。

反馈确认状态：

| 字段 | 含义 |
|---|---|
| `is_inherited=false` | 用户已评价当前分析内容 |
| `is_inherited=true` | 从历史轮次复制而来，当前内容已被修改，需要用户重新评分 |
| `source_feedback_id` | 复制来源反馈 ID，用于内部追踪历史链路 |

### 6.3 反馈保存失败

反馈保存失败时：

- 前端明确提示失败。
- 保留用户已填写内容。
- 用户可以重试。

## 7. 重新分析规则

### 7.1 无有效反馈

如果当前 `CURRENT` 分析轮次没有低分文字反馈：

```text
走普通完整分析流程：环节 7 + 环节 8 + 环节 9
```

普通完整分析会重新生成心情、标签、核心分析和认知分析。

### 7.2 有有效反馈

有效反馈定义：

```text
rating <= 3
comment 非空
is_inherited = false
```

如果存在有效反馈：

```text
不走环节 7
只走反馈版环节 8 和反馈版环节 9
```

反馈版重新分析不重新生成心情和标签。

### 7.3 反馈作用范围

反馈只作用于对应分析类型块。

示例：

```text
事件 A + BEHAVIOR_DECISION 的反馈
```

只影响：

```text
事件 A 的行为与决策分析
```

不影响：

- 事件 A 的其他分析类型。
- 其他事件的行为与决策分析。
- 日记级行为与决策分析。

### 7.4 反馈版环节输入

反馈版环节 8、9 不传原始日记。

输入包括：

- 结构化日记 `structured_diary`
- 上一轮分析结果 `previous_analysis`
- 对应分析类型块的有效反馈 `feedback`
- 原环节 8 或环节 9 的完整要求

原因：

- 环节 8、9 的事实依据是结构化日记。
- 原始日记会引入噪声。
- 如果结构化日记错误，应通过重新整理解决，不属于分析反馈范围。

### 7.5 保存规则

反馈版重新分析成功后，仍保存一个完整的新分析轮次。

新分析轮次由两部分组成：

- 有反馈的分析类型块：使用重写结果。
- 无反馈的分析类型块：沿用上一轮结果。

反馈复制规则：

- 上一轮所有反馈复制到新分析轮次。
- 如果某个分析类型块被本轮反馈重写，复制后的反馈设置 `is_inherited=true`。
- 如果某个分析类型块未被重写，复制后的反馈设置 `is_inherited=false`。
- 用户重新评分后，当前轮次反馈更新为 `is_inherited=false`。
- 旧轮次反馈始终保留，不被覆盖或删除。

## 8. 前端交互

### 8.1 反馈入口

每个分析类型标题右侧展示星级。

示例：

```text
行为与决策分析        ☆ ☆ ☆ ☆ ☆
分析内容 1
分析内容 2
```

适用范围：

- 日记级分析类型块。
- 事件级分析类型块。

### 8.2 低分反馈

用户点击 1-3 星：

- 在当前分析类型块内展开输入框。
- 必须填写反馈意见。
- 提交后保存。

### 8.3 高分反馈

用户点击 4-5 星：

- 立即保存。
- 不强制填写反馈意见。

### 8.4 已反馈状态

已反馈后默认显示：

```text
星级 + 已反馈 / 修改
```

点击后可以查看完整意见并编辑。

### 8.5 已修改待重新评分状态

重新分析后，如果分析类型块内容被反馈重写，页面显示：

```text
星级 + 已修改 / 重新评分
```

该星级来自复制反馈，只表示上一轮评价，不表示用户已认可当前新内容。

用户重新评分后，状态恢复为：

```text
星级 + 已反馈 / 修改
```

## 9. 软删除规则

当前删除日记是硬删除。本需求将删除日记改为软删除。

`diaries` 增加：

```text
deleted_at
deleted_by
```

用户删除日记时：

- 设置 `deleted_at`。
- 设置 `deleted_by`。
- 不删除整理结果。
- 不删除事件。
- 不删除历史分析。
- 不删除反馈。
- 不删除任务。

普通用户查询必须只返回：

```text
deleted_at IS NULL
```

软删除后的日记：

- 不允许编辑。
- 不允许整理。
- 不允许分析。
- 不允许重新分析。

管理员未来可支持：

- 查看已删除日记。
- 恢复日记。
- 手动物理清理。

本需求只预留数据基础，不实现管理端页面。

## 10. 备份恢复

备份导出需要包含：

- 历史分析轮次。
- 历史分析项。
- 分析反馈。
- 日记软删除字段。

恢复时应保留这些数据。

## 11. 验收标准

- 一篇日记多次分析后，可以保留多轮分析历史。
- 每篇日记最多一个 `CURRENT` 分析轮次。
- 前端在每个分析类型标题右侧展示星级反馈。
- 1-3 星不填写意见时不能提交。
- 4-5 星可以直接保存。
- 同一用户重复反馈同一分析类型块会更新原反馈。
- 有低分文字反馈时，重新分析不走心情和标签环节。
- 有低分文字反馈时，只重写对应分析类型块。
- 无反馈时，重新分析走普通完整分析流程。
- 删除日记后，普通用户列表和详情不可见。
- 删除日记后，历史分析和反馈仍保留。
- 删除日记后，不允许再次整理或分析。
