# 日记管理平台 — 产品设计规格

> 版本：v1.2 | 日期：2026-07-02

---

## 1. 产品定位

面向个人用户的 AI 驱动型日记与自我认知平台。核心价值是通过日记数据建立深度自我理解，并获得个性化人生指导。

- **目标用户**：个人使用
- **使用场景**：手机端为主要记录入口，手机和电脑端都能查看和管理

---

## 2. 功能模块

### 2.1 模块一：日记记录与整理

#### 录入与组织

| 项目 | 说明 |
|---|---|
| 录入方式 | 粘贴语音转文字 + 直接打字输入 |
| 日记结构 | 一篇日记 = 一条文本，一天多篇就建多条独立日记 |
| 原始文本 | 保存原始文本，不可覆盖、不可删除 |
| 多端支持 | 手机和电脑端都能查看和管理 |

#### AI 整理

| 项目 | 说明 |
|---|---|
| 触发方式 | 用户随时手动触发，在日记详情页点击"整理"按钮 |
| 重复整理 | 可重新整理覆盖之前结果，也可手动修改 |
| 整理能力 | 保真结构化整理：修正错别字、语句通顺、合并重复表达、按事件重组结构 |
| 整理范围 | 一次完成：生成标题、生成摘要、规整内容、提取元数据 |
| 原文展示 | 默认显示整理版内容，原始文本可展开查看 |
| 可编辑性 | 所有 AI 生成内容（含元数据）均可手动修改 |

#### AI 整理后正文格式

整理后的正文包含两部分：

1. **结构化日记**：把录音转文字产生的混乱文本整理成保真的事件档案，不做内容压缩。
2. **日记分析**：基于结构化日记进行分析，具体格式后续细化。

> 第一阶段优先保证结构化日记的正确性。结构化日记只整理原文明确表达的内容，不推断、不补充、不拔高。

整理结果采用两层格式：

- **内部存储格式：JSON**。用于程序处理、内容检查、搜索、后续画像沉淀和结构化扩展。
- **用户展示格式：Markdown / 富文本**。用于日记详情页阅读和人工编辑。

#### AI 输出约束

AI 输出约束分为两层：结构化日记改写边界、日记分析推导边界。

**结构化日记允许改写：**

- 修正错别字。
- 修正语病。
- 删除口头禅和无意义重复。
- 合并重复表达。
- 调整语序。
- 把口语化表达整理成通顺句子。
- 按事件和字段重新组织内容。

**结构化日记禁止改写：**

- 新增原文没有的信息。
- 替用户补动机。
- 替用户补结果。
- 替用户补反思。
- 把模糊表达改成确定结论。
- 删除关键事实。
- 改变事件因果关系。
- 改变情绪强度。
- 把用户原本的不确定表达改成确定表达。

**日记分析允许推导：**

- 基于当天事实分析情绪触发点。
- 基于当天行为提炼当天应对方式。
- 基于当天表达分析关注点、需求与自我理解。
- 识别明显认知偏差并温和校准。
- 给出低成本、具体、可执行建议。

**日记分析禁止推导：**

- 引用当天日记以外的信息。
- 做长期人格判断。
- 做心理诊断。
- 给用户贴标签。
- 没有依据地强行纠错。
- 否定用户感受。
- 输出命令式建议。
- 输出高成本建议。
- 把推导写成绝对事实。

#### 结构化日记规则

**总体原则**

- 结构化日记是证据层，目标是把口述流水账整理成清晰、稳定、可追溯的事件记录。
- 可以修正错别字、语病、不通顺表达，可以合并重复内容，可以调整内容顺序。
- 不允许补充原文没有表达的动机、结果、感受、反思或经验。
- 原文没有明确表达的字段，统一写：`原文未明确`。
- 重复表达只保留信息最完整、表达最清楚的一版。
- 对模糊表达采用“保留原始表达 + 标注未明确点”的方式处理，不强行解释成明确结论。

**事件拆分规则**

- 采用**事件档案型**结构，一篇日记可以拆分为多个事件。
- 事件按**目标**拆分为主：只要“想解决的问题 / 想完成的事”不同，就拆成不同事件。
- 时间、地点、人物、场景、主题作为辅助判断，不作为主拆分标准。

**生成流程**

1. **文本清洗**：修正语病、错别字、断句、口头禅和明显重复，让原始口述文本变得可处理，但不改变含义。
2. **事件识别**：识别原文中提到了哪些事，形成事件列表。
3. **事件归类**：把原文中分散在不同位置的内容归到对应事件下，完成同一事件的信息聚合。
4. **事件内文本重组**：对每个事件内部的信息重新排序，生成逻辑清晰、读起来通顺的事件文本；顺序可以不同于原文，但不能改变事实。
5. **结构化模板填充**：把事件内容填入固定字段：背景、动机、过程、结果、感受、反思与成长；原文未明确的字段写“原文未明确”。
6. **内容检查与修正**：检查是否存在编造原文没有的内容、推断动机、推断感受、推断反思或成长、过度总结、事件归类错误、字段放错位置等问题；发现问题时直接生成修正版并替换初稿，修正后不再重新检查。
7. **正式存储**：将通过检查或已完成修正的内容保存为正式整理结果。

**内容检查记录**

- 内容检查记录内部保留，用户不可见。
- 用途是调试整理质量、排查提示词问题、辅助后续优化。
- 第一阶段采用最小记录结构，不设计复杂审计系统。

| 字段 | 说明 |
|---|---|
| check_item | 检查项 |
| status | 通过 / 已修正 |
| issue | 发现的问题 |
| fix | 修正动作 |
| before | 修正前片段 |
| after | 修正后片段 |

**单个事件固定字段**

```markdown
## 事件：事件标题

### 背景
### 动机
### 过程
### 结果
### 感受
### 反思与成长
```

**字段定义**

| 字段 | 定义 | 归入内容 | 不归入内容 |
|---|---|---|---|
| 背景 | 事件发生前已经存在的上下文和外部条件 | 事情出现的前因、时间、地点、人物、环境、外部限制、客观条件、已有安排 | 主观目的不放背景，放动机；实际行动不放背景，放过程 |
| 动机 | 原文明确表达的“我为什么要做这件事” | 想解决的问题、想达成的目标、为什么在意、当时的考虑、期待、目的 | 外部原因放背景；具体行动放过程；原文没说原因时不推断 |
| 过程 | 事件实际推进经过，按发生顺序整理 | 我做了什么、对方做了什么、中间变化、沟通、协作、冲突、等待、尝试 | 最终状态放结果；整体情绪变化放感受；事后经验放反思与成长 |
| 结果 | 事件最后形成的状态和后续影响 | 是否完成、是否解决、是否有反馈、后续影响、遗留问题、当前状态 | 情绪不放结果；评价和经验总结不放结果 |
| 感受 | 对整个事件情绪变化的总结 | 主要情绪、情绪变化、情绪转折点、压力、烦躁、轻松、开心、失望、被忽视、被回应等体验 | 不复述过程细节；不写事后经验；不做心理分析 |
| 反思与成长 | 原文明确表达的事后理解、判断、感悟、学到的东西、自我认识 | 我怎么看这件事、哪里做得好或不好、明白了什么、学到了什么、下次想怎么调整、对自己的认识 | 不写原文没说的经验；不推断隐含道理；不拔高；不拆成内部小标题 |

**过程表达规则**

- 过程由多个步骤组成，用编号步骤展示。
- 每个步骤写成通顺完整的一句话。
- 如果某一步本身包含当时感受，可以自然融合进句子。
- 不使用“步骤 + 当时感受”的子项结构。

示例：

```markdown
### 过程
1. 我主动去找他，但他没有理我，我觉得很烦躁。
2. 后来他的领导介入并批评了他，我觉得事情终于有了回应，心情好了很多。
```

**感受表达规则**

- 过程里可以写具体步骤中的即时感受。
- 独立的感受字段只总结整个事件的情绪变化。
- 感受字段不复述过程细节。

示例：

```markdown
### 感受
这件事里的情绪从烦躁、被忽视，转为被回应后的轻松和高兴。
```

**反思与成长表达规则**

- “反思与成长”可以承载反思、感悟、成长、自我认识等内容，但展示时不拆成内部小标题。
- 只有原文明确表达了对应内容时才整理。
- 原文没有明确表达时，写：`原文未明确`。

示例：

```markdown
### 反思与成长
我意识到以后遇到这种不回应的情况，不能一直重复找同一个人，而是要更早判断是否需要换一种推进方式。
```

**模糊表达处理规则**

- 当原文出现模糊表达时，保留原始表达，并标注具体未明确的点。
- 不根据上下文强行解释成明确结论。
- 不把模糊表达改写成原文没有支撑的判断。

示例：

```markdown
### 过程
我提到这件事“挺麻烦”，但原文未明确麻烦具体来自哪里。
```

#### 日记分析

日记分析是整理结果的第二部分，基于结构化日记进行分析。

**指导思想：日记分析的目标是帮助用户认清自己。**

日记分析不是评价用户，也不是替用户下结论，而是帮助用户从当天记录中看见：

- 自己当时有什么情绪变化。
- 自己采取了什么行为和决策。
- 自己真正关注什么。
- 这些关注背后反映了什么当下需求。
- 自己如何理解这件事。
- 这件事反映出自己看重什么。
- 自己对世界、他人、自己、知识或方法的理解是否存在明显偏差。
- 接下来可以做什么低成本、具体、可执行的调整。

日记分析属于解释层，允许基于当天事实进行推导，但必须遵守以下边界：

- 只分析当天这篇日记，不引用长期历史。
- 不做长期人格判断。
- 不做心理诊断。
- 不给用户贴标签。
- 较强推断必须写依据，依据来自当天结构化日记中的具体事件或事实。

当前日记分析包含：

1. **情绪分析**：用自然语言描述主要情绪、情绪变化和触发点，不使用百分比。
2. **行为与决策分析**：先描述当天具体行为和决策，再基于当天事实提炼当天体现出的行为模式线索。
3. **关注点、需求与自我理解**：分析用户当天真正关注什么，以及这些关注背后反映出的当下需求、自我叙事和价值排序。
4. **认知校准**：识别用户对世界、他人、自己、知识、方法或事件因果的理解是否存在明显偏差，并在有依据时进行温和纠正。
5. **可行动建议**：给出 1-3 条具体、低成本、可执行的建议。

**情绪分析** 的定义：

分析用户在当天事件中的主要情绪、情绪变化路径，以及触发这些情绪变化的具体原因。

分析内容：

- 用户出现了哪些主要情绪。
- 情绪是如何变化的。
- 哪些事实触发了情绪变化。
- 情绪背后反映了什么被触动。

禁止项：

- 不用百分比量化。
- 不做心理诊断。
- 不把短期情绪说成长期状态。
- 不写“你是一个情绪化的人”。

承接的自我认识角度：

- 情绪触发点。
- 控制感与不确定性带来的情绪反应。

**行为与决策分析** 的定义：

分析用户当天面对事件时采取了什么行动、做了什么选择，以及这些行为和选择体现出的当天应对方式。

分析内容：

- 用户先做了什么，后做了什么。
- 用户在关键节点做了什么选择。
- 用户是主动推进、等待观察、寻求外部帮助，还是回避处理。
- 行为背后体现出的当天应对方式。
- 行为带来了什么结果或影响。

禁止项：

- 不上升为长期人格。
- 不写“你一直都是……”。
- 不写“你有控制欲”“你是回避型人格”等标签。
- 不脱离当天事实分析行为模式。

承接的自我认识角度：

- 行为反应方式。
- 决策方式。
- 问题处理路径。

**关注点、需求与自我理解** 的定义：

分析用户当天真正被什么牵动，这些牵动背后反映了什么当下需求、未说出口的期待、边界感、自我叙事和价值排序。

分析内容：

- 用户真正关注的是什么。
- 用户当下想要什么。
- 用户害怕或抗拒什么。
- 用户正在维护什么。
- 用户对这件事形成了什么理解。
- 这件事反映出用户看重什么。

内部分析框架：

- 用户真正想要什么。
- 用户害怕或抗拒什么。
- 用户正在维护什么。
- 用户如何理解这件事。
- 用户看重什么。

这些问题只作为内部分析框架，不必在展示层显式拆成小标题。输出时应使用自然段，帮助用户理解自己为什么会被这件事牵动。

常见分析方向：

- 真正想要什么：被回应、被理解、结果明确、责任清楚、关系稳定、事情推进。
- 害怕或抗拒什么：被忽视、不公平、失控、责任模糊、投入没有回报。
- 正在维护什么：边界、尊严、秩序感、投入感、公平感、掌控感。
- 如何理解这件事：用户把事件解释成什么，例如“我的表达没有被看见”“又是我一个人在推动”。
- 看重什么：效率、公平、尊重、确定性、责任、关系、自主性。

禁止项：

- 不做心理诊断。
- 不写长期人格结论。
- 不把推导写成绝对事实。
- 不写“你缺乏安全感”“你很依赖认可”。
- 不替用户扩展到原文没有支撑的人生经历。

承接的自我认识角度：

- 未说出口的期待。
- 边界感。
- 控制感与不确定性。
- 自我叙事。
- 价值排序。

**认知校准** 的定义：

识别日记中用户对世界、他人、自己、知识、方法或事件因果的理解，判断其中是否存在明显的过度概括、绝对化、误解、片面理解或事实性错误，并在有依据时进行温和纠正。

分析对象：

- 对世界的判断。
- 对他人的判断。
- 对自己的判断。
- 对事件原因的判断。
- 对知识点、方法论、工作方法的理解。
- 对经验教训的归纳。

允许项：

- 指出过度概括。
- 指出绝对化表达。
- 指出事实支撑不足。
- 指出知识理解错误。
- 补充更准确的理解。
- 把“情绪中的判断”和“事实可支持的判断”分开。

禁止项：

- 不否定用户感受。
- 不站在道德高地教育用户。
- 不把所有负面判断都改成积极话术。
- 不在不确定时强行纠错。
- 不对专业知识胡乱纠正。
- 不把认知校准写成行动建议。

与其他模块的边界：

- **关注点、需求与自我理解**：解释“用户为什么这样看”。
- **认知校准**：检查“用户这样看是否准确、是否过度、是否需要补充”。
- **可行动建议**：给出“下次可以怎么做”。

处理规则：

- 对世界、他人、自我的整体判断，要优先区分情绪表达和事实可支持的结论。
- 对知识点、方法论、工作方法的错误理解，如果有足够把握，可以直接指出并补充更准确理解。
- 如果原文信息不足或模型没有足够把握，应写“原文不足以判断该理解是否准确”，不能装作确定。

**可行动建议** 的定义：

基于当天分析，给出用户下次遇到类似情况时可以尝试的低成本、具体、可执行行动。

分析内容：

- 用户下次可以尝试怎么表达。
- 用户下次可以如何降低不确定性。
- 用户下次可以如何区分事实、情绪和解释。
- 用户下次可以如何保护边界。
- 用户下次可以如何把需求说清楚。

承接的自我认识角度：

- 从自我理解走向下一次行动。
- 把情绪、需求、边界转化为具体做法。

**可行动建议** 的表达规则：

- 使用“下次可以尝试……”这类建议式表达。
- 不使用“你应该……”这类命令式表达。
- 建议服务于下一次遇到类似情况时的具体行动。
- 建议必须低成本、具体、可执行。
- 不输出泛泛而谈的鸡汤。
- 不输出高成本建议，例如辞职、结束关系、重大关系决策等，除非原文明确表达相关打算。

**日记分析内部检查机制：**

- 生成日记分析后，进行一次内部检查。
- 如果发现问题，直接生成修正版替换分析初稿。
- 修正后不重新检查。
- 检查记录内部保留，用户不可见。

检查项：

- 是否引用了当天日记以外的信息。
- 是否做了长期人格判断。
- 是否贴标签或做心理诊断。
- 较强推断是否缺少依据。
- 认知校准是否否定了用户感受。
- 认知校准是否在依据不足时强行纠错。
- 可行动建议是否具体、低成本、可执行。
- 是否出现“你应该……”这类命令式表达。
- 是否出现鸡汤式、空泛建议。
- 是否出现原文没有支撑的高成本建议。

| 标签 | AI 整理时自动提取，用户可修改，也可手动新建标签 |
| 心情 | AI 整理时自动提取，用户可修改 |
| 地点 | AI 整理时自动提取，用户可修改 |

> 不额外增加其他元数据字段。

#### 日记状态

| 状态 | 说明 | 原始文本 | 参与分析 |
|---|---|---|---|
| 草稿 | 保存后，可继续编辑 | 可修改 | 否 |
| 已发布 | 发布后，原始文本锁定，可触发整理 | 不可改 | 否 |
| 已整理 | AI 整理完成，整理内容可手动修改 | 不可改 | 是 |

> 状态流转：草稿 →（发布）→ 已发布 →（整理）→ 已整理

- **时间线视图**：按时间倒序列出日记

#### 筛选

- **按标签筛选**：通过标签分类过滤日记

#### 搜索

- **全文搜索**：仅搜索整理后的内容（标题、摘要、正文），不搜索原始文本

### 2.3 模块三：日记详情（含 AI 对话）

> 从模块二点击进入，展示日记整理后的内容，同时可围绕该篇日记与 AI 展开反思对话。

#### 日记详情展示

- 展示 AI 整理后的结构化日记内容，按事件档案展示每个事件的背景、动机、过程、结果、感受、反思与成长
- 原始文本可展开查看
- 元数据（标签、心情、地点）可编辑
- 显示与该篇日记关联的待办事项（见模块九）
- 提供"整理"按钮，可触发或重新触发 AI 整理

#### 反思对话

- **入口**：日记详情页内嵌对话区域
- **上下文范围**：以当前日记为主，AI 可参考近期日记做关联分析
- **交互方式**：问答式 + 引导反思式

#### 数据反哺

- 对话内容作为数据源，24h 无新消息后自动沉淀到人物画像、心路历程和认知洞察模块

### 2.4 模块四：定期回顾（含 AI 对话）

> 隔一段时间对日记进行总结，AI 生成回顾文档，用户可围绕回顾内容与 AI 对话。与日记详情逻辑一致：内容查看 + AI 对话。

#### 回顾周期

| 周期 | 说明 |
|---|---|
| 日度 | 每日回顾 |
| 周度 | 每周回顾 |
| 月度 | 每月回顾 |
| 季度 | 每季度回顾 |
| 年度 | 每年回顾 |

#### 回顾流程

1. **系统自动提示**：在对应时间节点提示用户进行回顾（如每周日提示周回顾）
2. **AI 生成回顾文档**：AI 汇总该时间段的日记内容，按指定格式生成回顾文档
3. **查看回顾 + AI 对话**：用户查看回顾文档，可围绕回顾内容与 AI 展开对话

> 回顾流程与日记"整理→对话"逻辑一致：生成结构化文档 → 基于文档对话。

#### 回顾文档

- **展示方式**：与日记详情类似，展示回顾文档内容 + 内嵌 AI 对话区域
- **回顾文档格式**：后续细化

#### 数据反哺

- 回顾对话内容作为数据源，24h 无新消息后自动沉淀到人物画像、心路历程和认知洞察模块

### 2.5 模块五：人物画像（"你是谁"）

#### 8 个维度

1. 性格特征
2. 情绪模式
3. 价值观
4. 兴趣偏好
5. 行为模式
6. 人际关系
7. 成长轨迹
8. 压力源与应对方式

#### 画像结构

每个维度按以下结构组织：

| 组成部分 | 说明 |
|---|---|
| 总体描述 | 对该维度的概括性描述 |
| 特征标签 | 关键特征标签（如"偏内向""做事有条理"） |
| 支撑证据 | 每个特征关联具体的日记片段作为证据 |

#### 画像初始生成

- **触发时机**：首篇日记整理后自动生成初始画像

#### 呈现方式

- **专属画像页面总览**：以结构化页面展示全部 8 个维度的画像概览
- **AI 伙伴对话深度探讨**：通过 AI 伙伴对画像内容进行深入探讨（注意：不是独立的 AI，就是通过 AI 伙伴来实现）

#### 更新机制

画像更新有两条路径：

**路径一：自动沉淀（直接更新，事后可改）**

| 触发条件 | 说明 |
|---|---|
| 整理日记时 | 自动更新 |
| 日记详情对话 | 24h 无新消息后自动沉淀 |
| 回顾对话 | 24h 无新消息后自动沉淀 |
| AI 伙伴对话 | 24h 无新消息后自动沉淀 |

> 自动沉淀产生的变更直接生效，用户事后可在画像页面手动修改。

**路径二：AI 伙伴引导编辑（需用户确认）**

- 通过 AI 伙伴的**心理咨询师**角色实现
- AI 基于日记原始内容作为证据进行剖析，引导式分析
- **需用户确认后才修改画像**，不是用户说什么就是什么

#### 矛盾证据处理

- 当日记中出现矛盾证据时，**保留矛盾两面**
- 例如："偏内向，但在熟悉的人面前外向"

#### 变更历史

- 保留画像的变更历史，用户可查看每个维度的历史变更记录

| 自我成长 | 自我认知、情绪状态、兴趣爱好相关 |

**AI 对话探索**

- 用户可深入提问，如"我对某件事的态度是怎么变化的"
- **入口**：点击后跳转到 AI 伙伴对话，携带心路历程上下文

### 2.8 模块八：AI 伙伴（独立入口，围绕"你这个人"）

> 围绕用户个人展开的深度对话，聚焦人生指导和深度反思，与日记详情对话、回顾对话各自独立、上下文不混淆。

#### 5 个角色

| 角色 | 定位 |
|---|---|
| 心理咨询师 | 情绪疏导、焦虑分析、压力管理 |
| 人生教练 | 人生方向、目标规划、决策辅助 |
| 职业顾问 | 基于价值观和行为模式的职业建议 |
| 关系顾问 | 基于人际关系图谱和互动模式的关系建议 |
| 成长伙伴 | 追踪成长轨迹，停滞时提醒、进步时鼓励 |

#### 角色选择机制

- **默认**：AI 根据对话内容自动判断角色，界面上显示当前角色
- **切换**：用户可中途切换角色，上下文保持连续

#### 对话基础

- 基于人物画像 + 心路历程 + 认知洞察的结构化数据
- 同时可查阅历史日记原文作为补充
- 不是泛化的建议，而是真正了解用户这个人之后给出的指导

#### 对话内容反哺

- 对话中产生的自我认知、情感倾诉、决策思考等，沉淀到人物画像、心路历程和认知洞察

### 2.9 模块九：待办事项（轻量扩展）

#### 创建方式

- 可独立创建
- 可通过 AI 对话过程中产生
- 可从目标（OKR）拆解而来
- 日记整理时提取的待办事项，用户确认后创建到待办模块

#### 待办字段

| 字段 | 说明 |
|---|---|
| 标题 | 待办的标题/内容 |
| 截止日期 | 截止日期或指定日期 |
| 优先级 | 高 / 中 / 低 |

#### 循环待办

- 支持自定义循环规则（如每周一三五、每月第二个周五）
- 待办统一概念，不区分一次性和循环

#### 进度更新

- 用户手动更新待办进度
- 日记详情页显示与该篇日记关联的待办，用户可在此查看待办状态

### 2.10 模块十：目标管理 OKR（轻量扩展）

#### 三层结构

**目标（Objective）**

| 字段 | 说明 |
|---|---|
| 标题 + 描述 | 描述期望达成的结果，如"4月通过软考" |
| 起止日期 | OKR 的开始日期和截止日期 |
| 状态 | 进行中 / 已完成 / 已放弃 |

**关键步骤（Key Results）**

| 字段 | 说明 |
|---|---|
| 标题 | 目标的里程碑 |
| 进度百分比 | 由用户**手动更新**，不自动计算 |

- KR 下关联待办列表，**仅做展示，不参与进度联动**
- 待办与 KR 为**一对一关联**，一个待办只能关联一个 KR

**待办（Tasks）**

- 具体的执行事项

#### 待办展示

- 统一待办列表中展示所有待办（含已关联 KR 和未关联 KR 的）
- 已关联 KR 的待办标记其所属 KR

**页面清单（6 个页面）：**

2. **日记浏览页（主页·日记 Tab）** — 顶部导航（月份切换）+ 搜索框 + 日历/时间线切换 + 日历网格（心情颜色 + 整理状态标记）+ 标签筛选 + 右下角浮动 + 按钮 + 底部 Tab 栏
3. **日记录入页** — 顶部日期选择 + 全屏文本输入区 + 底部保存草稿/发布按钮
4. **日记详情页（已整理）** — 标题 + 元数据横排（心情/地点/标签可编辑）+ 结构化日记内容 + 原始文本可展开 + 底部对话区（消息流 + 输入框）
5. **日记详情页（未整理）** — 日期 + 原始文本 + 底部"整理"按钮，无对话区
6. **我的页面（我的 Tab）** — 用户信息 + 模块入口列表（人物画像/心路历程/认知洞察）+ 设置

**日记状态流转：** 草稿 →（发布）→ 已发布 →（整理）→ 已整理

### 6.5 AI 提示词设计

**日记整理提示词**

输入：日记原始文本
输出：标题、摘要、心情、地点、标签、结构化日记正文

提示词要点：
- 润色文字，修正错别字，语句通顺，不改变原意，不压缩核心内容
- 按事件档案型结构重组内容，一篇日记可拆成多个事件
- 事件按目标拆分为主，场景、主题、人物、时间作为辅助判断
- 按“文本清洗 → 事件识别 → 事件归类 → 事件内文本重组 → 结构化模板填充 → 内容检查与修正 → 正式存储”的流程生成结构化日记
- 每个事件固定包含：背景、动机、过程、结果、感受、反思与成长
- 只整理原文明确表达的内容，不推断、不补充、不拔高
- 原文没有明确表达的字段，统一写“原文未明确”
- 重复表达合并，只保留信息最完整的一版
- 过程按步骤写成通顺完整句子，步骤中的即时感受可自然融入句子
- 感受字段只总结整个事件的情绪变化，不复述过程细节
- 结果字段只写事件状态和后续影响，不写感受和评价
- 反思与成长字段不拆内部小类，且不整理原文未明确表达的隐含经验
- 元数据从内容中推断

**反思对话提示词**

输入：当前日记内容 + 近期日记（关联参考）+ 对话历史 + 用户最新消息
输出：AI 回复

提示词要点：
- 围绕日记内容提问和引导反思
- 帮助用户深入思考事件背后的感受和原因
- 语气温暖真诚，像朋友聊天
- 不做泛泛的建议
