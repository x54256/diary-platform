# 日程管理规格

## Problem Statement

用户需要在日记平台中安排和执行按时间发生的行动项。现有行动管理设计只定义轻量待办和 OKR，无法在手机上按一天的时间线查看任务、处理同一时段多任务、完成逾期任务或打印可线下勾选的周日程。

## Solution

在行动管理的待办能力上建立日程模块。用户从日记页顶部的二段下拉或可点击备用入口进入日程页，创建单次、全天或循环日程任务，并在单日与周视图中执行日程实例。单日视图压缩无任务空档且完整纵向展示同一时段任务；周视图提供周概览和双日时间轴两种布局。用户可点击任务完成，逾期完成时可选填写理由。周视图提供浏览器打印入口，打印七天按列的时间轴、全天区域和可手工勾选的任务。

## User Stories

1. 作为已登录用户，我想从日记页进入日程页，以便在记录日记后安排当天行动。
2. 作为已登录用户，我想通过可点击入口进入日程页，以便在浏览器手势不可用时仍能访问日程。
3. 作为已登录用户，我想新建单次任务，以便安排一次明确的行动。
4. 作为已登录用户，我想填写任务名称、开始时间和结束时间，以便知道行动内容和时间边界。
5. 作为已登录用户，我想新建循环任务，以便安排重复发生的行动。
6. 作为已登录用户，我想选择每天、每周指定星期或每月指定日期的循环，以便覆盖固定周期任务。
7. 作为已登录用户，我想设置每月第 N 个星期几的循环，以便安排复杂周期任务。
8. 作为已登录用户，我想将循环设置为永久、截止日期或发生次数结束，以便控制循环边界。
9. 作为已登录用户，我想限制任务在同一天开始和结束，以便日程的日期归属明确。
10. 作为已登录用户，我想在单日时间线查看当天任务，以便按时间执行。
11. 作为已登录用户，我想让无任务时间被压缩并保留实际时间标签，以便减少无效滚动且不丢失时间语义。
12. 作为已登录用户，我想在同一时段看到所有任务纵向完整排列，以便任务不会被折叠或隐藏。
13. 作为已登录用户，我想在单日时间线看到当前时间线，以便判断任务是否临近或逾期。
14. 作为已登录用户，我想点击任务完成或取消完成，以便快速维护任务状态。
15. 作为已登录用户，我想在结束时间已过后完成任务时看到逾期理由输入提示，以便记录原因，也可跳过理由。
16. 作为已登录用户，我想编辑单次任务，以便修正任务名称或时间。
17. 作为已登录用户，我想删除单次任务，以便移除不再需要的安排。
18. 作为已登录用户，我想编辑循环任务的仅本次实例，以便应对临时变化而不影响后续。
19. 作为已登录用户，我想编辑或删除循环任务的后续实例，以便从指定发生日期起调整计划。
20. 作为已登录用户，我想在周视图中查看一周日期范围，以便获得全局安排。
21. 作为已登录用户，我想在周视图中看到当天日期的红色圆形强调，以便快速定位今天。
22. 作为已登录用户，我想在周概览中同时看到左侧时间轴和七天任务，以便比较任务发生时间。
23. 作为已登录用户，我想通过周视图按钮切换为双日时间轴布局，以便放大查看相邻两天的任务。
24. 作为已登录用户，我想在两种周布局中点击任务完成，以便不必切回单日视图。
25. 作为已登录用户，我想在周视图使用低强调度的打印图标，以便需要时打印且不干扰日常执行。
26. 作为已登录用户，我想通过浏览器打印预览打印一周日程，以便选择已安装的打印机。
27. 作为已登录用户，我想获得七天按列、按时间轴排布且每项附手工勾选框的打印页，以便线下执行任务。
28. 作为已登录用户，我想在日程页使用悬浮圆形加号新增任务，以便快速添加而不遮挡主要内容。
29. 作为已登录用户，我想创建全天日程，以便记录不占用具体时刻的安排。
30. 作为已登录用户，我想让全天日程显示在时间轴顶部并参与周打印，以便统一查看和线下执行。
31. 作为已登录用户，我想让每月 31 日循环在 2 月等短月安排到月末，以便每月都有一次日程。
32. 作为已登录用户，我想让不存在的“第 N 个星期几”在当月跳过，以便循环规则保持严格语义。

## Implementation Decisions

- 日程属于阶段五行动管理中的待办能力；首期只允许在日程页手动创建，不从日记整理或 AI 对话自动创建，也不实现 OKR 关联。
- 日程数据与日记整理、分析的异步任务分离，使用独立的用户归属、日程任务定义和日程实例模型。日程任务定义保存名称、是否全天、开始日期、定时字段、循环规则和循环结束条件；日程实例保存归属日期、名称和计划时间快照、完成状态、完成时间和可选逾期理由。
- 单次日程任务创建一个日程实例；循环日程任务创建后立即持久化未来 180 天的日程实例。每日维护任务补齐未来 180 天，日程查询在返回前补齐请求日期范围。所有完成、逾期理由和单次修改均直接写入对应日程实例。
- 不支持跨日日程。非全天日程必须有开始和结束时间，且服务端拒绝结束时间不晚于开始时间；全天日程使用显式全天标识，不填写定时字段。
- 无限循环不会生成全部未来实例。已发生实例永久保留；漏办日程实例保持未完成状态并保留原计划日期。
- 循环规则支持每 N 天、每 N 周（指定星期）和每 N 月（指定日期或第 N 个星期几）。每月指定日期超出当月天数时月末对齐；不存在的第 N 个星期几则跳过当月。
- 日程 API 以当前登录用户为数据边界，并提供：任务创建、任务定义更新、单次实例更新、删除、日期范围查询与实例完成状态切换。所有写入返回日程实例，避免客户端自行推导最终状态。
- 日期范围查询直接返回已持久化的日程实例，并按日期、全天优先级、开始时间、创建顺序稳定排序。前端根据同一开始时间分组后纵向渲染，不折叠实例。
- 日记页顶部二段下拉提供“松开进入日程”手势，同时提供可点击备用入口。底部导航新增日程入口，使日程可被稳定发现。
- 单日视图默认展示。全天日程固定在顶部全天区域；定时日程使用真实时间标签和压缩空档；有任务的时间段按任务实例完整展开；任务卡片本身可完成或取消完成，不显示“点击完成”等说明文本。
- 周视图以周一为首日，固定显示周日期范围、当前日期红色圆形强调、左侧时间轴与七天列。周视图提供周概览和双日时间轴两个可切换布局；打印入口只在周视图显示，使用小图标。
- 新建入口为距右侧安全边距一致的圆形悬浮加号，不使用大面积文字按钮。
- 完成已超出计划结束时间的实例时，前端弹出可跳过的逾期理由输入；提交空理由依旧完成任务。
- 打印使用浏览器打印预览，打印当前周视图显示的周。打印专用布局为一周七列加时间轴和顶部全天区域，每个任务显示名称、计划时间和空的线下勾选框；不打印线上完成状态、逾期理由、空档说明或编辑控件。
- 系统时区固定为 `Asia/Shanghai`。用户可提前完成已生成的未来日程实例；仅晚于计划结束时间的完成操作提示逾期理由。
- 数据库变更以新增迁移交付，保持现有 PostgreSQL 与 SQLAlchemy 模式；接口使用既有 FastAPI 路由、认证依赖和前端 API 封装。

## Testing Decisions

- 测试唯一切口是日程 REST API，验证接口对外可观察的请求、响应、状态变化和用户隔离，不测试组件内部实现、CSS 类名或渲染细节。
- 使用现有后端测试结构和认证测试方式，为创建、查询、修改、删除和完成接口建立集成测试。
- 创建测试覆盖单次、全天、固定循环、复杂循环、三种循环结束条件、月末对齐和第 N 个星期几跳过规则；跨日或结束时间不晚于开始时间必须返回验证失败。
- 查询测试覆盖给定日期范围内的已生成实例、实例窗口补齐、同一开始时间多个实例、稳定排序、无任务日期和漏办实例。
- 状态测试覆盖完成、取消完成、提前完成、逾期完成的空理由与非空理由、完成时间记录和用户之间不可读取或修改彼此任务。
- 循环修改测试覆盖仅本次实例与从指定日期开始的后续实例，确认已发生实例不被后续修改重写。
- 删除测试覆盖单次实例和循环后续实例的可见性变化。
- 删除测试验证单次、已发生未完成和未来实例均物理删除；历史完成实例不受循环后续修改影响。
- 打印不作为服务端状态测试对象；其输入数据由同一日期范围查询契约保证。

## Out of Scope

- 从日记整理、AI 对话或 OKR 自动创建日程任务。
- 任务与 OKR 关键结果的关联及进度联动。
- 跨日、多日日程。
- 任务提醒、通知、共享日历、外部日历同步和时区切换。
- 拖拽调整时间、批量编辑、任务标签、优先级和附件。
- 原生打印机直接控制、PDF 导出和线上完成状态的打印。
- 针对页面组件的自动化交互测试。

## Further Notes

- 规格使用“日程任务”指用户的行动项；“日程实例”指某个日期实际执行的安排；“日记整理任务”和“分析任务”仍指既有后台异步任务，三者不得混用。
- 周打印的目的为线下打钩，打印输出必须独立于线上完成状态。
- 日程入口的下拉手势受移动浏览器回弹和下拉刷新影响，因此可点击入口和日程 Tab 是必需的可用性保障。
