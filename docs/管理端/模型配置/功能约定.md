# 模型配置功能约定

核对基线：2026-10-29。模型清单、渠道、用途与环节配置集中维护；实现机制和生效边界见[实现设计](实现设计.md)。

## 1. 对象与职责

| 对象 | 管理内容 |
|---|---|
| 模型清单 | 模型类型、厂商、调用名称、能力梯队/分类、思考能力、特点、评分和启用状态 |
| 调用渠道 | API 基地址、加密保存的密钥、渠道思考参数模板及启用状态 |
| 渠道支持模型 | 某渠道支持哪些模型、关联是否启用 |
| 用途默认配置 | 一项业务使用哪个可调用模型及默认思考状态 |
| 环节覆盖 | 指定业务步骤独立覆盖模型、思考状态；未覆盖字段分别继承 |
| 整理流程开关 | 是否执行清洗审核、内容审核，由整理流程配置单独维护 |

模型厂商与调用渠道分离：同一模型可以由多个渠道调用，同一渠道可以支持多种类型。能力清单不保存调用密钥；密钥不随查询返回。管理端未提供合法可调用配置时，对应 AI 功能明确失败。

## 2. 模型、协议与用途

| 模型类型 | 派生协议 | 当前用途 |
|---|---|---|
| `language` | `openai_chat` | `organize` 整理、`analysis` 分析、`graph` 事件建图、`chat` 对话 |
| `asr` | `dashscope_asr` | `transcription` 语音转写 |
| `embedding` | `openai_embeddings` | `graph_embedding` 图谱向量 |

协议由类型派生，渠道模型关联不保存另一份协议或调用别名，实际调用名取 `model_catalog.model_name`。独立搜索向量化与定期回顾用途已移除；当前用途由服务端清单提供。本文只说明图谱用途的管理配置，知识库内部设计另行维护。

模型能力分类是模型自身能力，不等同为平台用途。语言分类包括通用对话、深度推理、长上下文、代码能力、轻量高速；ASR 分实时和录音文件识别；向量模型使用文本向量化分类。梯队、分类与思考能力使用固定选项，完整值由管理接口返回。

## 3. 管理交互与引用保护

### 模型清单

- 可按类型、梯队、分类、状态和关键词筛选，查看厂商、名称、能力、思考模式等详情。
- 可新增自定义模型，新增默认启用；必需字段为模型类型、厂商、模型名称、能力梯队和分类，其余字段以接口模型为准。
- 系统预置模型由初始化清单补齐，管理员可维护支持的运行属性；编辑范围与原始来源分开处理。
- 被用途或环节设置引用的模型不能直接禁用或删除。

### 渠道与支持模型

- 渠道可维护名称、API 基地址、密钥、思考参数及启用状态。
- 编辑时留空密钥表示保留旧值；清空密钥通过独立操作。
- 查询仅显示密钥已配置与否；前端不接收明文或密文。
- 同一个渠道与模型只能关联一次；渠道详情和模型详情维护同一关联数据。
- 被用途或环节使用的渠道、渠道模型不能禁用、删除；被使用渠道不能直接清空密钥。先解除配置引用再操作。
- 修改渠道地址、思考模板或模型属性时，必须考虑尚在执行的任务，不能把引用保护理解为所有运行快照均受到完整保护。

## 4. 两级配置及思考模式

每个字段独立继承：

```text
有效模型 = 环节指定模型，否则用途默认模型
有效思考状态 = 环节指定开关，否则用途默认开关
```

用途级语言配置须有布尔思考状态；环节思考为继承、开启、关闭三态，分别对应 `NULL/TRUE/FALSE`。模型覆盖为空表示继承；两个覆盖字段都为空时可删除覆盖记录，界面仍显示服务端生成的完整环节。

| 模型 `reasoning_mode` | 有效思考状态 |
|---|---|
| `unsupported` | 只能关闭 |
| `switchable` | 可开或关，渠道须有对应参数模板 |
| `always_on` | 必须开启，渠道须有开启参数 |

ASR 与图谱向量用途的思考状态必须为空。语言模型开启或关闭的实际请求字段由渠道 `thinkmode` 模板决定，不能只保存页面开关而不向提供方传递。

所有有效组合均须通过模型类型、模型/渠道/关联启用状态、密钥和思考能力校验。例如分析默认开启思考，而元数据环节覆盖到不支持思考的模型且仍继承开关，则必须拒绝保存，管理员应显式关闭该环节或换模型。

## 5. 环节与流程开关

| 用途 | 当前配置环节 |
|---|---|
| 整理 | 文本清洗、清洗审核、事件整理、三字段结构化、内容审核 |
| 分析 | 元数据/心情/标签、核心分析、认知分析、行动规划、反馈核心分析、反馈认知分析 |
| 建图 | 要点生成、审核修正、独立复核、关系判定、盲判与裁决 |

具体键和所属用途由后端固定映射提供。普通分析与反馈重分析是不同路径，一次任务不因存在多个配置键就顺序调用所有环节。

当前整理流程仅提供清洗审核和内容审核两个可选开关；关闭时对应步骤透传上游结果、不发起该环节调用。流程是否执行与模型是否思考是两类设置。对话、ASR 和图谱向量使用用途默认配置，不提供当前环节覆盖列表。

管理页面显示当前覆盖、继承和最终生效值；保存提交用途与环节配置，服务端校验最终组合后统一提交，任一不合法则不得部分保存。具体生效时机按任务实现说明，不能概称修改后所有任务立即变更。

## 6. 测试调用

- 可测试页面尚未保存的配置，或读取已保存用途/环节配置；测试不直接替代保存。
- 语言模型通过固定最小请求测试，需带最终有效的思考参数。
- 向量模型执行实际最小向量化请求并确认返回向量；当前测试维度为 1024。
- ASR 当前只做静态配置校验并返回跳过真实音频测试的结果。
- 保存不以真实测试通过作为前置。测试会访问所选渠道，结果与错误不得泄露密钥。

## 7. 生效时机与设计对应

| 调用路径 | 配置生效方式 |
|---|---|
| 应用内整理流水线 | 每次创建步骤 LLM 时解析当前用途与覆盖；已发出的调用不变，后续步骤和重新调用读取新配置 |
| 对话 | 每次对话调用读取当前 `chat` 设置 |
| 语音协议适配 | 请求时解析当前 `transcription` 设置，批次词表另有模型与指纹冻结规则 |
| 图谱与接入图谱任务的应用内分析 | 创建任务时冻结模型、地址、思考参数和其他运行配置；任务恢复继续使用冻结参数，密钥按原渠道当前值读取 |
| Skill 整理/分析 | 生成端模型由运行 Skill 的环境决定，不能假定本管理端配置选择了该生成模型；涉及服务端向量或保存工具的配置以对应实现为准 |

源码中保留的旧独立分析流水线与当前日记分析入口必须区分，详见实现设计。管理员变更配置后应先确认目标任务属于逐调用读取还是冻结任务。

## 8. 验收与范围

- 三种模型类型、六个当前用途及固定环节可正确列出和保存。
- 模型/思考独立继承，渠道模板与最终思考能力组合正确。
- 类型不符、禁用、缺密钥、缺渠道关系或非法思考配置不能保存或执行。
- 模型/渠道/关联被默认或覆盖引用时受到破坏操作保护。
- 清空密钥、编辑留空和普通查询的语义明确，查询不返回认证值。
- 语言、向量、ASR 测试行为分别可核验；保存失败不部分提交。
- 动态读取与冻结任务的生效规则分别验证，恢复任务不会无说明地漂移配置。
- 移动端可编辑控件实际字号至少 `16px`，保留缩放。

本模块不提供配置历史版本管理、自动故障换模型、单用户/单日记的用途覆盖、全局温度和超时/重试编辑。代码现有任务冻结机制属于任务实现，不等同为管理端配置历史。
