# 备份与恢复功能约定

核对基线：2026-10-29。对应[实现设计](实现设计.md)，定时执行的取舍见[定时备份决策](定时备份决策.md)。

## 1. 目标与边界

超级管理员导出、迁移补齐和恢复系统中的核心日记数据。备份包含用户信息及加密密码字段，必须控制下载、上传、解密与操作权限。

本能力为固定范围的逻辑数据导出/导入。当前采用相同 ID 跳过、逐条尽力导入的策略，已有数据不覆盖；整库物理恢复、覆盖导入和导入事务整体回滚不在当前能力内。

## 2. 当前数据范围

当前包格式为 schema v3，数据表按以下顺序组织与导入：

| 顺序 | 表 | 含义 |
|---|---|---|
| 1 | `users` | 用户及其加密密码 |
| 2 | `diaries` | 日记原文、日期、状态与删除标记 |
| 3 | `organize_tasks` | 整理与分析任务记录 |
| 4 | `diary_organized` | 当前结构化日记 |
| 5 | `diary_events` | 日记事件 |
| 6 | `analysis_runs` | 分析轮次 |
| 7 | `analysis_items` | 日记级和事件级分析项 |
| 8 | `analysis_feedback` | 分析反馈 |
| 9 | `tags` | 用户标签 |
| 10 | `diary_tags` | 日记与标签关联 |
| 11 | `event_tags` | 事件与标签关联 |
| 12 | `favorites` | 日记和事件收藏 |

导出使用表字段，不额外排除软删除日记。未选择筛选时包含这些表的全部记录；筛选时按匹配日记收集关联数据。

对话、批注、日程、热词与人物资料、独立行动项、模型配置、图谱任务及图谱结果、过程日志、语音批次及音频对象均未列入当前范围。业务继续扩展时必须先调整表清单、外键顺序、包版本和验证规则，不能据“全量备份”名称推定全库已覆盖。

## 3. 导出约定

- 在管理端 `/admin/backup-restore` 发起，支持全量、按用户、按日记日期及用户与日期交集四种范围。
- 按日期使用 `diaries.diary_date`；筛选后只导出匹配日记所属用户及关联数据。指定用户没有匹配日记时，当前筛选路径不会单独导出该用户。
- 导出任务异步执行，页面展示阶段、当前表、状态和结果摘要。
- 运行中可请求取消；当前取消在逐表检查点生效，压缩阶段的边界见实现差异。
- 加密 ZIP 中每张表对应一个 JSON Lines 文件，每行一条记录，并包含 `manifest.json`。
- manifest 应说明系统、schema 版本、导出时间、任务/备份包标识、筛选范围、逐表数量和逐文件摘要。整包摘要和字段版本的旧目标尚未实现，见第 8 节。
- 使用部署环境提供的 `BACKUP_MASTER_KEY` 加密；缺少密钥时禁止导出或解密。密钥不得写入包、数据库、报告和日志。
- 导出包默认有效 7 天，过期拒绝下载；自动物理清理的实现情况需与元数据过期分开说明。

## 4. 导入约定

1. 管理员上传加密 ZIP，服务端同步预检。
2. 页面按表展示预计新增、跳过、失败及摘要。
3. 管理员确认范围和跳过策略后，基于成功的预检记录发起异步导入。
4. 按父表到子表的顺序导入；已有主键记录跳过，不覆盖。
5. 父数据不存在或单条插入失败时记录原因，继续处理其他记录。
6. 每条成功记录独立提交，任务结束生成逐表报告，存在失败时状态为 `partial_failed`。

预检必须拒绝无法解密、缺失必要文件、无效 JSON 和不兼容 schema 的包。目标还包括字段完整性、内部重复和外键校验；当前预检深度与正式导入之间的差异见实现设计。

- 预检时可引用包内父记录或数据库已有父记录；正式导入重新检查当时数据库状态。
- 任务记录中的 `running` 状态按原字段导入，不自动解释为后台任务可以续跑。
- 正式导入开始后不支持取消和整批回滚；单行数据库失败只回滚该次插入。
- 报告应含新增、跳过、失败数，以及表、记录 ID 和原因摘要，避免复制原文或密码字段。

## 5. 页面、确认与记录

页面独立于用户端底部菜单，包含导出、上传预检/导入、备份恢复记录三部分。导出和正式导入前展示二次确认，至少包括操作范围、是否含加密密码、加密与保留期、已存在 ID 跳过及审计说明。

统一记录列表承载任务、进度、下载和报告入口。当前界面展示类型、状态、范围、阶段/表、创建和完成时间、结果与错误摘要；详情不显示原始业务内容。设计要求标明操作人，实际响应字段覆盖情况见实现差异。

导出、下载、预检和导入均形成记录，导出取消更新其任务记录。目标保留期为备份包/导入报告 7 天、审计记录 90 天；当前代码对这些期限的执行不完整，不应把目标写成已经实现的自动清理。

## 6. 定时全量备份

- 应用内调度每天在配置的本地时间触发，默认 `Asia/Shanghai` 的 `02:00`。
- 时间使用 `HH:MM`，时区使用 IANA 名称；非法配置在启动时明确报错。
- 应用启动计算严格晚于当前时间的下一次触发，不补跑错过的日期。
- 每次执行调用同一全量导出服务，成功落包并保存任务结果；单次失败立即再尝试一次，两次失败记录后等待下次调度。
- 新定时任务不取消、不等待前一次任务，允许并行且各自记录。
- 备份目录可配置，容器重建后的保留依赖部署卷持久化。
- 采用单 worker/单调度实例运行；当前未实现多实例分布式去重或锁。

## 7. 验收口径

- 普通用户不能访问管理端或备份接口，管理员能完成筛选导出、下载、预检、确认导入和报告查询。
- ZIP 加密、逐文件完整性、版本不兼容拒绝、父子顺序、已有 ID 跳过和逐条失败继续符合规则。
- 筛选不带入范围外日记数据，关联用户及收藏范围一致。
- 取消不损坏其他任务；重复下载形成独立记录。
- 定时触发时间、启动不补跑、失败重试一次及并行执行可核验。
- 到期下载限制、文件和报告物理清理应分别测试，不能用有过期字段代替清理验收。
- 报告、审计与日志不暴露日记原文、密码值、密钥或 ZIP 内容。

## 8. 已知差异与恢复前置

| 设计约定 | 当前实现事实 |
|---|---|
| 7 天清理包和报告、90 天清理审计 | 包记录有过期字段且下载校验时间；报告也有到期字段，当前未实现统一物理清理与到期报告过滤 |
| 整包摘要、字段版本与完整字段预检 | manifest 仅逐表 count/SHA-256；预检按主键、父引用与解析检查，未完整执行字段类型/必填字段插入验证 |
| 取消形成独立审计，详情展示操作人 | 取消更新原导出记录；列表/详情响应未返回操作人字段 |
| 数据恢复前终止活动语音批次并清理音频 | 旧语音约定提出此要求，当前 `import_backup` 未实现该前置协调 |
| 有序保存后可恢复正在运行的业务任务 | 导入仅保留任务记录状态，图谱/语音等完整运行上下文不在包内 |

因此执行导入前应人工核对正在运行的日记/语音任务、缺失模块数据和密钥兼容性；不能将一次尽力补充导入视为整套系统恢复完成。本轮未改写数据或执行导入。
