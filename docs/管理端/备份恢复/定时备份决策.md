# 应用内定时全量备份决策

状态：已接受。原决策保留，2026-10-29 归入备份恢复模块。

## 背景与选择

当前部署以单个应用实例、单 worker 运行。系统需要每天自动生成固定日记核心范围的全量备份，并复用现有导出、加密和记录能力。

选择应用进程内调度器，在可配置的 IANA 时区与 `HH:MM` 时间触发，默认 `Asia/Shanghai` 的 `02:00`。应用启动不补执行；单次失败立即重试一次，两次失败后等待下一日计划。

新定时任务不取消、不等待仍在运行的前一任务，允许并行且分别记录。包目录通过配置指定，生产部署必须持久化该目录。

## 理由与影响

应用内调度可直接复用现有备份服务及鉴权上下文，减少外部定时触发和接口认证链路的维护成本。允许并行避免长任务阻塞下一次计划，代价是额外数据库、内存与磁盘压力。

单 worker/单调度实例是当前运行前提；源码只有实例内启动保护，没有跨进程/跨副本分布式锁。扩展部署副本数前，须重新选择调度归属与去重机制。

当前执行机制与已核实缺口见[实现设计](实现设计.md)，数据范围及保留期见[功能约定](功能约定.md)。
