# 系统备份与恢复执行计划

## 1. 目标

实现一个仅超级管理员可用的系统备份与恢复能力，覆盖核心数据加密导出、备份包预检、异步导入、任务记录、审计追踪和页面入口。

## 2. 实施原则

- 先实现核心闭环，再补充体验优化。
- 不覆盖已有数据。
- 不把日记原文、密码字段、密钥内容写入报告和审计详情。
- 页面只保留一个“备份恢复记录”，不拆任务记录和审计记录两个列表。
- 当前系统无附件、无登录令牌、无第三方授权表，不做相关实现。

## 3. 阶段计划

### Phase 1：权限与基础模型

目标：建立超级管理员访问控制和备份恢复任务记录基础。

任务：

- 确认现有用户模型中的超级管理员识别方式。
- 如果当前无角色字段，补充最小权限识别方案。
- 新增备份恢复任务记录模型。
- 新增备份恢复审计元信息字段。
- 定义任务状态枚举。
- 定义操作类型枚举。
- 增加记录保留规则：审计 90 天、导入报告 7 天、导出包 7 天。

产出：

- 后端模型。
- 数据迁移脚本。
- 权限校验工具。

验收：

- 普通用户访问备份恢复接口返回无权限。
- 超级管理员可访问备份恢复接口。

### Phase 2：导出服务

目标：完成核心数据导出为加密 ZIP。

任务：

- 定义导出范围解析逻辑。
- 实现全量、用户、日记日期、用户和日记日期交集四种导出范围。
- 按表流式生成 JSONL。
- 生成 `manifest.json`。
- 计算每个数据文件摘要和整包摘要。
- 使用 `BACKUP_MASTER_KEY` 加密 ZIP。
- 实现异步导出任务。
- 实现导出任务取消和临时文件清理。
- 实现导出包 7 天过期清理。

产出：

- 导出服务。
- 导出任务接口。
- 导出下载接口。
- 导出取消接口。

验收：

- 能生成加密 ZIP。
- ZIP 内包含 manifest 和 9 张表的 JSONL 文件。
- 取消导出后任务状态为已取消，临时文件被清理。
- 过期导出包不可下载。

### Phase 3：导入预检服务

目标：上传 ZIP 后同步完成导入预检。

任务：

- 实现 ZIP 上传和解密校验。
- 读取并校验 `manifest.json`。
- 校验 schema 版本兼容性。
- 校验 JSONL 文件存在、可解析、摘要匹配。
- 校验表内 ID 重复。
- 校验关联关系。
- 根据目标库现状统计新增、跳过、失败数量。
- 按表输出预检结果。
- 版本不兼容时禁止进入正式导入。

产出：

- 预检接口。
- 预检结果结构。

验收：

- 合法备份包返回按表统计结果。
- 损坏备份包预检失败。
- 版本不兼容备份包预检失败。

### Phase 4：正式导入服务

目标：预检通过并二次确认后异步导入。

任务：

- 实现导入任务创建。
- 按外键依赖顺序导入 9 张表。
- 已存在 ID 跳过。
- 父数据缺失时记录单条失败并继续。
- `running` 任务保持原状态导入。
- 记录每张表新增、跳过、失败数量。
- 生成导入报告。
- 导入任务不可取消。

产出：

- 导入任务接口。
- 导入报告结构。
- 导入进度查询接口。

验收：

- 已存在 ID 不覆盖。
- 单条失败不影响其他数据导入。
- 导入完成后能查看报告。
- 报告不包含日记原文和密码字段。

### Phase 5：前端页面

目标：完成独立管理端入口和备份恢复页面。管理端与用户端隔离，不复用用户端底部 Tab，不在“我的”页提供入口。

任务：

- 新增管理端路由 `/admin`。
- 新增管理端登录页 `/admin/login`，或复用登录能力但使用管理端入口承载登录后跳转。
- 新增 `/admin/backup-restore` 页面。
- 新增管理端布局，包含顶部栏、左侧系统管理导航和主内容区。
- 管理端仅允许 `username == "admin"` 的超级管理员访问。
- 用户端不展示“系统备份与恢复”入口。
- 实现导出范围表单。
- 实现导出二次确认。
- 实现 ZIP 上传和预检结果展示。
- 实现导入二次确认。
- 实现备份恢复记录列表。
- 实现记录详情、进度、下载、取消、报告入口。
- 实现无权限页面或无权限提示。

产出：

- 管理端页面。
- 前端路由。
- 管理端权限拦截逻辑。

验收：

- 超级管理员能完整完成导出和导入流程。
- 用户端没有备份恢复入口。
- 普通用户直接访问管理端页面被拦截。
- 管理端页面不显示用户端底部 Tab。

### Phase 6：清理、审计与验证

目标：补齐高敏感能力的清理和验证。

任务：

- 实现导出包过期清理任务。
- 实现导入报告过期清理任务。
- 实现审计记录 90 天清理任务。
- 补充关键单元测试和接口测试。
- 补充大文件和异常包测试。
- 补充权限测试。
- 更新数据库设计文档。

产出：

- 清理任务。
- 测试用例。
- 文档更新。

验收：

- 过期数据按规则清理。
- 权限、导出、预检、导入、报告和异常场景测试通过。

| `/api/admin/backup-restore/exports/{id}/download` | GET | 下载导出包 |

| `/api/admin/backup-restore/imports/{id}/report` | GET | 查看导入报告 |
| `/api/admin/backup-restore/records` | GET | 查询备份恢复记录 |
| `/api/admin/backup-restore/records/{id}` | GET | 查询记录详情 |

## 6. 测试计划

### 6.1 权限测试

- 普通用户不能看到入口。
- 普通用户不能访问接口。
- 超级管理员能访问页面和接口。

### 6.2 导出测试

- 全量导出。
- 按用户导出。
- 按日记日期导出。
- 用户和日记日期交集导出。
- 未配置 `BACKUP_MASTER_KEY` 时禁止导出。
- 导出取消后清理临时文件。
- 导出包过期后不可下载。

### 6.3 预检测试

- 合法包预检成功。
- manifest 缺失预检失败。
- 版本不兼容预检失败。
- JSONL 损坏预检失败。
- 摘要不匹配预检失败。
- 外键缺失统计为失败。

### 6.4 导入测试

- 新数据成功导入。
- 已存在 ID 跳过。
- 关联父数据缺失时单条失败。
- `running` 任务保持原状态。
- 导入报告不包含敏感正文。

### 6.5 页面测试

- 用户端不展示备份恢复入口。
- 管理端仅超级管理员可访问。
- 普通用户访问 `/admin` 或 `/admin/backup-restore` 被拦截。
- 管理端页面不显示用户端底部 Tab。
- 导出二次确认展示完整风险信息。
- 导入预检按表展示。
- 备份恢复记录展示状态、阶段和操作。

## 7. 实施顺序

1. 后端权限与记录模型。
2. 导出服务。
3. 导入预检服务。
4. 正式导入服务。
5. 前端入口和页面。
6. 清理任务。
7. 测试和文档更新。

## 8. 风险控制

| 风险 | 控制方式 |
|---|---|
| 备份包泄露 | 强制加密，7 天过期，不记录密钥 |
| 普通用户越权 | 前后端都做超级管理员校验 |
| 导入破坏已有数据 | 已存在 ID 一律跳过，不覆盖 |
| 版本不兼容导致数据错乱 | manifest 版本不兼容时禁止导入 |
| 报告泄露敏感内容 | 报告只记录表名、ID、原因摘要 |
| 大数据导出超时 | 导出异步执行 |
| 大数据导入超时 | 正式导入异步执行 |
