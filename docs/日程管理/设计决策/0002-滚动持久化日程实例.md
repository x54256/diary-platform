# 滚动持久化日程实例

状态：已接受。核对日期：2026-10-29。

## 背景与选择

日程任务定义规则，日程实例承载用户实际执行状态。漏办追溯、单次修改、后续修改和按日查询都需要稳定的实例身份，因此将未来窗口的实例持久化，并保留已发生实例。

## 结果与实现关系

长期维护目标为未来 180 天。当前创建请求同步生成近期 7 天，剩余范围由持久化维护任务补齐；服务启动与每日维护继续滚动扩展。普通列表读取只查持久化实例，不生成数据。

这一分工使读取与外部节假日服务解耦，同时引入后台任务完成前远期实例尚未齐备的时间窗口。实例唯一约束和删除墓碑共同保证重试幂等及单次删除不再生。具体恢复机制、边界与差异见[实现设计](../实现设计.md)。
