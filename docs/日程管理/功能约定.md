# 日程管理功能约定

> 核对日期：2026-10-29。单次、全天、循环日程及日记行动项同步入口已有实现。
> 本文定义业务与交互约定；现行执行路径及尚未对齐的规则见[实现设计](实现设计.md)。

## 1. 目标与范围

用户从底部“日程”入口安排和执行具体日期的行动，查看日视图、相邻双日时间轴、日程列表和周打印。日程既可手工创建，也可由用户在日记“行动”面板确认同步创建。

日程负责时间安排和实例执行；日记行动项负责日记中的可执行事项。关联规则统一见[行动项功能约定](../行动管理/日记行动项功能约定.md)，全局待办和 OKR 的后续范围见[待办与目标规划](../行动管理/待办与目标规划.md)。

## 2. 核心对象

| 对象 | 业务含义 |
|---|---|
| 日程任务 | 一次性或循环安排的定义，保存名称、开始日期、时间和循环规则 |
| 日程实例 | 日程任务在某个日期发生的一次执行安排，承载计划快照、完成状态和执行备注 |
| 循环规则 | 周期、间隔、日期条件及结束条件的组合 |
| 节假日年度数据 | 中国法定放假日与调休上班日的年度缓存 |
| 维护任务 | 在请求完成后继续补齐或清理实例的后台任务 |

一个日程任务可以产生多个实例；用户完成、备注和单次修改的对象是具体实例。日记整理任务、分析任务属于后台处理流程，不能与日程任务混用。

## 3. 创建规则

- 已登录用户创建本人日程，名称去除首尾空格后不能为空。
- 新建开始日期为今天或未来日期。
- 单次日程产生一次执行安排；循环日程按有效规则产生多个实例。
- 全天日程明确标记为全天，不填写具体时刻；定时日程必须同时填写开始和结束时间，结束时间晚于开始时间，日期归属为同一天。
- 用户在保存前看到名称、日期、时间与自然语言循环摘要。
- 基础循环先展示；间隔、每月第 N 个星期几和结束条件放在高级设置中。
- 日程实例持久化，长期滚动维护未来 180 天窗口。请求与后台如何分工由实现设计说明。

## 4. 循环规则

星期编码统一为 `0=周日`、`1=周一`，界面一周从周一开始；展示顺序与存储编码分别维护。

| 规则 | 含义与边界 |
|---|---|
| 不重复 | 只在开始日期发生 |
| 每 N 天 | 从开始日期起每 N 天发生，N ≥ 1 |
| 每 N 周 | 从开始日期所在周期计算间隔，按所选星期发生 |
| 每 N 月指定日期 | 按指定日发生；超过当月天数时对齐月末，如每月 31 日在二月发生于二月末 |
| 每 N 月第 N 个星期几 | 只在指定位置发生；该月不存在时跳过，如某月没有第五个周一 |
| 每 N 年 | 按指定月日发生；二月二十九日在非闰年对齐二月末 |
| 工作日 | 按节假日数据加入调休上班日，排除法定放假日 |
| 休息日 | 按节假日数据加入放假日，排除调休上班日；连续休息日每天生成一次 |

每周、每月、每年的基础选择可由创建日期推导默认星期或月日。高级周期默认间隔为 1，间隔不得小于 1。工作日和休息日当前按日期是否符合分类判断，不按高级间隔跳过符合日期。

循环结束条件三选一：永久、截止日期或发生次数。截止日期不得早于开始日期；次数至少为 1；截止日期与次数不能同时设置。不重复规则不设置循环结束条件。

## 5. 节假日与实例维护

- 有有效年度数据时，工作日与休息日以缓存中的调休、放假日期修正自然星期。
- 无有效数据时，工作日按周一至周五、休息日按周六和周日兜底，不阻塞其他规则的日程。
- 已成功获取的年度非空数据继续复用。原需求要求缺失年度每日重试；现行实现的重试间隔及差异见实现设计。
- 自动修正只作用于未来、未完成、未被手工修改的实例；历史、已完成和手工修改实例保留。
- 漏办实例继续保留原计划日期和未完成状态，用户可以稍后完成。
- 无限循环持续补齐窗口，不一次生成无限未来。

## 6. 浏览与交互

### 日视图与双日时间轴

- 默认进入日视图，顶部显示周日期并可选择日期、前后切换及按年周定位。
- 全天实例显示在时间轴上方；定时实例保留真实时间标签，无任务空档可以压缩。
- 同一时段的全部实例纵向完整展示，任务不能因时间重叠而被折叠隐藏。
- 日期切换支持移动端横向滑动；周视图当前使用相邻双日时间轴。
- 卡片展示名称、计划时间、完成状态和执行备注预览；点击卡片查看详情，独立完成按钮切换完成状态。
- 新建入口位于顶部工具栏。原浮动加号、七列周概览等历史交互与现行页面的差异见实现设计。

### 列表、漏办与打印

- 日程列表按日期范围查看，漏办入口帮助追踪尚未落实的安排；漏办列表当前采用每条任务演变链的最近一条实例判断，详见实现设计。
- 用户可以对未来已生成实例提前完成，也可以对历史未完成实例补记完成。
- 执行备注属于实例，可独立新增、修改或清空，不回写日记行动项。
- 周打印通过浏览器打印预览进行，使用独立布局，每周七列、时间轴、全天区域和空的线下勾选框。
- 打印内容包含名称及计划时间，勾选框不反映线上完成状态；不打印编辑控件、执行备注或线上操作状态。
- 当前桌面打印入口允许选择多个周，按周组织打印；每周从周一开始。

## 7. 修改与删除

| 操作 | 功能约定 |
|---|---|
| 修改单次日程 | 更新唯一执行安排；若关联行动项，同步双方字段 |
| 循环“仅此日程” | 只修改选定实例，记录手工修改标记，不回写行动项通用规则 |
| 循环“此日程及以后” | 从选定实例发生日期起调整后续安排，保留之前已发生实例 |
| 删除单次或循环单次实例 | 经范围确认后从正常查询中移除；不导致已删除实例被自动补齐 |
| 删除循环当前及以后 | 截止原循环，移除指定日期及后的安排，保留之前历史 |

用户确认删除范围后执行；关闭有未保存修改的编辑面板时提示放弃或继续。业务上的不可见与存储层的墓碑、物理清理由实现设计定义。

原需求对后续修改还要求保护已发生、已完成及手工修改实例。当前路由的部分分支尚未完整满足这些约束，不能将差异视为已通过，详见[规则对照](实现设计.md#7-设计与实现差异)。

## 8. 权限、时间与验收

- 任务、实例和维护记录均按用户归属隔离，不能通过其他用户的 ID 读取或修改安排。
- 产品时间语义使用 `Asia/Shanghai`。后端新建与维护部分路径使用服务器 `date.today()`，部署时区要求及差异见实现设计。
- 移动端可编辑控件实际字号不小于 `16px`，保留用户缩放能力。
- 创建验收覆盖单次、全天、全部循环类型、间隔、三种结束条件、月末对齐、闰日、第五个星期几缺失及无效跨日时间。
- 维护验收覆盖窗口补齐、去重、后台失败恢复、节假日兜底，以及历史/已完成/手工修改保护。
- 执行验收覆盖完成、取消完成、提前与逾期完成、完成时间、执行备注、漏办筛选及用户隔离。
- 修改与删除验收覆盖 `single`、`following`、任务演变链、行动项关联、单次删除后不再生及后台清理。
- 页面验收覆盖重叠实例完整展示、压缩空档、周一起始、列表、双日切换、确认弹窗及手机可读性；打印另行验证七列布局与线下勾选。

详细请求/响应以[接口模型](../../backend/schemas/schedule.py)及[路由](../../backend/routers/schedules.py)为准。当前测试覆盖和未覆盖范围见实现设计。
