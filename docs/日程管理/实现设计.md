## 2. 数据与身份

`ScheduleTask` 保存规则，`ScheduleOccurrence` 保存具体日期的计划快照和执行状态。实例通过 `(task_id, scheduled_date)` 唯一约束保证同任务同日只有一条。

循环修改产生新任务时，`source_task_id` 指向原任务，形成演变链，供漏办聚合等功能识别同一安排的历史。实例保留完成时间、执行备注和手工修改标记。

`ScheduleMaintenanceJob` 保存操作、起始日期、状态、重试次数、可执行时间及运行环境；`ENSURE` 补齐，`DELETE` 清理。表字段完整定义以模型为准。

## 3. 创建与实例维护

1. 创建请求通过 `ScheduleTaskCreate` 校验并保存规则；新建开始日期使用服务器当天作为下限。
2. 请求内只用已有节假日缓存生成近期实例，`IMMEDIATE_WINDOW_DAYS=7`；不在请求路径访问节假日服务。
3. 非单次任务同事务写入 `ENSURE` 维护任务，起点为近期范围之后；提交后返回已经生成的实例。
4. 后台约每 2 秒读取一条可执行维护任务，继续补齐至当前日期后 180 天。
5. 服务启动及每天 `00:05 Asia/Shanghai` 为所有用户维护窗口。年度数据获取仅由这一维护路径触发。
6. 列表读取直接查询已经持久化的实例，不生成实例，也不访问外部服务。

生成器按日期扫描规则、一次查询已有日期，批量 `INSERT ... ON CONFLICT (task_id, scheduled_date) DO NOTHING`。单次删除保留 `deleted` 实例占位，生成器会将其视为已有日期，阻止重新生成。工作日/休息日修正只删除未来窗口内未完成且未手工修改的不合规实例。

维护任务按 `TASK_ENVIRONMENT` 隔离。重启把本环境 `running` 改回 `queued`；失败后延迟 5 分钟重试，累计 3 次后标为 `failed`。当前进程调度按单 worker 使用，没有分布式抢占锁。

## 4. 循环与节假日

- 规则匹配统一由 `occurs` / `_matches_rule` 实现；次数结束通过从原任务开始日期累计符合规则的日期计算。
- 每月日期和年度闰日使用月末对齐；每月第 N 个星期几必须真实存在。
- 工作日/休息日从年度缓存加载修正集合，未覆盖日期按自然星期判断。
- 年度缓存有非空有效数据后永久复用；无效或获取失败的年度缓存，当前 `HOLIDAY_RETRY_INTERVAL` 为 30 天。每次后台维护调用刷新函数，但间隔内不重新请求。
- 请求头、服务地址和解析字段以节假日服务源码为准；文档不复制外部接口协议。

## 5. 修改、完成与删除

完成接口只接收 `completed`，设置实例状态及完成时间，并在同一事务调用 `sync_action_from_occurrence`。执行备注通过独立 `/note` 接口保存，空白转换为空值。

编辑路径先比较日期、循环类型、结束条件及周期参数是否变化：

- 发生规则变化时，截断原任务，生成带 `source_task_id` 的新任务；近期实例同步替换，更远实例排入删除/补齐任务；调用行动关联迁移。
- 未发生规则变化时，直接更新选定实例并设置 `manually_modified`，再按 `scope` 调用行动回写。

因此 `scope` 不是当前分支的唯一控制条件。完整的“仅此日程/此日程及以后”目标语义与现行实现存在差异，见第 7 节。

删除单个实例将状态改为 `deleted`。删除循环当前及以后先截止原任务，近期范围物理删除，更远范围交给持久化 `DELETE` 任务。随后同事务处理行动关联或重新选择完成锚点。

## 6. 查询、漏办与前端

普通查询按用户、日期范围、状态非 `deleted` 过滤，按归属日、全天优先、开始时间和创建时间排序。

漏办接口采用上海当前时间：历史日期，或今日已过结束时间的非全天实例为候选；排除每日间隔为 1 的任务。沿任务演变链分组，每组先取最新候选，再只保留该实例仍为 `pending` 的组。因此该入口是近期未落实安排的聚合，不等于全部历史未完成实例列表。

当前页面的日/周切换对应单日和双日时间轴；卡片入口查看详情，完成按钮调用 `toggleSchedule`，备注单独编辑。源码仍残留旧逾期理由函数，但页面现行完成入口不经过该函数。

打印弹层选择一或多个周，另行加载范围内实例，按七列和空线下勾选框输出，不将线上完成结果打印为已勾选。

## 7. 设计与实现差异

| 设计约定或旧文档说法 | 当前源码事实 | 维护要求 |
|---|---|---|
| 创建立即持久化完整 180 天，查询前补齐 | 创建近期 7 天，后台补齐；读取不生成 | 功能约定保留滚动窗口目标，按本实现分工理解；后台失败时不能保证任意查询范围已补齐 |
| 年度数据为空时每日重试 | 空/失败结果等待 30 天后重试 | 保留原每日重试需求与现行策略差异，后续变更需明确选择 |
| 逾期完成弹可跳过理由并保存 | 现行完成载荷无理由字段；执行备注独立保存 | 不能把旧弹窗和 `overdue_reason` 残留当作有效链路 |
| 循环按 `scope` 区分单次/后续修改 | 是否变化日期或周期决定是否拆任务 | `scope=single` 改规则仍走后续拆分；`scope=following` 只改名称/时间只改选定实例，需后续修复 |
| 后续修改保护历史完成实例 | 当前范围替换只按日期过滤，未限定 `pending` 或 `manually_modified` | 不承诺所有完成/手工修改保护已实现 |
| 所有删除均物理删除 | 单次墓碑、后续近期物理删除、远期异步删除 | 删除验收按可见性、避免再生和后台清理分别验证 |
| 上海日期为所有边界 | 生成和创建校验使用服务器 `date.today()`，漏办和定时触发显式上海时区 | 部署时区须与产品一致；代码未统一时间来源 |
| 浮动新建按钮、七列交互周概览、当前时间线 | 新建在顶部，交互周布局为双日；七列主要用于打印，未见当前时间指示线的有效渲染 | 历史交互目标未完整覆盖，不能按旧文档验收通过 |
