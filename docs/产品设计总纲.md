# 日记管理平台产品设计总纲

> 核对日期：2026-10-29。本文维护产品定位、模块边界、能力状态与规划；具体规则和已知差异由模块文档维护。

## 1. 产品定位

平台围绕个人主动记录的数据，支持保存经历、整理日记、分析与反思、维护行动和日程，并为后续自我认识提供事实基础。

主要场景：

- 手机或电脑输入文字、上传录音、查看和维护日记。
- 将原始记录整理为有序事件，并生成分析、反馈和行动项。
- 查看事件、批注和对话，安排日程并记录执行。
- 管理员维护模型调用配置、数据备份与恢复。

## 2. 角色和访问边界

| 角色 | 当前职责 |
|---|---|
| 普通用户 | 管理本人的日记、行动、日程、热词和人物资料 |
| 超级管理员 | 在普通用户能力外维护备份恢复及模型配置；当前按内置管理员用户名判断 |
| Skill 调用方 | 通过固定接口和服务端绑定用户执行受支持的数据操作，权限机制与浏览器登录分开 |

界面由用户端和管理端组成。受保护业务按用户隔离；登录、注册等身份入口有自己的访问规则。来源上下文等路径已发现的权限缺口在模块文档显式列出，产品隔离目标与当前实现分别说明。

## 4. 设计与实现的关系

功能约定定义目标行为、输入输出、边界和验收标准。实现设计说明具体路径、状态、数据、关键依赖及恢复方式。重要规则通过设计与实现对应表联系，实际覆盖不足单独列出。

AI 整理与分析各有两种实现：

- 应用内：用户在页面触发，后端任务运行模型处理并保存结果。
- Skill：在对话中读取来源、澄清、审阅和确认，通过固定工具校验与保存。

两种路径的人工参与、首次/重复执行、反馈重分析和任务恢复能力分别核对。功能设计不等于某一条调用路径，代码现状也不会自动替代仍有效的目标规则。

## 6. 页面导航

用户端底部保留日记、日程、回顾、AI伙伴和我的。日记、日程、我的已有对应页面；回顾和 AI伙伴保留路由入口，当前没有业务页面。

管理端导航保留备份与恢复、模型管理、渠道管理、模型设置。日程、行动项和语音等功能的详细入口见各模块说明。

## 7. 全局约束与维护

- 个人数据、来源上下文和后台任务按用户及任务环境隔离；服务端执行最终权限检查。
- 认证配置、模型密钥和完整个人正文的排查输出遵守 [AGENTS.md](../AGENTS.md)。
- 移动端编辑控件实际字号不低于 `16px`，保持用户缩放能力。
- 规则只在所属模块完整定义一次；其他模块说明调用关系并引用。
- 重要设计决策保留背景、原因、影响和现行状态；有效案例和验收边界随功能文档维护。
- 过程材料提炼后清理，尚未解决的差异不能随旧文件删除而丢失。
