## 2. 准备配置与数据库

本文后续启动流程以已有适配当前代码的数据库为前提。新环境须先创建数据库、安装扩展并完成基础结构及升级；仓库目前没有从空库一次完成当前结构的统一初始化入口，单独启动应用不能完成这一步。

在项目根目录运行：

```bash
cd backend
cp .env.example .env
```

首次准备 PostgreSQL 时，由数据库管理员在 `psql` 中创建独立角色和数据库，示例名称按环境替换：

```sql
CREATE ROLE diary_user LOGIN;
\password diary_user
CREATE DATABASE diary_platform OWNER diary_user;
```

`\password` 交互设置认证值，避免明文出现在命令历史。随后使用有权限的账号在目标库安装所需 `vector` 扩展，并核对业务结构与历史迁移；创建数据库不等于已初始化应用结构。

完成下一节的 Python 虚拟环境与依赖安装后，可以生成配置所需随机值。以下命令由维护者本地运行，输出直接写入本地配置，不复制到讨论、日志或版本库：

```bash
venv/bin/python -c 'import secrets; print(secrets.token_urlsafe(32))'
venv/bin/python -c 'from cryptography.fernet import Fernet; print(Fernet.generate_key().decode())'
```

第一条可分别生成 JWT 签名密钥和独立备份主密钥；第二条生成合法 Fernet 密钥。已有环境的密钥涉及历史数据解密与备份恢复，按原环境维护，不因更新代码重新生成覆盖。

在本地配置文件中填写数据库、JWT 签名密钥、Fernet 加密密钥、备份主密钥及 MinIO 参数。字段名和默认值以 [Settings](../../backend/config.py) 为准；真实认证值保存在本地配置中。

- `.env` 按进程工作目录解析，后端必须从 `backend` 目录启动。
- 模型 API 地址、密钥、模型选择和思考模式由管理端维护。
- 本地和生产共享数据库时，设置不同 `APP_ENV`，隔离后台任务执行环境。
- Skill API 配置绑定用户和 Token；Token 为空时接口关闭，配置只在有对应调用需求时启用。

已有数据库升级前核对 [迁移与数据约束](../系统架构/数据模型与迁移.md)。启动代码会检查图谱基础表和事件字段；`create_all` 无法替代迁移，也无法自行补齐 pgvector 扩展。

本地已有的 `docker/docker-compose.infra.yml` 可以提供 PostgreSQL 与 MinIO；该文件被 Git 忽略，各环境需独立维护。确认连接目标和持久化目录后，在项目根目录运行：

```bash
docker compose -f docker/docker-compose.infra.yml up -d
```

## 3. 启动后端

首次创建虚拟环境：

```bash
cd backend
python3.11 -m venv venv
venv/bin/python -m pip install -r requirements.txt
```

另开终端，在项目根目录运行：

```bash
cd backend
venv/bin/python -m uvicorn main:app --reload --port 8000
```

服务启动会恢复后台任务并启动调度器。排查业务前，确认目标环境和任务范围。

## 4. 启动前端

使用 Node.js 20，与 [Docker 构建环境](../../docker/Dockerfile) 保持一致：

```bash
cd frontend
npm ci
npm run dev
```

| 入口 | 本地地址 |
|---|---|
| 前端 | `http://localhost:3000/secret/` |
| 后端根路径 | `http://localhost:8000/diary` |
| API 文档 | `http://localhost:8000/diary/docs` |
| 业务 API | `http://localhost:8000/diary/api` |

前端路径和 API 地址来自 [Nuxt 配置](../../frontend/nuxt.config.ts) 与 package 脚本。`NUXT_APP_BASE_URL` 控制前端前缀，`NUXT_PUBLIC_API_BASE` 控制接口基址。

## 5. 构建和验证

```bash
cd frontend
npm run build
npm test
```

后端在 `backend` 工作目录用 `venv/bin/python` 运行与修改相关的测试。需要数据库的测试必须使用测试本身要求的隔离实例；不得将生产数据库作为测试目标。

日志保存在 `backend/logs/`。排查时只输出必要的任务 ID、状态和错误类型，认证配置及个人正文按 [开发约束](../../AGENTS.md) 处理。

本轮文档整理没有启动数据库、运行迁移或发布应用；上述步骤是维护指南，具体部署环境的可用性需要在执行时验证。
