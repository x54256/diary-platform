# 语音录入需求规格

> 功能状态：已实现  
> 事实基线：2026-07-31 代码  
> 本文完整保留原设计中的目标、用户流程、页面、文件、状态、错误、安全、备份和验收需求；技术实现移入系统设计。

## 1. 背景

原设计提出时，日记录入页只支持手工输入文本。本需求增加一段或多段录音上传、语音识别和整批成功后由后台自动创建正式日记的能力；该能力当前已实现。

本功能使用阿里云百炼 `fun-asr` 录音文件识别 HTTP API，不使用 Python SDK。

## 2. 目标

- 支持在现有日记输入框中混合使用手工文字和语音转写文本。
- 支持一次选择任意数量的录音文件，单文件最大 300 MB。
- 同一批次最多并行转写 3 段，其余录音排队。
- 只有整批有效录音全部成功时，后台才创建正式日记。
- 后台保存不依赖页面是否停留、是否轮询或是否模拟点击保存。
- 失败项支持手动重试、删除；整批支持取消。
- 服务重启后能够恢复尚未完成的任务。
- 转写成功后删除原始音频，只保留最终文本。

## 3. 非目标

- 不支持浏览器直接录音。
- 不把音频作为正式日记附件长期保存。
- 不在日记详情页提供音频播放。
- 不增加日记草稿状态。
- 不支持实时流式识别。
- 不支持说话人分离和敏感词过滤；语音转写启用定制热词。
- 不使用 DashScope Python SDK。
- 不改变无语音场景下现有的手工保存流程。

## 4. 核心概念

### 4.1 语音处理批次

语音处理批次表示一次“原输入文字 + 多段录音”的后台处理任务。

批次不是日记草稿：

- 它不出现在日记列表、日历和搜索结果中。
- 它不能进入 AI 整理或分析。
- 它只保存完成本次后台任务所需的输入快照、音频项状态和最终结果。
- 只有批次全部成功后，系统才创建一条现有 `diaries` 表中的正式日记。

### 4.2 原输入文字

用户点击“开始转写”时，系统固定当前日期和输入框文字。该文本记为 `base_text`。

后台最终保存的 `original_text` 为：

```text
base_text

第 1 段录音转写文本

第 2 段录音转写文本
```

空文本片段不参与拼接，每个非空片段之间插入两个换行符。

### 4.3 日期锁

同一用户、同一日记日期，同一时间只能存在一个已开始处理且未结束的批次。

- 当前日期处理中时，该日期的录入页只读。
- 用户可以返回日记首页，再进入其他日期继续记录。
- 批次完成、取消或过期后释放日期锁。
- 日期锁只限制处理中批次，不改变“一天可以创建多篇正式日记”的现有规则。

## 5. 用户流程

### 5.1 无语音

保持现有逻辑：

1. 用户输入文字。
2. 用户点击“保存”。
3. 前端调用现有 `POST /api/diaries`。
4. 创建正式日记并进入详情页。

### 5.2 语音批次全部成功

1. 用户选择一个或多个音频文件。
2. 页面逐个上传文件，后端写入 MinIO 对象存储并展示上传进度。
3. 所有文件上传成功后，“开始转写”按钮可用。
4. 用户点击“开始转写”。
5. 后端固定 `diary_date` 和 `base_text`，批次进入排队状态。
6. 当前日期页面进入只读状态；用户可以返回其他页面。
7. 后端最多并行处理 3 个音频项。
8. 所有有效音频项成功后，后端在事务中创建正式日记。
9. 后端删除 MinIO 音频对象，批次记录创建出的 `diary_id`。
10. 用户仍在页面时，前端轮询到完成状态，更新页面文本并进入日记详情页。
11. 用户已经离开时不影响保存，新日记直接出现在列表和日历中。

### 5.3 存在失败项

1. 任意音频项失败后，批次进入 `PARTIAL_FAILED`。
2. 成功项保存转写文本，但整批文本不写入输入框，也不创建日记。
3. 成功项对应的MinIO 音频对象立即删除。
4. 失败项MinIO 音频对象保留 7 天。
5. 用户可以：
   - 手动重试失败项；
   - 删除失败项；
   - 取消整批。
6. 重试或删除后，只要剩余音频项至少有一项成功且全部为成功状态，后台立即创建正式日记。
7. 如果删除后不存在任何成功音频项，则取消批次，不因 `base_text` 单独触发自动保存。

### 5.4 取消整批

取消时：

- 不创建日记。
- 删除所有MinIO 音频对象。
- 终止尚未提交给 Fun-ASR 的排队项。
- 对已经提交给 Fun-ASR 的任务停止本地轮询；如果提供方任务仍在执行，其结果不再使用。
- 返回 `base_text` 和 `diary_date`，供当前页面恢复原输入。
- 释放日期锁。

### 5.5 失败批次过期

- 失败音频保留 7 天供用户重试。
- 超过 7 天后，批次进入 `EXPIRED`。
- 删除MinIO 音频对象、转写文本和原输入文字等敏感业务数据，仅保留必要的任务审计字段。
- 释放日期锁。

其他清理规则：

- 未点击“开始转写”的 `COLLECTING` 批次超过 24 小时后删除文件和批次。
- `COMPLETED`、`CANCELLED`、`EXPIRED` 批次只保留不含正文的任务元数据 30 天，之后物理删除。
- 正式日记创建成功后，正文以 `diaries.original_text` 为唯一正式存储；批次中的 `base_text` 和音频项转写文本随音频对象一起清除。

## 6. 页面设计

### 6.1 正常录入状态

现有输入框底部增加“添加语音”入口，下面展示MinIO 音频对象卡片：

- 文件名；
- 文件大小；
- 上传进度；
- 上传成功状态；
- 删除按钮。

全部文件上传成功后显示“开始转写（N）”。

### 6.2 当前日期处理中

- 保留顶部返回按钮。
- 不增加“切换日期”按钮。
- 日期、输入框和语音上传入口只读。
- 显示“该日期正在后台生成日记，其他日期不受影响”。
- 显示每个音频项的排队、转写和成功状态。
- 返回页面不会取消后台任务。

### 6.3 部分失败

- 顶部明确提示“尚未写入正文，也没有创建正式日记”。
- 成功项显示成功状态和只读文本预览。
- 失败项显示错误摘要、重试和删除按钮。
- 提供“重试失败项”和“取消整批并恢复原输入”。
- 页面说明失败音频保留 7 天。

### 6.4 后台保存成功

- 后台创建日记成功后，批次已持有 `diary_id`。
- 页面仍打开时根据 `diary_id` 读取正式日记，同步最终文本状态，再使用替换导航进入 `/diary/{diary_id}`。
- 页面不调用现有日记创建接口，不模拟点击保存，不重复提交正文。

### 6.5 页面状态获取

第一版采用轮询，不使用 WebSocket：

- 处理中：每 2 秒查询一次。
- 页面不可见时：暂停轮询。
- 页面恢复可见时：立即查询一次。
- 批次进入终态后停止轮询。
- 轮询只负责展示，后台任务和正式日记创建不依赖轮询。

## 7. 文件规则

### 7.1 文件限制

- 单文件最大 300 MB，即 `314572800` 字节。
- 页面不限制文件数量。
- 产品不额外限制音频时长；Fun-ASR 自身最大支持 12 小时，超过后按模型失败处理。
- 支持格式：`aac`、`amr`、`avi`、`flac`、`flv`、`m4a`、`mkv`、`mov`、`mp3`、`mp4`、`mpeg`、`ogg`、`opus`、`wav`、`webm`、`wma`、`wmv`。
- 后端同时校验扩展名、Content-Type 和实际文件大小；扩展名与 Content-Type 仅用于快速拒绝，Fun-ASR 识别结果是最终格式判定依据。

### 7.2 上传策略

- 文件选择后立即上传到本系统服务器，不消耗模型额度。
- 每个文件独立请求，避免多文件总大小导致单次请求过大。
- 上传流式写入 MinIO，不把整个 300 MB 文件读入内存。
- MinIO 不可用或容量不足时上传失败，已经成功的其他音频项保持不变。
- 页面数量不设固定上限，但对象存储容量仍是系统安全边界。

### 7.3 对象存储

- 音频保存到配置的 MinIO Bucket，数据库只保存不可公开的 `storage_key`。
- 对象键由服务端根据批次 ID 和随机值生成，不直接使用用户路径。
- 原文件名只作为展示信息保存。
- MinIO 数据目录必须使用持久化卷。

## 8. 统一响应状态

前端主要依据以下字段渲染：

```json
{
  "id": "batch-uuid",
  "diary_date": "2026-07-17",
  "status": "PROCESSING",
  "diary_id": null,
  "items": [
    {
      "id": "item-uuid",
      "sort_order": 0,
      "filename": "voice.m4a",
      "file_size": 123456,
      "status": "RUNNING",
      "transcript_preview": null,
      "error_code": null,
      "error_message": null,
      "retry_count": 0
    }
  ]
}
```

服务端不得返回：

- `storage_key`；
- MinIO 签名地址及访问凭据；
- 完整提供方响应；
- API Key。

## 9. 错误处理

| 场景 | HTTP/状态 | 用户提示 |
|---|---|---|
| 文件超过 300 MB | `413` | 单个音频不能超过 300 MB |
| 格式不支持 | `415` | 不支持该音频格式 |
| 对象存储不可用或容量不足 | `507` | 音频存储不可用，请稍后再试 |
| 同日期已有处理中批次 | `409` | 该日期正在生成日记 |
| 批次已开始后重复开始 | `409` | 当前批次已经开始处理 |
| 音频仍在上传 | `409` | 请等待全部音频上传完成 |
| Fun-ASR 限流 | 音频项保持排队或失败 | 服务繁忙，可稍后重试 |
| Fun-ASR 无法下载文件 | `FAILED` | 语音文件读取失败，请重试 |
| 识别结果为空 | `FAILED` | 未识别到有效语音 |
| 失败项已过期 | `410` | 语音已过期，请重新上传 |
| 批次不存在或不属于用户 | `404` | 任务不存在 |

错误日志必须记录本地批次 ID、音频项 ID、提供方任务 ID和请求 ID，不记录 API Key、签名地址和完整日记文本。

## 10. 测试设计

### 10.1 后端单元测试

- 单文件上传大小边界：`300 MB` 允许，超过 1 字节拒绝。
- 不支持格式拒绝。
- Fun-ASR 提交请求头和请求体正确。
- 提供方状态映射正确。
- ASR 提交请求在有热词列表时正确传入 `vocabulary_id`。
- 热词、人物姓名和常用名能够合并去重并生成稳定指纹。
- 热词指纹未变化时复用词表，变化时完整更新词表。
- 同一批次内多个音频复用同一个词表 ID。
- 不支持热词的模型跳过热词后继续识别。
- 结果 JSON 正确提取 `transcripts[].text`。
- 空转写结果标记失败。
- 并发槽最多为 3。
- 多音频完成顺序不同，最终文本仍按 `sort_order` 拼接。
- 任意失败时不创建日记。
- 重试成功后自动创建日记。
- 删除失败项后自动创建日记。
- 删除全部音频后不因 `base_text` 自动创建日记。
- 取消批次不创建日记并释放日期锁。
- 失败项 7 天后过期清理。
- 同用户同日期并发开始只允许一个成功。
- 不同日期允许同时处理。
- 最终化被重复调用只创建一条日记。
- 文件删除失败不回滚正式日记。
- 服务重启后各状态恢复正确。
- 用户不能读取、重试或取消其他用户的批次。
- MinIO 签名地址错误、过期、失效时拒绝访问。

### 10.2 前端测试

- 上传进度和错误正确展示。
- 全部上传成功前不能开始转写。
- 当前日期处理中页面只读并保留返回按钮。
- 页面返回后重新进入能恢复批次状态。
- 页面不可见时暂停轮询，恢复时立即刷新。
- 部分失败时正文不变化。
- 重试、删除和取消按钮状态正确。
- 完成后使用后端返回的 `diary_id` 进入详情页。
- 完成后前端不再调用 `POST /api/diaries`。

### 10.3 集成验收

1. 输入一段文字并上传两段录音。
2. 点击开始转写后立即返回首页。
3. 进入其他日期创建普通日记，操作不受影响。
4. 等待原批次全部成功。
5. 原日期新增一篇正式日记，正文顺序正确。
6. 重复刷新和重启服务均不会重复创建日记。

失败场景：

1. 上传三段录音，使其中一段转写失败。
2. 确认没有创建正式日记。
3. 确认两段成功文本未写入正文。
4. 手动重试失败项。
5. 全部成功后只创建一篇正式日记。

## 11. 安全与隐私

- ASR API Key 由管理端模型配置维护，后端加密存储，前端不得读取明文。
- 用户音频不写入日志。
- 日记正文和转写全文不写入普通应用日志。
- 音频对象签名地址不写入完整访问日志。
- 转写成功后立即删除原音频。
- 失败音频最多保留 7 天。
- 过期清理同时清除业务文本和 MinIO 对象键。
- 正式环境应将 HTTP 升级为 HTTPS，避免音频和签名地址被窃听。

## 12. 备份与恢复

- 正式日记仍按现有备份流程导出和恢复。
- `transcription_batches`、`transcription_items` 和MinIO 音频对象属于运行期数据，不进入备份包。
- 执行数据库恢复前，必须取消所有非终态语音批次并清理MinIO 音频对象，避免恢复后的用户数据与旧后台任务交叉。
- 数据库备份恢复不承担语音任务恢复；“服务重启恢复”只针对数据库和持久化卷保持不变的正常部署重启。

## 13. 当前实现校正

- 音频对象当前存储于 MinIO，不通过应用本地临时下载接口提供给 Fun-ASR。
- 模型、API 地址和密钥由管理端模型配置维护。
- 用户热词、人物姓名和常用名组成批次使用的 ASR 词表。
- 单文件默认上限为 300 MiB，后台默认并发数为 3，失败批次默认保留 7 天。
