# 日记对话需求规格

> 功能状态：已实现，存在数据边界偏差  
> 事实基线：2026-07-31 代码

## 1. 目标

用户围绕一篇日记进行连续对话，借助日记内容和历史消息回顾经历、澄清想法并获得引导式提问。

## 2. 原有对话需求

- **入口**：日记详情页内嵌对话区域
- **上下文范围**：以当前日记为主，AI 可参考近期日记做关联分析
- **交互方式**：问答式 + 引导反思式

## 数据反哺

- 对话内容作为数据源，24h 无新消息后自动沉淀到人物画像、心路历程和认知洞察模块

> “24 小时后反哺人物画像、心路历程和认知洞察”属于未实现的数据飞轮规划，不属于当前对话能力。

## 3. 当前业务规则

- 对话来源为 `diary_detail`，保存所属用户和来源日记 ID。
- 用户可以创建对话、读取消息并连续发送消息。
- 系统保存用户消息和 AI 回复，并按创建时间加载上下文。
- AI 上下文包含日记原文、整理结果和历史消息。
- 对话使用管理端配置的“对话”用途模型。
- 对话及消息只能由所属用户访问。

## 4. 当前实现偏差

对话本身已经校验用户，但构建来源上下文时只按日记 ID 查询，没有同时限定当前用户。该偏差必须修复，不能作为目标需求接受。

## 5. 验收标准

- 用户只能访问本人对话和本人日记上下文。
- 多轮消息顺序稳定，刷新后历史不丢失。
- 模型不可用时保留已保存消息并返回明确错误。
