# AI 整理需求规格

> 功能状态：已实现  
> 事实基线：2026-07-31 代码  
> 本文恢复原日记核心设计中的完整整理需求、输出规则和示例；已由代码证明失效的旧状态描述不再保留。

## 1. 目标

AI 整理把用户的原始日记转换为保真、可读、可编辑的结构化日记。整理只处理表达和组织，不承担心理分析、行为推断或长期画像。

## 2. 功能规则

| 项目 | 说明 |
|---|---|
| 触发方式 | 用户随时手动触发，在日记详情页点击"整理"按钮 |
| 重复整理 | 可重新整理覆盖之前结果，也可手动修改 |
| 整理能力 | 保真结构化整理：修正错别字、语句通顺、合并重复表达、按事件重组结构 |
| 整理范围 | 生成引入段、事件、琐事和后续计划；标题、摘要、地点在后续 AI 分析环节生成 |
| 原文展示 | 默认显示整理版内容，原始文本可展开查看 |
| 可编辑性 | AI 生成的结构化内容可手动修改 |

## AI 整理后正文格式

整理后的正文包含两部分：

1. **结构化日记**：把录音转文字产生的混乱文本整理成保真、好读的自然日记，不做内容压缩。
2. **日记分析**：基于结构化日记进行分析，具体格式后续细化。

> 第一阶段优先保证结构化日记的正确性和可读性。结构化日记只整理原文明确表达的内容，不推断、不补充、不拔高。

整理结果采用两层格式：

- **内部存储格式：JSON**。用于程序处理、内容检查、搜索、后续画像沉淀和结构化扩展。
- **用户展示格式：Markdown / 富文本**。用于日记详情页阅读和人工编辑。

## AI 输出约束

AI 输出约束分为两层：结构化日记改写边界、日记分析推导边界。

**结构化日记允许改写：**

- 修正错别字。
- 修正语病。
- 删除口头禅和无意义重复。
- 合并重复表达。
- 调整语序。
- 把口语化表达整理成通顺句子。
- 按事件重新组织内容。
- 剔除不承载信息价值的口头语言噪音，用书面逻辑重新组织表达。例如：
  - 根据上下文推测并修正语音识别错误（如"spilm和看奶"→"Scrum 和看板"）
  - 补全口语中隐含的逻辑连接词（如"所以""但""反而"）
  - 将口语过渡语简化为书面时间标记（如"再讲一个今天早晨的事"→"今天早上"）
  - 理顺语音转文字中时间线混乱的表述，按实际时间先后重组
  - 删除元叙述（关于写日记行为本身的表述，如"闲着也是闲着就说两句""刚讲到哪了"）
  - 将意识流问答式表达改为紧凑的书面叙述

**结构化日记禁止改写：**

- 新增原文没有的信息。
- 替用户补事实。
- 替用户补动机。
- 替用户补结果。
- 替用户补反思。
- 把模糊表达改成确定结论。
- 删除关键事实。
- 改变事件因果关系。
- 改变情绪强度。
- 把用户原本的不确定表达改成确定表达。

**日记分析允许推导：**

- 基于当天事实分析情绪触发点。
- 基于当天行为提炼当天应对方式。
- 基于当天表达分析关注点与需求。
- 识别明显认知偏差并温和校准。
- 给出低成本、具体、可执行建议。

**日记分析禁止推导：**

- 引用当天日记以外的信息。
- 做长期人格判断。
- 做心理诊断。
- 给用户贴标签。
- 没有依据地强行纠错。
- 否定用户感受。
- 输出命令式建议。
- 输出高成本建议。
- 把推导写成绝对事实。

## 结构化日记规则

**总体原则**

- 结构化日记是证据层，目标是把口述流水账整理成清晰、稳定、可追溯、可阅读的日记记录。
- 可以修正错别字、语病、不通顺表达，可以合并重复内容，可以调整内容顺序。
- 不允许补充原文没有表达的动机、结果、感受、反思或经验。
- 不展示原文没有明确表达的内容，不写：`原文未明确`。
- 重复表达只保留信息最完整、表达最清楚的一版。
- 对模糊表达采用“保留原始表达 + 标注未明确点”的方式处理，不强行解释成明确结论。
- 用户展示格式以自然叙事为主，避免把事实信息拆成表单。
- 整理不是总结。生活细节、人物互动、玩笑、情绪表达、临时转念、观点推演、具体计划默认保留，不能因为不影响主线就删除。
- 观点类内容必须保留推理过程，不能只保留结论。
- 原文中无法归入事件、琐事、后续计划的开场白或闲聊内容，应提取为日记开头的背景引入段。
- 引入段仅整理原文已有内容，AI 不主动生成。
- **最高准则**：尊重事实但不过度尊重原文。整理结果必须让人能看懂，这是给人读的。
- **剔除无信息价值的口头语言**：语音转文字中大量存在不属于日记内容的语言噪音（录音过程自语、叙述过渡、走神重复、无意义填充等），只要不承载事件、情感或认知信息，都应剔除。
- **事件描述围绕事件本身，用书面逻辑组织**：事件正文只包含与事件相关的信息（时间、地点、人物、经过、感受、思考），用书面逻辑重新组织表达，按时间先后单向叙述，补全隐含的逻辑关系，结合上下文修正语音识别错误，确保可读性。

  样例（以下均为上述原则的具体推导，不作为独立规则）：
  - 元叙述（关于写日记行为本身的表述，如"闲着也是闲着就说两句""刚讲到哪了"）不承载事件信息，应剔除
  - 口语过渡语（如"再讲一个今天早晨的事"）中"今天早上"是事件时间信息要保留，"再讲一个...的事"是叙述噪音要去掉
  - 口语中隐含的逻辑转折需补全连接词（如"下楼腿都在抖，走起路来就好很多"→"下楼腿都在抖，但走起路来就好很多"）
  - 时间线来回跳跃（如今→昨→今→明）应按实际时间先后单向重组
  - 语音识别乱码需结合上下文推测修正（如"spilm和看奶"→"Scrum 和看板"）
  - 同一信息只保留一次，不因原文在多处提及就重复出现

**事件拆分规则**

- 采用**自然日记整理格式**，一篇日记可以拆分为多个事件。
- 事件按**目标**拆分为主：只要“想解决的问题 / 想完成的事”不同，就拆成不同事件。
- 时间、地点、人物、场景、主题作为辅助判断，不作为主拆分标准。
- 没有展开讲、但有记录价值的内容归入“琐事”。
- 明确指向未来安排的内容归入“后续计划”。
- 不把未来安排混入已经发生的事件正文。
- 不把未展开的工作进展、生活插曲强行并入不相关事件。
- 同一段原文中涉及多个独立工作事项（如软件过程文档、东莞项目收尾、前端 DUS 工作），即使原文未明确分隔，也应依据事项本质拆分为独立事件。

**生成流程**

1. **轻度清洗**：修正语病、错别字、断句，删除口头禅和明显重复。保留原文表达结构，不改变含义，只做基础文本修正。
2. **深度重组**：剔除不承载信息价值的口头语言噪音，理顺时间线混乱的表述，补全隐含的逻辑连接词，改写口语表达为书面叙述，结合上下文修正语音识别错误，去除重复内容。用书面逻辑重新组织表达，整理力度要足够。
3. **事件识别**：识别原文中提到了哪些事，形成事件列表；同时识别原文开头无法归入事件、琐事、后续计划的开场白或闲聊内容，提取为引入段（introduction）。
4. **事件归类**：把原文中分散在不同位置的内容归到对应事件下，完成同一事件的信息聚合。
5. **事件内文本重组**：对每个事件内部的信息按实际发生的时间先后顺序重新排列，采用单向时间流叙述（不回跳时间），生成逻辑清晰、读起来通顺的事件文本；用书面逻辑重新组织表达，不是轻度清洗原文。
6. **自然日记格式生成**：把每个事件整理为"事件标题 + 事件正文 + 可选感受 + 可选反思与成长"。事件正文合并原来的背景、动机、过程、结果，写成自然段。
7. **内容检查与修正**：检查是否存在编造原文没有的内容、推断动机、推断感受、推断反思或成长、过度总结、事件归类错误、事实拆分过碎、生活细节丢失、思考链条被压缩、观点只剩结论、时间线来回跳跃、元叙述未删除、重复内容未去重、语音识别乱码未修正、口语表达未改写为书面通顺表述、输出不让人能看懂等问题；发现问题时直接生成修正版并替换初稿，修正后不再重新检查。
8. **正式存储**：将通过检查或已完成修正的内容保存为正式整理结果。

**内容检查记录**

- 内容检查记录内部保留，用户不可见。
- 用途是调试整理质量、排查提示词问题、辅助后续优化。
- 第一阶段采用最小记录结构，不设计复杂审计系统。

| 字段 | 说明 |
|---|---|
| check_item | 检查项 |
| status | 通过 / 已修正 |
| issue | 发现的问题 |
| fix | 修正动作 |
| before | 修正前片段 |
| after | 修正后片段 |

**单个事件展示格式**

```markdown
## 事件：事件标题

事件正文。把背景、动机、过程、结果合并成一段或多段自然语言，按阅读顺序整理，不强制拆字段。

### 感受

### 反思与成长
```

**完整整理结构**

整理后的日记按以下顺序组织：

1. **开头引入段**（可选）：原文中无法归入事件、琐事、后续计划的开场白或闲聊内容的整理版
2. **事件**（一个或多个）：`## 事件：事件标题`
3. **琐事**（可选）：`## 琐事`
4. **后续计划**（可选）：`## 后续计划`

> 日记分析（心情、标签、分析六部分）不在整理结构中，而是在 AI 智能分析阶段独立生成（见"AI 智能分析"章节）。

**事件正文表达规则**

- 事件正文承载原来的背景、动机、过程、结果。
- 事件正文写成自然段，不默认使用编号。
- 只有原文步骤非常清晰、且编号能明显提升可读性时，才使用编号。
- 事件正文可以包含当时发生的即时感受，但不展开心理分析。
- 事实信息优先合并写，避免被拆成过细字段。
- 生活细节默认保留，包括具体行为、人物互动、玩笑、吐槽、临时插曲和有记忆点的表达。
- 思考类事件要保留思考链条，包括触发原因、推理过程、尝试方向、工具选择、判断变化和阶段性结论。
- 观点类事件要保留观点推演，包括原始判断、支撑理由、类比、转折、保留意见和后续认知方向。
- 事件标题要具体概括“发生了什么”，不使用过泛的主题词。
- 事件标题优先使用“具体人物 / 具体对象 + 具体动作 / 变化”的句式。

示例：

```markdown
## 事件：今天早晨林萧鹏问我版本管理平台是否有用，他准备把它重新做出来

今天早晨林萧鹏突然问我管理平台当时用起来感觉怎么样，有没有效果。我说有效果，但后来被合并到超图后就被否定了。他说现在准备重新搞一套，因为他在做 AI 项目版本管理时也遇到了一些问题。我想把原来的版本管理平台捡起来继续做，一方面是给自己一个学习软件开发全流程的机会，另一方面也是把之前没完成的遗憾补上。
```

**琐事展示格式**

```markdown
## 琐事

1. 琐事内容一
2. 琐事内容二
3. 琐事内容三
```

- 标题固定为 `## 琐事`。
- 内容使用编号列表。
- 琐事为可选块，只有原文存在未展开但有记录价值的内容时才展示。
- 琐事指无实质价值、仅简单提及、未展开描述（缺乏细节、情感或因果逻辑）的内容，通常篇幅短、信息密度低。
- 已归入事件的内容不得再出现在琐事中（去重约束）。

**后续计划展示格式**

```markdown
## 后续计划

1. 计划内容一
2. 计划内容二
```

- 标题固定为 `## 后续计划`。
- 内容使用编号列表。
- 后续计划为可选块，只有原文存在明确指向未来安排的内容时才展示。
- 后续计划按重要性排序，而非按原文时间顺序排列。
- 反思与成长中提到的后续计划，也需同步列入后续计划部分。
- 后续计划条目需改写为语义清晰的书面表述，不保留口语化的模糊表达。

**感受表达规则**

- 事件正文里可以写具体经过中的即时感受。
- 独立的感受字段只总结整个事件的情绪变化。
- 感受字段不复述过程细节。
- 只有原文明确表达情绪时，才展示感受字段。

示例：

```markdown
### 感受
这件事里的情绪从烦躁、被忽视，转为被回应后的轻松和高兴。
```

**反思与成长表达规则**

- "反思与成长"可以承载反思、感悟、成长、自我认识等内容，但展示时不拆成内部小标题。
- 只有原文明确表达了对应内容时才整理。
- 原文没有明确表达时，不展示该字段。
- 有多条反思时，使用编号列表展示。
- 只有一条反思时，直接写自然段，不加编号。

示例：

```markdown
### 反思与成长
我意识到以后遇到这种不回应的情况，不能一直重复找同一个人，而是要更早判断是否需要换一种推进方式。
```

**模糊表达处理规则**

- 当原文出现模糊表达时，保留原始表达，并标注具体未明确的点。
- 不根据上下文强行解释成明确结论。
- 不把模糊表达改写成原文没有支撑的判断。

示例：

```markdown
## 事件：处理一件挺麻烦的事

我提到这件事“挺麻烦”，但原文未明确麻烦具体来自哪里。
```

## 3. 当前触发与状态规则

- `saved` 或 `organized` 日记可以手动触发整理。
- `analyzed` 日记不能重新整理，只能重新分析。
- 重复触发有效运行任务时复用原任务。
- 整理成功后日记进入 `organized`，并清除脏标记。
- 用户可以继续编辑结构化结果；修改原文后需要重新整理。
- 心情、标签和各类分析不属于整理输出，由 AI 分析流水线生成。

## 4. 验收总则

- 整理结果不得增加原文没有表达的事实。
- 信息只能重组和修正表达，不得用摘要替代完整经历。
- 事件、琐事和后续计划必须按文中规则归类。
- 可选字段没有依据时保持为空，不以套话补齐。
- 结构化结果必须可被前端编辑并稳定落库。
