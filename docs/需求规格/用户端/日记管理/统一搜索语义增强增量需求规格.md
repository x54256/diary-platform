## 1. 变更摘要

在已验收的 pg_trgm 关键词搜索之上**叠加 embedding 语义向量层**，形成「关键词 + 语义」**混合共存**检索：两者并行召回，按 **RRF（Reciprocal Rank Fusion，`score = Σ 1/(k+rank)`）** 融合排序。关键词分支行为不变（不替换），语义分支以「事件三层语义分块」向量化实现，结果仍以**事件为单位**聚合回现有统一事件卡。

## 3. 新增需求池（增量 P0/P1/P2）

> 仅列**增量变更**；旧 PRD 既有条目（如日期筛选、分页、用户隔离）不在本池重复。  
> 优先级：P0 必须 / P1 重要 / P2 增强。

### P0（核心，必须实现）

- **P0-SEM-1 语义分块表 + pgvector + 三层向量化逻辑**
  - 新增 chunk 表，每行 = 一个事件的某一语义层分块，字段：`event_id` + `chunk_type ∈ {fact, self_understanding, cognition}` + `content`(Text) + `embedding vector(N)`（N 与模型绑定，见待确认 #1）。
  - 向量化粒度 = **按语义维度分三层**（非全事件合并、非字段级分块）：一个事件拆 3 块，每块一个 embedding：
    - **fact（事实层）** = `event_title` + `body` + `feeling`(感受) + `reflection`(反思与成长)
    - **self_understanding（自我理解分析）** = 分析的 `EMOTION`(情绪) + `SELF_UNDERSTANDING`(关注点与需求) + `BEHAVIOR_DECISION`(行为与决策) + `ACTION_SUGGESTION`(可行动建议)（不含 feeling/reflection，二者已并入 fact 层）
    - **cognition（认知整理分析）** = 分析的 `COGNITIVE_CALIBRATION`(认知校准) + `COGNITION_ENHANCEMENT`(认知完善) + `QUESTION_ANSWER`(问题解答)（content/question，不变）
  - 启用 `pgvector` 扩展；向量列类型 `vector(N)`；索引类型（HNSW vs IVFFlat）见待确认 #2。
  - 分块口径与卡片 `build_sections(current_run, ...)` 一致：分析取**仅 CURRENT 轮次 EVENT 作用域**（对齐旧 PRD 已确认口径）。

- **P0-SEM-2 semantic_search 分支（向量召回）**
  - 查询文本经 embedding API 向量化后，在 chunk 表按向量相似度（如 cosine `<=>` 算子）检索，返回命中的 `event_id` 候选集合及语义排名（rank）。
  - 命中任一 `chunk_type` 即视为该事件在语义分支命中；按事件去重，聚合回事件级。

- **P0-SEM-3 hybrid RRF 融合排序**
  - `mode = hybrid` 时：分别取关键词分支排名（pg_trgm `similarity` 排名）与语义分支排名（向量相似度排名），按 **RRF 融合**：`score = Σ 1/(k + rank)`（k 见待确认 #3），降序排序。
  - `mode = keyword` / `semantic` 时：仅走对应单分支，排序沿用该分支排名。
  - 融合后仍需按事件去重、分页（复用现有 `limit`/`offset` + 精确 `total` 机制）。

- **P0-SEM-4 mode 参数（接口扩展）**
  - `GET /diaries/search` 新增 `mode` 参数：`mode ∈ {keyword, semantic, hybrid}`，**默认 `hybrid`**。
  - 其余既有参数（`q`/`start_date`/`end_date`/`limit`/`offset`/`user_id` 隔离/软删除过滤）不变。

### P1（重要）

- **P1-SEM-1 增量同步写 embedding**
  - 新事件创建 / 该事件分析完成时，应用层**异步**调用 embedding API 计算三层 chunk 并写入 chunk 表（触发方式见待确认 #6）。
  - 与旧 PRD 触发器维护 `search_text` 机制并行、互不干扰。

- **P1-SEM-2 查询 embedding 缓存（策略待确认）**
  - hybrid / semantic 模式每次搜索需多一次「查询文本 embedding」API 调用；是否对相同 `q` 做缓存（缓存时长/粒度）见待确认 #4。
  - 缓存命中时跳过 embedding API 调用，直接复用向量做语义检索。

### P2（增强）

- **P2-SEM-1 前端 mode 切换 UI（是否做待确认）**
  - 是否在搜索框旁提供 keyword/semantic/hybrid 切换控件；默认 hybrid 是否暴露切换见待确认 #5。

- **P2-SEM-2 命中层展示 / 语义得分呈现**
  - 在事件卡上**标注命中层类型**（fact / self_understanding / cognition），复用现有高亮样式；可选展示语义得分/融合得分。
  - 不引入「块卡片」，保持统一事件卡形态。

## 4. UI 影响

- **复用现有搜索入口与事件卡**：沿用 `frontend/pages/index.vue` 顶部搜索框 + feed 区域，沿用 `EventCard` 统一事件卡；**不新建搜索页、不新建块卡片**。
- **高亮体现「命中层」**：
  - 关键词分支行为不变——命中关键词在完整内容中高亮（前后不截断）。
  - 语义分支新增**命中层标注**：后端返回命中事件的命中 `chunk_type`（fact / self_understanding / cognition），前端在对应内容区叠加「命中层」标记（如标签/着色/角标），使「为何召回该事件」对用户可见。
  - 混合模式下，事件可能因关键词命中、语义命中、或两者兼有而被召回；命中层标注覆盖所有命中层。
- **mode 切换 UI**：默认 `hybrid`；是否提供 keyword/semantic/hybrid 前端切换控件**待用户拍板**（见 §5 #5），本 PRD 不预置决定。
- **加载/空态**：语义/混合模式需容纳「查询 embedding API 调用」的额外延迟（沿用现有 loading/骨架屏）；语义无结果时回退提示沿用现有空态文案，无新增 UI 决策。

## 5. 待确认问题

> 以下 6 条为**用户尚未拍板**的细节，原样列出，标注「待用户拍板」。本 PRD 不擅自决定或排版，全部交回主理人最终确认。

1. **embedding 模型具体选型与维度**【待用户拍板】：云端 API 具体用哪个（OpenAI `text-embedding-3-small` 1536 维 / 智谱 `embedding-2` / 通义 `text-embedding-v3` 等）？维度 N 决定 `vector(N)` 列长度，且与模型绑定（换模型需全量重算）。
2. **pgvector 索引类型**【待用户拍板】：HNSW vs IVFFlat（影响建索引方式与查询性能）。
3. **RRF 的 k 值**【待用户拍板】：融合公式 `score = Σ 1/(k + rank)` 的 k（常用 60），是否调整。
4. **查询 embedding 缓存策略**【待用户拍板】：hybrid / semantic 模式每次搜索多一次查询文本 embedding API 调用，是否对相同 `q` 做缓存（缓存时长/粒度）。
5. **前端 mode 切换 UI**【待用户拍板】：是否需在搜索框旁提供 keyword/semantic/hybrid 切换控件，还是默认 hybrid 不暴露切换。
6. **增量同步触发方式**【待用户拍板】：新事件/分析完成时应用层异步调 embedding API 写 chunk 表，具体用后台任务 / 消息队列 / 请求时同步（需确认工程形态）。

## 6. 风险 / 注意

- **历史数据未向量化在 hybrid 下的表现**：按已确认决策（历史向量化暂缓），代码改造阶段不回填历史事件 embedding；混合模式下旧事件**仍经关键词分支召回**（语义分支暂不含旧数据），过渡平滑，但旧事件不会因语义相似被召回——属预期过渡态，非缺陷。
- **云端 API 数据出网隐私**：embedding 模型为云端 API，事件内容（含感受/反思/分析）将出网调用；需评估隐私合规与数据最小化（如仅送分块 `content`、不送用户标识）。
- **模型锁定（换模型需全量重算）**：维度 N 与模型绑定，一旦选定，后续更换模型需对所有 chunk 重算 embedding；建议选型时即考虑长期稳定性。
- **混合检索的额外延迟**：每次 hybrid / semantic 搜索多一次「查询文本 embedding」API 调用，叠加向量检索与 RRF 融合计算，端到端延迟高于纯关键词；可通过查询 embedding 缓存（待确认 #4）缓解。
