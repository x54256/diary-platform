# 日记详情展示需求规格

> 功能状态：已实现  
> 事实基线：2026-07-31 代码  
> 本文保留原页面布局、事件卡片、字段映射和交互细则，并按当前代码修正状态与流水线顺序。

> 前端实现参考文档，指导日记详情页（`/diary/[id]`）的布局、交互与数据绑定。

---

## 1. 概述

### 1.1 页面状态

日记详情页根据日记当前状态，呈现两种布局形态：

| 布局形态 | 触发条件 | 说明 |
|---|---|---|
| **单 Tab（日记 Tab）** | 状态为 `已保存` 或 `已整理` | 仅展示日记结构化内容 |
| **双 Tab（日记 Tab + 分析 Tab）** | 状态为 `已分析` | 新增分析 Tab，展示 AI 分析结果 |

### 1.2 状态流转

```
已保存 → 已整理 → 已分析
```

- **已保存**：用户提交原始文本，可查看，可触发"AI 整理"
- **已整理**：AI 整理完成，结构化数据就绪，可触发"AI 分析"
- **已分析**：AI 分析完成，双 Tab 可用

## 2. 日记 Tab 整体布局

从上到下依次排列，所有区块纵向堆叠：

```
┌─────────────────────────────┐
│  NavBar                     │
├─────────────────────────────┤
│  元数据区域                  │
│  (mood · location · tags)   │
├─────────────────────────────┤
│  摘要 (summary)             │
├─────────────────────────────┤
│  引入段 (introduction) [可选]│
├─────────────────────────────┤
│  事件卡片 1                 │
│  事件卡片 2                 │
│  ...                        │
├─────────────────────────────┤
│  琐事 (trivia)      [可选]  │
├─────────────────────────────┤
│  后续计划 (plans)   [可选]  │
├─────────────────────────────┤
│  原始文本           [折叠]  │
└─────────────────────────────┘
```

### 2.1 NavBar

- **标题**：取 `organized.title`
- **无标题时**：显示 `diary_date`（格式如 `2026-07-06`）
- 左侧返回按钮，右侧操作按钮（见第 8 节）

### 2.2 元数据区域

横排展示，各元素以间距分隔，**有值才显示**：

```
[心情]  [地点]  [标签1] [标签2] [标签3] ...
```

| 字段 | 展示方式 | 数据来源 |
|---|---|---|
| 心情（mood） | 文字显示 | `organized.analysis.mood`（仅已分析状态展示） |
| 地点（location） | 文字显示 | `organized.location` |
| 日记级标签 | 行内小标签，按类型着色 | 从所有事件的 `tags` 中去重汇总 |

**日记级标签生成规则**：

- 遍历 `organized.events` 中所有事件的 `tags`
- 按标签的 `type` + `name` 组合去重
- 横向排列，按标签类型分别着色（颜色方案见第 7 节）

### 2.3 摘要

- 数据来源：`organized.summary`
- 一段纯文本，直接渲染
- 样式：正文字号，适当行距

### 2.4 引入段（introduction）

- 数据来源：`organized.introduction`
- **可选**：有内容时展示，无内容时不占空间
- 样式：与摘要区分，可用斜体或浅色文字

### 2.5 事件列表

- 一个或多个事件卡片，纵向排列
- 详见第 3 节

### 2.6 琐事（trivia）

- 数据来源：`organized.trivia`
- **可选**：有内容时展示
- 折叠式卡片，默认展开
- 详见第 4 节

### 2.7 后续计划（plans）

- 数据来源：`organized.plans`
- **可选**：有内容时展示
- 折叠式卡片，默认展开
- 详见第 5 节

### 2.8 原始文本

- 数据来源：`diary.original_text`
- 折叠展示，默认收起
- 标题："原始文本"
- 展开后显示完整原始文本，使用 `pre` 或等宽字体保持原始格式

## 3. 事件卡片设计（核心）

### 3.1 默认状态：收起

```
┌───────────────────────────────────┐
│ ▶ 事件标题                        │
│   [domain标签] [topic标签] ...    │
└───────────────────────────────────┘
```

展示内容：
- **事件标题**：`event.event_title`
- **事件级标签**：`event.tags`，标题下方一行展示，行内小标签样式

### 3.2 展开状态

```
┌───────────────────────────────────┐
│ ▼ 事件标题                        │
│   [domain标签] [topic标签] ...    │
│ ───────────────────────────────── │
│ 事件正文段落 1                    │
│                                   │
│ 事件正文段落 2                    │
│ ───────────────────────────────── │
│ 感受                              │
│ 感受内容...                       │
│ ───────────────────────────────── │
│ 反思与成长                        │
│ 反思内容...                       │
│ ───────────────────────────────── │
│ AI 分析                           │
│                                   │
│ 自我理解与行动                    │
│  1. 情绪分析...                   │
│  2. 行为与决策分析...             │
│  3. 关注点与需求...                │
│  4. 可行动建议...                 │
│                                   │
│ 认知整理                          │
│  1. 认知校准...                   │
│  2. 问题解答 Q/A                  │
│  3. 认知完善...                   │
└───────────────────────────────────┘
```

展示内容：

| 区块 | 数据来源 | 是否必选 | 说明 |
|---|---|---|---|
| 事件标题 | `event.event_title` | 是 | |
| 事件级标签 | `event.tags` | 否 | 按 5 类着色 |
| 事件正文 | `event.body` | 是 | 多段落按顺序展示，段落间空行分隔 |
| 感受 | `event.feeling` | 否 | 有内容时显示，小标题"感受" |
| 反思与成长 | `event.reflection` | 否 | 有内容时显示，小标题"反思与成长" |
| AI 分析 | `event.analysis` | 否 | 任一分析字段有内容时显示 |

### 3.2.1 事件级 AI 分析

事件级 AI 分析由后端组装到对应事件的 `event.analysis`，前端不做 `event_index`、标题或排序字段匹配。

事件卡片展开后，AI 分析默认显示在事件正文、感受、反思与成长之后，并使用“AI 分析”标题与日记原始内容分隔。

AI 分析分为两个浅色区块：

| 分组 | 模块 | 数据来源 | 展示方式 |
|---|---|---|---|
| 自我理解与行动 | 情绪分析 | `event.analysis.emotion_analyses` | 条目列表 |
| 自我理解与行动 | 行为与决策分析 | `event.analysis.behavior_decision_analyses` | 条目列表 |
| 自我理解与行动 | 关注点与需求 | `event.analysis.self_understanding_analyses` | 条目列表 |
| 自我理解与行动 | 可行动建议 | `event.analysis.action_suggestions` | 条目列表 |
| 认知整理 | 认知校准 | `event.analysis.cognitive_calibration_analyses` | 条目列表 |
| 认知整理 | 问题解答 | `event.analysis.question_answers` | Q/A 卡片 |
| 认知整理 | 认知完善 | `event.analysis.cognitive_enhancements` | 条目列表 |

空数据规则：

- 某个模块数组为空时，隐藏该模块。
- 某个分组下所有模块为空时，隐藏该分组。
- `event.analysis` 不存在，或所有分析字段都为空时，隐藏整个 AI 分析区域。
- 事件级 AI 分析按数据是否存在显示，不强依赖日记状态。

问题解答结构：

```json
{
  "question": "问题",
  "answer": "回答"
}
```

展示为：

```
┌───────────────────────────────────┐
│ Q：问题内容                        │
│ A：回答内容                        │
└───────────────────────────────────┘
```

### 3.3 交互行为

- **点击卡片标题区域**（标题 + 标签所在区域）切换展开/收起
- **默认状态**：收起
- 展开/收起使用折叠箭头图标指示（▶ 收起 / ▼ 展开）
- 过渡动画：可选，建议使用 `max-height` 或 `v-show` + transition

### 3.4 事件正文渲染

- `event.body` 为数组结构时，每个元素为一个段落，按顺序渲染
- 段落间使用适当间距（如 `mb-3`）
- 支持纯文本渲染，无需 Markdown 解析

## 6. 分析 Tab 布局

**仅在日记状态为 `已分析` 时可见。**

分析 Tab 展示日记级分析，数据来源为 `organized.analysis`。从上到下纵向排列：

```
┌───────────────────────────────────┐
│  心情（醒目展示）                 │
├───────────────────────────────────┤
│  自我理解与行动                  │
│   - 情绪分析                     │
│   - 行为与决策分析               │
│   - 关注点与需求                  │
│   - 可行动建议                   │
├───────────────────────────────────┤
│  认知整理                        │
│   - 认知校准                     │
│   - 问题解答                     │
│   - 认知完善                     │
└───────────────────────────────────┘
```

### 6.1 各部分详情

| 分组 | 模块 | 数据来源字段 | 展示说明 |
|---|---|---|---|
| 顶部 | 心情 | `organized.analysis.mood` | 大字号或醒目样式展示，如"平静 / 专注" |
| 自我理解与行动 | 情绪分析 | `organized.analysis.emotion_analyses` | 条目列表 |
| 自我理解与行动 | 行为与决策分析 | `organized.analysis.behavior_decision_analyses` | 条目列表 |
| 自我理解与行动 | 关注点与需求 | `organized.analysis.self_understanding_analyses` | 条目列表 |
| 自我理解与行动 | 可行动建议 | `organized.analysis.action_suggestions` | 条目列表 |
| 认知整理 | 认知校准 | `organized.analysis.cognitive_calibration_analyses` | 条目列表 |
| 认知整理 | 问题解答 | `organized.analysis.question_answers` | Q/A 卡片 |
| 认知整理 | 认知完善 | `organized.analysis.cognitive_enhancements` | 条目列表 |

### 6.2 规则

- **全部只读**，不可编辑
- “今日心情”在顶部单独醒目展示
- “自我理解与行动”“认知整理”使用浅色区块展示
- 普通分析模块使用条目列表展示
- `question_answers` 使用 Q/A 卡片展示，只显示 `question` 和 `answer`
- 某个模块数组为空时隐藏该模块
- 某个分组下所有模块为空时隐藏该分组
- `organized.analysis` 不存在，或所有分析字段都为空时，显示“暂无分析数据”
- 事件标签不在分析 Tab 展示，标签展示在日记 Tab 的事件卡片内（见第 3 节）

## 7. 标签颜色方案

5 类标签使用不同颜色区分，统一使用 Tailwind CSS 色值：

| 标签类型 | 含义 | Tailwind 背景色 | Tailwind 文字色 | 示例 |
|---|---|---|---|---|
| `domain` | 领域标签 | `bg-blue-100` | `text-blue-800` | 工作、学习 |
| `topic` | 主题标签 | `bg-green-100` | `text-green-800` | 项目进展、技术探索 |
| `person_object` | 人物/对象标签 | `bg-orange-100` | `text-orange-800` | 张三、某项目 |
| `psychological` | 心理主题标签 | `bg-purple-100` | `text-purple-800` | 焦虑、成就感 |
| `knowledge` | 知识点标签 | `bg-teal-100` | `text-teal-800` | 设计模式、沟通技巧 |

### 7.1 标签样式规范

```html
<span class="inline-block px-2 py-0.5 rounded-full text-xs font-medium bg-blue-100 text-blue-800">
  工作
</span>
```

- 形状：圆角药丸（`rounded-full`）
- 尺寸：`text-xs`，`px-2 py-0.5`
- 背景色浅、文字色深
- 行内展示（`inline-block`），标签间 `mr-1 mb-1`

## 8. 操作按钮

根据日记状态展示不同按钮，按钮位于 NavBar 右侧区域：

| 日记状态 | 可用按钮 | 说明 |
|---|---|---|
| 已保存 | **AI 整理** | 触发整理流程 |
| 已整理 | **编辑** · **AI 分析** · **重新整理** | 编辑跳转编辑页；分析触发分析流程；重新整理触发再次整理 |
| 已分析 | **编辑** · **重新分析** | 日记 Tab 中编辑按钮仍可用，结构化结果可编辑；重新分析触发再次分析 |

### 8.1 按钮样式建议

| 按钮 | 样式 |
|---|---|
| AI 整理 / AI 分析 | 主色按钮（`btn-primary`） |
| 编辑 | 次要按钮（`btn-secondary` / outline） |
| 重新整理 / 重新分析 | 文字按钮或弱化按钮（`btn-ghost` / `text-sm`） |

## 9. 分析进度展示

### 9.1 进度步骤

触发分析后，按顺序展示 3 个串行环节的状态（待处理 / 进行中 / 已完成）：

| 环节 | 名称 | 说明 |
|---|---|---|
| 1 | 心情与标签提取 | 提取当天心情、生成事件标签 |
| 2 | 核心分析与建议 | 情绪分析、行为与决策分析、关注点与需求、可行动建议 |
| 3 | 认知分析 | 认知校准、问题解答、认知完善 |

三个环节串行执行：心情与标签提取完成后进入核心分析，核心分析完成后进入认知分析。每个环节完成后保存 checkpoint。

### 9.2 实现机制

- **复用现有整理进度的轮询机制**
- 通过 `task_type` 字段区分整理任务和分析任务：
  - `task_type = "organize"` → 整理进度
  - `task_type = "analyze"` → 分析进度
- 轮询接口、进度条组件、状态更新逻辑与整理流程保持一致

### 10.2 分析 Tab 数据映射

| 展示内容 | 数据来源 | 说明 |
|---|---|---|
| 心情 | `organized.analysis.mood` | 顶部醒目展示 |
| 情绪分析 | `organized.analysis.emotion_analyses` | 自我理解与行动 |
| 行为与决策分析 | `organized.analysis.behavior_decision_analyses` | 自我理解与行动 |
| 关注点与需求 | `organized.analysis.self_understanding_analyses` | 自我理解与行动 |
| 可行动建议 | `organized.analysis.action_suggestions` | 自我理解与行动 |
| 认知校准 | `organized.analysis.cognitive_calibration_analyses` | 认知整理 |
| 问题解答 | `organized.analysis.question_answers` | 认知整理，Q/A 卡片 |
| 认知完善 | `organized.analysis.cognitive_enhancements` | 认知整理 |

### 10.3 状态与数据可用性

| 状态 | 可用数据 |
|---|---|
| 已保存 | `original_text` |
| 已整理 | `organized` + `organized.events`（可无 tags / analysis） |
| 已分析 | `organized` + `organized.events`（含 tags，可含 event.analysis）+ `organized.analysis` |

### 10.4 后端返回格式约定

`GET /api/diaries/{id}` 必须返回已经组装好的详情数据。后端负责把事件级分析放入对应事件的 `analysis` 字段，前端不做 `event_index`、标题或排序字段匹配。

关键结构：

```json
{
  "id": "diary-id",
  "original_text": "原始日记文本",
  "diary_date": "2026-07-07",
  "status": "analyzed",
  "organized": {
    "title": "标题",
    "summary": "摘要",
    "location": "地点",
    "introduction": "引入段",
    "trivia": [],
    "plans": [],
    "analysis": {
      "mood": "平静 / 专注",
      "emotion_analyses": [],
      "behavior_decision_analyses": [],
      "self_understanding_analyses": [],
      "action_suggestions": [],
      "cognitive_calibration_analyses": [],
      "question_answers": [
        {
          "question": "问题",
          "answer": "回答"
        }
      ],
      "cognitive_enhancements": []
    },
    "events": [
      {
        "id": "event-id",
        "event_title": "事件标题",
        "body": [],
        "feeling": [],
        "reflection": [],
        "tags": [],
        "analysis": {
          "emotion_analyses": [],
          "behavior_decision_analyses": [],
          "self_understanding_analyses": [],
          "action_suggestions": [],
          "cognitive_calibration_analyses": [],
          "question_answers": [
            {
              "question": "问题",
              "answer": "回答"
            }
          ],
          "cognitive_enhancements": []
        },
        "sort_order": 0
      }
    ]
  }
}
```

接口规则：

- `organized.analysis` 是日记级分析；无分析结果时返回 `null`。
- `organized.events[].analysis` 是事件级分析；该事件无事件级分析时返回 `null` 或省略字段。
- 日记级和事件级分析使用同一套字段名，通过层级区分。
- 所有分析数组字段没有内容时返回空数组，不返回空字符串。
- `question_answers` 元素只包含 `question` 和 `answer` 两个字段。
- `mood` 只出现在 `organized.analysis`，事件级 `analysis` 不包含 `mood`。

| `AnalysisGroup.vue` | 分析分组区块（自我理解与行动 / 认知整理） |
| `QuestionAnswerCard.vue` | 问题解答 Q/A 卡片 |
| `AnalysisProgress.vue` | 分析进度展示（复用整理进度组件） |


## 11. 收藏

- 顶部操作区支持收藏或取消收藏整篇日记。
- 每个事件标题区域支持独立收藏或取消收藏。
- 收藏请求需要防重复提交，最终状态以服务端为准。
- 首页收藏视图统一展示日记收藏和事件收藏。

## 12. 划线批注

- 用户可以在结构化日记和分析内容中选择文本创建批注。
- 批注使用段落、字符偏移、选中文本和前后文共同定位。
- 批注评论支持新增、修改和删除。
- 内容编辑后按定位规则保留、合并或软删除受影响批注。
- 详细规则见[日记批注需求规格](日记批注需求规格.md)。

## 13. 长事件标题吸附

- 事件标题滚出日记内容区后，页面可在内容区顶部显示当前事件标题。
- 吸附标题保留事件收藏操作。
- 切换 Tab、进入编辑状态或离开事件区域后及时清除吸附状态。

## 14. 移动端表单约束

所有可编辑控件的实际字号不得小于 `16px`，并验证 iOS Safari 聚焦时页面不会自动放大。
