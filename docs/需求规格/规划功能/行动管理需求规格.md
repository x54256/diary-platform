# 行动管理需求规格

> 功能状态：部分实现。独立待办和目标管理尚未实现；已经落地的时间型行动管理见[日程管理需求规格](../用户端/日程管理/日程管理需求规格.md)。

## 1. 功能目标

系统把日记、回顾和 AI 对话中产生的行动项落到轻量待办和 OKR 中，形成从记录到行动的闭环。

---

## 2. 功能范围

### 2.9 模块九：待办事项（轻量扩展）

#### 创建方式

- 可独立创建
- 可通过 AI 对话过程中产生
- 可从目标（OKR）拆解而来
- 日记整理时提取的待办事项，用户确认后创建到待办模块

#### 待办字段

| 字段 | 说明 |
|---|---|
| 标题 | 待办的标题/内容 |
| 截止日期 | 截止日期或指定日期 |
| 优先级 | 高 / 中 / 低 |

#### 循环待办

- 支持自定义循环规则（如每周一三五、每月第二个周五）
- 待办统一概念，不区分一次性和循环

#### 进度更新

- 用户手动更新待办进度
- 日记详情页显示与该篇日记关联的待办，用户可在此查看待办状态

### 2.10 模块十：目标管理 OKR（轻量扩展）

#### 三层结构

**目标（Objective）**

| 字段 | 说明 |
|---|---|
| 标题 + 描述 | 描述期望达成的结果，如"4月通过软考" |
| 起止日期 | OKR 的开始日期和截止日期 |
| 状态 | 进行中 / 已完成 / 已放弃 |

**关键步骤（Key Results）**

| 字段 | 说明 |
|---|---|
| 标题 | 目标的里程碑 |
| 进度百分比 | 由用户**手动更新**，不自动计算 |

- KR 下关联待办列表，**仅做展示，不参与进度联动**
- 待办与 KR 为**一对一关联**，一个待办只能关联一个 KR

**待办（Tasks）**

- 具体的执行事项

#### 待办展示

- 统一待办列表中展示所有待办（含已关联 KR 和未关联 KR 的）
- 已关联 KR 的待办标记其所属 KR

## 3. 待细化内容

- 日记整理和 AI 对话中待办的提取、确认和创建流程。
- 待办、循环待办、KR 的数据模型与接口设计。
- OKR 进度手动更新规则。
- 日记详情页、待办列表和 OKR 页面之间的关联展示。
