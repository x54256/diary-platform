# 知识库管理需求规格

> 功能状态：未实现  
> 需求基线：2026-08-11 已确认方案  
> 首版范围：从单篇已分析日记沉淀只读原子事件，并提供事件列表与详情。

## 1. 功能目标

知识库首版把结构化日记事件进一步整理为能够独立理解和浏览的原子事件。用户可以从日记详情页手动执行沉淀，并在独立知识库入口按发生时间回看这些事件。

首版完成后形成稳定的事件事实层，为后续人物、事项和洞察提供输入。后续阶段通过沉淀成功记录的 `completed_stage` 继续推进，不重新提取已有原子事件。

## 2. 首版边界

### 2.1 纳入范围

- 已分析日记的手动知识沉淀。
- 从一篇日记的结构化事件中提取原子事件。
- Token 超长时按完整结构化事件分批调用模型。
- 异步任务、断点恢复、失败重试和事务发布。
- 日记详情页的未沉淀、处理中、失败和已沉淀状态。
- 知识库原子事件列表、原子事件详情和来源日记入口。
- 独立 `knowledge` 模型配置。

### 2.2 后续阶段

- 人物识别、人物关系与人物页。
- 事项匹配、事项发展与事项页。
- 洞察提取、更新与洞察页。
- 基于已有原子事件的阶段升级任务。

### 2.3 首版不提供

- 原子事件人工编辑、删除、合并、撤回或重新沉淀。
- 原子事件关键词搜索、向量检索和 GraphRAG。
- 独立 AI 语义审核。
- 知识历史版本和恢复。
- AI 伙伴读取知识库。

## 3. 来源边界

- 一次任务只处理当前一篇日记。
- 日记必须处于 `analyzed` 状态。
- 模型输入只包含当前日记的结构化事件标题、正文、感受和反思，以及日记日期。
- 同日其他日记、日记原文、日记级摘要、标签、重要性、情绪分析、行为分析、需求分析、认知校准和行动建议不作为输入。
- 一个原子事件只能来源于一个结构化日记事件，不跨事件合并。
- 当前日记必须至少包含一条结构化事件；事件数组为空时任务不得启动。
- 任一结构化事件的标题、正文、感受和反思全部为空时，任务不得启动。

## 4. 原子事件

### 4.1 定义

原子事件是一件能够脱离其他内容独立理解和使用的完整事情。

先判断新内容是否只是当前事情的步骤、交流、判断、决定、结果或必要背景；属于其中之一时合并。只有新内容自身构成另一件完整事情，并且不属于当前事情的连续完成过程时才拆分。目标、场景、人物、地点、时间、句子、段落、动作、观点或金额的单项变化都不能直接决定拆分。

每个结构化日记事件至少生成一个原子事件。一个结构化事件包含多个明显独立事情时，可以生成多个原子事件；每件独立事情恰好出现一次。

### 4.2 字段

| 字段 | 需求 |
|---|---|
| 标题 | 不超过 20 个字符，具体说明发生了什么 |
| 来源片段 | 模型返回的非空字符串数组，按返回顺序保存和展示 |
| 事件内容 | 无固定长度、能够独立理解的事件主要脉络 |
| 发生日期 | `YYYY-MM-DD` |
| 发生时刻 | 能够确定到小时和分钟时使用 `HH:mm`，否则为空 |

来源片段不保存原文位置。程序校验字段结构，不比较来源片段或事件内容是否与输入逐字一致。模型返回内容通过结构校验后直接保存。

### 4.3 事件内容要求

- 保持来源叙述视角和实际说话者。
- 使用自然、直接的现代汉语，尽量延续来源的说话方式，避免公文式、文言式或压缩式表达。
- 在不改变含义的前提下按实际先后组织内容，并补足来源内唯一明确的指代。
- 围绕当前事情的核心发展，保留理解事件所需的经过、互动、决定、结果、前置过程、失败尝试、中间转折和当前状态。
- 保留与主线直接相关的重要感受、经验、方法、感悟和判断。
- 可以合并重复表达，省略不影响主线理解的枝节，但不能遗漏改变事件发展、结果或认识的关键信息。
- 已执行但没有明确结果的行为不能补写结果。
- 决定、承诺和计划不能改写为已经执行或完成。
- 担忧、期待、感悟、判断和主观看法不能改写为客观事实、确定因果或实际结果。
- 来源存在矛盾、错误或缺失时保留原表达。
- 保留与当前事件相关的合法 `<time>` 标签。

### 4.4 时间

- 发生日期和时刻表示标题及事件内容所表达的核心行为、结果或决定实际发生的时间。
- 核心是结果或决定时使用其发生时间，否则使用核心行为发生时间。
- 计划执行时间、截止时间和预约时间只保留在事件内容中。
- “今天”“昨天”等相对日期依据日记日期换算。
- 核心日期无法确定时使用日记日期。
- 模糊时段或冲突时刻不能写入发生时刻。

## 5. 触发与任务

### 5.1 入口条件

同时满足以下条件时，日记详情页显示可用的“沉淀到知识库”：

- 当前用户拥有该日记。
- 日记处于 `analyzed` 状态。
- 当前日记包含有效的结构化事件。
- 日记尚无成功沉淀记录。
- 已配置独立 `knowledge` 模型。
- 当前用户没有其他活动知识任务。

未配置模型时保留入口但禁用，并提示“请先配置知识模型”。

### 5.2 状态

| 页面状态 | 含义 | 操作 |
|---|---|---|
| 未沉淀 | 当前来源尚未生成正式原子事件 | 沉淀到知识库 |
| 处理中 | 任务处于 `QUEUED` 或 `RUNNING` | 等待并自动刷新 |
| 处理失败 | 当前来源任务处于 `FAILED` | 重试 |
| 已沉淀 | 已存在 `knowledge_deposits` | 查看知识 |

同一用户同时只能有一个活动知识任务。同一操作被重复提交时返回当前活动任务，不重复执行。

### 5.3 执行流程

1. 校验来源、权限、模型配置和重复沉淀。
2. 冻结当前日记结构化事件、来源修订和模型配置。
3. 按 Token 预算划分批次。
4. 逐批调用模型并执行 JSON 与字段结构校验。
5. 汇总当前日记全部结果。
6. 在一个事务中写入成功记录、原子事件和任务成功状态。
7. LangGraph 完全结束后清理任务 checkpoint；清理失败由后台清理器补偿。

首版不执行第二次 AI 审核。拆分或事件内容的语义质量问题不会阻止结构合法的结果发布。

### 5.4 分批与恢复

- 一个结构化事件不能拆到两个批次。
- 单个结构化事件本身超过预算时仍作为独立批次完整传入。
- 每个批次完成后保存 LangGraph checkpoint。
- 进程中断或 worker 租约过期后，任务从未完成批次继续。
- 已完成批次不重复调用。
- 模型接口临时错误按系统全局次数重试当前批次。
- JSON 结构错误最多使用一次修复提示词。
- 失败任务在来源未变化时原地重试并沿用 checkpoint。
- 结构化来源修订变化时旧任务失效，旧 checkpoint 被清理。
- `run_token` 作为本次 worker 的非持久化运行时参数，不写入或从 checkpoint 恢复；每个节点执行前和模型返回后都必须确认任务执行权仍有效。
- 旧 worker 失去执行权后只能退出，不能把新 worker 已经领取的任务改为失败。
- `SOURCE_CHANGED` 的 checkpoint 在图退出后由 worker 清理，节点内部不得清理后继续返回。

## 6. 正式发布与一致性

- 任一批次调用或结构校验失败时，不写入正式原子事件。
- 成功记录、全部原子事件和任务成功状态必须在同一个数据库事务内提交。
- 正式事务任一步骤失败时整批回滚。
- 发布节点重复执行不能重复创建成功记录或原子事件。
- 每篇日记最多存在一条成功沉淀记录。
- 每个来源结构化事件至少对应一个原子事件。
- 同一来源事件内的 `source_order` 唯一且从 0 开始连续生成。
- 成功记录的 `completed_stage` 首版为 `ATOMIC_EVENTS`。
- 日记成功沉淀后，原文、结构化内容和分析结果不能再修改、重新整理或重新分析。
- `analyzed` 日记的前后端删除操作均被拒绝。
- 日记删除、重新整理、重新分析、结构化内容修改以及整理和分析后台最终提交都必须在锁定来源后检查成功沉淀记录，不能使用无锁的“先查询再写入”。
- 知识任务启动时拒绝已有活动整理或分析任务的日记；知识任务活动期间拒绝新的来源修改、整理、分析和删除操作。双方触发或写入前必须锁定同一日记后再检查冲突状态。

## 7. 页面需求

### 7.1 导航与风格

- 使用默认布局的主页面底部导航新增第六项“知识”，进入 `/knowledge`；日记详情继续使用现有 `auth` 布局，不显示底部标签栏。
- 页面沿用现有 44px 顶栏、52px 底栏、白色背景、圆角描边卡片和主色操作按钮。
- 页面主体占满可用宽度，不设置固定宽度或最大宽度；水平内边距复用日记管理的 `px-4`。
- 状态区、事件列表和事件卡片随父容器宽度伸缩。
- 按钮和链接点击区域高度不小于 44px。
- 页面没有可编辑控件；后续新增控件时实际字号不得小于 16px。
- ASCII 线框图只表达移动端的信息结构，不限制实际页面宽度。
- 320px 宽度下六个底部标签必须保持可辨识、可点击且不重叠；平板和桌面端不得出现固定窄栏或横向溢出。
- 公共 `NavBar` 和 `BottomTabBar` 的内部操作项容器继续沿用现有组件布局；其 `max-w-md` 不作为页面主体宽度限制。

完整 ASCII 线框图见[知识库系统设计](../../系统设计/知识库/知识库系统设计.md#9-页面设计)。

### 7.2 日记详情

- 在日记详情“日记”页签的可滚动内容底部展示知识沉淀卡片，不新增底部栏或覆盖现有固定操作区。
- 处理中只显示通用状态，不展示批次数或百分比。
- 失败状态显示脱敏错误和重试操作。
- 成功状态显示生成的原子事件数量和“查看知识”。

### 7.3 原子事件列表

- 每次加载 20 条。
- 按发生日期、发生时刻、写入时间和 ID 倒序稳定排列。
- 滚动接近底部时自动加载下一页。
- 卡片展示发生时间、标题、最多三行事件内容和来源信息。来源信息统一为“日记日期 ·《日记标题》· 对应的结构化事件标题”。
- 首版不提供搜索和筛选。

### 7.4 原子事件详情

- 列表和详情使用现有 `default` 布局并保留底部导航，详情顶栏提供返回操作。
- 展示标题、发生时间、完整事件内容、全部来源片段和来源日记入口。入口展示“日记日期 ·《日记标题》· 对应的结构化事件标题”。
- 来源片段按模型返回顺序逐段展示。
- 合法 `<time>` 标签显示标签内文字，其他内容全部按纯文本转义。
- 页面不得把模型文本作为 HTML 直接渲染。

## 8. 权限、隐私与日志

- 任务、成功记录和原子事件都以当前用户为访问边界。
- 用户只能触发、查询和重试自己的任务。
- 用户只能查看自己的原子事件和来源日记。
- 模型请求正文和原始响应写入现有 AI 交互日志，每条最多保留前 2000 个字符，超长时同时记录原始长度；认证头和 API Key 不得进入日志。
- 日记正文、模型完整输入输出、来源片段和事件内容不得写入其他普通日志、指标标签或错误响应。
- LangGraph checkpoint 按数据库敏感数据处理，成功后清理。
- 失败 checkpoint 只为恢复保留；来源失效时立即清理。
- checkpoint 不保存解密后的模型 API Key；每次调用时从加密配置读取到内存。

## 9. 已知限制

- 首版依赖单次模型提取，没有独立语义审核。
- 已发布的拆分或事件内容错误无法编辑、撤回或重新沉淀。
- 事件时间无法识别时使用日记日期，页面无法区分该日期与准确发生日期。
- 不提供知识搜索，事件只能按时间浏览。
- 不展示人物、事项和洞察关系。

## 10. 验收标准

- 已分析、结构化事件有效、未沉淀且模型已配置的日记能够启动任务。
- 入口不可用时页面显示具体原因。
- 未配置模型时入口可见但禁用，并显示明确原因。
- 空结构化事件不能进入模型调用。
- 没有任何结构化事件的日记不能创建批次或成功沉淀。
- 每个用户最多运行一个知识任务，重复触发和重复重试不会产生并行执行。
- 一个结构化事件可以拆出多个原子事件，每个原子事件只来源于一个结构化事件。
- 每条结构化事件至少生成一个原子事件。
- 原子事件只保存标题、来源片段、事件内容和时间四类业务字段。
- 模型结果只经过确定性结构校验，不执行 AI 语义审核。
- 多批任务中断后从未完成批次恢复，已完成批次不会重复调用。
- 租约过期的旧 worker 不能在模型返回后写入 checkpoint 或覆盖新 worker 结果。
- 来源变化后旧任务不能发布冻结结果，且图退出后清理旧 checkpoint。
- 旧 worker 的迟到异常不能覆盖新 worker 的任务状态。
- 生成失败和发布失败都不会留下部分正式数据。
- 发布节点重复执行不会生成重复事件。
- 成功后 `completed_stage=ATOMIC_EVENTS`，且日记不能再次沉淀。
- 成功任务的 checkpoint 在 LangGraph 返回后清理；进程中断或清理失败时由后台清理器完成。
- 沉淀成功记录与来源修改、重新分析和后台分析提交并发时，只能有一方在统一加锁检查后成功。
- 知识库底部入口、列表、详情和来源日记跳转可用。
- 列表按发生时间稳定分页，卡片事件内容最多显示三行。
- 时间标签安全展示，模型文本不会作为 HTML 执行。
- 所有任务与事件接口执行用户所有权校验。
- 320px 移动端宽度下六个底部标签不重叠。
- 768px 和 1280px 宽度下，知识页面主体与日记管理一致占满可用内容区，卡片随容器扩展。
