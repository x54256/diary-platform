# 流水线环节模型配置需求规格

> 功能状态：已实现  
> 事实基线：2026-07-31 代码

## 1. 目标

超级管理员可以在业务用途默认配置之上，为日记整理和分析的具体环节选择更合适的模型及思考模式。

## 2. 配置范围

整理流水线支持配置文本清洗、清洗审核、事件整理、结构化和内容审核等环节；分析流水线支持配置元数据与标签、核心分析和认知分析等环节。具体环节键以系统返回的配置清单为准。

对话和语音转文字当前只使用用途级配置，不提供环节级覆盖。

## 3. 继承规则

- 环节模型未指定时，继承所属业务用途的默认模型。
- 环节思考状态未指定时，继承所属业务用途的默认思考状态。
- 模型和思考状态分别继承，互不绑定。
- 环节被关闭时直接透传上一步结果，不调用模型。
- 配置修改后，对新启动或从 checkpoint 恢复的任务生效。

## 4. 能力约束

- 不支持思考的模型只能关闭思考。
- 强制思考的模型只能开启思考。
- 支持开关的模型允许管理员选择开启或关闭。
- 最终配置仍须满足模型类型、渠道、密钥和启用状态要求。

## 5. 页面要求

- 模型设置页先展示用途级默认配置，再展示整理和分析的环节配置。
- 页面同时显示配置值与最终生效值，使管理员能够识别继承结果。
- 保存前完成能力校验，并指出具体不合法环节。

## 6. 验收标准

- 未覆盖环节正确继承用途配置。
- 单独覆盖模型或思考状态时，另一项仍正确继承。
- 不合法的思考状态不能保存或执行。
- 关闭环节后不产生该环节的模型调用。
