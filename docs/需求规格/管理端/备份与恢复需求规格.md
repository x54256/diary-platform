# 备份与恢复需求规格

> 功能状态：已实现  
> 事实基线：2026-07-31 代码

## 1. 业务背景

当前系统已沉淀用户、日记原文、AI 整理结果、事件、AI 分析结果和标签关系。超级管理员需要在受控环境中导出这些核心数据，并在需要时把备份包导入系统，用于系统级数据备份、恢复和迁移补齐。

该能力涉及用户数据和 `password_encrypted` 字段，属于高敏感操作。

## 2. 系统目标

系统提供一个仅超级管理员可用的“系统备份与恢复”页面，支持加密导出核心系统数据、上传备份包预检、确认后异步导入，并对导入导出全过程进行记录和审计。

## 3. 系统边界

### 3.1 负责范围

- 导出核心系统数据为加密 ZIP 备份包。
- 支持全量导出、按用户筛选导出、按日记日期筛选导出、用户与日记日期交集导出。
- 支持上传 ZIP 备份包并执行同步预检。
- 支持预检通过后异步导入。
- 导入时已有 ID 一律跳过，不覆盖。
- 导入失败按单条数据记录失败原因，继续处理其他数据。
- 提供备份恢复记录，承载任务进度、下载、报告和审计详情入口。
- 记录导出、下载、取消、预检、导入等操作审计。

### 3.2 不负责范围

- 不导出过程日志：`diary_check_logs`、`diary_clean_check_logs`。
- 不导出对话数据：`dialogs`、`dialog_messages`。
- 不处理附件。当前系统没有附件表和附件字段。
- 不支持覆盖导入。
- 不支持版本不兼容备份包导入。
- 不支持导入任务取消和回滚。
- 不展示日记原文、密码字段、密钥内容到记录、报告和审计详情中。

## 4. 参与者

| 参与者 | 说明 |
|---|---|
| 超级管理员 | 唯一允许执行系统备份与恢复的用户 |
| 系统 | 执行导出、加密、预检、导入、记录和过期清理 |

## 5. 权限与入口

### 5.1 入口

系统分为用户端和管理端，备份恢复能力只放在管理端。

用户端：

- 入口：`/`
- 使用者：普通用户、超级管理员作为普通用户使用时
- 主要设备：手机
- 功能：日记、回顾、AI 伙伴、我的
- 不提供系统备份与恢复入口

管理端：

- 入口：`/admin`
- 登录页：`/admin/login`
- 默认页面：`/admin/backup-restore`
- 使用者：超级管理员
- 主要设备：桌面端
- 功能：系统备份与恢复

```text
用户端 /
└─ 日记、回顾、AI 伙伴、我的

管理端 /admin
└─ 系统管理
   └─ 备份与恢复
```

用户端不展示管理端入口。

### 5.2 页面路由

```text
/admin
/admin/login
/admin/backup-restore
```

### 5.3 访问控制

- 访问用户端 `/` 时，登录成功后进入日记首页。
- 访问管理端 `/admin` 或 `/admin/backup-restore` 时，未登录则进入 `/admin/login`。
- 管理端登录成功且当前用户为超级管理员时，进入 `/admin/backup-restore`。
- 当前系统超级管理员判定规则为 `username == "admin"`。
- 普通用户访问管理端时返回无权限页面。
- 用户端不承载 ZIP 上传、备份下载、预检和导入操作。

## 6. 导出需求

### 6.1 导出范围

导出范围只包含数据库设计文档中的 3.1 至 3.6、3.9 至 3.11：

| 表 | 业务含义 |
|---|---|
| `users` | 用户 |
| `diaries` | 日记原文和日记状态 |
| `organize_tasks` | 整理和分析任务 |
| `diary_organized` | 日记整理结果 |
| `diary_events` | 日记事件 |
| `analysis_runs` | 日记分析轮次 |
| `analysis_items` | 日记级与事件级分析项 |
| `analysis_feedback` | 用户分析反馈 |
| `tags` | 标签 |
| `diary_tags` | 日记标签关系 |
| `event_tags` | 事件标签关系 |

当前系统认证授权信息实际只包含 `users.password_encrypted`。如果后续新增登录令牌或第三方授权表，再纳入该能力的高敏感备份范围。

### 6.2 筛选规则

- 不选择筛选条件时，导出全部范围数据。
- 按用户筛选时，导出指定用户及其关联数据。
- 按日记日期筛选时，按 `diaries.diary_date` 过滤日记及其关联数据。
- 同时选择用户和日记日期时，取交集。
- 筛选导出时，只导出被筛选到的日记所属用户及其 `password_encrypted`。
- `organize_tasks` 导出被包含日记关联的全部任务，包括 `running`、`completed`、`failed`。

### 6.3 备份包格式

- 导出包格式为加密 ZIP。
- ZIP 内部每张表一个 JSON Lines 文件，一行一条记录。
- ZIP 包含 `manifest.json`。
- 导出包命名规则为：`diary-platform-backup-{导出时间}-{任务ID}.zip`。

### 6.4 manifest 内容

`manifest.json` 记录：

- 系统版本。
- 备份 schema 版本。
- 导出时间。
- 导出任务 ID。
- 导出范围。
- 表清单。
- 字段版本。
- 每张表数据条数。
- 每个数据文件完整性摘要。
- 整包完整性摘要。

### 6.5 加密规则

- ZIP 使用系统配置的备份主密钥自动加密。
- 备份主密钥通过环境变量配置，例如 `BACKUP_MASTER_KEY`。
- 主密钥不写入数据库、日志、审计记录和导出包。

### 6.6 导出任务

- 导出异步执行。
- 导出进度展示阶段和当前表名。
- 导出运行中允许超级管理员取消。
- 取消后系统停止生成 ZIP，并清理临时文件。
- 导出包生成后 7 天内可下载，过期自动删除。
- 导出、下载、取消均写入备份恢复记录。

## 7. 导入需求

### 7.1 导入流程

1. 超级管理员上传加密 ZIP。
2. 系统同步执行预检。
3. 页面展示按表统计的预检结果。
4. 超级管理员二次确认。
5. 系统异步执行正式导入。
6. 页面展示导入进度。
7. 任务完成后生成导入报告。

### 7.2 预检规则

预检内容包括：

- ZIP 能够解密。
- `manifest.json` 存在且格式正确。
- 备份 schema 版本兼容。
- 表清单完整。
- JSONL 文件可解析。
- 字段完整性满足导入要求。
- ID 格式合法。
- 文件摘要和整包摘要匹配。
- 数据内部 ID 不重复。
- 外键关联关系可校验。
- 预计新增、跳过、失败数量可统计。

版本不兼容时禁止导入。

### 7.3 预检展示

预检结果按数据表展示：

| 数据 | 新增 | 跳过 | 失败 | 说明 |
|---|---:|---:|---:|---|
| 用户 | 10 | 2 | 0 | 已存在 ID 自动跳过 |
| 日记 | 300 | 15 | 1 | 1 条关联用户缺失 |

### 7.4 导入策略

- 导入按外键依赖顺序执行。
- 已存在 ID 一律跳过，不覆盖。
- 用户先导入，再导入用户下的数据。
- `running` 任务保持原状态导入。
- 关联父数据缺失时，该条数据导入失败，继续导入其他数据。
- 正式导入开始后不可取消。
- 不执行自动回滚。

### 7.5 导入顺序

```text
users
diaries
organize_tasks
diary_organized
diary_events
analysis_runs
analysis_items
analysis_feedback
tags
diary_tags
event_tags
favorites
```

### 7.6 导入报告

导入报告记录：

- 每张表新增数量。
- 每张表跳过数量。
- 每张表失败数量。
- 失败记录的表名、ID、原因摘要。
- 跳过记录的表名、ID、原因摘要。

导入报告保留 7 天。

## 8. 页面需求

页面名称为“系统备份与恢复”。该页面属于管理端，不使用用户端底部 Tab，不放入用户端“我的”页。

页面包含三块：

1. 导出数据。
2. 导入恢复。
3. 备份恢复记录。

```text
│              │                                             │
└──────────────┴─────────────────────────────────────────────┘
```

### 8.2 备份恢复页面线框


### 8.3 二次确认

导出、导入正式执行前均需要二次确认。

确认内容包括：

- 操作类型。
- 操作范围。
- 是否包含 `password_encrypted`。
- 加密方式。
- 导出包有效期。
- 已存在 ID 跳过规则。
- 审计记录说明。

## 9. 备份恢复记录

页面只保留一个“备份恢复记录”列表，同时承载任务记录和审计入口。

列表字段：

| 字段 | 说明 |
|---|---|
| 类型 | 导出、导入、下载、取消、预检 |
| 状态 | 等待中、运行中、成功、失败、部分失败、已取消、已过期 |
| 范围 | 全量、用户、日记日期、用户和日记日期交集、备份包导入 |
| 当前阶段 | 阶段和当前表名 |
| 操作人 | 执行操作的超级管理员 |
| 创建时间 | 操作创建时间 |
| 完成时间 | 操作完成时间 |
| 结果摘要 | 数量和失败摘要 |
| 操作 | 下载、取消、查看进度、查看报告、查看详情 |

详情中展示审计元信息，不展示日记原文、密码字段、密钥内容和 ZIP 内容。

审计记录保留 90 天。

## 10. 非功能需求

| 类型 | 需求 | 验收口径 |
|---|---|---|
| 安全性 | 仅超级管理员可访问备份恢复能力 | 普通用户访问管理端返回无权限，用户端不展示备份恢复入口 |
| 安全性 | 备份包必须加密 | 未配置 `BACKUP_MASTER_KEY` 时禁止导出和导入 |
| 安全性 | 敏感内容不进入报告和审计详情 | 报告和审计详情不包含日记原文、`password_encrypted`、密钥和 ZIP 内容 |
| 可靠性 | 导入采用尽力导入策略 | 单条失败不影响其他数据导入，任务结束后生成失败报告 |
| 一致性 | 已存在 ID 不覆盖 | 目标系统存在相同 ID 时该条记录跳过 |
| 可观测性 | 导入导出进度可见 | 页面展示阶段和当前表名 |
| 可追溯性 | 高危操作可审计 | 导出、下载、取消、预检、导入均生成记录 |
| 兼容性 | 不兼容备份包禁止导入 | manifest 版本不兼容时预检失败，无法开始正式导入 |

## 11. 验收标准

- 超级管理员能从管理端 `/admin` 进入“系统备份与恢复”页面。
- 用户端不展示“系统备份与恢复”入口。
- 普通用户访问 `/admin` 或 `/admin/backup-restore` 返回无权限。
- 超级管理员能发起全量导出并获得加密 ZIP。
- 超级管理员能按用户、按日记日期、按用户和日记日期交集导出。
- 导出 ZIP 包包含 `manifest.json` 和每张表的 JSONL 文件。
- 导出 ZIP 包 7 天后不可下载。
- 超级管理员上传 ZIP 后能看到按表统计的预检结果。
- 版本不兼容 ZIP 禁止导入。
- 正式导入时已有 ID 跳过，不覆盖。
- 关联父数据缺失时单条失败，其他数据继续导入。
- 导入完成后能查看报告。
- 备份恢复记录能查看任务状态、结果摘要和审计详情。
