# 定期回顾页面与交互设计

> 文档状态：现行设计；第一阶段周/月已实现，季/年暂未启用  
> 设计基线：2026-08-01 当前前端与定期回顾需求、系统设计  
> 对应需求：[定期回顾需求规格](../../需求规格/规划功能/定期回顾需求规格.md)  
> 系统设计：[定期回顾系统设计](定期回顾系统设计.md)

## 1. 设计目标

回顾页面不是统计仪表盘，而是一份适合连续阅读、核对和反思的周期文档。页面需要同时满足：

1. 用户先快速看清本周期的主要事情，再自然进入分析和行动。
2. 六个生活领域能帮助定位，但不把叙事切成大量表格和指标。
3. 事实、分析和行动在同一领域内连续呈现，不拆成三个 Tab。
4. 来源、版本、评分和编辑能力随时可用，但不打断主阅读路径。
5. 延续当前系统的移动端优先、暖色主色、白色卡片、轻量顶部导航和底部操作方式。

## 2. 总体方案

### 2.1 页面结构

```text
/review
└─ 回顾时间线
   ├─ 周 / 月 / 季 / 年筛选
   ├─ 全部周期回顾混合排序
   └─ 任务中心入口

/review/tasks
└─ 回顾任务中心
   ├─ 新建过去周期的生成任务
   ├─ 等待中与进行中任务
   ├─ 失败任务与重试
   └─ 已完成任务（默认折叠）

/review/{reviewId}?version={versionId}
└─ 回顾详情
   ├─ 周期与版本信息
   ├─ 生活领域吸附导航
   ├─ 每个领域：事件 → 分析 → 行动
   ├─ 来源抽屉
   ├─ 版本抽屉
   ├─ 完整重新生成
   └─ 根据事件修改更新分析和行动

/review/{reviewId}/threads/{threadId}/edit?version={versionId}
└─ 单条发展主线叙事编辑

/review/{reviewId}/chat?version={versionId}
└─ 当前版本独立对话
```

### 2.2 布局选择

- 回顾时间线使用 `default` 布局，保留底部五个 Tab。
- 任务中心、回顾详情、编辑和对话使用 `auth` 布局，不显示底部 Tab，自行提供顶部导航和底部操作区。
- 页面主体延续当前系统的 `max-w-md mx-auto`，移动端铺满，桌面端居中显示，不在第一版引入双栏。
- 详情页使用单一纵向阅读流，生活领域标签仅用于锚点定位，不切换或隐藏正文。

## 3. 视觉语言

### 3.1 与当前系统保持一致

| 元素 | 设计 |
|---|---|
| 页面背景 | `neutral-50` |
| 内容卡片 | 白色、`rounded-lg`、浅边框，避免重阴影 |
| 主色 | 当前 `primary-600` 暖橙色 |
| 正文 | `neutral-700/800`，行高 1.7 |
| 次要信息 | `neutral-400/500` |
| 正向状态 | 低饱和绿色，不大面积铺色 |
| 提醒状态 | 低饱和琥珀色 |
| 错误状态 | 低饱和红色，错误文案给出下一步 |

### 3.2 三层内容的视觉区分

不使用三个大色块，避免页面像报表。每个生活领域是一张主卡片，内部使用轻量标题和左侧短色线区分：

```text
事件层  「我的回顾」     暖橙色短线，第一人称正文
分析层  「观察与分析」   中性紫灰短线，第二人称正文
行动层  「下一步」       绿色短线，可操作卡片
```

用户看到的是自然语言标题，不展示内部的 `EVENT/ANALYSIS/ACTION`、证据类型或评价类型代码。

### 3.3 生活领域图标

```text
💼 工作与事业          🌿 身心健康
🤝 关系与社交          📚 学习与个人成长
🏠 生活管理与资源      🎈 休闲与体验
```

图标只帮助扫视，不依赖颜色表达领域含义。

交互规则：

- 首次进入默认“全部”，之后记住用户最后一次筛选。
- 主列表同时展示所有已实现周期类型，按 `period_end` 倒序，而不是按生成时间排序。
- 周期结束日期相同时按“年 → 季 → 月 → 周”排序，让高层总结先于下层细节。
- 第一阶段只显示“全部 / 周 / 月”；季度、年度实现后再自动增加筛选项，不展示不可用占位。
- 列表按年份月份显示轻量分组标题，筛选不会改变排序规则。
- 每张卡片第一行明确显示“周回顾 / 月回顾 / 季度回顾 / 年度回顾”，避免周卡片淹没高层回顾。
- 卡片摘要由系统生成，最多显示三行；领域最多显示三个，其余用 `+N`。
- 点击卡片进入当前版本详情，并清除该回顾的“新”标记。
- 有任一未读回顾时，底部“回顾”Tab 显示红点。
- 右上角使用任务列表图标；等待中、进行中和失败任务数量显示为角标。按钮提供 `aria-label="回顾任务"`，首次上线时用一次性提示气泡说明“在这里查看和新建回顾任务”。

### 4.2 任务状态提示

```text
┌──────────────────────────────────┐
│ 2 项任务进行中，1 项需要处理    › │
└──────────────────────────────────┘
```

- 任务详情不混入回顾卡片时间线，主页只在筛选条下方显示一条紧凑状态入口。
- 没有进行中或失败任务时不显示该入口。
- 点击进入任务中心；离开主页不会终止任务。
- 某份已有回顾正在生成新版本时，在对应卡片显示小型“新版本生成中”标签，当前版本仍可打开。


不使用“暂无数据”作为唯一文案，要说明何时自动产生以及用户可以做什么。按钮进入任务中心的新建状态。

## 5. 回顾任务中心

任务中心是独立页面，统一承载自动任务、手动任务、重试和补生成过往回顾，不再使用底部抽屉。

### 5.1 任务列表

```text
┌──────────────────────────────────┐
│ ←          回顾任务          新建 │
├──────────────────────────────────┤
│ 进行中 2 项                      │
│                                  │
│ ┌──────────────────────────────┐ │
│ │ 月回顾 · 2026 年 7 月         │ │
│ │ 自动生成                      │ │
│ │ ◌ 正在形成分析与行动           │ │
│ │ ━━━━━━━━━━━──────             │ │
│ └──────────────────────────────┘ │
│                                  │
│ ┌──────────────────────────────┐ │
│ │ 周回顾 · 7月27日－8月2日      │ │
│ │ 手动重新生成                  │ │
│ │ 等待处理                      │ │
│ └──────────────────────────────┘ │
│                                  │
│ 需要处理 1 项                     │
│ ┌──────────────────────────────┐ │
│ │ 周回顾 · 7月20日－7月26日     │ │
│ │ 本次生成没有完成              │ │
│ │ [重试]              查看说明 ›│ │
│ └──────────────────────────────┘ │
│                                  │
│ 已完成 18 项                  展开 │
└──────────────────────────────────┘
```

交互规则：

- 默认展开“进行中”和“需要处理”，默认折叠“已完成”。
- 等待中与运行中统一归入“进行中”；失败任务归入“需要处理”。
- 已完成任务展开后按完成时间倒序，点击跳转到该任务产生的固定回顾版本。
- 只展示人能理解的步骤：“整理来源 / 梳理主要事件 / 形成分析与行动 / 正在保存”。
- 不展示 Token、模型名称、内部 step key 和技术错误。
- 错误说明使用业务语言；重试使用原冻结来源，需要最新数据则进入回顾详情执行完整重新生成。
- 自动重试的多次尝试合并在同一任务卡片中，不在列表重复铺开。
- `SKIPPED_NO_DATA` 放在已完成分组，文案为“这个周期没有可用于回顾的记录”，不显示为失败。

### 5.2 新建任务

点击“新建”进入任务中心内的创建状态：

```text
┌──────────────────────────────────┐
│ ←          新建回顾任务            │
├──────────────────────────────────┤
│ 回顾类型                         │
│ [ 周回顾 ● ] [ 月回顾 ]           │
│                                  │
│ 选择周期                         │
│ ‹ 2026 年 7 月 ›                 │
│                                  │
│ ○ 7月 6日－7月12日               │
│ ● 7月13日－7月19日               │
│ ✓ 7月20日－7月26日   已有回顾     │
│                                  │
│ 将使用目前保存的事件、分析、日程和 │
│ 上一同级回顾生成一个固定版本。     │
│                                  │
│ [          开始生成          ]   │
└──────────────────────────────────┘
```

交互规则：

- 类型选择只显示已经实现的周期。第一阶段只有周、月；季、年实现后自动出现，不展示“即将开放”。
- 只列出已经结束且符合生成时间边界的周期。
- 已有回顾的周期不可重复“首次生成”，点击后提示“这个周期已有回顾”，主操作改为“查看回顾”。
- 正在生成的周期显示进度且不可再次提交。
- 月回顾未等到包含月末日期的自然周结束时显示“尚未结束”，不可选择。
- 周、月、季、年都只能选择已经自然结束且依赖生成尝试已经完成的周期，不能创建当前或未来周期任务。
- 无有效来源时任务进入 `SKIPPED_NO_DATA`，页面提示“这个周期没有可用于回顾的记录”，不创建空回顾卡片。

### 6.2 阅读顺序

每个有效领域严格按以下顺序：

```text
领域标题与核心关注
  → 我的回顾：事实主线
  → 观察与分析：有证据的分析角度
  → 上期行动回看（存在时）
  → 下一步：本期候选行动
```

- 不展示空领域、空分析角度或“本期无内容”占位。
- 核心关注是一句短标题，不单独堆成标签云。
- 事件主线正文保持第一人称；分析面向用户使用自然第二人称。
- 一条主线正文超过约八行时默认完整展示，不做“展开全文”截断；回顾是阅读主体，不以列表效率牺牲叙事。

### 6.3 领域吸附导航

```text
┌──────────────────────────────────┐
│ 💼 工作事业  🤝 关系社交  🌿 健康 ›│
└──────────────────────────────────┘
```

- 只显示本期有内容的领域。
- 点击标签平滑滚动到领域标题。
- 页面滚动进入下一个领域时，选中态随之变化。
- 标签栏吸附在 44px 顶栏下方；横向滚动时隐藏滚动条。
- 不使用一次只显示一个领域的 Tab，避免用户误以为其他领域没有内容，也保持跨领域连续阅读。

### 6.4 顶部状态提醒

来源或分析状态发生变化时，在摘要与领域导航之间显示一条提醒：

```text
┌──────────────────────────────────┐
│ 来源已有更新                      │
│ 2 篇日记和 1 个下级回顾出现新版本。 │
│ 当前内容不会自动改变。 [完整重新生成]│
└──────────────────────────────────┘

┌──────────────────────────────────┐
│ 事件事实已由你修改                 │
│ 当前分析可能不再适用。             │
│               [更新分析和行动]     │
└──────────────────────────────────┘
```

提醒可关闭，但详情菜单中继续保留对应操作。

## 7. 分析评分与反馈

评分沿用当前日记分析组件的规则，但在移动端改为更紧凑的卡片内布局。

### 7.1 未评分与高评分

```text
决策与问题解决
你先验证关键假设再扩大投入……

查看依据                    ☆☆☆☆☆
```

- 点击 4～5 星后立即保存，并短暂显示“已保存”。
- 点击已评分星级可以重新选择。
- 星级表示用户对分析内容的认可，不展示“正确率”含义。

### 7.2 1～3 星或填写文字反馈

```text
┌──────────────────────────────────┐
│ 决策与问题解决                   │
│ ……                              │
│                                  │
│ ★★☆☆☆                            │
│ ┌──────────────────────────────┐ │
│ │ 哪里不准确？希望怎么调整？    │ │
│ │                              │ │
│ └──────────────────────────────┘ │
│ 1～3 星需要说明原因       [提交] │
└──────────────────────────────────┘
```

- 1～3 星自动展开反馈输入，未填写不能提交。
- 4～5 星也可以通过“补充反馈”展开输入。
- 继承反馈显示“来自上一版本，请重新确认”，不能显示成当前版本已确认。
- 输入框实际字号不小于 `16px`。

## 8. 行动交互

### 8.1 候选行动

```text
┌──────────────────────────────────┐
│ ○ 联调前确认三个核心边界          │
│   依据：决策与问题解决             │
│   下期可检查：是否留下确认结果      │
│                                  │
│ [ 确认 ]      编辑      忽略      │
└──────────────────────────────────┘
```

- “确认”是主操作，使用浅主色按钮；确认后不自动创建日程。
- “编辑”打开小型底部抽屉，只编辑行动文本，不改变分析依据。
- “忽略”立即折叠该项，并显示可撤销 Toast：“已忽略，撤销”。
- 已忽略行动集中到领域末尾的“查看 N 项已忽略行动”，默认不占阅读空间。

### 8.2 已确认行动

```text
┌──────────────────────────────────┐
│ ● 联调前确认三个核心边界    已确认 │
│                             编辑 › │
└──────────────────────────────────┘
```

- 已确认不是“已完成”，图标不能使用任务完成勾选框。
- 用户可以修改内容或取消确认。
- 取消确认需要二次确认，因为它会影响下一同级周期的自动核查。

### 8.3 上期行动回看

```text
上期行动回看
┌──────────────────────────────────┐
│ 完成原型小范围验证                │
│ 本期记录显示已经完成，并留下结果。  │
│ 2 条依据                         │
└──────────────────────────────────┘

┌──────────────────────────────────┐
│ 每晚提前半小时停止工作             │
│ 当前记录中没有找到足够的落实证据。  │
│ 这不代表没有执行。                 │
└──────────────────────────────────┘
```

不展示内部的 `FULFILLED/NOT_ASSESSABLE` 状态码，直接使用自然语言，并严格保留“没有证据不等于没有执行”的边界。

## 11. 事件叙事编辑

第一版只允许按发展主线修改用户可见叙事，不向用户暴露节点、关系、领域和来源 ID。

```text
┌──────────────────────────────────┐
│ 取消        编辑我的回顾      保存 │
├──────────────────────────────────┤
│ 工作与事业                       │
│ 从方案不确定到完成原型验证         │
│                                  │
│ ┌──────────────────────────────┐ │
│ │ 本周我先梳理了方案边界，随后  │ │
│ │ 完成了小范围原型验证……        │ │
│ │                              │ │
│ │                              │ │
│ └──────────────────────────────┘ │
│                                  │
│ 保存后会创建新版本，不会修改原日记。│
│ 当前分析会标记为“可能已过期”。     │
└──────────────────────────────────┘
```

交互规则：

- 通过主线右下角“编辑”进入全屏编辑页，减少长文本和软键盘对详情阅读的干扰。
- 标题和领域只读，只编辑叙事正文。
- 保存前后内容完全相同时禁用“保存”。
- 离开有未保存修改的页面时弹出“放弃修改 / 继续编辑”。
- 保存成功后返回新版本详情，并显示“更新分析和行动”。
- 文本框实际字号不小于 `16px`，使用自动增高，正文不套固定小高度滚动框。

## 12. 重新生成

详情底部 `···` 菜单包含：

```text
根据最新来源重新生成整个回顾
根据事件修改更新分析和行动
查看所有版本
```

两种生成不能合并为一个模糊按钮。

### 12.1 完整重新生成

适用于日记、日程、下级回顾或上一同级回顾已经变化：

```text
读取最新来源
  → 重新组织事件
  → 重新生成分析和行动
  → 创建新版本
```

点击“根据最新来源重新生成整个回顾”后打开确认抽屉：

```text
┌──────────────────────────────────┐
│ 重新生成整个周回顾？              │
│                                  │
│ 将读取最新日记、分析反馈、日程和   │
│ 上一周回顾，重新组织事件并更新分析 │
│ 和行动。                          │
│ 当前版本和对话都会保留。           │
│                                  │
│ [ 取消 ]       [ 开始生成 ]       │
└──────────────────────────────────┘
```

### 12.2 根据事件修改更新分析和行动

事件叙事保存后不自动调用 AI，先创建事件编辑版本，并显示：

```text
┌──────────────────────────────────┐
│ 事件内容已修改                    │
│ 当前分析和候选行动可能不再适用。   │
│             [更新分析和行动]      │
└──────────────────────────────────┘
```

用户主动点击后执行：

```text
冻结当前用户编辑后的事件层
  → 不调用事件组织环节
  → 只重新生成分析和行动
  → 创建新版本
```

- 用户修改后的事件叙事必须原样进入新版本，不能被 AI 再次组织或覆盖。
- 已确认行动继续保留；新的候选行动根据新分析产生并按映射规则合并。
- 当前事件没有修改或分析未过期时，不显示该操作。

两类任务的共同规则：

- 生成期间继续展示当前版本，顶部显示进度提醒，任务中心同步展示进度。
- 已确认行动和用户事实修正不会静默丢失。
- 完成后不强行跳转；显示“新版本已生成”提醒，由用户选择切换。

## 13. 回顾对话

对话使用独立全屏页面，避免长回顾正文、固定输入栏和底部 Tab 同时争夺空间。

```text
┌──────────────────────────────────┐
│ ←       与本周回顾对话      v3  │
├──────────────────────────────────┤
│ 基于 7月27日－8月2日 · v3         │
│ 当前对话不会混入其他版本。    详情 ›│
│                                  │
│                    ┌───────────┐ │
│                    │ 为什么我这 │ │
│                    │ 周总在调整 │ │
│                    │ 方案？     │ │
│                    └───────────┘ │
│                                  │
│ ┌──────────────────────────────┐ │
│ │ 从这份回顾看，调整主要发生在… │ │
│ │ ……                           │ │
│ └──────────────────────────────┘ │
│                                  │
├──────────────────────────────────┤
│ [ 围绕这份回顾继续聊…… ]    →   │
└──────────────────────────────────┘
```

- 每个版本只有一个独立对话；切换版本不会带入旧版本消息。
- 顶部版本标签不可直接切换，点击后返回对应版本详情，避免用户在对话中无感切换上下文。
- 输入栏固定底部并适配安全区域；输入实际字号不小于 `16px`。
- 新对话为空时提供不超过三个基于当前回顾的起始问题，例如“这周最值得保留的做法是什么？”，点击即填入输入框，不自动发送。

## 14. 状态与反馈

### 14.1 加载

- 列表首次加载使用 2～3 张卡片骨架，不用全屏 Spinner。
- 详情使用摘要、领域卡片骨架，避免加载完成后大幅跳动。
- 来源和版本抽屉单独加载，不阻塞详情正文。

### 14.2 操作反馈

| 操作 | 反馈 |
|---|---|
| 评分保存 | 卡片内短暂显示“已保存” |
| 行动确认 | 原位更新为“已确认” |
| 行动忽略 | 折叠并提供可撤销 Toast |
| 事件编辑保存 | 返回详情并显示新版本提示 |
| 开始生成 | 抽屉关闭，卡片或顶部出现进度 |
| 生成完成 | 应用内红点、列表“新”、当前页提示可切换 |
| 失败 | 保留当前版本，提供重试和说明 |

### 14.3 网络与并发

- 重复点击生成、评分、确认行动时禁用对应按钮，避免重复提交。
- 事件编辑基准版本过期时不覆盖，提示“回顾已经有新版本，请返回后重新编辑”。
- 网络失败保留输入内容，不能清空反馈、行动编辑或事件叙事。

## 15. 可访问性与移动端约束

- 所有可点击区域最小高度或宽度为 44px；星级按钮保持当前 32px 视觉尺寸，但外层点击热区达到 44px。
- 颜色之外同时使用文字、图标或形状表达状态。
- 横向领域导航支持键盘焦点和屏幕阅读器，选中项使用 `aria-current`。
- 抽屉打开后焦点进入抽屉，关闭后回到触发按钮；支持 Esc 关闭。
- 事件叙事、反馈、行动编辑和对话输入的实际字号不得小于 `16px`。
- 不使用 `user-scalable=no` 或 `maximum-scale=1`。
- 实现后必须在 iOS Safari 验证输入聚焦不放大、底部安全区、软键盘遮挡和抽屉滚动。

## 17. 页面验收重点

- 时间线能混合展示不同周期类型，按周期结束时间排序，并按筛选隐藏其他类型。
- 任务中心能展示等待、进行中、失败、无数据和已完成任务；已完成默认折叠，失败可重试。
- 详情按领域连续呈现事件、分析和行动，空领域与空角度不出现。
- 领域吸附导航不会遮住领域标题，浏览器返回后保留滚动位置。
- 来源可以从月、季、年逐级定位到底层日记或日程。
- 切换版本时事件、分析、行动、反馈和对话入口同时变化。
- 低评分必须填写反馈；继承反馈不会显示成当前已确认。
- 候选行动可编辑、确认、忽略和撤销，不会自动创建日程。
- 事件编辑只修改主线叙事，保存后创建新版本并提示分析可能过期。
- 完整重新生成会重新组织事件；仅更新分析和行动时，用户编辑后的事件叙事保持不变。
- 生成期间旧版本仍可阅读，任务失败不破坏当前版本。
- 所有移动端编辑控件满足 16px 和 iOS Safari 不自动放大要求。
