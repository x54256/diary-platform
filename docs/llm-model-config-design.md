# 管理端模型管理需求设计

> 本文描述待实施的管理端模型管理方案。当前代码仍主要通过 `.env` 中的模型配置调用 AI；代码是当前事实来源。

## 1. 背景

当前系统中语言模型和语音识别模型都由配置文件固定：

- 日记整理、分析、对话使用同一个语言模型配置。
- 语音转文字使用固定 ASR 模型配置。
- 管理端无法选择模型、维护调用渠道、启用或禁用模型。

后续模型选择应从配置文件迁移到管理端。模型能力清单来自《大模型能力排序表（含打分）.xlsx》，初始化入库后由管理端维护。

## 2. 核心原则

1. 模型厂商和调用渠道分离。
2. 模型清单描述模型能力，不保存 API Key。
3. 调用渠道描述 API 地址和密钥，不绑定厂商。
4. 渠道支持模型通过独立关系维护。
5. 业务用途只选择已经可调用的渠道模型。
6. `.env` 不再作为模型运行兜底；未在管理端完成配置时，对应 AI 功能不可用。

示例：

```text
模型：deepseek-chat
模型厂商：DeepSeek
调用渠道：阿里百炼 / DeepSeek 官方 / 私有网关
```

同一个模型可以被多个渠道调用，同一个渠道也可以同时支持语言模型和 ASR 模型。

## 3. 管理端菜单

新增三个管理端菜单：

```text
系统管理
├─ 备份与恢复
├─ 模型管理
├─ 渠道管理
└─ 模型设置
```

职责划分：

| 页面 | 职责 |
|---|---|
| 模型管理 | 管理模型能力清单，支持初始化模型和自定义模型 |
| 渠道管理 | 管理 API 调用渠道，以及渠道支持哪些模型 |
| 模型设置 | 配置整理、分析、对话、语音转文字当前使用的模型 |

## 4. 数据模型

### 4.1 `model_catalog`

模型能力清单。初始化数据来自 Excel，后续支持新增自定义模型。

字段：

```text
id
model_type              language / asr
provider_name           模型原始厂商，仅展示和筛选
model_name              模型名称，默认调用名
ability_tier            能力梯队
ability_category        精简能力分类
original_category       Excel 原始能力分类
core_features           核心特点
scenarios               适用场景
score                   数值分
score_label             原始分数字符串
enabled                 是否启用
is_custom               是否自定义模型
created_at
updated_at
```

删除规则：

- 如果模型通过 `channel_models` 被 `model_settings` 使用，禁止删除。
- 否则允许删除，并级联删除相关 `channel_models`。

### 4.2 `api_channels`

调用渠道。渠道只表示账号、API 地址和密钥，不区分语言或语音。

字段：

```text
id
name
api_base_url
api_key_encrypted
enabled
created_at
updated_at
```

规则：

- API Key 使用现有 Fernet 加密能力保存。
- 前端不返回明文，只显示“已配置 / 未配置”。
- 编辑时留空表示不修改已有密钥。
- 提供“清空密钥”按钮。
- 如果渠道下任一 `channel_model` 正被 `model_settings` 使用，禁止清空密钥、禁用渠道、删除渠道。
- 删除渠道时只删除渠道和渠道模型关系，不删除模型清单。

### 4.3 `channel_models`

渠道支持模型关系。只表达“这个渠道可以调用这个模型”。

字段：

```text
id
channel_id
model_id
enabled
created_at
updated_at
```

唯一约束：

```text
channel_id + model_id
```

规则：

- 同一个渠道下，同一个模型只能关联一次。
- 实际请求的模型名直接使用 `model_catalog.model_name`。
- 调用协议由模型类型派生：`language` 使用 `openai_chat`，`asr` 使用 `dashscope_asr`。
- 如果 `channel_model` 正被 `model_settings` 使用，禁止禁用或删除。

### 4.4 `model_settings`

业务用途当前模型设置。该表只保存当前运行选择，不记录历史。

字段：

```text
id
setting_key             organize / analysis / chat / transcription
channel_model_id
updated_by
updated_at
```

唯一约束：

```text
setting_key
```

## 5. 枚举定义

### 5.1 模型类型

```text
language
asr
```

### 5.2 调用协议

```text
openai_chat
dashscope_asr
```

协议不入库，由模型类型派生：`language` 使用 `openai_chat`，`asr` 使用 `dashscope_asr`。

### 5.3 业务用途

```text
organize        整理
analysis        分析
chat            对话
transcription   语音转文字
```

### 5.4 模型能力分类

语言模型能力分类描述模型本身能力，不描述日记平台业务用途。

语言模型：

```text
通用对话
深度推理
长上下文
代码能力
轻量高速
```

ASR 模型：

```text
实时语音识别
录音文件识别
```

## 6. 用途约束

| 用途 | 模型类型 | 协议 |
|---|---|---|
| organize | language | openai_chat |
| analysis | language | openai_chat |
| chat | language | openai_chat |
| transcription | asr | dashscope_asr |

保存 `model_settings` 时必须校验：

1. 渠道已启用。
2. 渠道已配置 API Key。
3. `channel_model` 已启用。
4. 模型类型符合用途约束。

保存不要求真实测试通过。

```text
│ 管理模型能力清单。初始化模型和自定义模型都在这里维护。                         │
├──────────────────────────────────────────────────────────────────────────────┤
│ 类型 [全部 ▼]  梯队 [全部 ▼]  分类 [全部 ▼]  厂商 [全部 ▼]  状态 [全部 ▼] 搜索 │
│                                                                  [新增模型]  │
├────┬──────────┬────────────┬────────────┬──────────────┬────────┬──────┬────┤
│状态│ 类型      │ 能力梯队     │ 能力分类     │ 模型名称       │ 厂商    │ 分数 │操作│
├────┼──────────┼────────────┼────────────┼──────────────┼────────┼──────┼────┤
│ ON │ language │ T0 旗舰全能 │ 通用对话     │ qwen-max      │ 通义    │ 8.5  │详情│
```

模型详情支持：

- 查看完整能力信息。
- 启用 / 禁用。
- 删除。
- 编辑渠道关系。

自定义模型新增后默认启用。自定义模型必须填写模型类型、厂商、模型名称、能力梯队、能力分类、分数、核心特点和适用场景。

能力梯队和能力分类使用固定选项，不允许自由输入。

### 7.2 渠道管理

```text
┌──────────────────────────────────────────────────────────────────────────────┐
│ 渠道管理                                                                      │

├──────────────────────────────────────────────────────────────────────────────┤
│ API 渠道                                                       [新增渠道]     │
├────┬──────────────┬──────────────────────────────┬────────┬───────────────┤
│状态│ 渠道名称       │ API 地址                       │ 密钥状态 │ 操作           │
```

渠道详情支持：

- 编辑渠道名称。
- 编辑 API 地址。
- 更新 API Key。
- 清空 API Key。
- 启用 / 禁用。
- 删除渠道。
- 批量维护支持模型。

### 7.3 渠道支持模型

渠道详情和模型详情都可以维护 `channel_models`，底层操作同一张表。

```text

│ 阿里百炼 · 支持模型                                                  │
├────────────────────────────────────────────────────────────────────┤

├────┬──────────┬────────────┬────────────┬──────────────┬──────────┤
│启用│ 类型      │ 梯队        │ 分类        │ 模型名称       │ 调用名     │
├────┼──────────┼────────────┼────────────┼──────────────┼──────────┤
│[x] │ language │ T0.5 推理   │ 深度推理     │ deepseek-r1   │ deepseek-r1│
│[x] │ language │ T4 极速     │ 轻量高速     │ qwen-flash    │ qwen-flash │
│[ ] │ language │ T0 旗舰     │ 通用对话     │ glm-4.5       │ glm-4.5    │
```

保存粒度由页面自行处理。推荐：

- 渠道详情批量保存当前渠道的模型关联。
- 模型详情批量保存当前模型的渠道关联。

选择链路：

```text
业务用途固定模型类型
→ 选择渠道
→ 选择能力梯队
→ 选择能力分类
→ 选择模型
```

渠道变化后总是清空模型选择。

保存粒度：

- 四个用途一起保存。
- 页面展示未配置原因，例如“渠道未配置密钥”“渠道模型已禁用”。

## 8. 测试调用

语言模型支持固定最小测试：

```text
用户消息：返回 ok
期望：模型返回 ok 或包含 ok
```

测试调用不作为保存前置条件。

ASR 首版不做真实音频测试，只做静态校验。

## 9. 初始化数据

Excel 数据初始化入库：

- `模型能力排序` 初始化为 `language` 模型。
- `Sheet1` 初始化为 `asr` 模型。
- Excel 原始能力分类保存到 `original_category`。
- 系统按规则映射到精简 `ability_category`。

初始化只负责模型清单，不自动创建渠道和模型设置。

如果管理端未配置渠道、渠道模型和模型设置，则对应功能不可用。

## 10. 运行时规则

运行时按用途读取 `model_settings`：

```text
organize      → 日记整理流水线
analysis      → 普通分析、反馈重分析
chat          → 日记对话
transcription → 语音转文字
```

读取到 `channel_model` 后：

1. 校验模型、渠道、渠道模型均启用。
2. 校验渠道 API Key 已配置。
3. 根据模型类型选择调用适配器。
4. 使用 `model_catalog.model_name` 作为实际模型名。

未配置或校验失败时，对应功能返回明确错误：

```text
当前用途未配置可用模型，请在管理端模型设置中配置。
```

## 12. 验收标准

1. 管理端可以查看、筛选、启用、禁用、新增和删除模型。
2. 管理端可以创建渠道、维护 API 地址和 API Key。
3. 管理端可以从渠道或模型两个入口维护渠道支持模型。
4. 管理端可以为整理、分析、对话、语音转文字分别选择模型。
5. 禁用、删除、清空密钥时不会破坏正在使用的模型设置。
6. 未配置模型设置时，对应 AI 功能不可用并返回明确错误。
7. 语言模型测试调用可用，但保存不依赖测试结果。
