# 文档索引

本目录按“产品总纲 → 需求规格 → 系统设计”组织。

## 阅读入口

- [产品设计总纲](产品设计总纲.md)：产品边界、角色、功能地图和当前实现状态。
- [需求规格](需求规格/)：说明系统要解决什么问题、遵循什么业务规则以及如何验收。
- [系统设计](系统设计/)：说明当前代码如何实现需求，以及重要架构取舍。

## 文档状态

| 状态 | 含义 |
|---|---|
| 已实现 | 当前前后端已提供完整主流程 |
| 部分实现 | 只完成部分范围，文档必须指出缺口 |
| 未实现 | 规划需求，当前代码不提供该能力 |
| 现行 | 与当前代码对应的设计或说明 |
| 目标设计 | 已确认的目标实现方案，当前代码尚未提供该能力 |
| 审计记录 | 特定日期的核查结论，不代表持续更新的设计 |

## 维护约束

- 代码是“已经实现什么”的事实来源，需求规格是“系统应当做什么”的事实来源。
- 尚未实现的规划功能必须明确标记为未实现；已进入开发的功能应标注实际实现范围，不能把未启用周期写成已支持。
- 不再保留阶段性实施计划；重要且长期有效的技术取舍写入架构决策。
