# 事件关系识别 Skill 只读版开发与验证

日期：2026-10-22。状态：只读识别版已实现；未实现正式关系入库，未修改日记或图谱数据库。

## 交付范围

[Skill 入口](../../../skills/diary-event-relations/SKILL.md) 采用已选定的按日去重资料、明确配对、agent 逐对判断与来源核对方式。资源包括关系边界示例、结果协议、数据库工作流及评估说明，并提供正常自动发现的 UI 元数据。

实现脚本：

- [workflow.py](../../../skills/diary-event-relations/scripts/workflow.py)：预算分批、来源和规则指纹绑定、局部别名、逐对结构及连续短引检查、本地分批合并、冲突修订、备份、恢复、身份映射及 Markdown 汇总。
- [db_source.py](../../../skills/diary-event-relations/scripts/db_source.py)：数据库只读事务、用户及运行定位、正式来源与修订检查、中高准入覆盖、已有向量合法性、精确余弦召回、已发布历史与显式回放历史、数据库时点复验。

支持命令为 `find/prepare/read/record/status/check/verify/render`，没有数据库保存或迁移命令。当前历史池在 Python 中精确比较，保留最大要点得分后按事件取前五，未增加近似索引或关键词路径；数据增长后仍需性能评估。

默认配置 `max_batch_chars=12000`、`max_pairs_per_batch=12` 仅为显示保护起点，不是已证明最优的批大小或 Token 限额。单对完整资料超限时明确停止，不丢失内容。

最终 21 项测试通过，Skill 结构检查通过，本地 Markdown 引用无断链。测试涵盖：

- 用户与日期边界、来源修订／内容／重要性变化、完整中高准入、现有两种来源指纹协议。
- 数据库只读约束、JSON 数组类型、同模型 1024 维合法向量、向量内容变化拦截。
- 事件聚合在前五截断之前、稳定排序、阈值不补足、事件内容去重与完整拆批、单对超限无半套目录。
- 额外／重复／错误指纹结果、其他事件证据、非法或不唯一短引；无效输入不部分保存。
- 缺失结果不能完整交付、相同输入幂等、冲突修订显式替换与保留旧稿、零候选交付。
- 回放前一日修订使后一日依赖失效、Skill 版本及输入文件变化拦截。
- 数据库复验成功记录时点，后续复验失败清除旧成功标记，阅读稿正确显示未复验状态。

SQLite 用于隔离适配与只读测试，不等同于 PostgreSQL 的完整验收。以下另有真实 PostgreSQL 只读检查。

## 独立前向试跑

最终版本以新的干净 subagent 执行，只提供 Skill 与隔离构造来源包，不提供预期答案或旧实验结果；未访问网络、数据库、私人日记或外部模型 API。

6 个构造事件、15 个事件对，分两批实际完成 `read/record/status/check/render`，产出 3 条关系、12 对无关系：

1. 修车预约 → 实际修车：后续，EXPLICIT。
2. 收到老屋将拆消息 → 可能因此翻童年照片：引发，SPECULATIVE；未写成老屋已拆或确定因果。
3. 今天帮助找租房资料时想起去年的退租经历 → 去年退租：提及，EXPLICIT；保留提及方向。

主审随后检查三条关系与双方来源符合，并检查阅读稿明确写出尚未执行数据库复验。这是构造场景的行为试跑，不是三类真实日记关系的质量验收，也不报告准确率或 Token。

最终前向产物归档在 [independent-forward](independent-forward/forward-notes.md)，包括完整输入、分批输出、最终结果、真实身份映射及过程记录。第一次前向试跑曾发现阅读稿缺少复验状态说明，随后已修正、补测试，并由上述新的独立 subagent 重跑确认。
