# 日记整理 Skill 编写与评估调研

调研日期：2026-10-20。只采用实际打开的官方资料；未联网提交私人日记内容。以下区分开放格式要求、宿主行为、编写建议与本项目建议。

## 1. 开放格式要求

Agent Skills 的最低结构是目录内存在 `SKILL.md`，其 YAML 头包含有效的 `name` 和 `description`。`name` 须与父目录名一致，长度不超过 64 字符；`description` 非空且不超过 1024 字符。`scripts/`、`references/`、`assets/` 都是可选目录。正文没有固定章节模板；不是章节越齐越合规。[Agent Skills 规范](https://agentskills.io/specification)

当前 `diary-organizer` 已有有效名称、明确描述和所需目录，整体结构符合上述要求。本次没有运行规范参考校验器，结论来自文件阅读，不等同工具校验结果。

## 2. Codex 的发现路径与调用策略

当前 Codex 官方说明：仓库技能扫描从当前目录向仓库根寻找 `.agents/skills`，支持技能目录符号链接。普通仓库根 `skills/` 没有列为默认发现位置。`agents/openai.yaml` 的 `allow_implicit_invocation: false` 禁止隐式选择；显式 `$skill` 仍可调用。[Codex：Build skills](https://learn.chatgpt.com/docs/build-skills)

本项目把源文件放在 `skills/diary-organizer`，不能仅凭该目录及其中的 `openai.yaml` 就认定已经注册。用户要求后直接读取该文件并遵照执行，与宿主自动发现是两件事。若目标只是当前项目手动使用，不必把注册问题升级为内容缺陷；若目标是出现在技能选择器，应检查实际安装、符号链接或插件注册，再选择最小接入方式。

## 3. 主文件与按需资料

开放规范把技能分为元数据、激活后正文、按需资源三层；建议正文低于 5000 tokens、主文件低于 500 行，参考资料直接可达，避免深层引用。脚本应说明依赖、提供有用错误信息。[Agent Skills 规范](https://agentskills.io/specification)

当前主文件约 130 行，并且把示例和入库说明分离，已有渐进披露结构；没有因长度而强制继续拆分的依据。保真原则、澄清、整篇确认等每次必需约束应保留在主文件；入库实现和运行依赖按条件进入 `references/storage.md`。本项目专属用户名、Python 环境和数据库能力应标明适用范围，避免“用户直接提供文本”也被无条件数据库前置步骤阻塞。该分支建议是本项目推论，不是规范要求。

## 4. 指令、脚本与写入边界

OpenAI 建议一个技能聚焦一个工作，明确输入和输出；只有确定性行为或外部工具需求才优先加入脚本。[Codex：Build skills](https://learn.chatgpt.com/docs/build-skills)

据此，当前把名称读取、格式转换、来源指纹、预检和保存放脚本，把语义整理交给模型的边界合理。需要改进的不是继续增加语言处理脚本，而是明确“仅整理、整篇替换、局部修订”的可用入口及失败路径。若当前工具只支持整篇替换，应直接声明不支持已有分析的局部修改，不能靠提示词承诺工具未提供的能力。

## 5. 行为评估

Anthropic 官方建议先从真实失败建立代表性评估、记录无技能基线、用最少规则迭代，并通过新会话执行检查实际行为；示例可比抽象规则更清晰地传递边界。其“至少三项评估”和多型号测试是产品指南建议，不是开放格式强制项。[Skill authoring best practices](https://platform.claude.com/docs/en/agents-and-tools/agent-skills/best-practices)

本项目应把已经发生的问题转成私有、脱敏的语义回归案例，分别检查：是否补写结果、是否改变日记视角、是否把反思转计划、日常事件是否被升级、女性指代是否有足够证据、回答局部问题后是否等待整篇确认、用户改稿是否被覆盖。使用可接受条件与禁写事实评判，不要求唯一措辞。现有脚本单测能证明格式或写入保护行为，不能证明这些文本质量指标；本次没有执行模型行为评估，因此不能报告实际通过率。建议同场景比较旧规则、新规则和无技能基线，并保存模型版本及运行条件。
