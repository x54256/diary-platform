# 关系稿直接转换入库验收

日期：2026-10-22。需求：关系稿内容过多，改为类似事件整理、要点提取的 Markdown 主稿，经脚本转换入库。

## 已实现

- `draft.py` 定义严格 Markdown 稿件协议。正文保留关系／未决；无关系判断折叠到末尾；来源哈希、配对及方向标识用隐藏注释保存。不再输出来源复验时间、只读状态说明、重复的全部判断总表及重复要点主旨；有独立判断依据时保留，无需重复关系说明。
- `关系结果.md` 一旦存在即为当前主稿。`saved_results`、状态、检查、回放依赖及入库读取稿件，格式错误不降级使用旧缓存。`render` 首次生成，已有稿件时校验而不覆盖。
- `record --markdown` 支持批次 Markdown 合并；JSON 仅作内部批次缓存。`convert --markdown --output` 支持完全离线转换；`prepare-storage --markdown` 直接解析完整稿，用户不需要先手动同步 JSON。
- 入库包版本 2 冻结完整稿件文字与 SHA-256，并校验解析结果、规范化结果及映射信息一致。独立包仍不依赖原稿路径；正式保存使用包内稿件快照，修改后须准备新包。完整稿缺失事件对时拒绝入库，删除关系不隐含转为无关系。
- 新 checkpoint 保存稿件全文及指纹。历史版本 1 包仍支持状态查询，不允许作为新包写入；已有发布不覆盖。

## 验证

37 项本地 unittest 通过；4 项 PostgreSQL 测试在一次性本机 pgvector/pgvector:pg15 容器中显式执行并通过；Skill quick_validate 通过。正常本地测试未设置容器 URL 时跳过 4 项 PostgreSQL 测试，不计为已通过；本次另行显式运行。

新增测试覆盖三种状态完整往返、稿件优先于陈旧缓存、重复 render 保留人工稿、离线 CLI 转换及不覆盖输出、全文指纹绑定、未知结构／配对重复／缺失／假引文／端点错配拒绝、零候选、可选判断依据、多行原文 Markdown／竖线／Unicode 及引用空行、旧版本查询兼容性。

独立 subagent 只获得 Skill、任务与隔离原始来源，通过真实 CLI 执行：改稿（含两段描述）→ convert → prepare-storage → 默认只读 save → save --write → storage-status。旧 results.json 不同步，数据库与 checkpoint 仍保存改稿内容，三种判断齐全、原要点保留。未知字段与删除未决条目被拒绝。引文空行最终兼容 `>` 和 `> `，修正后重跑完整 CLI 验证通过。此项验证使用临时目录及内存 SQLite，不访问正式数据库。

## 按需事实澄清补充

已参考事件整理和要点提取 Skill，补齐关系 Skill 的澄清触发条件、集中提问与跨事件对去重、实际问答单独记录、用户跳过后保留未决、回答涉及来源外事实时先走正式要点修订，以及整稿确认与事实回答的区分。问答不混入可解析关系稿，不增加数据库字段，不将聊天回答直接当作正式要点证据。
