# 10月26日后续关系冗余检查：逐步骤输入输出

本材料解释拟议算法。使用10月26日真实来源、已识别关系和数据库历史边；未实施新算法或修改已发布关系。程序路径检查为实际只读计算，语义输出只完成下面Cube案例的演示，不将演示冒充整篇重评结果。

## 样本与回放范围

- 10月26日原识别：288对候选，35条关系，其中32条后续关系进入本检查。
- 只读回放：排除10月26日本次运行已发布的边，再加入其32条后续候选，模拟入库前组合。
- 历史边取冻结历史运行集合的当前已发布版本，共272条后续边；这不是历史时点数据库的精确恢复。
- 程序实际找到20条有替代路径的本批边；另外12条没有替代路径。20条是待语义检查数，不是应删除数。
- 其余3条原关系不进入本次后续冗余检查，沿用原结果。

## 步骤1：程序合并临时图

**输入：**本批32条后续候选、冻结历史运行中的272条后续边，以及关系身份和来源版本。

**输出：**临时后续图，标明每条边是历史边还是本批候选；不生成新的关系判断。

Cube部分的真实输入输出为：

```json
{
  "historical_edges": ["A→B", "B→C", "A→C"],
  "current_candidate_edges": ["A→D", "B→D", "C→D"]
}
```

文件：`步骤1-程序输入与临时图.json`，包含整批实际边端点；本样例历史边还含关系ID、说明，便于追溯。

## 步骤2：程序查找替代路径

**输入：**步骤1临时图和本批待检查边清单。

**处理：**逐条暂时排除待检查直连，搜索至少两跳的其他后续路径。已有历史边只作上下文，不在本批自动删除。

**输出：**整批20条待语义复核边、12条无需冗余复核的边。后者保留原判断，不代表程序重新核实了其事实。

Cube的实际路径搜索输出：

```json
{
  "needs_semantic_review": [
    {"edge": "A→D", "found_path": ["A", "B", "D"]},
    {"edge": "B→D", "found_path": ["B", "C", "D"]}
  ],
  "keep_without_alternative_path": ["C→D"]
}
```

文件：`步骤2-程序路径检查输出.json`，包含全部20条路径及12条保留边的真实ID。

这一步找到的是候选路径：A→B→D用了本批B→D，而B→D也待复核。不能直接拿这一条路径作为最终过滤依据。

## 步骤3：模型判断承接内容

**输入由程序准备：**待查直连、替代路径及必要上下文；每个事件的日期、标题和完整相关要点；路径各段的关系说明和要点证据；本批／历史身份。不能只发送A/B/C/D字母或事件标题。

本例输入A、B、C各1个完整要点，D的3个完整要点，以及历史3条边、本批3条边和程序找到的路径。详见`步骤3-模型输入-Cube样例.json`，保留原文、真实事件ID、要点ID和历史证据。

**模型处理：**判断整段是否都在推进同一次Cube切换，直连是否具有中间推进没有表达的独立内容；识别本批路径中其他待过滤边的影响。

**样例输出：**

```json
{
  "decisions": [
    {
      "edge": "A→D",
      "decision": "INDIRECT_FOLLOWUP",
      "reason": "工作计划到接口核对，已由中间分析、实现及对接安排完整承接，无额外直接内容",
      "approved_retained_path": ["A", "B", "C", "D"]
    },
    {
      "edge": "B→D",
      "decision": "INDIRECT_FOLLOWUP",
      "reason": "分析到核对补漏，已由实现及对接阶段承接，无额外直接内容",
      "approved_retained_path": ["B", "C", "D"]
    }
  ],
  "keep_current_edges": ["C→D"]
}
```

文件：`步骤3-模型输出-Cube样例.json`。这是当前模型基于真实内容作出的样例判断；其字段是拟议接口示例，不是当前保存脚本已支持的协议。

程序若首次提供的路径不充分，可以补充其他路径和相关要点继续判断。找到一条不充分的路径，不能直接推导不存在充分路径；尚未完成必要检查时标记检查未完成，不默认为无关系。

## 步骤4：程序校验最终保留图

**输入：**步骤1临时图、步骤3的保留／间接延续决定，以及模型认可的最终替代路径。

**处理：**同时移除本批拟过滤边，逐条校验其认可路径的各段仍然保留。程序只核对结构与模型认可路径是否一致，不自行证明路径语义。

**实际样例输出：**

```json
{
  "historical_edges_unchanged": ["A→B", "A→C", "B→C"],
  "current_edges_to_store": ["C→D"],
  "current_edges_to_archive_as_indirect": ["A→D", "B→D"],
  "checks": [
    {"edge": "A→D", "retained_path": ["A", "B", "C", "D"], "all_hops_retained": true},
    {"edge": "B→D", "retained_path": ["B", "C", "D"], "all_hops_retained": true}
  ],
  "result": "PASS"
}
```

文件：`步骤4-程序最终校验输出-Cube样例.json`。这一结构检查已在本地实际执行。

最初的A→B→D不再存在，但模型已经认可另一条最终保留路径A→B→C→D，所以A→D仍可过滤。若找不到仍存在的已认可路径，返回语义复核，不能带着失败结果发布。

## 步骤5：程序生成关系稿，用户确认

**输入：**最终保留边、间接延续及理由、完整校验结果。

**输出：**本批保留C→D，A→D与B→D记为间接延续，列明最终替代路径。文件：`步骤5-供用户确认的关系稿-Cube样例.md`。

本例中的历史A→C确实存在。由于本次只筛选新边，A→C保持原状；不能把本例输出声称为整个历史图已经变成纯A→B→C→D。

## 步骤6：用户确认后程序保存

**输入：**用户确认的整篇关系稿、预检冻结包和匹配指纹。

**预期输出：**本批直接边进入正式关系表，间接延续及判断理由进入归档，原历史边不变。保存时再次校验来源与图上下文；变化后停止并重新预检。

文件：`步骤6-待确认后的保存意图-Cube样例.json`，标明未执行。本例不触发对已发布运行的替换。
