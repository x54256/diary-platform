# 09-09、09-10 事件关系识别实验与方案选择

日期：2026-10-22。结论：采用**按日准备去重事件资料与明确事件对清单，由当前 agent 逐对判断并核对证据**的 Skill 方式；不要求每对单独读一次完整文件，不默认固定执行 A/B/C 三轮。资料超预算时按事件对拆成小批，保留完整要点。独立盲测用于开发验收，关键争议可另行独立复核。

这是本次主审根据真实实验作出的工程选择，不是统计证明批量方式普遍优于逐对方式。未创建正式 Skill、调用项目外部语言模型 API、执行迁移或发布图谱。

## 1. 输入与实验隔离

- 数据库只读导出用户指定的 2026-09-09、2026-09-10 两篇日记：分别为 7、4 个准入事件，共 83 条正式要点，运行均为 `POINTS_READY`。
- 导出使用 PostgreSQL 可重复读、只读事务，向量来自已有存储，没有重新生成；83 个向量均合法且模型标识一致。
- 当前事件正文与对应运行来源快照的正文逐项相同。未重新生成或改写原文、要点。
- 全量判断 55 对：09-09 同日 21 对，09-10 同日 6 对，跨日 28 对。三组使用相同事件、相同规则、相同配对，避免召回范围影响组织方式对照。
- 三个 subagent 从干净上下文启动，不互看结果、不读主审参照、原文或召回分数。语义输入均为同一份正式要点；主审另核对来源。
- 原始只读连接在沙箱内未成功，按只读网络权限流程重试后导出成功；没有把权限限制判断为数据库故障，输出未暴露认证信息。

冻结文件及来源摘要见 [snapshot-meta.json](snapshot-meta.json)、[source.json](source.json)、[experiment-rules.md](experiment-rules.md)。本实验只研究这两篇内部关系，不包含九月其他日记或八月历史。

**与旧方案的关系：**两组内容池判断用于考察“去重事件池＋明确配对＋独立双判”的组织方式。执行者均为宿主 subagent，未运行旧 Qwen API、旧提示词或原生产任务状态机；主审也没有按旧 C 提示做一次受控模型调用。因此不能称为旧生产 A/B/C 的效果或价格复现。本次足以支持选择新 Skill 的输入与工作方式，不足以比较宿主模型和旧模型的优劣。

## 3. 完整性与结果差异

[离线检查脚本](compare_results.py)实际运行通过：三组均完整覆盖 55 个 pair ID，无重复、缺失；关系端点、类型、确定性和要点编号均合法。程序检查不证明语义正确。[comparison.json](comparison.json)

三组状态有分歧的只有 P13。P37 的状态、类型、方向和确定性相同，但有一组选取额外的源要点。其他三条共同正例的自然语言描述也不同。

按旧程序“描述也必须逐字相同”的比较方式，两组内容池的 P09、P37、P48 都会进入裁决；其中 P09、P48 结构化字段完全相同，只是描述措辞不同。这说明不应把描述字面差异直接当作三条语义分歧。P37 有证据取舍及主体措辞问题，仍需具体审阅，不能只比较结构字段后跳过文字核对。

本轮没有发现第三事件串入本对的情况，但只测了一个小样本，不能据此排除旧批量串对风险。

## 4. 主审采用的结果

主审先于结果保存了 [初步参照](root-reference-before-results.json)，预先标出五项边界；随后依据双方要点与来源逐项审阅。采用结果不是用户确认真值，不能用它与同一轮判断相互印证后声称“100% 准确”。详细依据及参照变化见 [主审裁决记录](主审裁决记录.md)。

| 事件对 | 采用结果 | 核心理由 |
| --- | --- | --- |
| P09：尝试恢复心理学课程 → 想到居家空闲继续学习 | 后续，EXPLICIT | 同一具体学习过程出现新的时间安排打算；未写成已经执行 |
| P37：与颂梅争执及沟通 → 与小廖共同复盘 | 后续，EXPLICIT | 同次脚碰枕头的争执可定位；新增发录音、提醒复盘、AI 分析及共同讨论 |
| P48：想恢复心理学却缺少推动办法 → 居家学习的新安排 | 后续，EXPLICIT | 只表达心理学恢复这一局部事项的新计划，不扩大成四项活动均已恢复 |
| P06：已经部分恢复 ↔ 仍不知如何恢复 | UNRESOLVED | 同日状态叙述缺少可定位的阶段与顺序，不能靠排列强定方向 |
| P13：沟通总结以 AI 焦虑为例 → 工作和面试不自信 | NO_RELATION | 原文举例未唯一定位到另一个具体事件；不采纳逐对组额外生成的提及边 |

最终为 3 条后续关系、51 对无关系、1 对未决。[完整机器结果](final-results.json)、[可读关系与双方证据](关系结果.md)

P09、P48 的新计划边界是本次主审作出的解释，不是此前用户标注。规则允许记录来源明确表达的计划，不能把“没有执行”一概当无进展；同时必须证明同一具体事项及新安排，不能把相同主题或重新说一遍愿望当后续。未来回归需专门覆盖这条边界。

P13 的额外边是逐对方式在本次主审标准下未被采纳的候选，不能仅凭它给逐对方式计算通用误判率。它说明把输入拆成一对，仍可能把概括性表达过度对应到具体经历。

还发现内容池二把“我发录音、她发 AI 分析截图”写成“双方发送争吵录音”的主体漂移；主审已在独立最终稿中修正，保留原始输出。这一问题需要语义核对，结构校验或多组总体一致不会自动发现。

## 5. 召回单独评估

使用导出的同模型 1024 维向量计算精确余弦，按双方全部要点组合最大相似度聚合为历史事件分数，先应用 `0.4` 再取前五。只将 09-09 作为 09-10 的历史，未引入其他日期。

- 28 个完整跨日组合保留 18 对：7 对低于阈值，3 对因前五上限被排除。
- 加上 27 个同日比较对，按该基线实际需判断 45 对。
- 主审采用的三条跨日候选都被召回：P37 相似度约 0.6638、历史排名第一；P09 约 0.5473、排名第一；P48 约 0.4540、排名第二。
- 全量配对对照中的 10 个未召回事件对，本轮没有发现满足定义的关系；这只适用于这两篇及本次主审，不证明更长历史池没有遗漏。

完整命中、排名和证据要点 ID 见 [recall.json](recall.json)。保留当前阈值和前五基线，暂没有本轮证据支持增加关键词补漏、降低阈值或调整前五。未来需用更长历史池测试候选竞争和明确历史引用。

## 6. 最终选择及落地要求

**采用去重资料包、明确配对、逐对结果和来源复核。**这里“逐对”指判断与落结果的单位，不等于必须为每一对重复读取两份全文。严格逐对读 55 次没有在本轮表现出质量收益，还多产生了一条主审未采纳的边，重复输入明显增加。

具体落地：

1. **程序按日准备资料。**继承 0.4＋历史前五，同日全比较，冻结用户、事件、正式要点身份与范围；事件内容只在资料包中出现一次，明确列出本批要判断的对。
2. **按完整性控制显示。**输出紧凑正文，UUID 映射交程序持有；资料超出工具或上下文预算时按候选对拆批，批内事件去重。不能把被截断当作已读，单对再长也不能裁掉要点。具体批量上限仍需实现后测定，本轮不虚构最优批大小。
3. **agent 每对独立形成结论并落盘。**所有对包括无关系和未决都覆盖，语义不借第三事件补证；长任务允许按批保存与恢复。资料去重不改变每条关系必须有自身双侧证据的要求。
4. **交付前按来源复核。**正例检查具体事项、方向、计划／执行、动作主体及最小证据；负例回看是否漏掉明确联系；未决说明缺口。特别避免把“比如某类情况”直接定位成另一具体事件。
5. **不默认固定 A/B/C。**本轮两个内容池的实质结论相同，强制描述逐字比较反而把全部三条正例送入裁决；两份一致也无法保证主体措辞忠实。开发验收继续独立盲测，实际关键争议可按同一冻结来源单独复核。普通自查如实记为核对，不伪称独立审核。
6. **保留未决，不用重复调用制造确定性。**P06 留待必要的事实澄清；未决和执行错误分开。正式发布的实现仍按前述开发调研单独完成，当前结果不冒充已入库。

选择去重方案并不表示“越大批越好”。本轮两组已经出现显示截断，说明需要受控拆批；也不表示已经验证所有未来任务无需独立核验。当前决定的是首版 Skill 的默认工作方式，后续以保留集和真实失败决定是否增强。
