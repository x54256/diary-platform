# 热词与人物关系

核对基线：2026-10-29。本文集中说明用户维护的词汇、人物资料及其实现与调用关系。账号凭据和访问控制见[账号与权限](../账号与访问/账号与权限.md)。

## 1. 功能边界

用户维护本人的热词和人物关系，辅助语音识别及日记整理、分析。资料通过“我的”页面进入。账号信息由认证接口提供；本模块提供热词和人物关系的增删改查。

| 对象 | 作用 | 主要内容 |
|---|---|---|
| 热词 | 提高专名、术语的语音识别准确率 | 一条用户维护的词汇 |
| 人物关系 | 为人物称呼和身份理解提供参考 | 姓名、常用名、性别、与用户的关系 |
| ASR 词表状态 | 记录当前用户已同步到提供方的词表 | 远程词表 ID、模型、内容指纹 |

资料归属当前用户。共享同一词汇的不同用户各自维护自己的记录，识别与分析上下文不能跨用户混用。

## 2. 功能约定

### 热词

- 用户可查看、新增、修改、删除本人热词。
- 去除首尾空白后不能为空，长度上限为 100 个字符。
- 同一用户按不区分大小写的方式查重；重复新增或修改返回冲突。
- 资料更新不立即提交语音任务；后续语音批次按当时的完整资料重新核对词表。

### 人物关系

- 用户可查看、新增、修改、删除本人人物资料。
- 姓名及与用户的关系为必填，去除首尾空白后不能为空，各字段最多 100 个字符。
- 性别取 `male`、`female`、`unknown`；默认未知。
- 每人最多提供 20 个常用名。常用名去除首尾空白、忽略空项、按不区分大小写去重。
- 同一个人的姓名和常用名不能冲突；同一用户下其他人物的姓名、常用名也不能互相占用。
- 列表按创建时间倒序展示；删除按用户归属查找记录后执行。

输入校验以[接口模型](../../backend/schemas/voice_profile.py)为准：常用名原始列表的最大长度先由模型验证，随后执行空项和重复项归一化；不能假定去重后不超过 20 项就一定通过输入校验。

## 3. 与日记能力的衔接

| 使用方 | 读取内容 | 语义边界 |
|---|---|---|
| 语音识别 | 热词、人物姓名、常用名 | 构造识别提示词表；关系描述不作为词条正文 |
| 应用内 AI 整理 | 人物主名、常用名和性别等最小称呼参考 | 具体称呼处理遵循整理规则，不能凭资料补写经历 |
| 应用内 AI 分析 | 姓名、常用名、性别和人物关系 | 理解身份与指代的参考，不自动把关系解释写成来源事实 |
| Skill 整理与分析 | 各自导出的当前用户人物资料 | 以对应导出、校验和保存协议为准，不能认为资料更新会自动改写已确认稿件 |

跨模块规则各维护一份：资料字段和唯一性由本文定义；词表绑定、模型降级与批次复用由[语音实现设计](../日记管理/语音录入/实现设计.md)定义；整理和分析如何使用人物资料由对应功能约定定义。

人物关系维护的是用户提供的基础资料。知识图谱中的人物实体和推断关系按知识库设计另行维护，当前不能据同名直接声明二者已经建立自动同步或统一实体绑定。

## 4. 实现与约束

| 代码 | 职责 |
|---|---|
| [用户资料路由](../../backend/routers/voice_profile.py) | 热词与人物关系接口、归属查询、查重、提交及错误映射 |
| [接口模型](../../backend/schemas/voice_profile.py) | 字段长度、必填、性别枚举和常用名归一化 |
| [持久化模型](../../backend/models/voice_profile.py) | `hot_words`、`person_relations`、`asr_vocabularies` |
| [人物上下文](../../backend/services/person_relations.py) | 按用户读取并转换为非 ORM 的上下文对象 |
| [词表构造](../../backend/services/asr_vocabulary.py) | 合并词条、稳定排序、指纹和同步状态 |
| [后台词表同步](../../backend/services/transcription_tasks.py) | 批次首次提交前按模型和指纹同步 |
| [热词页面](../../frontend/pages/profile/hot-words.vue) | 热词维护交互 |
| [人物列表](../../frontend/pages/profile/person-relations.vue) / [新增](../../frontend/pages/profile/person-relations/new.vue) / [编辑](../../frontend/pages/profile/person-relations/[id].vue) | 人物关系维护交互 |

接口统一在 `/diary/api` 下，以当前用户作为列表和单条读写条件。不存在或非本人的 ID 返回 `404`。热词查重在应用层使用小写比较；人物姓名和常用名使用 `casefold` 集合比较。数据库另约束同一用户下原始热词、人物主名唯一；数据库唯一约束与应用层不区分大小写的校验不是同一个范围。

`load_person_relation_context` 按创建时间升序返回姓名、常用名、性别、关系；`load_person_name_gender_context` 提供整理使用的最小字段集合。调用方应保持用户 ID 和来源一致。

ASR 集合合并时对词条使用 `casefold` 去重、稳定排序，并连同权重、语言生成 SHA-256 指纹。保存远程词表 ID、目标模型和指纹后，批次可复用同一绑定。资料更新不直接修改运行中批次的本地绑定字段；但后续批次可更新同一远端词表 ID 的内容，当前未实现跨批次不可变内容隔离。

## 5. 验收与已知边界

- 只能读写本人热词与人物资料；其他用户可分别保存同名热词。
- 空白、超长、非法性别、人物称呼冲突与重复热词被明确拒绝。
- 常用名顺序和内容归一化稳定，人物上下文不会读到其他用户的数据。
- 后续语音批次使用更新词表，同批次音频复用本地固定的词表 ID；需要另行验证后续批次更新远端词表时旧批次内容是否保持一致，当前实现不能提供该保证。
- 不支持热词的 ASR 模型能降级；其他同步异常应反馈真实错误。
- 移动端可编辑控件实际字号至少 `16px`，允许用户自行缩放。

现有词表测试见[词表测试](../../backend/tests/test_asr_vocabulary.py)。前端控件字号与人物冲突的完整并发行为仍须按对应场景验收；本次文档核对未执行浏览器或真实 ASR 调用。

当前应用查重与保存分开进行，数据库对常用名没有跨人物集合唯一约束；不能将顺序请求校验等同为并发请求下完整的大小写、别名唯一性保证。此为需要保留的实现边界，本轮不改变代码。

## 6. 候选材料的处理

热词候选建议和逐条语境包含待核实的称呼与尚未采纳词条。它们不自动成为正式资料或全局替换词典；仍未确认的项目由用户核实后再维护。相关材料归入[热词候选资料](候选资料/热词候选-20261027/候选建议.md)，后续清理须先处理未确认项和独有规则。
