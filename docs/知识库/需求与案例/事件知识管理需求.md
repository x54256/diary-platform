# 事件知识管理需求

整理日期：2026-10-29。本文保留事件知识的有效业务目标，并核对 2026-08-31 旧方案中已被后续第一层实现替代的部分。业务案例见[事件知识业务案例](事件知识业务案例.md)，关系与探索目标见[事件关系与探索需求](事件关系与探索需求.md)。

## 1. 目标与概念

把结构化日记中的经历整理为可独立理解、可定位和引用的事件内容，再基于有出处的内容识别事件关系。知识组织应服务于回看经历、理解联系及后续自我认识，而不是只完成一条调用流水线。

当前第一层直接以来源结构化事件作为事件身份，通过有序要点保存主旨与详细内容，以要点作为向量及关系证据单元。旧方案的独立 `knowledge_atomic_events` 不是当前正式实现的节点表。

保留以下设计边界：

- 事件拆分与合并由上游整理承担，知识处理不能因关联数量或表达维度不同而重复创建来源事件。
- 一个来源事件可以形成多个要点并与多个其他事件发生不同的直接联系。
- 要点能够脱离临近文本理解，但每个主体、观点、计划和结果仍能追溯来源，保留必要上下文。
- 心理过程和个性分析属于后续层的独立设计，不能把第一层要点生成当成已完成上层认识。

## 2. 来源与保真约定

来源为当前用户的结构化事件及受控导出的事实材料。输入的实际字段与准入条件由第一层对应实现说明；旧“凝练只用标题和 body、不用感受反思”属于已替代的单一凝练协议，不作为所有实现的通用限制。

每项输出需保持：

1. 叙述视角、实际说话者、主体归属及来源顺序。
2. 独立事实、行为、状态、观点、体验、判断、计划、理由、条件、转折、结果、时间、数字、对象与备选方案。
3. 明确表达、本人推测、本人原因解释和系统解释的区别。
4. 已执行、已决定、承诺、计划、期待、担忧和缺少结果等状态的区别。
5. 来源中的歧义、矛盾和证据缺口，不用未经核验的解释将其抹平。

可以删除完全重复且无新增语义的表达、无意义口头填充及已有明确纠正依据的口误。修正与删减必须能说明依据。模型复核、程序结构校验和人工审阅承担不同职责，单一“通过”不能代替内容保真。

旧 `coverage` 表要求逐项说明源信息如何被保留或合法删除，其完整性目标仍有效；当前具体审核协议以第一层规则为准，不要求恢复旧 `coverage` 字段。

## 3. 时间与来源身份

- 日记归属日期、实际发生日期和未来计划日期分别表达。
- 能确认的实际发生时间应保留证据；不能因为源日记日期存在就断定事件当日发生。
- 相对日期应结合日记日期和语境解释，无法判断时保留原意及未知状态。
- 计划执行、截止和预约时间只在具有相应语义的位置保存，不覆盖实际发生日期。
- 时间标记的展示、正文和结构化字段如何转换由具体实现约定，不能在来源定位时静默丢失原有自然表达。
- 关系及上层分析引用来源身份和本轮有效结果，来源或要点变化后必须核对引用是否仍成立。

## 4. 触发、恢复与发布

### 业务约定

- 所有触发、恢复、查询及发布校验用户所有权和当前来源版本。
- 任务保存来源和配置依据，运行中或恢复时发现不兼容的来源变化，应明确失效，不强行覆盖。
- 处理过程保留足以恢复的进度，已完成且来源仍有效的步骤不无说明地重复调用。
- 正式发布前检查事件覆盖、要点序号、向量、关系端点和证据有效性。
- 同一发布入口重复执行不能产生重复正式结果；模型调用、检查与正式数据保存的原子边界必须写清。

### 当前入口与旧方案差异

| 范围 | 当前实现或保留边界 |
|---|---|
| 应用内分析 | 已接入图谱任务，图谱阶段与分析阶段由任务配置及发布逻辑协调 |
| 单独建图、历史处理 | 已有 `/graph/build`、历史建图和任务恢复入口；旧“一律不补存量”的约束已被替代 |
| Skill 要点与关系 | 通过独立导出、审阅、预检和保存协议分阶段执行，不与完整应用内分析宣称为同一事务 |
| 事件准入 | 应用内当前建图处理中/高重要性事件；各 Skill 及补充工具的实际范围独立核对，不沿用旧“全部事件必定生成独立知识实体”的描述 |
| 正式发布 | 应用内完整任务在最终发布事务校验来源、依赖与完整性；Skill 分阶段保存遵循各自事务 |
| 修订来源 | 已入图内容受写入约束，过时运行、修订与依赖失效必须按当前协议处理 |

当前完整数据表和状态不在需求中重复展开，参照第一层实现说明与[图谱路由](../../../backend/routers/graph.py)、[任务工作流](../../../backend/services/graph_workflow.py)、[发布服务](../../../backend/services/graph_publish.py)。

## 5. 展示与查询目标

保留事件内容、来源日记、来源事件及其关系可追溯的需求。当前日记详情已有事件要点与关系图视图；不能将旧独立 `/knowledge` 页面描述为现有功能。

仍有独立价值、尚未作为现行界面交付的浏览需求：

- 可跨日记浏览事件，按可确认的发生时间、写入时间和稳定身份排序分页。
- 卡片展示时间、标题、内容预览和“日记日期 · 日记标题 · 来源事件标题”。
- 进入详情可读完整内容、回到来源，并在有关系时进入探索视图。
- 旧设想每页 20 条、卡片最多三行，作为跨日记列表候选交互保留；是否新建独立知识页及其导航需重新确认。
- 模型文本按受控标记或纯文本渲染，禁止任意 HTML 执行；按钮触控目标至少 44px，新增可编辑控件字号至少 16px。

旧事项列表、全览更新、匹配与只读遗留页已不属于当前运行能力；其实现要求不再保留为待办。若重新设计事项，应重新确认目标和边界，不能自动恢复旧事项模型。

## 6. 权限、隐私与验收

- 来源、要点、向量、运行、关系、证据和图谱探索全程按用户隔离。
- 调用与恢复记录不存解密后的 API Key，普通错误不返回原始请求、认证信息和完整个人内容。
- 来源检查、模型审核、程序验证和人工审阅的结论应有对应记录，不能把流程完成等同为语义质量达标。
- 历史原规格“AI交互日志每条只保留前2000字符”的描述与当前数据库调用审计记录不同；实际记录范围、脱敏与访问控制以现行实现说明为准，不能把截断承诺写成已实现。

核心验收：信息不丢失或篡改，事件身份不因要点拆分而混淆，引用可以准确回溯，保存前阻止来源与依赖失效，失败和恢复不重复发布，用户隔离不被图谱遍历绕过。

## 7. 本次移除的过时实现约定

已被后续实现替代的独立知识任务/成功沉淀记录、单一 AE 表、事项遗留 UI、固定凝练批次状态、body 单向量与独立搜索共享、LOW 候选枚举以及“全部数据都在首次分析一次生成”的细节不再作为当前需求。涉及独有关系边界与真实案例的内容保留在[关系与探索需求](事件关系与探索需求.md)及[业务案例](事件知识业务案例.md)，不因旧实现退出而丢弃其验证价值。
