# 数据飞轮应用规划

> 功能状态：未实现。当前日记、分析和对话数据已落库，但尚未形成自动更新人物画像、心路历程和认知洞察的闭环。

## 1. 功能目标

系统把日记内容、日记详情对话和 AI 伙伴对话统一沉淀到人物画像、心路历程和认知洞察，让平台随使用持续理解用户。

---

## 2. 数据闭环与更新机制

整个平台形成**数据飞轮**，使用越多 AI 越懂用户：

| 数据来源 | 触发时机 | 沉淀去向 |
|---|---|---|
| 日记内容 | 用户手动触发"整理" | → 人物画像 + 心路历程 + 认知洞察 |
| 日记详情对话 | 24h 无新消息自动沉淀 | → 人物画像 + 心路历程 + 认知洞察 |
| AI 伙伴对话 | 24h 无新消息自动沉淀 | → 人物画像 + 心路历程 + 认知洞察 |

> 自动沉淀产生的变更直接生效，用户事后可手动修改。仅 AI 伙伴心理咨询师角色引导编辑画像时需用户确认。

### 2.1 对话分离设计

下表是仍保留的对话来源规划；每种来源须分别绑定证据与上下文：

| | 日记详情对话 | AI 伙伴对话 |
|---|---|---|
| **聚焦** | 围绕具体日记 | 围绕"你这个人" |
| **定位** | 记录后的反思 | 人生指导和深度反思 |
| **入口** | 日记详情页内嵌 | 独立入口 |
| **上下文** | 互不混淆 | 互不混淆 |

### 2.2 模块初始化时机

| 模块 | 初始生成时机 |
|---|---|
| 人物画像 | 首篇日记整理后自动生成 |
| 心路历程 | 首篇日记整理后自动生成 |
| 认知洞察 | 首篇日记整理后自动生成 |

---

## 3. 待细化内容

- 24h 无新消息后的沉淀任务调度。
- 自动沉淀结果的证据链、变更历史和回滚机制。
- 用户手动修改与 AI 自动更新之间的优先级规则。
- 跨模块数据更新的一致性与幂等设计。

## 4. 规划状态与证据要求

24 小时无新消息触发、首次整理后初始化、自动更新直接生效和事后修改均为原产品规划，当前未实现。现有日记/分析/对话落库不等于自我认知闭环已建立；定期回顾及其对话已移除，未来来源须重新确认。

新增认识必须可追溯到原始证据，区分本人补充、本人解释和系统推断，保留反例、时间条件与撤回记录。自动更新、用户手动修订、伙伴引导确认三条路径的冲突优先级、任务幂等、源内容变化后联动失效与权限均待设计。
