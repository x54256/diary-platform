### 设计与两种实现

- 应用内通过日记分析、历史建图或仅建图入口运行，按冻结来源与配置处理并发布。
- 要点Skill提供来源导出、代理成稿、按需澄清、预检及要点/向量保存；关系Skill提供冻结候选、判断、稿件、冗余复核与独立关系保存。
- 两种方式共用业务语义，但事件范围、输入字段、审核、人工确认、运行状态与可见性并不完全一致，实现文档逐项对照。

当前正式数据使用来源结构化事件、要点、要点向量、三类有向事件关系与证据。人物节点及人物相关关系仍保留为设计范围，个人资料中的人物称呼不能替代图谱实体落地。

重复报告、已被最终候选覆盖的中间稿、恢复checkpoint和逐次成功请求流水在提炼结论后清理。保留的实验代码及固定输入仍在原路径，未修改其执行行为；缺失旧来源、外部模型变化和已清理向量流水导致的复现边界均在证据索引说明。
