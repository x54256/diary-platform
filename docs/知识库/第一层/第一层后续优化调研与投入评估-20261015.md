# 第一层后续优化调研与投入评估

日期：2026-10-15。范围：结合 Qwen/Kimi 对照、历史脚本与正式流程，调研优化方法并判断投入优先级。本文保留建议阶段的判断；用户随后授权执行优化，并授权11个历史事件用于召回校准，实施结果见[第一层最小优化实施与验收](第一层最小优化实施与验收-20261015.md)。

## 1. 是否继续优化

建议继续一轮范围明确的最小优化验证。目标是消除已复现的阻断和漏检，不以主观评分从 93.5 提高到 100 作为目标。

依据：

- Kimi 要点平均 93.5 分，是助手对四事件最后合法候选的主观评审。两模型都只有三事件通过、一事件失败，完整自动处理能力仍有实际阻断。
- 相同固定要点与向量下，四组关系正例中两组被 0.5 阈值过滤；Kimi 强制送判后四组均识别为 RELATED。召回阶段已经成为独立瓶颈，继续优化判定提示无法让被过滤的事件进入模型。
- 原脚本与正式实现下一轮合并修正都没有接收上一轮独立复核的具体意见。修正请求重新审核候选，需要再次发现同一问题。这是既有流程行为，不是两份代码之间的实现偏差。
- 审核要求同时输出 issues 和 summary_ok/detail_ok，三者存在确定性对应关系。Kimi 两次出现有 detail 问题却标 detail_ok=true，被程序正确拒绝；格式失败还有一份不合法 JSON。存在可以精简的协议冗余。

评分高不能代替结构可用、事实忠实和关系覆盖；但现有证据也不支持为个人项目增加复杂的训练、检索和多模型系统。

## 3. 调研结果与适用性

### 3.1 原文证据驱动的核验

[CoVe 原论文](https://arxiv.org/html/2309.11495v2)将核验拆为问题并隔离原答案，减少重复已有错误；同时明确仍会产生错误且增加计算量。[QAFactEval](https://aclanthology.org/2022.naacl-main.187/)研究对原文和生成内容的问答一致性，指出问题生成及可回答性检查影响效果，问答与蕴含检查能提供互补信号。

适用于我们：主体、一次/多次、预测/实际、指代和因果都是能对原文提具体问题的事实。当前错误并非缺少网上知识，原文就是事实来源，不需要让模型联网找依据。

建议先在现有修正请求中传入上轮复核 issues，并要求基于原文逐项核实、修正或说明不成立。保留对全部候选的检查，避免只修局部、遗漏其他事实；复核意见仍可出错，不能作为必须服从的标准答案。原文支持与修正结果继续由独立复核检查。保持两轮上限，正常调用阶段不增加。

暂不直接引入“每个原子事实一次调用”的完整 CoVe 流水线，也不逐字强制复制原文。前者增加调用和过程状态，后者不符合现有自然、近乎无损重写的目标。只有反馈闭环仍不能处理明确反例时，再在现有审核内测试按事实核对来源证据。

### 3.2 精简审核协议与结构约束

[百炼结构化输出文档](https://help.aliyun.com/zh/model-studio/qwen-structured-output)区分 json_object 与严格 json_schema：前者不保证固定字段，后者用于结构约束。当前支持表列出 Qwen3.7-Flash 的 JSON Schema 支持；Kimi 列在 JSON Object 下，JSON Schema 列表未列 Kimi。不能因为其他厂商接口或开源模型支持 Schema，就假定当前百炼 kimi-k3 接口支持。

更贴合当前环境的优先方案是精简新版审核输出：以合法 issues 为唯一问题清单，由程序按 field 推导每个要点的 summary_ok/detail_ok，避免让模型重复输出同一判断。原句覆盖、候选连续引用、字段合法性和要点完整性仍保持严格校验。必须另立协议和提示版本，不能静默修改现有返回或将不合法输出改造成合法。

该改动能从协议中移除“有问题但又称通过”的重复表示，但不能保证模型发现所有语义错误。JSON 合法性与缺字段仍需处理。严格 Schema 是 Qwen 的可测选项；对 Kimi 仅作为需先做渠道兼容性探测的选项，不作为本轮承诺。

### 3.3 先校准召回，再考虑增加检索组件

[Sentence Transformers 官方评估文档](https://sbert.net/docs/package_reference/sentence_transformer/evaluation.html)提供 Recall@K、Precision@K、MRR 等检索评估。[官方检索与重排说明](https://sbert.net/examples/sentence_transformer/applications/retrieve_rerank/README.html)采用先检索候选、再精排的流程。精排只能处理已经进入候选的事件。

我们已有最多五个历史事件的上限，可以先固定前五，离线比较 0.5、0.4 和不设最低阈值三种方式。已有四事件小样本中 0.4 覆盖四组正例，0.5 只覆盖两组；这只证明参数值得重新评估，不证明 0.4 可直接上线。阈值放宽会增加候选及无关事件对，需要同时记录负例误判和模型请求量。

先使用既有已确认关系集，补齐原始输入后评估；把开发反例与未参与调整的样本分开。当前历史池没有触发前五截断，后续验收需要包含超过五个候选的情形。新样本范围和外发另行确认，本次不读取或发送新日记。

暂不新增中文分词、关键词检索、重排器或另一套向量模型。这些方法有适用场景，但当前已知瓶颈能先用现有检索参数验证；新增重排器也不能恢复已经被阈值删掉的事件。

### 3.4 保守生成与主题颗粒度

Kimi 本轮避免了 Qwen 的多项明显失真，但把聚餐拆成九点，按完整主题组织的得分反而降低。可小幅调整生成要求：优先保留原指代及确定性，合并同一活动的过程、感受和直接目的，只有新事项才另起要点，不固定输出条数。

这是表达与组织优化，优先级低于流程阻断和关系漏检。不得为提高表达得分而要求大幅改写、强行消歧，也不能仅因某词变化就当作事实错误。保持原有完整主题和全部有效信息要求。

### 3.5 裁决成本与盲判策略

Kimi 的四组分歧中，R01 状态不同，R04 证据序号及描述不同，R05/R06 仅 description 不同。当前按描述字符串比较，两组业务关系字段相同的结果也进入 C。

可在可靠性问题解决后测试将“关系字段分歧”与“描述措辞不同”分开处理。但不能直接忽略描述，因为其中可能包含新增因果或日期。还需明确描述的忠实性检查方式。本轮 C 一次处理四对；减少两对只降低该批输入输出，不会自动减少一次调用。

保留独立 B 的理由是：本轮 Kimi B 确实漏掉一个确认正例，由 C 恢复。没有证据支持直接删除 B/C；也没有证据支持继续增加更多同类判定器。暂不引入跨模型投票或更多审核轮次。

### 3.6 思考长度和耗时

[百炼 Kimi 官方文档](https://help.aliyun.com/zh/model-studio/kimi-api)说明 kimi-k3 始终思考且不支持 thinking_budget，不能承诺通过该参数限制本渠道的思考长度。简单压低最大输出会增加 JSON 不完整风险。

先控制请求数量、反馈传递和输出冗余，补齐测试记录的 finish_reason、返回模型名与完整用量，区分服务截断、非法 JSON 和逻辑校验失败。固定模型版本和参数做对照，避免同时调整温度、提示、模型和检索规则。

## 4. 建议执行顺序

| 优先级 | 建议 | 预期收益 | 主要代价与边界 |
| --- | --- | --- | --- |
| 第一优先 | 修正请求携带上轮独立复核 issues，并据原文核实 | 让修正明确处理已经发现的问题 | 需要新提示版本和回归，不增加正常调用阶段 |
| 第一优先 | 精简 issues 与 ok 的重复输出，程序推导状态 | 消除一类已经阻断任务的矛盾 | 需要协议版本调整，不代表解决语义漏检 |
| 第一优先 | 固定前五评估召回阈值 | 直接处理已有两组漏召回 | 候选变多，需评估负例与请求量 |
| 第二优先 | 核实结构化输出支持并补齐响应诊断 | 降低格式失败及排查成本 | Kimi 的当前 Schema 支持尚未实测 |
| 后续再评估 | 颗粒度、描述一致性与裁决成本 | 改善组织与效率 | 不作为此次阻断问题的前置条件 |
| 当前暂缓 | 更多模型投票、更多修正轮次、微调、检索组件扩展 | 本项目尚无对应收益证据 | 增加维护、成本与归因难度 |

## 5. 优化边界与停止标准

建议只再做一轮上述最小调整的验证，内部按单一变更逐步对照，最终再跑合并方案；不要一次改完后把收益归给某一项。Kimi 可作为候选实验模型继续验证，尚未授权替换正式模型绑定。

继续投入的判断标准应是：

1. 已知出差失败样本能够完成原流程，原句覆盖、引用与结构校验全部通过，最多两轮的边界保持明确。
2. 已知主体、次数、指代和确定性反例逐项消除，未见样本没有引入同类明显错误；不能只看平均文本分数。
3. 确认关系正例的召回覆盖、关系状态、类型和方向分别评估，已有“提及/引发”差异先在开发参照中统一，避免不同合理口径被计为模型错误。
4. 使用确认负例和超过五个候选的情形评估误判、截断与请求量；不能用四个正例全覆盖宣布总体通过。
5. 记录正常路径与失败路径的请求、Token、耗时，比较新旧代价；不通过无限重试换取完成。

满足约定验收后冻结版本，结束当前优化。若仍反复因同类审核协议或自由改写失败，停止堆叠提示和轮次，另行讨论更简单的来源片段保留方案及其对现有要点设计的影响。该后备方案属于设计变更，不在本轮直接实施。

上述标准是建议阶段提出的验收要求，不是已通过的指标。后续授权执行及实测结果另见实施记录。
