# 第一层 Qwen 与 Kimi 模型对照记录

日期：2026-10-15。用户要求将复测脚本的语言模型改为 kimi-k3，核对既有问题是否受模型影响。

## 1. 结论

语言模型对结果有直接影响：在相同关系输入下，Qwen 的 A/B 四次响应均因缺 reason 被拒绝，Kimi 的 A/B/C 三次响应均一次通过结构校验；四组确认正例最终均识别为 RELATED。但 Kimi 的 B 仍漏掉一组正例，由 C 恢复，不能将双判视为稳定正确。

更换语言模型没有消除全部问题。Kimi 的出差事件也因输出结构错误失败；固定要点的向量召回仍只覆盖四个确认正例中的两个。当前证据支持“语言模型表现是部分问题的原因”，不支持“全部问题由 Qwen 造成”或“Kimi 已全面通过质量验收”。

## 2. 对照条件

| 项目 | 控制方式 |
| --- | --- |
| 原文 | 与 Qwen 组相同的四个事件快照 |
| 固定关系输入 | 复用前次实现验收最终要点，与 Qwen 复测组完全相同 |
| 关系向量 | 直接复制 Qwen 复测组向量缓存，未重新编码 |
| 提示 | 要点冻结基线不变；A/B 均 v4；C 既定 adjudicate v3 |
| 思考模式 | 两组均显式 enable_thinking=true |
| 请求格式 | 沿用 json_object，未新增 Schema、温度或显式输出上限 |
| 流程 | 使用同一复测脚本；关系六对全部送判，正常召回覆盖另计 |
| 唯一指定变化 | 语言模型从 qwen3.7-flash-2026-07-15 改为 kimi-k3 |

已逐项比较 A/B 的 system 与 payload、四事件生成阶段的 system 与 payload，六项均完全相同。重试反馈及审核候选由各模型输出决定，后续请求自然分叉，不能宣称每一阶段输入都相同。

当前管理端未登记 Kimi。本次仅在实验请求中覆盖 model，不修改模型目录或用途绑定。[百炼 Kimi 文档](https://help.aliyun.com/zh/model-studio/kimi-api)将 kimi-k3 列为始终思考的模型；最小探测实测 HTTP 200、返回模型 kimi-k3、finish_reason=stop，并返回 JSON 和思考内容。

结果位于 `knowledge-graph/implementation-verification-20261014/kimi-k3-recheck-20261015/`。comparison-manifest.json 保存源文件、向量、提示与脚本指纹，execution-summary.json 保存请求统计和结果边界。此次向量缓存以及固定关系输入保留了原有要点中的已知语义问题，不能当作人工修正后的理想输入。

## 3. 固定输入的关系结果

Kimi A/B 均判断六对，C 处理四组分歧。三次请求全部一次通过结构校验。其余两对均输出 NO_RELATION，本报告不将它们自动计为已确认负例。

| 确认正例 | A | B | C/最终 | 正常召回是否覆盖 |
| --- | --- | --- | --- | --- |
| 聚餐督促阅读 ↔ 南通出差安排 | RELATED | NO_RELATION | RELATED | 是，同日完整比较 |
| 南通出差安排 ↔ 初到项目现场 | RELATED | RELATED | RELATED | 是 |
| 南通出差安排 ↔ 出差工作推进 | RELATED | RELATED | RELATED | 否，余弦 0.41350835 |
| 初到项目现场 ↔ 出差工作推进 | RELATED | RELATED | RELATED | 否，余弦 0.45247749 |

强制送判时，四组确认正例的关联状态均被识别。按正常召回规则，仅前两组会进入判定，仍只能形成其中两组的关系；另外两组在关系模型调用前就被过滤。因此，换语言模型可以改善判定，不能改变固定向量和固定阈值造成的漏召回。

首组最终输出为“出差安排 → 督促阅读”的引发关系，历史实验结果为“聚餐阅读 → 出差安排”的提及关系。本次只确认 RELATED 状态与已有正例标签相符，类型差异尚未取得用户确认，不能称为四组关系的类型、方向、证据及描述全部验收通过。

模型 B 仍把首组判成 NO_RELATION，没有识别“下周我不在家”与同篇出差安排的联系；C 通过上下文消歧恢复。C 的 reason 还对同日记录使用“较早/较晚”的措辞，不能据此推断实际发生先后。这表明 Kimi 仍需要逐项核对事实与理由。

## 4. 要点生成与审核

| 事件 | Qwen 最后候选要点数 | Kimi 最后候选要点数 | Kimi 流程结果 |

| 周日聚餐并督促小廖看书 | 4 | 9 | 合并审核判无问题，按原流程未执行独立复核 |
| 出差南通的行程安排与审批 | 4 | 4 | 第二轮修正失败，未通过 |
| 初到南通项目现场 | 2 | 3 | 合并审核判无问题，未执行独立复核 |
| 南通出差工作推进 | 1 | 1 | 合并审核判无问题，未执行独立复核 |

Kimi 的聚餐候选保留了“我们结婚”“他们家有个小女儿”“我提起阅读往事”“下周我不在家”，没有复现此前明确的结婚主体翻转、小廖家归属补全、说话主体改变或“独自在家”限定。出差候选也没有写成“多次退回”。这只说明这些具体反例本轮未复现，不代表零语义错误。

Kimi 出差候选仍新增“江边的景区”，并写“实际应该8点到”。独立复核识别了地点事实及确定性问题，要求修正，因而没有把这一事件作为最终通过结果。聚餐要点从四条增到九条，颗粒度不同，不能只比较错误条数就推断整体生成能力高低。

出差事件共发生六次请求：

1. 生成一次。
2. 第一轮合并审核两次：首次 issues 包含问题但 ok 标为 true，校验拒绝；重试通过。
3. 独立复核一次，发现仍有语义问题。
4. 第二轮合并审核两次：首次返回不合法 JSON；重试再次出现 issues 与 ok 矛盾，达到上限后停止。

第二轮最后响应对 detail 列出了问题，却同时返回 detail_ok=true。程序拒绝符合原校验规则；本次没有放宽要求，也没有追加无限重试。原调用记录未保存 finish_reason，无法从现有记录确认首次不合法 JSON 是否由服务截断造成，不将其根因写成已查明。

Kimi 另有一次不含日记的最小探测，不含在十五次样本请求内。向量请求为零，直接复用缓存。因出差要点未通过，没有继续执行四事件新候选关系组，避免用失败候选宣称完整闭环通过。此次不执行后续日记分析六阶段，不写入正式图谱，不修改管理端模型绑定。

本次只有每模型一组完整实验，不能用这些小样本给出整体准确率或稳定性排名。当前可以据此分开处理：语言输出质量用同输入对照验证，结构错误继续严格拒绝，召回阈值用确认关系集单独评估；不能仅替换语言模型就宣布方案全部验收通过。

## 6. 按历史口径对要点文本评分

用户要求沿用之前的打分逻辑。采用[历史 Kimi 对照报告](../../../knowledge-graph/validation-2026-08-26/combined-review-repair-kimi-20261012/对照验证报告.md)的四维百分制：忠实 40、完整 25、主题 15、表达 20。历史规则是助手对照原文主观评审，没有固定逐项扣分表。本节同样为非盲评，不是准确率；分数针对文本，不替代结构及流程验收。

评价对象为每事件最后合法保存的 candidate.json，summary 与 detail 分别核对。两模型的出差事件均未走完审核流程，下面仍对其最后候选评分，并保留“未通过”的事实；不采用结构失败响应中的候选，也不因流程失败直接将文本记为零分。模型均分按四事件等权计算，避免九要点事件获得更多权重。

评分依据：

- 聚餐 Qwen：主要事实与活动覆盖完整，四个主题组织清楚；但食物、身体反应、提起往事的主体及“独自在家”等新增或改变的事实拉低忠实度。“一些那些带有贬义色彩的言情剧”等处理性措辞也不自然。
- 聚餐 Kimi：关键主体、指代、阅读要求及原文观点保留较好；食物被补充为“点心”，有轻微具体化。九个要点把同一次活动及其感受、阅读要求及其目的拆散，主题组织扣分；“油滋麻花”“具体叫什么我也不记得”等仍偏口语，标题和详情重复较多，表达不因篇幅增加而加分。
- 出差 Qwen：主要信息完整，但“多次退回”、新增“名为江的景区”“抵达住处”及重复建立推迟出发的因果构成明确偏差；前两点均围绕审批延迟，主题略重复。较流畅的表达不能补偿事实错误。
- 出差 Kimi：审批过程及一次退回较忠实，主题明确；仍补充“江边”，并用“实际应该8点到”混合实际与估计，“不怎么管”也弱化了原文程度。独立复核已发现相关问题，但修正流程最终失败。文本 91 分不代表流程通过。
- 初到现场 Qwen：信息完整，但“应该算中心”被概括为“算是中心”、“挺舒服”变为“非常舒服”，并增加“性格”解释；现场环境和生活节奏合并在一个较长要点，层次不如 Kimi 清楚，“他们性格好沟通”表达生硬。
- 初到现场 Kimi：环境、生活节奏、工作协助三主题清楚，保留“应该”等限定；summary 的“顺利”增加了原文未明确的评价，忠实扣 1 分，表达仍有少量标题与详情重复。
- 工作推进 Qwen：工作与个人开发的信息完整、表达清楚；“为事项整理做前期工作”改成“对事项进行前期整理”，工作阶段表达不如原文精确。Kimi 保留“为事项整理做前期工作”，本次未发现明确事实偏差，因此忠实 40；两者仍有少量标题与正文重复，表达均未给满分。

Kimi 均分高 5.75 分，主要来自忠实度改善；聚餐组织颗粒度反而较差。两者完整性满分表示此次核心信息均得到覆盖，不表示新增信息正确。本次四事件与历史“怀念过去的日子”不是同一评分对象，不能把均分差直接解释为相对历史模型提升了多少。

这一百分制沿用的是要点文本标准。关系识别仍按确认标签核对关联状态、类型、方向、证据及召回覆盖，不将本节 93.5 分表述为整套图谱的质量分数。原始分项记录保存在本地 manual-quality-scores.json。
