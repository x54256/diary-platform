# 第一层建图任务与接口详细设计

更新日期：2026-10-14。状态：实现评审草案，接口尚未实现。

依据：[流程接入方案](第一层事件建图与分析流程接入实现方案.md)、[完整数据库设计](第一层事件图谱数据库完整设计.md)。本文件给出任务恢复和接口的具体实现契约。

## 1. 单一执行入口与任务身份

新建 `backend/services/graph_tasks.py` 管理全部建图写入任务。日记分析及历史入图都创建graph_tasks，worker根据entry_type运行单日完整分析或日期批量建图。现有后台 `_run_analyze` 不再额外调度同一任务。

ANALYSIS入口创建organize_tasks兼容记录，用同一UUID作为graph_tasks.id与organize_tasks.id，供现有任务轮询和analysis_runs.task_id引用。graph_tasks是唯一调度依据；organize_tasks只投影运行状态，不另行恢复或超时重启。创建、失败、恢复和完成状态均在同一事务同步两张表。

HISTORY入口只创建graph_tasks，不创建organize_tasks，不生成新的分析轮次。日期范围起止均包含；创建时按日期、日记ID排序保存graph_runs清单，不加载多日正文。已有有效图谱的日期记SKIPPED/ALREADY_PUBLISHED；未分析日记记SKIPPED/NOT_ANALYZED；没有日记的日期不建立运行记录。

## 2. 状态机

| 对象 | 合法转换 | 触发条件 |
| --- | --- | --- |
| 任务 | QUEUED→RUNNING | worker领取并分配run_token |
| 任务 | RUNNING→SUCCEEDED | 所有运行已发布或合法跳过 |
| 任务 | RUNNING→FAILED | 当前日期任一必要阶段失败 |
| 任务 | FAILED→QUEUED | 用户重试且来源、配置、历史依赖及新运行检查通过 |
| 任务 | FAILED→SUPERSEDED | 用户创建同日新的分析任务，旧任务不可恢复 |
| 运行 | QUEUED→RUNNING | 当前日期被处理，准备来源 |
| 运行 | QUEUED→SKIPPED | 已有有效图谱或历史日记未分析 |
| 运行 | RUNNING→FAILED→RUNNING | 失败并恢复同一运行 |
| 运行 | RUNNING→PUBLISHED | 正式发布事务成功 |
| 运行 | PUBLISHED→OBSOLETE | 接受该日记重新分析 |

任务整体成功不要求每个日期重新生成图谱，跳过原因必须单独统计。任务失败不回滚已发布较早日期，也不使较早日期运行变为FAILED。

没有自动业务重跑机制。worker因租约到期而恢复同一任务属于执行恢复，继续检查旧checkpoint与调用记录；不能将网络超时直接视为日记分析结果完成。

## 3. 来源冻结与阶段数据

ANALYSIS创建事务内校验整理来源、冻结完整单日来源及配置，再标记旧图谱过时。HISTORY在处理该日时冻结来源和当前有效分析轮次。先校验配置可用性和思考支持，再使旧结果过时，防止无效配置导致无效重建。

source_snapshot结构包含：日记ID和日期、整理记录ID、原标题与原文、按固定顺序的所有来源事件（ID、标题、body、feeling、reflection、有效重要性）、introduction、trivia、plans、用户人物资料引用、任务开始时的Asia/Shanghai分析日期。反馈分支额外冻结previous_run_id、上轮完整结果与有效反馈。

图谱只读取准入事件的标题和body；后续分析读取全部已冻结来源内容。人物资料用于后续分析上下文，本期不生成图谱人物节点。

source_sha256使用固定字段顺序的规范JSON计算，UTF-8、去除格式空白、保留数组顺序。发布和失败恢复时重新计算来源摘要；冻结的分析日期不随重试日期变化。该摘要用于一致性检查，不建立新的内容修订号业务。

| current_step | checkpoint保存内容 | 成功条件与恢复单位 |
| --- | --- | --- |
| PREPARE_SOURCE | 来源、eligible_event_ids、有序event_id_map | 来源结构合法；单日 |
| EXTRACT_POINTS | points_by_event、审核报告、round及event_cursor | 每个事件最后候选合法且核验通过；单事件单阶段 |
| EMBED_POINTS | 向量、模型标识、detail_sha256、point_cursor | 全部准入要点向量合法；单要点 |
| RECALL_PAIRS | 每事件候选、命中ID分数、recall_cursor、pairs | 历史准备完整且召回成功；单当前事件 |
| JUDGE_A | 批次、A有效逐对结果、待补判项 | 所有pair_id有一个有效结果；逐对 |
| JUDGE_B | 同一清单、独立B结果、待补判项 | 所有pair_id独立得到有效结果；逐对 |
| ADJUDICATE | 分歧清单、C有效结果、待补判项 | 全部分歧取得有效C结果；逐对 |
| CHECK_GRAPH | final_pair_results、正式写入候选、核验清单 | 无执行缺失；单日 |
| ANALYZE_METADATA | 情绪、标题、摘要、地点、标签候选 | ANALYSIS普通分支适用；单节点 |
| ANALYZE_CORE | 普通或反馈核心分析产物 | 构造完整本轮分析结果；单节点 |
| ANALYZE_COGNITION | 普通或反馈认知分析产物 | 构造完整本轮分析结果；单节点 |
| PLAN_ACTIONS | 独立行动项候选、稳定来源键 | 输入来自计划和本轮建议；单节点 |
| PUBLISH | 正式run_id、analysis_run_id、published标记 | 数据库短事务提交；单日 |

普通分支执行元数据、核心、认知、行动项；反馈分支的具体候选设计见[接入与清理设计](第一层分析接入与旧方案清理详细设计.md)。HISTORY在CHECK_GRAPH后直接进入PUBLISH。

checkpoint只由具有有效run_token的worker更新。每次模型输出保存到graph_model_calls后，合并已合法解析结果、推进游标与checkpoint在同一短事务完成。语义失败候选留存但不推进事件游标。

候选要点UUID在生成终稿后一次分配并保存，后续向量及关系证据用同一ID；恢复不重新分配。pair_id由无序双方事件UUID的稳定键派生，日期范围内不因拆批或重试变化。向量校验长度1024、数值有限及模长非零，拒绝非法余弦输入。

## 4. 并发、服务请求与恢复

领取任务采用行锁和条件更新；租约默认180秒，独立心跳默认30秒，均可配置。长模型请求期间继续心跳，不把模型正常思考当作15分钟固定超时。所有状态更新及发布携带run_token，失去执行权的worker立即停止正式写入。

同用户跨环境活动任务由数据库部分唯一索引限制；遇到其他活动任务返回409 USER_TASK_ACTIVE。同一个日记的重复分析请求遇到其原任务活动时返回原任务，不再创建或重复标记过时。

批量任务失败后重试，只恢复该任务首个失败运行。若失败后对应日期已创建新运行或已重新发布，旧任务恢复返回409 TASK_SUPERSEDED；不能覆盖后来结果。来源已变返回409 SOURCE_CHANGED。认证失效、冻结渠道不可用等错误记录后停止，不自动切换模型。

STARTED调用记录在重启后无响应时改为UNKNOWN，该单位重新请求。SUCCEEDED且程序校验通过的记录用于回放补齐checkpoint，不重复调用。调用已经计费但响应未落库的情况不能承诺零重复服务请求；保证正式发布幂等。

要点结构失败每阶段最多额外一次请求；要点审核修正最多两轮。关系每角色每批首次加一次补判；响应截断按预算拆分未完成项后执行唯一补判轮次，不因拆批无限重置重试次数。再次失败需用户恢复任务，记录新的恢复轮次，不覆盖原请求。

批次预算：配置明确提供context_limit、max_output_tokens、输入估算方法、安全预留与逐对输出预留。总输入及输出预留超过context_limit则拆批；单对完整内容仍放不下，返回INPUT_TOO_LARGE，不截断要点。向量单detail超渠道限制返回EMBEDDING_INPUT_TOO_LARGE，本期不静默切分改变检索单位。具体模型容量从已选渠道能力确认后冻结，不能在文档硬编码未核验的模型容量。

模型、关系、向量配置分别采用新graph配置；要点及关系A/B/C使用qwen3.7-flash-2026-07-15（2026-10-15用户决定），qwen3.7-flash为备用，图谱向量使用独立graph_embedding用途的qwen3.7-text-embedding-flash/1024，日记搜索原embedding用途配置保留。要点temperature不额外发送；其他请求参数按冻结基线加载。

成功后保留source_snapshot、调用记录和最终逐对结果用于审计；可以清理checkpoint内临时重复事件池和批次缓存。清理只发生在PUBLISHED确认后，不删除审计记录、不回滚已成功状态。首版不设置自动删除期限。

## 5. 接口路径与返回结构

以下路径是路由相对路径，应用统一挂载前缀为 `/diary`，Swagger完整路径为 `/diary/api/graph/...`。

路径以下均相对于项目现有API挂载前缀。使用现有用户鉴权，不接受请求指定其他user_id。

### 5.1 POST /diaries/{diary_id}/analyze

普通调用创建新分析运行；已分析日记调用即重新分析。活动的同日分析任务返回原任务。失败恢复仅通过retry接口，不因再次调用analyze自动接续旧失败任务。前端“重试”和“重新分析”分别调用对应入口。

接受后返回202：`{task_id, diary_id, entry_type:"ANALYSIS", status:"QUEUED", analysis_mode, current_step:null}`。ANALYSIS模式和反馈上下文在创建时确定并冻结。兼容旧status接口时将QUEUED/RUNNING投影为running、SUCCEEDED为completed、FAILED为failed；响应增加task_id及graph_run_id，不改变原task_type="analyze"语义。

### 5.2 POST /graph/history-build

请求：`{"date_from":"2026-08-01","date_to":"2026-08-31"}`。两字段必填，ISO日期，date_from不得大于date_to。首版不提供force、人物处理或后台自动回溯参数。

返回202：`{task_id, entry_type:"HISTORY", status:"QUEUED", date_from, date_to, total_days, published_days:0, skipped_days:0, failed_days:0}`。total_days为匹配当前用户未删除日记的运行数，不是日历天数；空范围返回SUCCEEDED的空任务。批量未分析日记跳过并显式计数。

### 独立建图入口 POST /graph/build（2026-10-19新增）

请求沿用日期范围结构。仅为当前用户范围内已整理或已分析的日记创建任务，未整理日记不纳入清单。

复用HISTORY状态机，在冻结配置中记录`graph_only=true`。允许来源没有已有分析轮次；生成要点、向量及事件关系后正式发布，不调用后续分析，不创建分析轮次，保留日记状态与原始内容。已发布日记仍按原规则跳过；失败恢复继续使用现有retry接口及冻结配置。原`/graph/history-build`的准入规则保持不变。

### 5.3 GET /graph/tasks/{task_id}

返回200：`{task_id, entry_type, status, date_from, date_to, current_run_id, current_diary_id, current_date, current_step, total_days, published_days, skipped_days, failed_days, pending_days, error, can_retry, runs}`。

runs每项：`{run_id, diary_id, diary_date, status, current_step, skip_reason, error}`。日计数来源于运行状态：PUBLISHED与同任务后来OBSOLETE均计为已执行发布日；SKIPPED为跳过；FAILED为失败；QUEUED/RUNNING为待完成。任务状态不根据最后一次HTTP调用推测。

error结构：`{code,message,stage,event_id,pair_id,call_id}`；不适用字段为null，不返回正文、认证信息或模型完整请求。

### 5.4 POST /graph/tasks/{task_id}/retry

无请求体。只允许FAILED任务，返回202同任务ID，retry_count递增。成功、过时调度、运行中的任务返回409；不存在或其他用户任务返回404。重试事务校验来源和后继运行，重新争取活动任务唯一约束，不重新冻结模型或重置来源。

### 5.5 图谱查询

- `GET /graph/diaries/{diary_id}`：返回当前PUBLISHED运行；无有效结果返回200 `{diary_id,run:null,events:[],relations:[]}`。
- `GET /graph/runs/{run_id}`：读取所属用户该次运行，允许查看OBSOLETE；明确返回status及published_at、obsolete_at。
- `GET /graph/events/{event_id}/neighbors`：读取当前用户有效入图事件及其直接关联事件，不包含同篇日记其他事件的旁支关系；事件没有有效图谱时返回404。

日记图谱查询返回本篇入图事件及有效关系两端的跨日事件节点。正式events每项包含event_id、run_id、diary_id、原标题、日记日期、可空发生日期、points；point包含id、no、summary、detail，不默认返回大向量。relations包含类型、方向、certainty、description、final_source及双方point_id/no。过程调用记录通过内部审计查询读取，不在普通结果接口输出。

## 6. 错误及HTTP映射

| 错误 | 返回或任务状态 |
| --- | --- |
| 日期格式、日期范围非法 | 422，未创建任务 |
| 日记、任务或运行不存在/非本人 | 404 |
| USER_TASK_ACTIVE、TASK_SUPERSEDED、SOURCE_CHANGED、INVALID_TASK_STATE | 409 |
| 日记尚未整理、缺少整理结果 | 409 SOURCE_NOT_READY |
| MODEL_NOT_CONFIGURED、THINKING_UNSUPPORTED | 创建前409；执行中任务FAILED |
| MODEL_CALL_FAILED、MODEL_OUTPUT_INVALID、POINT_REVIEW_FAILED | 任务FAILED，记录stage及调用 |
| MODEL_QUOTA_EXHAUSTED | 免费额度耗尽；任务FAILED且不追加结构重试或补判；恢复额度后重试 |
| EMBEDDING_NOT_READY、EMBEDDING_INPUT_TOO_LARGE、RECALL_FAILED | 任务FAILED，不返回正常空候选 |
| INPUT_TOO_LARGE、PAIR_RESULTS_INCOMPLETE | 任务FAILED，保留有效逐对结果 |
| PUBLISH_FAILED、DEPENDENCY_OBSOLETE | 任务FAILED，正式事务回滚 |
