# 第一层事件要点数据库设计

更新日期：2026-10-14。状态：实现评审草案，尚未执行迁移。

本文保留事件要点存储的业务约定；完整表字段、外键、任务审计、关系证据及迁移顺序统一见[第一层事件图谱数据库完整设计](第一层事件图谱数据库完整设计.md)。

## 1. 来源与准入

复用diary_events.id作为图谱事件标识，原标题、正文和来源日记由日记系统保存。新日记已整理即可进入分析前置建图；历史范围接口读取已分析日记。有效重要性优先取用户设置，否则取AI设置，仅中、高事件进入图谱。

模型核验通过后自动进入向量和关系阶段。新分析全部结束后统一发布；历史入口完成当天建图后发布。人工原文审阅用于开发验证和验收。

## 2. 要点身份与字段

| 字段 | 类型 | 可空 | 职责 |
| --- | --- | --- | --- |
| id | UUID | 否 | 当前运行要点的稳定证据身份 |
| run_id | UUID | 否 | 所属图谱运行 |
| event_id | UUID | 否 | 来源事件 |
| user_id | UUID | 否 | 用户隔离及证据复合外键 |
| no | INTEGER | 否 | 该运行该事件内连续序号1..N |
| summary | TEXT | 否 | 要点标题 |
| detail | TEXT | 否 | 详细内容 |
| embedding | VECTOR(1024) | 否 | 完整detail的向量 |
| embedding_model | TEXT | 否 | 模型及版本稳定标识 |
| created_at | TIMESTAMPTZ | 否 | 正式写入时间 |

唯一约束为 `(run_id,event_id,no)`。重新分析产生新run_id和新point_id，保留旧运行及证据；同一运行重复提交不产生第二套要点。正式表外键引用graph_run_events，summary、detail和模型标识去除首尾空白后必须非空。

序号连续性由程序检查，数据库唯一约束防重复。未完成核验、向量或正式发布的候选存于运行checkpoint，正式要点表不保存部分准备结果，因此正式embedding和embedding_model均必填。

## 3. 向量与检索

- 向量模型为qwen3.7-text-embedding，1024维，精确余弦检索；模型版本随任务冻结。
- 只使用完整detail生成向量，不拼接summary或原标题。
- 历史要点仅来自当前用户、较早日记日期且运行PUBLISHED的事件，事件is_in_graph=true。
- 当前事件全部要点与历史要点命中按历史事件聚合，分数取最高余弦相似度；阈值0.5，每当前事件最多5个历史候选，按分数降序、事件ID升序排序。
- 不在事件聚合前按要点数量截断，不建立首版近似向量索引。
- 向量缺失、版本不符、维度错误或检索失败时停止并记录错误，不能当作无关系。
- detail超模型限制时显式失败，不静默截断或改变检索单位。

## 4. 正式保存与证据

全部模型处理在事务之外完成。发布事务锁定用户、任务和所属日记，检查执行权、来源与历史运行仍有效，再一次性写入运行事件、完整要点、向量、关系及证据。

要点ID在候选终稿形成时预分配并保存于checkpoint，恢复沿用同一ID。关系证据引用point_id，经复合外键定位到正确的运行、来源事件与用户。no仅为本轮展示序号，不跨运行复用证据身份。

重新分析接受时旧运行改为OBSOLETE，对应事件is_in_graph=false；旧要点保留。新发布事务设置新运行PUBLISHED与入图标志。图谱查询及召回排除旧运行，历史追溯按run_id访问。

## 5. 索引与约束

主键id；唯一 `(run_id,event_id,no)` 同时支持按运行和事件有序读取；唯一 `(id,run_id,event_id,user_id)` 支持关系证据外键。no大于0、全部必填字段及文本非空白约束在迁移中定义，字段添加中文注释。

普通外键采用RESTRICT。源日记、事件删除需先明确图谱引用处理，不能通过旧知识库清理级联删除源数据。本期清理仅删除旧知识库专属表和配置。
