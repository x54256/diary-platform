# 本次建图失败样本与审核协议改进调研

日期：2026-10-19。范围：2026-08-17、08-18 两篇日记的真实调用审计及当前代码。本文是方案评估，未修改运行代码、重新调用模型或更新正式图谱。

## 1. 关系对象错位：事实与原因边界

争议对为“初到南通项目现场”与“出差南通的行程安排与审批”，pair_id 为 `pair-638b3e9e2dfa87966278bca9`。两次请求端点正确；两次输出均为 NO_RELATION，理由却讨论了“小豪聊天”。因此已确认的是理由对象错位，并未确认正确事件对的最终关系结论。

当前 `payload_for` 把事件合并为一个 `events` 池，用另一个 `pairs` 数组引用事件 UUID。A、B 使用相同模型、相同提示和同类批量输入，分别请求。批内确实存在被错用的聊天事件。这构成串对风险；没有单对与批量对照实验，不能把风险直接写成已证实的模型出错原因。

建议先比较：原批量输入、每对内嵌双方文本的批量输入、单对输入。固定样本与模型配置，重复评估端点错位率、关系正确性、耗时和 Token。最简单的输入改进是每对就近放置 A/B 标题和文本，由程序绑定 pair_id 与端点，减少模型跨表查 UUID。单对请求的额外延迟需实测，不能直接承诺提速。

无关系结论同样需要来源依据。程序可验证引用存在且属于当前端点；引用是否足以支持结论仍属于语义判断。仅返回正确 UUID 不能解决理由谈错对象。

## 2. 文献调研：修正模型也会制造错误

- [Large Language Models Cannot Self-Correct Reasoning Yet（ICLR 2024）](https://proceedings.iclr.cc/paper_files/paper/2024/hash/8b4add8b0aa8749d80a34ca5d941c355-Abstract-Conference.html)：在论文测试的推理任务中，缺少外部反馈的自我修正存在失败及表现退化。该结果不能直接推广为当前模型在日记任务上的定量结论；它支持避免把多轮自审视为正确性保证。
- [RARR（ACL 2023）](https://aclanthology.org/2023.acl-long.910/)：寻找证据后修正不受支持内容，并尽量保留原输出。可借鉴证据约束与最小修改；日记的证据来自冻结原文，不能用网上信息替换私人经历。
- [Evidence-based Factual Error Correction（ACL 2021）](https://aclanthology.org/2021.acl-long.256/)：以证据支持为目标编辑事实主张。可借鉴将每项修正绑定来源，而非仅依赖另一份模型意见。
- [Lost in the Middle（TACL 2024）](https://aclanthology.org/2024.tacl-1.9/)：所测任务中，信息位置会影响长上下文利用。本文未据此断言当前失败就是注意力偏移；本项目需要对照实验验证输入组织与输出负担的影响。

据此提出本项目方案：审核只定位问题并给出原文依据；修正返回字段级替换项；程序应用替换并保留其他字段；复核同时读原文、旧值、新值，检查原问题与新增失真；不通过则保留待处理状态，不发布有争议修正版。涉及代词、观点或主体不明时保留原表述和歧义，不强行补齐人物归属。

证据字符串真实不等于证据语义支持结论。程序约束能缩小错误范围，无法保证所有改写正确。

## 3. 当前协议中可移交程序的工作

| 当前要求 | 问题证据 | 建议分工 |
| --- | --- | --- |
| 模型回传原标题、连续序号 | 代码要求与输入相同或连续 | 标题由程序保留，序号由数组位置计算；稳定 ID 由程序分配 |
| 输入原句用 id，输出改用 source_unit_id | C14、C45 重复字段错误 | 输入输出使用同一命名，不要求模型转换 |
| 每轮抄回所有候选 | C12 缺候选；C13 无问题却改候选 | 无问题返回空问题清单；有问题返回定位明确的替换项，程序合并 |
| 每条原句写 comparison，每个要点回一项 checks | C47、C49 只返回部分编号 | 程序分配有限审核块并跟踪完成状态；模型进行块内语义比较并仅返回问题，不重复填写所有通过项 |
| 模型声明状态 | issues-v2 已由程序计算 | 保持由问题列表和任务完成状态计算，通过字段不再重复输出 |
| 模型复制候选引用 | 现有校验要求连续原文，仍有复杂负担 | 返回字段定位与编辑范围；程序校验旧值、范围及变更字段。证据原句由程序按 ID 提取 |
| 结构失败时完整重发 | 8 次失败本身累计约 12 分 6 秒 | 保留通过单元，重做失败块；冲突补丁和过期候选拒绝应用 |

分块审核必须同时包含足够上下文，覆盖检查需兼顾“原文是否遗漏”和“候选是否增添事实”两个方向。块调用完成只证明模型返回了结果，不证明它确实逐句理解；原协议的编号覆盖也没有提供这种证明。分块大小与输出精简的效果须通过回放比较，不能以减少报告长度替代正确性验收。

## 4. 推荐顺序与验收

1. 固定本次样本作为回归集：串对、主体颠倒、错误审核意见、字段错误、覆盖缺失及无问题改写。
2. 统一编号命名，移除标题、序号和完整未修改候选的重复输出，采用程序应用字段替换。
3. 比较内嵌端点与事件池输入；对非相关结果增加来源约束与语义验收。
4. 再评估分块、推理预算与并发。用事实忠实性、误改率、遗漏率、协议通过率、耗时、Token 共同验收。

以上需要评审后再实施。不能只以 JSON 合法、双判一致或任务发布成功作为内容正确的依据。
