# 第一层后续设计与实现差异

核对基线：2026-10-29 现行代码与原有方案。本文保留仍有效的未实现目标、尚未决定的协议取舍和已部分落地的方案；文档整理不执行协议切换、模型替换或历史数据重写。

## 1. 人物与关系的模型落地

[实体与关系模型](实体与关系模型.md)已经定义人物节点、人物关系、人物参与事件与事件涉及人物的语义，但图谱正式模型、识别流程、复用身份及查询尚未实现这些能力。

后续应先明确：

- 人物唯一身份与同名 / 别名消歧，何时复用已有节点，如何保留来源使用的称呼。
- 人物关系属于来源陈述、他人说法还是经用户更正的事实，随时间变化如何记录。
- “参与事件”要求有行动 / 表达 / 决定且构成核心过程或影响结果；只作背景、被回忆、被讨论或未产生作用的联系对象使用“涉及人物”。
- 人物节点和三类人物相关关系的证据身份、存储、冻结与历史修订，不能只在提示中要求模型输出。

个人资料提供的称呼、性别和关系可帮助理解，但不是上述图谱节点和边已实现的证明。

## 2. 模型协议简化：仍未实现的核心提案

10 月 19 日提案针对已出现的批量关系串对、主体颠倒、审核建议引入新错误及冗长重复输出。当前 `graph_points` 仍用整候选返回与完整审核，`graph_relations` 仍用事件池 / pair ID 的批量 A/B/C，因此不能将提案标为已实施。

### 2.1 单对局部身份的关系协议

拟议设计：

- 每次 A/B 只读取当前两个事件的完整要点，局部名称 `A/B` 和各自局部序号替代模型输入中的业务 UUID、跨池查找及第三事件。
- 模型输出 status、关系类型、方向 `A_TO_B/B_TO_A`、certainty、双方局部要点的唯一连续引用和 reason；程序映射回真实事件与稳定要点身份。
- 判断阶段没有第三事件，A/B 各自独立；分歧由 C 读取同一对和两份局部候选裁决。
- 比较结构化含义、规范证据集合，不因描述文字不同就必然裁决；理由不逐字匹配。
- 引用必须唯一连续，不能任取一个重复片段；映射后发布前再次核验，不能只在转换时检查一次。

这个原方案还建议无关系 / 未决返回双侧引用，当前 Skill 对负例不强制短引。该取舍需要独立验证，不能未经评估将负例证据要求推为两条实现的共同规范。

调用代价需要实测：单对输入减少定位负担，但候选多时 A/B 请求数明显增加；原 15 对示例至少 30 次 A/B，不能预先承诺加速。首版拟串行，限并发及其 checkpoint 合并 / 租约另行验证。

### 2.2 局部编辑与全事件复核的要点协议

拟议设计：

1. 生成仅返回 `summary/detail`，程序补原标题和连续序号。
2. 审核只发一份有段落分组的来源及当前候选，模型返回 `edits`、`additions`、`structure_issue`，不复写整个候选。
3. `edits` 定位旧 point_no 与单字段，携来源编号、问题和完整替换值；一个字段不得重复编辑。整组修改先校验，任一非法则全部拒绝。
4. `additions` 用修改前 `after_point_no` 定位，程序按数组顺序插入和重新编号；补充仅用于遗漏主题。
5. 首版不支持删除或重排。重复 / 组织错误无法局部修复时返回结构失败，禁止用空字符串或删正确内容掩盖；当前 retry 不清候选，不能假定恢复即可解决结构问题。
6. 独立复核读取完整来源与新候选，返回建议但不立即自动应用；下一轮修正重新核实意见，允许拒绝错误建议。
7. 来源和候选摘要绑定每次调用；有修改时保存旧候选、操作、差异和新版本，最终通过后才分配正式要点 UUID。

旧方案按原句编号回传完整检查痕迹；拟议方案减少重复字段但不再提供同等逐句回执。两者均不能证明模型真实逐句理解，遗漏检出、误改率与事实边界仍需人工语义参照。

### 2.3 结构化输出、缓存和版本隔离

当前应用请求 `json_object` 并进行本地校验，未启用该提案中的 strict Schema。是否可用必须在实际渠道、模型快照和思考配置下以无私人信息样例验证，不能根据供应商页面概览直接认定支持。

采用新协议时冻结 Schema / 提示 / 解析版本，保留旧解析器和执行分支；缓存键包括协议、局部映射、来源与候选版本、角色及尝试。新候选不可复用旧通过结论，不能让旧任务中途换协议。

结构失败、语义未通过、模型服务失败、执行中断分别处理；有限补答继续保留，不用无限重试代替质量改进。既有已发布结果的修正使用隔离回放及单独历史重评，不直接复用“跳过已发布”的普通入口覆盖。

## 3. 直接承接与召回改造：部分已实现

10 月 27 日方案的目标是使“后续事件”表达直接承接，允许分支与汇合，保留间接延续判断，而非给相似旧节点普遍建直连。

| 原方案内容 | 当前状态 |
|---|---|
| `INDIRECT_FOLLOWUP` 留档且不建边 | Skill 已实现，应用内尚未支持 |
| 替代后续路径搜索、逐边语义检查与最终路径闭包 | Skill 已实现 |
| 冻结历史正式后续边及要点内容，发布前复验范围新增 / 删除 / 变更 | Skill 已实现 |
| 全部初判后才生成最终稿、冗余报告绑定稿件与保存 | Skill 已实现 |
| 以完整语义组竞争选择直接前序，保留多个合理前序 | 尚未实现，当前仍逐对判断后复核路径 |
| 以当前每个要点保留召回覆盖，而非只取事件最大值 | 尚未实现 |
| 明确事项、对象、日期、引用的补召回 | 尚未实现 |
| 候选附近前序 / 后继链条扩展，区分上下文与新增配对 | 尚未实现 |
| 插入较早 / 中间日记后自动列出并重评受影响旧边 | 尚未实现通用流程 |

### 3.1 保留的直接承接准则

- 判断发生在具体事项，正式边仍挂事件；一个事件或要点可以包含多件事。
- 比较当前内容新变化及候选前序状态，区分真正直接接续、通过其他节点表达的间接延续、恢复旧安排和独立分支。
- 前序可以多于一个，不能按最近日期、每节点一个前序或最短路径机械选择。
- 直连有替代路径时仍可能覆盖路径以外的独立安排 / 行动 / 结果，不能自动删。
- 第三事件可以帮助选择前序，但正式关系事实必须由该边双方要点支持；引发和提及不参与后续传递约简。
- 缺失中间记录不证明远端一定是直接前序；没有现成路径的语义间接判断与当前依赖真实路径的过滤协议并不等价，需补设计后才能保存。

### 3.2 保留的分组与召回设计

候选池分开记录语义命中、明确指向和关系上下文。先保持来源覆盖，再评估成本；时间接近可以排序，不能硬截跨月历史。

围绕事项组织候选及必要链条，先看分支末端再给前序背景；这是阅读顺序，不删除所有旧节点。组过大时按事项拆分，竞争前序在选择时仍需合并比较。同天候选也参与，不只优化跨日。

比较“现召回+逐对”“现召回+分组选择”“新召回+分组选择”，分别衡量候选覆盖和选边收益，避免多项改动混成一个指标。

## 4. 其他已核实差异

| 边界 | 当前差异 / 后续要求 |
|---|---|
| 图谱事件范围 | 应用内中高，Skill 全部；两者没有统一的同一范围保证 |
| 要点输入 | 应用内仅正文，Skill 纳入新增感受 / 反思；需核对独立信息覆盖 |
| 人工澄清 | Skill 已有按需机制；应用内没有同等交互，不能把澄清常态化加到自动流程 |
| 向量与当前图可见性 | Skill 历史准入可为 `POINTS_READY`，页面边读取要求双端发布，保存与展示范围不同 |
| 批量审核中的语义串对 | 字段 / 引用合法不证明理由对应正确事件，保留独立对照与隔离输入验证 |
| 旧运行生效时点 | 应用内新建分析即标旧图过时；失败不自动恢复，需明确产品期望及旧证据可见性 |
| 补齐范围 | 缺失事件要点补齐不包含关系补判；不能将数据覆盖补齐等同于图谱修复 |

## 5. 后续落地门槛

先固定脱敏失败夹具和独立人工参照，再做协议映射 / 编辑原子性 / 缓存版本测试；之后验证实际渠道能力及真实模型回放，最后才接入新任务。

必须覆盖主体与次数、错误审核意见、观点归属、关联误建、A/B 互换、同名事件、无关元数据、超预算、来源变化及发布门禁。已有争议失败样本重复运行不能代替未见保留集。

直接承接另覆盖链式推进、分支汇合、恢复旧计划、多事项切换、无关系历史、补记日期和低语义排名的明确引用。确定程序约束全部通过，语义质量按已审定参照评估；正例数量、边数下降或模型自评不作为验收答案。

输入输出及失败证据入口见[验证边界与设计依据](验证边界与设计依据.md)。

## 6. 召回评估保留的开发缺口

[固定比较基准](../验证材料/召回评估-20261026/使用说明.md)承接10月26日评估；以下缺口仍需开发处理，删除历史问题流水不表示已修复。

- **正式要点修订入口**：已有有效要点不能直接覆盖，补齐仅支持缺失事件。需要保存旧版、更新向量、复验来源并明确下游失效范围；用户确认的新事实应形成可复验来源。
- **已确认配对补入**：购奶对应关系经用户确认，但历史排名25，不能靠Top10/20保证召回。新运行应允许有来源、可审计的明确指向补入，不能篡改既有冻结候选。
- **范围与完整性**：待处理日记与可召回历史分别冻结、展示；不能按月份目录隐式排除历史。范围内缺口先处理，范围外缺少正式要点应显式报告，不擅自扩提取。
- **语义与阅读完整性**：候选已召回仍可能漏判，合法引用仍可能描述超出要点。完整阅读双方要点，输出截断后补读；引用校验不代替主体、状态和确定性判断。
- **未决交付**：集中列出自包含问题及日期/事件定位，区分待提问、待回答、用户跳过和技术前置。具体视频或订单的对应关系不能凭同人物、同商品推定。
- **评估与计量**：未标注对保持未知；分开报告召回遗漏与判断漏判。多要点事件挤占Top K需控制变量验证；实际token、缓存、推理费用和墙钟耗时分别计量，未知值不得用工具字符估算。

历史处理已修正的版本指纹拦截、历史关系先发布前置等规则，统一见[关系识别实现](关系识别实现.md)与[存储与任务实现](存储与任务实现.md)，不再重复保留阶段记录。
