## 2. 后续分析阶段的具体输入与输出

冻结来源事件包含ID、原始顺序、标题、正文、感受和反思；低重要性事件仅不进入图谱，其分析输入仍保留。模型输入保留来源字段，不传要点或事件关系替代正文。

| 阶段 | 输入 | 输出及校验 |
| --- | --- | --- |
| 元数据与标签 | 本次冻结structured_diary | 标题、摘要、地点、心情、逐事件标签；事件数量与来源映射一致 |
| 核心分析 | 全部来源events、冻结person_relations | 逐事件分析和日记级分析；分析内容、建议和归属符合声明结构 |
| 认知分析 | 冻结structured_diary、person_relations | 认知校准、问题回答、认知完善；按事件映射及日记范围校验 |
| 行动项规划 | 来源plans、本轮核心分析的可行动建议、冻结日记和分析日期 | 独立行动候选、计划及建议的来源键、推荐日程；不创建日程实例 |

后续模型输入为每个来源事件增加event_id，输出必须原样返回event_id，title保持原标题。程序按ID映射，校验ID集合恰好覆盖本次输入、无重复、无额外事件；排序由冻结event_id_map还原。相同标题的不同事件仍可区分，不用相似标题或数组位置猜测归属。该接口调整必须同时更新六份分析提示及Schema，旧提示指纹仅作为调查记录。

具体输出契约：

- 元数据：`{title,summary,location,mood,event_tags:[{event_id,title,tags:{domain:[],topic:[],person_object:[],psychological:[],knowledge:[]}}]}`。标签值均为字符串数组。
- 核心：`{event_analyses:[{event_id,title,emotion_analyses:[],behavior_decision_analyses:[],self_understanding_analyses:[],action_suggestions:[]}],diary_analysis:{emotion_analyses:[],behavior_decision_analyses:[],self_understanding_analyses:[],action_suggestions:[]}}`。分析项为非空白字符串数组，无内容使用空数组，不省略事件。
- 认知：`{event_analyses:[{event_id,title,cognitive_calibration_analyses:[],question_answers:[{question,answer}],cognitive_enhancements:[]}],diary_analysis:{cognitive_calibration_analyses:[],cognitive_enhancements:[]}}`。字符串及问答字段分别检查，空项不写正式结果。
- 反馈：`{rewrites:[{scope,event_id,analysis_type,items}]}`。EVENT必须为本次来源event_id，DIARY的event_id为null；按冻结反馈确定允许重写的块，重复块或未知ID失败。QUESTION_ANSWER的items为question/answer对象数组，其余为字符串数组。合并后再次检查完整核心、认知输出契约。
- 行动：`{action_items:[{title,source:[{source_key,text}],schedule}]}`。source_key必须来自本轮提供的计划或建议集合；schedule沿用既有日程业务Schema的字段与校验，所有输出只作为候选，统一发布时保存行动项。

更新提示时只做本次接入需要的来源ID和结构一致性调整；旧分析内容规则在T01审阅后决定保留范围，不借此引入新的分析类型。

反馈分支建议：冻结上轮完整分析、有效反馈及来源；核心和认知阶段对反馈指定块重写，未指定块明确复用上一轮；无该类反馈时记录复用而不调用模型。元数据与标签复用上轮结果，行动项基于合并后的完整本轮建议重新规划。所有分支均先完整重建图谱，不复用旧图谱替代重建。

上一轮结果复用是分析产物的显式合并，不通过共享可变state实现。反馈处理提示也冻结、记录请求和结果，不能在任务恢复时读取新反馈替换旧输入。

分析前旧图谱过时的事务与新结果发布事务分开。图谱过时不提前修改旧分析轮次内容；旧分析轮次转历史及新CURRENT轮次生成仍收口于成功发布事务。UI在重分析运行或失败时展示任务状态，不能把旧轮次误显示为本次完成结果。

## 4. 发布保存的改造步骤

1. 将 `_persist_tags` 改为接收外部Session，不自己建立Session或commit；失败抛出，移除“失败不影响结果”的降级路径。
2. 将 `_save_analysis_result` 改为事务内写入函数，移除旧知识守卫、独立commit和日记完成状态更新。
3. 普通和反馈流水线只执行阶段并返回校验后的候选，不在图执行结束时自己保存或清理审计资料。
4. graph_publish锁定用户、任务、日记，先检查同task已有PUBLISHED运行；存在则返回幂等结果。
5. 校验当前及历史端点、来源摘要和全部候选；写图谱结果、分析轮次、标签与行动项；最后更新is_in_graph、日记、主任务和兼容任务状态，一次提交。
6. HISTORY跳过分析和行动项写入，保存已有analysis_run_id引用；每个日期独立提交。任务总状态仅在最后一个日期完成后设置SUCCEEDED。
7. 提交失败在另一个短事务记录FAILED；失败状态记录也检查执行令牌。成功后搜索索引增量更新保留为共享能力，不复用其向量作为图谱向量。

`analysis_history.create_analysis_run_from_state` 和 `action_items.apply_action_planning_result` 是现有事务函数的检查位置；实现时核对间接调用也无独立commit。已有分析、批注、反馈和日程处理语义不得由旧知识清理连带删去。
