# 事件关系识别实现

核对基线：2026-10-29 当前代码、关系 Skill 及配置。三类关系、固定方向与最小充分要点证据见[实体与关系模型](实体与关系模型.md)。

## 1. 共同判断约束

判断单位是具体事件对，完整读取双方要点详情并检查两个方向。同人物、同项目、相似主题、邻近日期和向量相似度均不足以建边。

同一事项的新行动、状态或结果可构成后续，明确形成新安排也是新状态，但不能写成已经执行。触发可来自事件中的部分信息；原文自己提出的推测性联系保留 `SPECULATIVE`，不能变成模型猜测的因果或外部事实认证。明确回忆、比较或联想必须定位具体经历，泛指条件举例不自动对应某个旧事件。

- `RELATED`：证据支持关系，类型、方向、确定程度、描述和双方证据完整。
- `NO_RELATION`：完整检查后未找到符合定义的联系。
- `UNRESOLVED`：已读完但仍有影响判断的具体事实缺口。
- `INDIRECT_FOLLOWUP`：当前 Skill 冗余复核得到的间接延续，只归档不建正式边；应用内协议尚不接受该状态。

工具失败、输入没读完、候选输出缺失属于执行未完成，不能改记无关系或未决。正式边的证据来自双方要点；同篇上下文帮助理解省略，不得依靠第三事件补出双方没有的关键动作、因果或动机。

## 2. 召回与候选的两种实现

| 项目 | 应用内 | 关系 Skill |
|---|---|---|
| 当前事件 | 应用内中高重要事件 | 当前运行全部事件 |
| 历史范围 | 同用户、更早日期、`PUBLISHED` 且事件有效入图 | 同用户、更早日期、`POINTS_READY` 或 `PUBLISHED` 的有效正式要点运行；跨月不截断 |
| 得分 | 当前 / 历史任意要点组合的最大余弦，先聚合历史事件 | 同样按事件最高要点相似度聚合；记录命中要点和分数 |
| 当前默认 | 配置缺省阈值 `0.4`、前 `5` 历史事件 | `min_similarity=0.4`、`top_k=6`，并保留全部分数 `>=0.5` 的事件，取并集 |
| 当天 | 当前单篇完整两两比较 | 当前单篇完整两两比较 |
| 历史池保护 | 查询已发布历史及同向量身份，依赖发布校验 | 冻结全部历史运行、来源 / 向量指纹、覆盖缺口；复验包括未被选中的历史事件 |

参数由 [应用配置](../../../backend/config.py)和 [Skill settings](../../../skills/diary-event-relations/settings.json)读取；任务冻结实际值，不能将缺省值写成所有历史运行都使用的参数。

两条实现均按真实事件 ID 去重，不把不同要点命中重复计为多个事件。不补足不足的 K，不以同月目录限制历史，不因缺失正式要点而悄悄把覆盖缺口记为完成。同日跨篇互比未实现。

## 3. 应用内 A/B/C 流水线

[graph_relations](../../../backend/services/graph_relations.py)执行召回、事件池读取、明确配对清单、预算分批和判断。当前仍使用去重事件池加 pair ID 的批量协议，不是 10 月 19 日提案中的纯单对 A/B 输入。

1. 每个角色按完整输入估算 token，连同最大输出和安全余量判断是否可容纳；单对也超限时报错，不截断全文。
2. A、B 使用同一冻结 v4 提示与模型配置，分别判断同一清单；B 输入不带 A 的结果。
3. 程序检查每对必填字段、枚举、身份、端点、证据编号及完整覆盖。合法结果先保存，缺失 / 错误项仅补答一次；截断批可拆分后重试。
4. A/B 比较 status；相关结果还比较类型、方向、确定性、证据序号和去除首尾空格的 description。描述字面不一致也会进入 C。
5. C 读取分歧对与两个候选裁决，最终来源标记 `AGREEMENT` 或 `ADJUDICATED`。三者相同配置不构成不同模型的独立事实认证。
6. 每对最终结果均归档，只有 `RELATED` 进入正式关系表。

应用内程序验证证据序号属于端点且非空、不重复，不检查自然语言理由是否串到同批第三事件。无关系结果间 A/B 的理由差异不触发裁决；两次同错不能靠该协议发现。

## 4. Skill 代理判断与可编辑稿

[关系 Skill](../../../skills/diary-event-relations/SKILL.md)由当前代理完成语义判断，不默认调用固定 A/B/C，也不默认启动独立审核代理。

- [db_source](../../../skills/diary-event-relations/scripts/db_source.py)读取来源；[workflow](../../../skills/diary-event-relations/scripts/workflow.py)构造冻结池、配对、批次和指纹。新数据库任务不再用本地 replay 稿限制历史范围。
- 默认每批最多 12 对、字符预算 12000，由配置控制。字符数是可读输出保护，不等于模型 token 预算。超限单对须完整补读，不能省略后声称读完。
- 事件以紧凑别名展示，隐藏真实身份由脚本映射；代理只判断清单中的对，不能顺手增加事件池中的其他组合。
- 每条相关结果选双方最小充分要点和连续短引。短引必须在对应详情中唯一出现；含糊时延长引用，不改写文字。程序保留码点位置与详情指纹。
- 无关系和未决保留具体理由，不强制为它们凑双侧短引。稿件清晰展示关系、方向、描述和必要证据，未决保留缺口，无关系折叠。
- `关系结果.md` 是可编辑主稿与入库来源，JSON 仅为批次缓存。已有稿件时状态检查和保存按稿件解析，解析失败不退回旧缓存掩盖错误。

### 4.1 澄清与来源修订

先核对双方全文、必要上下文和已有确认，仅在事实答案会改变是否建边、类型、方向或关键描述时问。问题必须自带双方日期、标题、要点编号及详情原文，用户无需回翻文件才能回答。

用户只补充事实，不需代选技术类别。跳过或记不清后保留未决；不能为了凑关系追问同主题事件。回答若只解释已有要点，可修订本对；若关系必须依靠正式要点之外的新事实，先走受支持的来源修订再新建识别运行，不能用聊天回答替代证据。

事实澄清与整稿确认分别记录，问题和回答放稿外。具体协议见[澄清说明](../../../skills/diary-event-relations/references/clarifications.md)。

## 5. 已实现的后续冗余复核

当前 Skill 已实现 10 月 27 日方案中的替代路径复核、间接留档及历史关系上下文冻结，入口为 [redundancy](../../../skills/diary-event-relations/scripts/redundancy.py)。

1. 完成全部初步配对后读取历史有效后续边，与当前新增后续边一起寻找替代路径；引发、提及不参与该过滤。
2. 程序仅标记存在替代路径的直连。代理逐条读取完整要点及路径，比较直连实际承接的事项，核实各路径段是否始终推进同一事项。
3. 只有替代路径完整表达该承接且直连无额外独立事项 / 行动 / 结果时，判为 `INDIRECT_FOLLOWUP`；部分覆盖、分支或恢复旧安排仍可保留直连。
4. 路径必须真实、连续、无环、至少两条边且不含自身；全部过滤同时生效后，认可路径不能包含本批被删除边。
5. 缺决定或路径失效时返回代理补审或恢复直连，全部完成后才可生成最终稿和预检包。不能把完整复核交给用户，只交一条样例称为完成。
6. 最终稿独立折叠间接延续及理由；归档初稿、历史上下文、逐条决定、认可路径和最终指纹。

“图上可达”不是语义冗余的充分条件，同一节点或要点可能混有多个事项；不能用纯图传递约简自动删除。无替代路径也不能证明直连必然正确。该功能尚未进入应用内 A/B/C 主链路。

## 6. 正式保存与重评

[storage](../../../skills/diary-event-relations/scripts/storage.py)将当前稿直接解析为独立完整包，包含身份、来源、全部判断、真实证据、依赖和冗余归档。预检重查全部来源和历史关系上下文；确认指纹绑定最终版本，不能复用旧稿授权。

普通识别只保存本地结果。明确确认当前完整稿后才执行写入；db / API 和云端完整流程的审阅边界分别见[数据访问配置](../../../skills/diary-workflow/references/api-mode.md)及[云端审阅规则](../../../skills/diary-workflow/references/cloud-review.md)。

正式保存仅补关系与证据、归档全部判断并将当前运行发布；不改要点 / 向量，不启动旧分析。`SKILL_AGENT` 是正式来源代码，完整审阅来源保留在 checkpoint，不冒充双判一致。

已发布结果修订须显式选择替换并备份旧关系、证据和归档。相同包幂等，换稿换指纹；替换不能绕过来源变化检查，也不隐式修改其他历史运行。

## 7. 当前边界与后续工作

- Skill 可引用只有 `POINTS_READY` 的历史要点，不要求历史关系先发布；当前页面的关系展示仍要求关系所属及双端运行 `PUBLISHED` 且端点有效，因此保存成功与即时可视范围必须区分。
- 10 月 27 日提出的分组竞争前序选择、按当前要点保留覆盖、明确指向补召回和链条邻域扩展尚未实现。现有“逐对判断后做路径复核”不等于已完成整份方案。
- 补入较早日记或中间阶段不会自动重评后续全部旧边；已有宽泛后续关系也不会因新规则自动变为直接前序。
- 判断质量分别评估候选覆盖、关系类型 / 方向、证据最小性、间接边误存、分支误删和未完成范围，不能用边数减少证明效果。

验证与保留证据见[验证边界](验证边界与设计依据.md)，尚未落地的完整方案见[后续设计](后续设计与实现差异.md)。
