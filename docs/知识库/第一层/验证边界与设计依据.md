# 第一层验证边界与设计依据

核对日期：2026-10-29。本文提炼影响现行设计的历史选择、质量反例和验收门槛；原始证据及其适用范围见[验证依据](../验证依据.md)。表中的模型、参数和指标均为特定实验的记录，不代表当前部署状态。

## 1. 验证分层

| 层次 | 应核对的内容 | 结论边界 |
|---|---|---|
| 工程正确性 | 身份、结构、引用、状态、事务、来源锁、租约及恢复 | 测试通过不能证明自然语言忠实或关系语义正确 |
| 要点质量 | 原文到要点完整、要点到原文有据，主体、次数、时间、态度和表达强度保持 | 模型自审与程序覆盖清单分别报告，保留人工反例 |
| 候选召回 | 固定语料、参数、人工参照下的正例覆盖和截断 | 未进入候选的漏检不能归到后续判定器；未标注对不是负例 |
| 关系判断 | 状态、类型、方向、描述、证据和直接承接 | A/B一致或边数减少不能代替人工语义核验 |
| 发布与读回 | 当次任务保存、数量、正式身份和依赖 | 发布成功不代表质量通过，也不证明以后数据库仍保持该状态 |

本轮只核对仓库与既有记录，没有重跑模型、查询业务数据库或重新计算历史指标。

## 2. 保留的设计取舍

### 2.1 要点生成与审核

| 历史路线 | 已观察的问题 | 对现行设计的启示 |
|---|---|---|
| 信息清单、要点、双向核验，再增加清单核验 | 清单与审核会一起漏掉“可能”等限定、补出规范解释或反转否定；增加调用仍未消除问题 | 没有同条件证据否定整条路线；现行采用简单生成和独立审核，避免把更多中间清单当质量证明 |
| 原文片段分配、词面保护、概括预算 | 指代和条件被切断，复制正文，补背景与再压缩互相冲突 | 保留忠实自然重写目标，程序引用检查承担定位职责，不取代语义检查 |
| 针对开发事件补充主题或答案 | 输出改善依赖具体答案，不能证明模型自主发现主题 | 用独立示例说明规则；参与提示开发的事件不再当未见测试集 |
| 先详情后标题、编辑任务、增加多轮审核变体 | 仍有主题合并、限定偏移、漏检和修正退步 | 不因单次改善继续堆叠阶段，改动分别验证成本和误修 |
| 思考模式、单模型和跨模型换位 | 思考和跨模型也会漏检或引入新错误 | 不把思考或模型多样性当准确性保证；历史用户未采用跨模型换位方案 |
| 审核与修正合并、再独立复核 | 请求阶段减少，但复核意见漏传和错误意见服从会影响结果 | 保留完整原文核实、独立复核和有限轮次；当前第二轮接收复核意见 |
| 同时返回问题与通过布尔值 | `issues` 与 `ok` 自相矛盾，结构重试也可能重复 | `issues-v2`以问题清单为唯一依据，由程序推导状态；旧任务保留旧协议 |

早期单开发事件的评分按忠实40、完整25、主题15、表达20加总，属于主观评审。记录中 r5 初稿82、开启思考78、Preview71、Kimi初稿84；原流程修正后 Qwen为88/86，Kimi为88/88，另一个新审核变体约80。这些值不构成模型排名、正确率或独立盲评。

10月12日合并审核对照，Kimi两份结果86/90，均值与旧独立修正88/88相同；调用减少而耗时未同比减少。随后0731复测两份主观88/89，同时变更提示与模型，不能把变化单独归因于提示。该轮固定的模型、重试次数和“未上线”状态属于历史阶段，后续协议与运行时配置以[要点实现](要点提取实现.md)为准。

三个取自 `data.json` 的真实示例用于说明生成规则后，不能再作为独立泛化评估事件。服务404、参数不支持、额度不足和网络失败单独记录，不当作生成质量分数。

### 2.2 候选与判定

- 早期逐要点关键词与向量取并集接近全量比较；RRF仍受关键词候选主导。某次关键词资格过滤中，要点命中减少52.3%，事件对只减少4.3%，说明缩小命中不必然缩小事件对成本。
- 纯语义对照曾将跨日候选由24对降为4对；这是当时数据的成本观察，不是覆盖率保证。后续必须用明确正例检查阈值和Top K漏召回。
- 逐对请求重复输入，批量去重降低重复，但多事件池引入串对风险。批量方案保持配对清单、预算与完整覆盖校验；纯单对协议仍是[后续提案](后续设计与实现差异.md)。
- B的独立输入曾检出A未发现的结果，C也曾恢复确认正例；同模型A/B仍会一致漏判。因此既不能以单例删除B/C，也不能以增加判定器替代质量验证。
- 当前A/B描述字面差异也会进入C，减少这类裁决需要同时设计描述忠实性校验，不能只忽略描述字段。

## 3. 必须持续保留的反例

| 回归维度 | 已观察的错误 | 必须验证的边界 |
|---|---|---|
| 指代与主体 | “他们家”被确定为某一家，并补出原文没有的时间关系 | 保留指代缺口，不为通顺擅自消歧 |
| 次数 | 一次退回加审批延迟写成“反复退回” | 等待、未通过与退回不能合并计数 |
| 确定性 | “好像现在去某地”写成“现在去了” | 推测、时态和实际发生分别保留 |
| 行动状态 | 已发消息变成原本想发；形成安排被写成已经执行 | 愿望、计划、决定、行动及结果分别核对 |
| 金额与反馈闭环 | 请求已经携带“两三百”的修正意见，模型候选仍返回“两三万” | 区分模型未执行修正、程序漏传和错误保存；保留实际输入输出 |
| 标题与详情 | 标题将“没告知”改成“已告知”，详情却保留否定 | 详情正确不能补偿标题失真 |
| 核心概念与表达 | 快乐改成成就感；误修把创造性快乐的变化改成含义不同或不自然句子 | 核实语义，不机械逐词对齐或服从审核意见 |
| 关系对象 | 事件ID和证据字段合法，理由却讨论同批第三事件 | 结构校验与理由归属分开验证 |
| 事项进展 | 进入现场、后续处理问题和取得结果被当作只有主题相似 | 用项目、地点、对象、任务和动作定位同一事项，不要求逐字回指 |
| 限定与关系范围 | 局部心理学学习形成安排，被扩大成所有活动已恢复 | 只表达本对证据支持的事项和状态，不沿关系传递补事实 |

真实请求与人工拟议格式分开保存，来源见[10月19日证据组](../验证依据.md#34-10-月-19-日实际错误与待确认协议)。额外结构错误按类别保留代表性原始记录，不能删除到只剩“质量有问题”的概述。

9月多日原型的原文核验曾发现27事件中14事件需要修正，涉及遗漏、归属、确定性与新增抽象结论。其整改版本、范围和逐事件记录见[原型样本核验](../验证材料/原型多日样本/原文核验.md)。这些历史样本保留作设计追溯，不套用当前生产模型或解释为当前错误率。

## 4. 10月15日校准结果与适用范围

固定开发集为三个日记日期的11事件、51要点、55个可能事件对。复用同一输入与向量，比较三种候选规则：

| 当时规则 | 候选对 | 6个确认正例被召回 | 最终识别正例 |
|---|---:|---:|---:|
| 阈值0.5、前五 | 21 | 4 | 3 |
| 阈值0.4、前五 | 32 | 6 | 5 |
| 无最低分、前五 | 47 | 6 | 5 |

- 0.5漏掉两条得分0.4231、0.4923的确认关系；0.4在该集恢复候选覆盖，但仍有一条已召回关系最终为未决。
- 22条确认负例中21条判无关系、1条未决，不能将“无误连”表述为全部正确排除。
- 0.4相对0.5多11对，约增加52%的候选；这是候选量变化，不是固定请求费用增幅。
- 无最低分时实际出现前五截断，0.4在该集没有超过五个达标历史候选；不能据此保证大历史池质量。
- 两个模型失败候选保留在独立诊断输入中，不代表11事件端到端通过。三档共用候选并集的一次A/B/C输出，不是分别跑了三套生产批次。
- Kimi要点9/11获得模型通过，Qwen原四事件3/4；人工仍发现确定性、单位和动作等错误。相同原四事件的新旧流程均为3/4，不能宣称完成率提高或语义验收通过。

冻结来源、最终候选、人工参照、分数、判断、请求汇总及代表失败见[校准证据](../验证依据.md#32-10-月-15-日要点优化与召回校准)。历史向量流水清理后只保证原统计可查，不承诺离线重算embedding。

当前仍需分别验证状态、类型、方向、描述与证据；这组状态统计不等于每个细节均准确。[保留集原报告和标签](../验证依据.md#33-10-月-14-日未见样本保留集)继续保留。

## 6. 后续验收要求

1. 开发反例与未参与调参的保留集分开，固定来源、规则、模型身份与配置后再比较。
2. 只改变一个因素或明确报告同时变化；自然重写、简化协议、模型切换与召回变化分别核对。
3. 结果同时报告正常与失败路径的请求、token和耗时；网络失败单列，响应耗时之和不冒充墙钟时间。
4. 覆盖同名事件、主体、次数、金额、态度、计划状态、观点归属、语义串对、A/B互换和错误审核意见。
5. 覆盖跨月、超过K的竞争池、低语义分的明确指向、同日跨篇、分支汇合、间接路径、多事项和历史补记；未实现的场景明确列缺口。
6. 工程测试保持来源锁、事务回滚、幂等、环境隔离、预算、协议版本和失败恢复门禁。
7. 反复同类失败时先重新评估生成目标与协议，不通过无限提示叠加、无限重试或更改确认标签取得“通过”。

新增模型调用、历史重评或正式数据修订另按对应执行入口与权限约定处理。本轮文档整理不执行这些操作。
