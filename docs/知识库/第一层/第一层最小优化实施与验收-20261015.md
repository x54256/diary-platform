# 第一层最小优化实施与验收

日期：2026-10-15。依据用户“执行优化吧”及允许使用8月17、18、23日11个历史事件的授权执行。范围为要点审核闭环、审核协议精简、固定前五的召回校准。正式业务库只读，未写入图谱，未执行后续六阶段分析。

## 2. 验证方法

工程回归使用独立的本地PostgreSQL测试库，43项图谱相关测试通过，覆盖审核新旧协议、恢复、配置冻结、召回前五、事务发布和迁移。随后新增“两轮持续有问题即停止”和“裁决多余编号给出具体错误”两个测试，共45个不同测试通过。默认改为0.4后，针对配置冻结、精确召回、协议和校准的10项测试再次通过；最后新增编号回归后，9项协议及校准单测通过。未在正式业务库运行写入测试。

真实模型实验分别使用：

- Qwen：既有四事件，复用原生成初稿，仅重新执行新版审核修正。
- Kimi：授权的11个历史事件，其中四个复用同原文的既有Kimi生成初稿，七个新生成；语言模型为`kimi-k3`，开启思考。
- 召回：Flash向量模型`qwen3.7-text-embedding-flash`，1024维，完整detail逐条编码；相同固定要点和向量比较三档规则。关系A/B共用v4提示，C沿用既有裁决提示。

正式管理端语言模型绑定保持Qwen。实验借用正式要点状态机，但模型运输沿用历史脚本：请求超时600秒，服务默认温度与输出长度；正式调用的超时及输出上限不同。因此本轮结果用于比较协议、闭环与召回，不能声称完整复现了线上所有调用参数。

“模型审核通过”仅表示该次流程的模型清单无问题；是否忠实仍须独立对照原文。召回的历史参照仅含28对关联状态，包含6个正例，不能代表所有事件对已完成标注，也不能替代关系类型、方向和证据的验收。

## 3. 开发中遇到的问题与处理

| 问题 | 原因与处理 | 结果 |
| --- | --- | --- |
| 有issues却同时输出通过 | 旧协议要求模型重复表示同一个判断；新版只保留issues，由程序计算状态 | 新版移除了这类逻辑矛盾的输出字段；结构与语义问题仍须分别检查 |
| 下一轮重新发现同一个问题 | 旧合并修正没有收到独立复核意见；新增反馈字段并随检查点保存 | 真实请求及失败恢复测试均确认意见送达 |
| 结构错误仍然出现 | 模型仍会写错顶层字段或引用；保留严格校验，将具体错误反馈后最多补一次输出 | 未把不合法结果静默转成合法结果，达到上限后停止 |
| Qwen聚餐结构补答超时 | 首次输出引用不连续，补答遇到网络超时 | 保存transport_error；该事件失败，不计作语义误判或协议必然失败 |
| Kimi出差最终误报 | 原文明确“就不上午去了，就下午再出发”，最后复核却否认原计划上午有依据 | 保留原任务失败；仅为独立召回实验提供带原文核对理由和输入哈希的例外清单 |
| 模型发现金额错误却没有修正 | 小豪事件原文“两三百”被改为“两三万”；第二轮已收到明确复核意见，但修正版仍保留错误 | 最终独立复核再次指出金额错误，任务在两轮后失败；仅冻结失败候选用于召回诊断，不认可其忠实性 |
| 模型放过其他语义变化 | Qwen出差仍有“多次退回”等失真；Kimi同事信息存在“好像去北京”变为“去了北京”等变化 | 本轮没有达到全部事实忠实的验收要求，不能以结构通过替代质量通过 |
| 裁决多输出一个事件对且脚本错误说明为空 | C首次输出8个请求编号之外的`P039_dup`；复测脚本原编号断言没有说明文字 | 原始记录保留；一次补答后输出合法。脚本补充预期/实际编号错误信息，并通过对应回归，不追加模型重测 |

## 4. 真实验证结果

### 4.1 要点流程

| 事件 | Kimi（11事件） | Qwen（原四事件） |
| --- | --- | --- |
| 出差行程安排 | 失败：最终复核否认原计划上午的依据 | 模型通过，但独立核对仍有多次退回等失真 |
| 暴雨蹚水 | 模型通过 | 未测 |
| 误咬洁厕灵 | 模型通过 | 未测 |
| 聚餐阅读 | 模型通过 | 失败：结构补答网络超时 |
| 洗牙拔牙 | 模型通过 | 未测 |
| 初到项目现场 | 模型通过 | 模型通过 |
| 小豪分手 | 失败：金额百倍错误未修正 | 未测 |
| 出差工作推进 | 模型通过 | 模型通过 |
| 同事近况 | 模型通过 | 未测 |
| 宠物体检 | 模型通过 | 未测 |
| 父母身体 | 模型通过 | 未测 |

Kimi为9/11模型通过，原四事件子集为3/4；Qwen为3/4。两组旧协议的原四事件也各为3/4，因此没有证据声称此次调整提高了该子集的完成率。原有`issues`与`ok`矛盾已从新协议移除，但阻断原因转为模型语义误报、其他结构错误或网络问题。

Kimi模型通过的事件仍存在独立核对发现的变化：暴雨候选把“我们的车”限定为“电动车”；同事候选把“好像现在去北京”改成“现在去了北京”，把“从哪知道李恒”改成“怎么认识李恒”；洗牙候选把已发微信改成原本想发。小豪最后候选除金额错误外，摘要仍有计划与实际混淆、擅加“前任”身份。这些反例表明本轮语义验收未通过。

小豪金额错误已核对第二轮请求、原始响应和最终候选：请求确实携带上轮指明“两三百”的意见，第二轮原始响应的`candidate`本身仍写“两三万”，保存的候选与之相同。证据指向模型没有执行修正，不能归因为程序漏传意见或保存了旧候选。

### 4.2 新增要点请求成本

| 实验 | 新请求 | 有响应 | 结构错误响应 | 网络失败 | 响应total_tokens合计 | 成功响应耗时之和 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| Kimi 11事件 | 28 | 28 | 3 | 0 | 238712 | 3725.90秒 |
| Qwen 4事件 | 7 | 6 | 2 | 1 | 38439 | 364.28秒 |

扣除了每组复用的四份生成初稿，包含补答请求；Kimi另有七次新生成。网络超时没有用量及耗时记录，表中耗时不含其等待时间；耗时相加也不等于并行执行的墙钟时长。结构错误中Kimi为顶层字段错误，Qwen为漏要点检查及不连续引用。不得将两组不同规模实验直接比较单位效率或费用。

### 4.3 召回校准

11事件共51个要点、55个可能事件对。相同输入下结果如下：

| 规则 | 候选事件对 | 已确认正例覆盖 | 无原确认标签的候选 |
| --- | ---: | ---: | ---: |
| 阈值0.5，前五 | 21 | 4/6 | 0 |
| 阈值0.4，前五 | 32 | 6/6 | 5 |
| 无最低分，前五 | 47 | 6/6 | 19 |

0.5漏掉“出差安排—工作推进”（0.4231）与“初到现场—工作推进”（0.4923）。无最低分时，8月23日四个事件各有七个历史事件，实际发生前五截断；0.4规则在本样本中尚未出现五个以上达标历史候选。前五的严格上限另由隔离数据库与边界单测验证，不能宣称已经验证更大规模历史池的质量。

出差、小豪两个模型失败候选通过显式诊断清单冻结，包含输入SHA及具体理由。原任务保持失败；小豪的金额错误保留在实验输入中，六个确认正例均不含该事件，但它参与候选竞争。因此这里评价的是独立召回规则，不能算11事件端到端通过。

三档共用候选并集的一份A/B/C判定，控制相同事件对的模型输出，避免将三次独立采样的差异误认为阈值收益。这不等于分别执行三套生产批次；批次上下文和正式Token预算分批的影响没有在本实验中单独验证。

选择0.4作为新任务默认：相对0.5新增11对，其中2个确认正例，其余9对A/B均判无关系；取消最低分额外增加15对，没有新增确认正例覆盖。0.4的候选量相对0.5增加约52%，这是本样本的代价，不代表固定请求费用增幅。旧任务继续使用已冻结的阈值；新进程加载配置后，新任务冻结0.4。未改正式模型绑定。

### 4.4 最终关系判定

| 规则 | 6个确认正例最终识别 | 确认正例漏检 | 22个确认负例误连 | 确认负例判无关系 | 确认负例未决 | 未标注的RELATED |
| --- | ---: | ---: | ---: | ---: | ---: | --- |
| 0.5，前五 | 3 | 3 | 0 | 21 | 1 | 无 |
| 0.4，前五 | 5 | 1 | 0 | 21 | 1 | 无 |
| 无最低分，前五 | 5 | 1 | 0 | 21 | 1 | 聚餐阅读—初到现场 |

0.4新增召回的两个正例最终都识别为RELATED。仍未识别的正例是“洗牙拔牙—宠物体检”：虽然双方都记载同一次洗牙拔牙结果，C以无法区分新进展与重复回顾为由判UNRESOLVED。该事件对已召回，剩余问题发生在关系判断阶段；本轮保留既有确认标签，不为提高结果改标签。

确认负例“误咬洁厕灵—宠物体检”最终也为UNRESOLVED。因此“误连为0”不能解释成22个负例全部正确排除；其中一个仍未明确判断。无最低分额外输出的“聚餐阅读—初到现场”没有原确认标签，不能直接计作正确关系或误判。

A/B四个批次一次结构通过，47对共出现8对分歧，其中5对关联状态不同。C第一次额外输出`P039_dup`被拒，第二次补答合法，没有第三次请求。实际校准共6次语言请求，total_tokens合计117263，成功响应耗时之和1661.07秒；另有6次向量请求、3290 tokens。三档共用这6次语言请求，不能将其当作三档各自的成本。

本次聚餐与出差安排被判“提及事件”，与前轮Kimi四事件实验的“引发事件”不同。关联状态之外的类型、方向及描述没有完整确认参照，仍不宣称全部准确。

## 5. 后续边界

本轮保留两轮上限，不新增更多审核器或提示轮次。更改生成目标、改为保留来源片段、切换正式语言模型均属于后续决策，不在本轮直接实施。

本轮三项优化均完成代码实现、逐项检查和有限真实验证：审核重复状态已移除，具体复核意见已送达，0.4的开发集召回覆盖改善。但要点仍有失真和误报，6个确认关系正例最终只识别5个，整体质量验收未通过。按本轮投入边界停止继续叠加提示或重试，保留结果供下一步设计判断。

## 6. 复现与证据

从`backend`目录使用Python 3.11环境执行，加载现有`.env`。以下命令会调用已配置的真实模型，成功缓存直接回放；已有服务失败不会自动反复请求。

```bash
venv/bin/python scripts/recheck_graph_quality.py \
  --folder ../knowledge-graph/implementation-verification-20261014/optimized-kimi-20261015 \
  --phase points --model kimi-k3 --optimized

venv/bin/python scripts/calibrate_layer1_recall.py \
  --folder ../knowledge-graph/implementation-verification-20261014/optimized-kimi-20261015 \
  --reviewed-inputs ../knowledge-graph/implementation-verification-20261014/optimized-kimi-20261015/reviewed-retrieval-inputs.json

venv/bin/python -m unittest tests.test_graph_point_protocol tests.test_graph_recall_calibration -q
```

本地实验材料位于`knowledge-graph/implementation-verification-20261014/optimized-kimi-20261015/`与`optimized-qwen-four-20261015/`。`point-outcomes.json`记录逐事件结果，`points/*/checkpoint.json`记录轮次与待修正意见，模型阶段JSON保留请求、完整输出和错误，`new-point-request-metrics.json`记录扣除复用初稿后的本轮请求统计。`calibration/recall.json`记录55对分数、三档候选及诊断例外；最终判定与指标另存`final.json`、`metrics.json`。这些文件包含个人原文及模型输出，仅作为本地验收材料。
