# 第一层完整隔离实测

本次范围：08-23 的 4 个准入事件作为历史样本，08-26 的 6 个准入事件作为当前样本。原文来自同一用户；08-23 通过只读 SQL 导出，08-26 使用此前冻结的来源文件。

## 运行阶段

1. `export`：冻结原文、来源 ID、日期及有效重要性。AI 重要性及其理由用于确认已有重要性分析结果；不把旧 `analysis` 字段是否为空作为准入判断。
2. `points`：使用已确认的要点提示版本，生成要点、合并审核修正、按原流程复核；保存全部响应。结构违规保留失败记录，不采用无审核依据的改写。
3. `audit`：额外独立复核最终候选，不传此前审核意见。该额外复核及最多一次修正属于本次试验质量检查，单独记录。
   本次额外复核仍有遗漏，随后执行 `source-fixes` 保存 Codex 原文审阅确定的最小修正，使用 `source-fix-review` 重新复核受影响的 3 个事件；该补充复核显式关闭思考，配置独立保存。
4. 原文审阅：Codex 对照原文检查最终要点并记录结果。此审阅是实测输入检查，用户尚未逐条人工确认，不提交正式图谱。
5. `embeddings`：仅发送要点 `detail`，使用现有已授权阿里云渠道的 `qwen3.7-text-embedding`，要求 1024 维并检查数值、返回顺序和模型标识。
6. `load`：载入专用隔离 PostgreSQL；建立 `vector(1024)` 字段、约束和中文 GIN 表达式索引。事件表只复制检索需要的元数据，用于试验。
7. `relations`：先完整比较 08-23 的 6 对事件，再在测试库中准备其历史入图状态；对 08-26 每个要点执行关键词 OR / `ts_rank` 和余弦精确距离两路历史检索，每路前 10 条；按事件去重，加入当天 15 对，逐对读取全部要点并判断关系，校验确定性与引用，映射证据 ID，保存候选记录。
8. `boundaries`：在回滚事务中验证其他用户、未入图、当天及未来事件不会进入历史候选，验证缺失向量会阻止双路检索。

历史 `is_in_graph=true` 是本次隔离检索测试的前置状态。正式关系表、独立关系语义核验、用户人工确认及整日发布仍属于后续设计范围；本次不执行生产发布。

## 环境

- 容器：`diary-layer1-test-20261012`，仅绑定本机 `55432` 端口；测试库 `layer1_test`。
- 基础镜像：zhparser 项目的 `zhparser/zhparser:bookworm-16`，拉取摘要 `sha256:317d08c186a8629ad02bddaa8bff3580b9da67814042ee4b08deda57b4d0d8f5`。
- 容器中安装 `postgresql-16-pgvector`；实际扩展版本保存于 `database-preparation.json`。
- 中文配置 `layer1_zh` 使用 zhparser；映射 `n,v,a,i,e,l` 到 simple 字典。应用提交原文，由数据库分词。
- 关系模型 `deepseek-v4-flash-0731`，增加 `certainty` 和原文明示推测关系准入规则，完整提示保存于 `relation-config.json`。
- 向量 API 实测返回 1024 维，因此沿用现有配置；未切换为此前调研的 `text-embedding-v4`。

后端命令在 `backend` 目录使用 `venv/bin/python -m scripts.validate_layer1_full <阶段>`。运行需网络授权；程序不输出连接串或密钥。结果已有时使用已保存响应，不覆盖来源快照。

试验结束后已导出测试库并停止专用容器，容器及数据保留。需要本机复核时可执行 `docker start diary-layer1-test-20261012`。`load` 会拒绝覆盖已有表，重跑应使用新的测试库及输出目录，或直接检查已保存响应。

## 记录与限制

原始模型输出与失败响应保存在 `points/`、`relations/`；两路检索 SQL、分词词项、命中排名、分数、向量及候选并集单独保存。模型调用费用按服务实际账单核算，已保存响应中的 Token 用于统计可观测消耗。

本样本用于验证流程。原文无直接证据的 `data.json` 扩写关系不能作为真值；跨日正例是否存在需单独依据原文核验，不能仅凭运行成功宣布召回质量通过。
