# 线上镜像打包部署流程

目标：在本地 ARM 机器构建 x86 镜像，上传到服务器，并用原生 Docker 更新线上应用。

基础设施与应用分开管理：

- `docker/docker-compose.infra.yml`：PostgreSQL、MinIO，仅在首次部署或基础设施变更时操作。
- `docker/docker-compose.prod.yml`：应用容器，日常发布只更新该 Compose。

## 0. 应用快速更新步骤

```shell
docker buildx build --platform linux/amd64 -f docker/Dockerfile -t 8.138.211.67:5000/diary-platform:latest --load .
docker push 8.138.211.67:5000/diary-platform:latest

ssh root@8.138.211.67
i-7xva84auygwvnq3d5jfr

cd /root/workspace/diary-platform
docker compose -f docker-compose.prod.yml down
docker compose -f docker-compose.prod.yml up -d --pull always


docker tag 8.138.211.67:5000/diary-platform:latest 8.138.211.67:5000/diary-platform:backup
```

如果需要更新 docker-compose 文件：

```shell
scp docker/docker-compose.prod.yml root@8.138.211.67:/root/workspace/diary-platform/
i-7xva84auygwvnq3d5jfr
```

## 1. 前置文件

项目根目录必须存在：

```text
docker/docker-compose.infra.yml
docker/docker-compose.prod.yml
```

文件职责如下：

- `docker/docker-compose.infra.yml` 包含 PostgreSQL、MinIO、端口映射和数据持久化目录。
- `docker/docker-compose.prod.yml` 仅包含应用运行环境变量和应用端口。

`docker/docker-compose.prod.yml` 中的数据库和 MinIO 地址必须保持为：

```env
DATABASE_URL=postgresql+psycopg://root:5456@host.docker.internal:5432/my_db
MINIO_ENDPOINT=host.docker.internal:9000
MINIO_PUBLIC_ENDPOINT=8.138.211.67:9000
```

`docker/docker-compose.*.yml` 包含敏感信息，不能提交到 git。

## 2. 本地构建 x86 镜像

### 2.1 构建应用镜像

在项目根目录执行：

```bash
docker buildx build --platform linux/amd64 -f docker/Dockerfile -t diary-platform:latest --load .

docker tag diary-platform:latest 8.138.211.67:5000/diary-platform:latest
docker push 8.138.211.67:5000/diary-platform:latest
```

```sh
# 远程服务器
docker run -d -p 5000:5000 --name registry registry:2
vim /etc/docker/daemon.json
{
  "insecure-registries": ["8.138.211.67:5000"]
}
sudo systemctl daemon-reload
sudo systemctl restart docker

# 本地 docker 也要加上面配置，重启 docker 服务
```

确认镜像存在：

```bash
docker images | grep diary-platform
```

## 3. 导出镜像包

导出应用镜像：

```bash
docker save diary-platform:latest -o diary-platform-latest-amd64.tar
```

## 4. 上传部署文件

服务器部署目录：

```text
/root/workspace/diary-platform
```

创建服务器目录：

```bash
ssh <user>@<host> "mkdir -p /root/workspace/diary-platform"
```

上传镜像包和 compose 文件：

```bash
scp diary-platform-latest-amd64.tar root@8.138.211.67:/root/workspace/diary-platform/

scp docker/docker-compose.infra.yml root@8.138.211.67:/root/workspace/diary-platform/docker/

scp docker/docker-compose.prod.yml root@8.138.211.67:/root/workspace/diary-platform/docker/
```

## 5. 服务器更新容器

登录服务器：

```bash
ssh root@8.138.211.67
i-7xva84auygwvnq3d5jfr
```

进入部署目录：

```bash
cd /root/workspace/diary-platform
```

检查两个 Compose 文件：

```bash
docker compose -f docker/docker-compose.infra.yml config
docker compose -f docker/docker-compose.prod.yml config
```

基础设施首次部署或基础设施 Compose 发生变更时：

```bash
docker compose -f docker/docker-compose.infra.yml up -d
docker compose -f docker/docker-compose.infra.yml ps
```

确认 PostgreSQL 健康：

```bash
docker exec postgres pg_isready -U root -d my_db
```

确认 MinIO 存活：

```bash
curl -fsS http://127.0.0.1:9000/minio/health/live
```

基础设施使用宿主机目录持久化数据：

```text
/root/workspace/postgres
/root/workspace/minio-data
```

停止基础设施时禁止使用 `down -v`，避免误删数据卷。日常应用发布不需要停止 PostgreSQL 或 MinIO。

加载新镜像：

```bash
docker load -i diary-platform-latest-amd64.tar
```

基础设施正常后，再更新应用容器：

停止旧容器：

```bash
docker compose -f docker/docker-compose.prod.yml down
```

启动服务：

```bash
docker compose -f docker/docker-compose.prod.yml up -d
```
